## 2. 总览结论

从现有样本看，轻量化提示词下的“不稳定”至少有两种失败模式：

1. **部署触发后的 run 详情查询接口返回 HTML 404**
   - 失败点落在 `deployment_trigger_submit` 之后
   - 部署前所有阶段都通过
   - 失败信息统一表现为：
     - `Cannot GET /api/altus-managed/sessions/:sessionId/runs/:deployRunId`

2. **部署面板停在收敛态或错误态，E2E 轮询最终超时**
   - 失败点落在真正部署后半段
   - 表现为：
     - `bindingState = public_settling`
     - `latestStatus = FAILED`
     - `analytics.status = bound`
     - 最终报错 `deployment panel settled not ready`

也就是说，当前“轻量化提示词部署不稳定”不是单一根因，而是：

1. 有时死在 **部署触发后的 run 状态查询接口**
2. 有时死在 **部署已触发后的收敛与验证阶段**

```text
failed to parse JSON from http://127.0.0.1:4000/api/altus-managed/sessions/:sessionId/runs/:deployRunId
Cannot GET /api/altus-managed/sessions/:sessionId/runs/:deployRunId
```

这说明在轻量化提示词样本里，当前最新一轮失败不是：

1. 工作区没生成出来
2. 模板基线不通过
3. 部署根本没触发

而是：

1. 网站源码生成完成
2. 官方固定模板壳存在
3. 部署模板基线通过
4. 聊天触发部署也提交成功
5. 但部署触发后的 run 详情查询接口返回了 HTML 404

### 5.2 另一类失败原文

另一类失败是：

```text
[timeout] deployment panel settled not ready
bindingState = public_settling
latestStatus = FAILED
analytics.status = bound
```

这说明还有一类失败不是接口 404，而是部署链路进入了后半段，但没有稳定收敛到最终可交付状态。

## 6. 成功与失败的分界点

### 6.1 成功样本的共同特征

成功样本的共同特征是：

1. `managed_run_terminal.runStatus = completed`
2. `workspace_marker_source = passed`
3. `deployment_template_baseline.status = ready`
4. `deployment_trigger` 之后还能继续走到：
   - `deployment_state_persisted`
   - `public_url_reachable`
   - `analytics_bootstrap_published`
   - `browser_visit_public_url`
   - `analytics_status`
5. 最终：
   - `bindingState = ready`
   - `deploymentStatus = SUCCESS`
   - `analyticsStatus = tracking`

### 6.2 最新失败样本的共同分界点

最新两个失败样本都停在：

1. `deployment_trigger_submit = passed`
2. 下一步想轮询 deploy run 详情
3. 结果接口返回 HTML 404

所以这两个最新失败样本的明确分界线就是：

- **部署触发已提交**
- **部署后续 run 状态查询接口不可用**

### 6.3 另一类失败样本的分界点

`public_settling` 超时那类失败的分界线是：

1. 部署动作已经继续往后走
2. 也拿到了 `publicUrl/publicDomain`
3. 但 provider 最终状态变成 `FAILED`
4. analytics 只到 `bound`
5. 最终部署面板没有稳定收敛

## 7. 初步观察

只基于现有日志，不做额外猜测，当前可以先得到这几个结论：

1. 轻量化提示词并不是“稳定失败”，而是“成功与失败混杂”
2. 最新两次失败，问题已经前移到 **部署触发后的 run 详情查询接口**
3. 另一些失败，问题落在 **部署后半段收敛**
4. 在最新两次失败里，部署前面的生成链路其实是正常的：
   - 会话创建正常
   - runtime 启动正常
   - managed run 正常完成
   - 工作区正常生成
   - 模板基线正常通过
5. 因此如果只看“轻量化提示词下部署不稳定”，至少要分开看这两层：
   - **触发后 run 查询是否稳定**
   - **真正部署后的公网与 analytics 收敛是否稳定**
