# 发布与访问功能设计

## 1. 功能定位

“发布与访问”是部署工作台的默认二级页，承担最核心的闭环：

- 发布新版本
- 查看当前状态
- 打开网站
- 查看历史版本
- 查看发布日志

## 2. 页面结构

建议保持以下信息块：

- 顶部发布摘要卡
- 当前访问地址
- 快速操作区
- 版本时间线
- 当前版本详情
- 资源状态
- 发布日志

## 3. 数据依赖

当前可复用的数据：

- `configured`
- `canDeploy`
- `latestStatus`
- `deployments`
- `domains`
- `logs`
- `project/service/environment`

后续建议新增的数据：

- 明确的阶段态字段
- 最近一次成功发布时间
- 部署来源摘要
- 回滚可用性标记

## 4. 计划设计方式

### 当前阶段

- 保持“发布工作台”作为默认页。
- 继续强调主访问地址与主操作按钮。
- 版本历史改为卡片式而不是纯下拉选择。

### 下一阶段

- 增加分步骤状态条：准备资源、同步源码、构建、发布成功。
- 增加发布完成后的成功反馈区。
- 为首次发布和更新发布区分不同文案。

## 5. 审核点

- 默认页是否继续叫“发布”，还是改回“概览”。
- 日志和版本详情是否应该继续同屏显示。
