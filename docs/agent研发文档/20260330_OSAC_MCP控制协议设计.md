# OSAC MCP 控制协议设计 [20260330-1027已采用]

更新时间：2026-03-30

## 1. 目的

本文档是 [20260330_OSAC驱动Altus模式MCP运行时注册设计.md](/Users/watson/codingProj/oneceo/docs/agent研发文档/20260330_OSAC驱动Altus模式MCP运行时注册设计.md) 的协议拆分稿，专门描述：

1. `apps/api -> OSAC` 的 MCP 控制指令
2. OSAC 回传的状态消息
3. session tool 查询协议

## 2. 协议原则

1. 不再使用 `ADD_MCP_SERVER / REMOVE_MCP_SERVER` 作为 Altus mode 主协议
2. 控制粒度从“配置 server”升级为“管理 provider 生命周期”
3. 所有协议必须绑定 `taskSessionId`、`bindingId`、`profileId`
4. 所有状态回传都必须可落库、可审计、可恢复

## 3. Server -> OSAC 指令

### 3.1 `REGISTER_MCP_PROVIDER`

```json
{
  "type": "REGISTER_MCP_PROVIDER",
  "payload": {
    "bindingId": "binding-1",
    "profileId": "profile-1",
    "taskSessionId": "task-session-1",
    "displayName": "GitHub - Prod",
    "serverName": "github--task-session-1--profile-1",
    "sourceType": "local_stdio",
    "transport": {
      "command": ["npx", "-y", "@modelcontextprotocol/server-github"]
    },
    "runtimeEnv": {
      "GITHUB_PERSONAL_ACCESS_TOKEN": "xxx"
    },
    "headers": {},
    "attachToSession": true
  }
}
```

### 3.2 `UPDATE_MCP_PROVIDER_ENV`

```json
{
  "type": "UPDATE_MCP_PROVIDER_ENV",
  "payload": {
    "providerId": "provider-1",
    "runtimeEnv": {
      "GITHUB_PERSONAL_ACCESS_TOKEN": "new-token"
    },
    "headers": {
      "Authorization": "Bearer new-token"
    }
  }
}
```

### 3.3 `ATTACH_MCP_PROVIDER_TO_SESSION`

```json
{
  "type": "ATTACH_MCP_PROVIDER_TO_SESSION",
  "payload": {
    "providerId": "provider-1",
    "taskSessionId": "task-session-1"
  }
}
```

### 3.4 `DETACH_MCP_PROVIDER_FROM_SESSION`

```json
{
  "type": "DETACH_MCP_PROVIDER_FROM_SESSION",
  "payload": {
    "providerId": "provider-1",
    "taskSessionId": "task-session-1"
  }
}
```

### 3.5 `REMOVE_MCP_PROVIDER`

```json
{
  "type": "REMOVE_MCP_PROVIDER",
  "payload": {
    "providerId": "provider-1"
  }
}
```

### 3.6 `LIST_SESSION_MCP_TOOLS`

```json
{
  "type": "LIST_SESSION_MCP_TOOLS",
  "payload": {
    "taskSessionId": "task-session-1"
  }
}
```

## 5. 错误语义

统一错误码建议：

1. `provider_not_found`
2. `provider_start_failed`
3. `provider_attach_failed`
4. `provider_detach_failed`
5. `provider_env_invalid`
6. `provider_transport_invalid`
7. `session_not_found`
8. `tool_schema_load_failed`

## 6. 协议实施要求

1. 所有指令都必须带 requestId
2. 所有响应都必须能映射到 requestId
3. provider 状态变化必须异步上报，不依赖请求同步返回
4. `LIST_SESSION_MCP_TOOLS` 必须返回当前 session 真实可调用工具，不返回 definition 静态声明
## 7. MCP 高风险工具调用统一确认标准

所有 MCP provider 的高风险 `tools/call` 必须遵循统一确认标准，详见：

- `docs/agent研发文档/20260504_MCP高风险工具调用统一确认标准_[20260504-1256已采用].md`

协议层约束：

1. `tools/call` 在进入真实 MCP provider 前，必须由 API broker 进行风险分类。
2. send/create/update/delete/share/permission/deploy 等会改变外部状态的 MCP 调用，必须先返回 `confirmation_required`，由前端显示统一确认 UI。
3. 用户必须点击确认 UI 的 `确认执行` 才能生成一次性 confirmation token；普通聊天文本不能作为授权。
4. confirmation token 必须绑定 user、task session、run、connector/provider、tool name 与 arguments hash。
5. token 只允许执行同一参数的同一次 tool call，执行完成或失败后必须失效。
6. 如果无法提取可复核目标对象，例如 recipient、file id、event id、repo、deployment id，broker 必须拒绝执行并要求 agent 补齐目标。
7. OSAC 与 sandbox 不得绕过 API broker 直接执行高风险 MCP tool call，也不得持有长期确认权限。
8. 所有确认、拒绝、消费、失败事件必须可审计并可关联 run event。
