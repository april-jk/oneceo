# 20260502 会员与Agent权益管理数据模型设计 [尚未采用]

## 1. 设计目标

本文件定义会员体系的数据模型、索引、约束与迁移顺序，目标是保证会员类型、用户归属、默认权益发放和审计记录都能在数据库层闭环。

## 2. 关系边界

会员体系需要对接的既有实体：

1. `app_users`：用户主表
2. `credit_transactions`：积分交易表
3. `task_creation_sessions`：任务创建会话
4. `task_session_runs`：任务执行运行

会员体系不替代积分体系，只向积分体系发起默认权益发放。

## 3. 核心表

### 3.1 membership_plans

会员类型定义表。

建议字段：

- `id`
- `code`
- `name`
- `status`
- `default_credits`
- `allowed_agent_levels_json`
- `benefits_json`
- `description`
- `sort_order`
- `effective_from`
- `effective_until`
- `created_by`
- `created_at`
- `updated_at`

建议约束：

- `code` 唯一
- `status` 仅允许 `active` / `inactive`
- `allowed_agent_levels_json` 必须是合法 tier 数组

### 3.2 user_memberships

用户当前会员归属表。

建议字段：

- `id`
- `user_id`
- `membership_plan_id`
- `status`
- `started_at`
- `expires_at`
- `source_type`
- `source_id`
- `assigned_by`
- `assigned_reason`
- `created_at`
- `updated_at`

建议约束：

- 同一用户同一时刻只能有一条 `active`
- `expires_at` 可空，表示长期有效
- 到期后可保留为历史记录

### 3.3 membership_grants

会员默认权益发放记录表。

建议字段：

- `id`
- `user_id`
- `membership_plan_id`
- `grant_credits`
- `grant_reason`
- `grant_status`
- `credit_transaction_id`
- `created_at`

建议约束：

- `credit_transaction_id` 唯一
- 同一分配动作只能发放一次

### 3.4 membership_audit_logs

会员管理审计表。

建议字段：

- `id`
- `actor_id`
- `action`
- `target_type`
- `target_id`
- `before_json`
- `after_json`
- `reason`
- `created_at`

建议动作：

- `membership_plan.create`
- `membership_plan.update`
- `membership_plan.disable`
- `user_membership.assign`
- `user_membership.expire`
- `membership_grant.issue`
- `membership_grant.replay`

## 4. 索引设计

### 4.1 membership_plans

- `idx_membership_plans_code`：`code` 唯一索引
- `idx_membership_plans_status`：按状态查询
- `idx_membership_plans_sort_order`：列表排序

### 4.2 user_memberships

- `idx_user_memberships_user_id`：按用户查会员
- `idx_user_memberships_plan_id`：按会员类型查用户
- `idx_user_memberships_status`：按状态筛选
- `idx_user_memberships_expires_at`：到期扫描

### 4.3 membership_grants

- `idx_membership_grants_user_id`
- `idx_membership_grants_plan_id`
- `idx_membership_grants_created_at`

### 4.4 membership_audit_logs

- `idx_membership_audit_logs_actor_id`
- `idx_membership_audit_logs_target_type_target_id`
- `idx_membership_audit_logs_created_at`

## 5. 数据流

### 5.1 创建会员类型

1. 写入 `membership_plans`
2. 写入审计日志
3. 刷新缓存

### 5.2 分配用户会员

1. 写入或更新 `user_memberships`
2. 若需要，写入 `credit_transactions`
3. 写入 `membership_grants`
4. 写入审计日志

### 5.3 到期处理

1. 定时扫描 `expires_at`
2. 将 `active` 改为 `expired`
3. 写入审计日志
4. 清理权限缓存

## 6. 事务边界

建议把“会员分配 + 默认积分发放 + 审计”放在同一个事务里。

建议顺序：

1. 锁定目标用户的会员记录
2. 写 `user_memberships`
3. 写积分交易
4. 写 `membership_grants`
5. 写 `membership_audit_logs`

## 7. 初始化数据

初始数据建议仅保留三条：

1. `free`
2. `pro`
3. `max`

其中 `free` 不发放默认积分，`pro`/`max` 的默认积分由运营配置。

## 8. 迁移顺序

1. 先建表，不接路由
2. 再补服务层读写
3. 再补后台配置
4. 最后接入任务创建校验
