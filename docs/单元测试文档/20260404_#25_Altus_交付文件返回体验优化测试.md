# 2026-04-04 #25 Altus 交付文件返回体验优化测试

## 1. 测试目标

验证 Altus managed 模式下，最终 deliverable 一旦持久化完成，就会先通过独立的 `deliverables_ready` 事件进入前端对话流，而不是继续等待 `run_completed`；同时缩短后端 deliverable 持久化阶段的串行等待。

## 2. 测试依据

1. `docs/agent研发文档/Altus接管模式参照Suna重构设计/07_前端对话页与交互状态.md`
2. `docs/agent研发文档/20260327_交付物出Sandbox闭环_实现与验证.md`
3. Issue `#25`

## 3. 测试单元清单

1. 后端 deliverable 持久化不再按附件串行上传
2. 后端在 deliverable 持久化完成后，先发 `deliverables_ready`
3. 前端只要从 managed `deliverables_ready` / `assistant_message` / `status_update` metadata 读到 `deliverables`，就立即生成 `managed_deliverable_card`
4. 没有 deliverables 时，`run_completed` 仍继续兜底网页类 `managed_artifact_card`
5. 原有 managed recovery / stream URL / session resolution 回归不受影响
