# 03 后台管理登录与页面改造设计 [20260402-1137已采用]

## 1. 现状问题

当前 [apps/admin_management/web/src/App.tsx](/Users/watson/codingProj/oneceo/apps/admin_management/web/src/App.tsx) 直接渲染完整后台，没有管理员认证入口；[apps/admin_management/server/index.ts](/Users/watson/codingProj/oneceo/apps/admin_management/server/index.ts) 也没有身份中间件。

这导致后台仍是“可访问即使用”的工具后台，而不是正式管理系统。

这里还需要明确一条数据边界：

1. 管理员身份来自独立的 `admin_users`
2. 不能与用户态 `app_users` 共用同一张表

## 2. 页面目标

### 2.1 后台登录页

路由：

`/login`

目标：

1. 建立管理员登录态
2. 区分普通用户身份与管理员身份
3. 阻止未授权访问后台页面

### 2.2 后台首页改造

目标：

1. 在现有导航和模块基础上加一层管理员上下文
2. 顶部显示管理员身份、角色、登出入口
3. 所有后台请求都带正式管理员登录态

## 3. 管理员模型

首批建议只区分两类：

1. `admin`
2. `super_admin`

首批权限口径：

1. `admin` 可查看和执行常规治理动作
2. `super_admin` 可做高风险平台级操作

不在本轮展开更细粒度角色矩阵。

管理员数据模型与普通用户分离：

1. `admin_users`
2. `admin_user_sessions`

不与用户态：

1. `app_users`
2. `app_user_sessions`

共表。

## 4. 后台访问守卫

规则：

1. 进入后台根路由先调用 `/admin/auth/me`
2. 未登录则跳转 `/login`
3. 已登录但无管理员角色则返回无权限页

## 5. 页面结构调整

### 5.1 登录后框架

保留现有左侧导航结构，但新增：

1. 顶部身份条
2. 当前管理员信息
3. 最后登录时间
4. 登出按钮

### 5.2 审计展示

后台内涉及：

1. skills 管理
2. connector guide 管理
3. sandbox 管理
4. conversation 管理

的关键操作都需要记录：

1. `operatorUserId`
2. `operatorRole`
3. `targetResource`
4. `targetUserId`
5. `action`

## 6. 后端改造点

### 6.1 管理后台认证 API

新增：

1. `POST /admin/auth/login`
2. `POST /admin/auth/logout`
3. `GET /admin/auth/me`

### 6.2 中间件

新增：

1. `requireAdminAuth`
2. `requireSuperAdmin`（仅高风险操作使用）

当前所有 `/api/*` 后台路由后续都要挂在管理员鉴权之后。

本轮检查后，后台需要加管理员守卫的模块不是部分，而是全部现有管理路由：

1. `dashboard`
2. `audit`
3. `conversations`
4. `agent-management`
5. `skill-management`
6. `connector-guides`
7. `osac-releases`
8. `sandbox-management`
9. `kvm`
10. `hosts`

### 6.3 开发态网络边界

为了支持 Linux 开发机在局域网内直接访问后台，同时不破坏 Windows / macOS 本地开发，管理后台的开发态地址必须拆成三类独立配置：

1. `bind host`
2. `proxy target host`
3. `cors allowed origins`

约束：

1. 后台 API 默认监听 `0.0.0.0`
2. Vite dev server 默认监听 `0.0.0.0`
3. Vite 反代后台 API 时默认固定连接 `127.0.0.1:${ADMIN_MANAGEMENT_PORT}`，不能把 `0.0.0.0` 当作代理目标
4. 后台 CORS 不能写死为单个 `http://localhost:5174`
5. 开发态默认允许 `localhost`、`127.0.0.1` 和当前 dev server 端口上的私网 IP 来源
6. 需要显式限制来源时，使用独立的 `ADMIN_MANAGEMENT_CORS_ORIGINS` 配置覆盖

## 7. 与主站用户体系的关系

规则：

1. 后台和主站不共用同一身份表
2. 管理员账户通过 `admin_users` 独立维护
3. 普通用户不会因为注册主站账号而自动拥有后台权限
4. 若未来需要同邮箱双身份，也只允许通过显式映射，不允许物理共表

## 8. 验收标准

1. 未登录不能进入后台首页
2. 无管理员角色的用户不能访问后台
3. 后台每个关键操作都有明确管理员身份审计
4. 后台页面顶部能清晰显示当前管理员是谁
5. 后台接口层不存在绕过管理员登录态的匿名访问
6. 后台首页在治理接口返回缺字段、空数组或局部数据异常时，只允许降级为空态或错误提示，不允许整页白屏
7. 后台登录态从匿名页切换到主界面时，`App` 的 Hook 顺序必须稳定；禁止在匿名态提前 `return` 后，再于登录态分支新增 `useMemo` 等 Hook
