# 15 输入框斜线引用与Token化交互优化 [20260405-1738已采用]

日期：2026-04-05

关联事项：

- GitHub Issue `#27`

## 1. 背景

当前输入框附加能力主要依赖附件按钮，存在两类问题：

1. 引用效率低：用户无法通过键盘快速引用 skills/mcp。
2. 语义不连贯：输入文本与已确认引用之间缺少“从文本到结构化 token”的明确过渡。

## 2. 目标

在输入框中提供斜线引用交互，并支持“纯文本 `/xxxx` 与结构化引用 token 的双向转换”。

目标行为：

1. 键入 `/xxxx` 时保持纯文本。
2. 确认引用后（选择或空格确认）将该片段转换为整体 token。
3. token 支持移除并回退为文本片段（双向转换）。

## 3. 范围

本轮仅覆盖用户主对话输入框（`Home` 页面两种输入态）：

1. 初始输入模式
2. 聊天输入模式

引用类型：

1. `skills`：来源于现有可用 skills 列表
2. `mcp`：仅来源于用户已完成授权（`authorized`）且可用的 `custom_mcp` 连接器

## 4. 非目标

1. 不改后端技能/连接器数据模型。
2. 不改消息区已有引用块（`#26` 结果保留）。
3. 不引入独立富文本编辑器，仅在现有 textarea 上实现轻量 token 交互。

## 5. 交互设计

## 5.1 斜线触发

1. 输入框末尾匹配 `/query` 时显示建议面板。
2. 支持后缀约束：
   - `/xxx-skills`：仅查 skills
   - `/xxx-mcp`：仅查 mcp
3. 未带后缀时默认混合检索。

## 5.2 选择与确认

1. 鼠标点击建议项可确认引用。
2. 键盘支持上下选择。
3. 按空格或回车可确认当前高亮项并转成 token。
4. 当建议列表可见时，回车优先执行“选中候选”，不得触发消息发送。

## 5.3 token 渲染

1. token 仅在当前输入区内容域内以整体胶囊展示，保持输入框外层样式不变。
2. token 包含类型标识（skill/mcp）和名称。
3. token 支持单个删除。
4. 通过斜线确认的 `skill` 不再在附件条重复展示，避免双重显示。

## 5.4 双向转换

1. 从文本到 token：
   - `/xxx` -> 选择确认 -> token
2. 从 token 到文本：
   - 删除 token 时回填 `/xxx-<type>` 到输入框末尾

## 6. 数据与发送

1. `skills` token 会同步到现有附件技能集合，沿用当前发送链路。
2. `mcp` token 作为输入元数据扩展字段发送（`metadata.mcpReferences`）。
3. 无正文但有引用 token 时允许发送，使用最小占位文案。

补充修正（2026-04-22）：

1. Altus managed 模式下，`skills` token 与 `mcp` token 的发送条件不能绑定“是否存在文件附件”。
2. 只要存在已确认的 `skill`/`mcp` token，就必须进入 `metadata.skills` / `metadata.mcpReferences`，包括：
   - 主对话发送
   - 澄清问题回答发送
3. 否则会出现“输入框 token 已显示，但本次 run 实际未带上 skill”的假选择问题。

## 7. 验收标准

1. `/xxxx` 输入时仍为纯文本。
2. 空格或选择确认后，该片段转为 token。
3. `skills` 与“已配置完成”的 `mcp` 可生成 token，未授权 `mcp` 不显示在候选中。
4. 删除 token 可回退为文本引用片段。
5. 发送后不影响现有消息级引用块与主流程稳定性。
6. 候选列表显示期间，回车不会触发发送消息。
6. 至少包含：
   - 斜线解析/选择逻辑单测
   - UI 冒烟测试

## 9. 结论

本方案用最短路径实现键盘友好的引用能力，满足“斜线文本输入 -> 结构化 token -> 可逆回退”的核心目标，并与 `#26` 的消息展示能力闭环衔接。
