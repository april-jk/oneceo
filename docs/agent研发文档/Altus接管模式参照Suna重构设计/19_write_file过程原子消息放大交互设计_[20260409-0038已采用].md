# 19_write_file过程原子消息放大交互设计_[20260409-0038已采用]

日期：2026-04-09  
关联事项：Issue [#37](https://github.com/april-jk/oneceo/issues/37) 后续体验增强

## 1. 背景

当前 `write_file` 已有 SSE 进度文本（如“生成中 N 字符”），但展示仍是小尺寸原子消息（chip 形态），在代码生成阶段可读性不足。

用户期望在 `write_file` 进行中：

1. 临时放大该工具原子消息（横向更宽、纵向更高）。
2. 在放大区域内直接显示“代码新增内容”。
3. 放大区域尺寸固定，不随代码量持续增高。
4. 当生成结束（completed/failed）后，恢复为原子消息常规尺寸。

## 2. 目标

1. 提升 `write_file` 进行中可见性，减少“等待但看不到内容”的体感。
2. 保持现有消息流与状态语义不变，仅增强 UIUX。
3. 让过渡动画自然，不打断会话阅读节奏。

## 3. 交互方案

## 3.1 状态机

`write_file` 工具消息新增三态显示：

1. `compact`（默认）：现有 chip 形态。
2. `expanded`（仅运行中）：固定宽高的大卡片，显示代码新增预览。
3. `compact-final`（终态）：完成/失败后收起回 chip。

状态切换规则：

1. `tool_call_started/progress` 且 `toolName=write_file` -> `expanded`
2. `tool_call_completed/failed` 且 `toolName=write_file` -> `compact-final`

## 3.2 尺寸与布局

桌面端（`>=1024px`）：

1. 展开卡片宽度：`min(720px, 86vw)`
2. 展开卡片高度：`220px`（固定）
3. 代码区高度：`152px`（固定，超出滚动）

平板/移动端（`<1024px`）：

1. 展开卡片宽度：`100%`
2. 展开卡片高度：`190px`（固定）
3. 代码区高度：`126px`（固定，超出滚动）

## 3.3 展示内容

展开态头部：

1. 左侧：`写入文件` + 目标路径
2. 右侧：`进行中` 状态标记 + `已生成 N 字符`

展开态主体：

1. 仅显示“代码新增预览”（来自 `writeFileProgress.preview`）
2. 字体使用等宽字体（现有 `font-mono`）
3. 保留换行与缩进（`whitespace-pre-wrap`）
4. 超长内容滚动，不扩展卡片高度
5. 进行中每次增量更新时自动滚动到最底部，持续显示最新生成代码
6. 代码预览不做中途截断，不显示 `[truncated]`，始终展示当前已生成代码全文

终态收起后：

1. 回到原子 chip
2. hover 详情仍可查看摘要与完整信息

## 3.4 动画

进入展开：

1. 宽高过渡：`180ms ease-out`
2. 透明度 + 位移：`opacity 0->1`, `y 6->0`

退出收起：

1. 宽高回退：`140ms ease-in`
2. 内容区淡出再收起

## 4. 实现边界

仅改 `write_file` 的 UI 展示，不改：

1. SSE 事件类型
2. 数据持久化模型
3. 其他工具（`shell_execute/read_file/...`）外观

## 5. 代码落点（计划）

1. `apps/web/client/src/pages/Home.tsx`
   - `ManagedToolItem` 增加 `write_file` 运行中展开态
   - 新增 `WriteFileProgressPanel`（可内联或抽组件）
2. （可选）`apps/web/client/src/components/`
   - 若逻辑过长，抽 `ManagedWriteFileExpandedCard.tsx`
3. 测试：
   - `apps/web/client/src/tests/managed-write-file-progress-visibility.test.ts` 增加展开/收起断言
   - 新增 Playwright 用例验证运行中展开、完成后收起

## 6. 验收标准

1. 触发 `write_file` 后，原子消息自动展开为固定尺寸大卡片。
2. 展开卡内可见代码新增预览，且高度固定、内容滚动。
3. `write_file` 完成或失败后，自动收回原子消息尺寸。
4. 非 `write_file` 工具消息外观与行为不受影响。
5. 桌面与移动端都可正常展示，不出现布局溢出。

## 7. 风险与控制

风险：

1. 频繁 progress 更新可能导致重渲染抖动。
2. 长文本预览可能影响列表滚动性能。

控制：

1. 对 preview 文本保留现有截断上限。
2. 展开区固定高度 + 内容滚动，避免列表被持续撑高。
3. 仅在 `write_file + running` 条件下启用展开态。
