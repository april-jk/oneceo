# GitHub 连接器授权页使用逻辑设计 [20260330-1000已采用]

## 1. 动机与目标

**当前问题：**
现有的连接器授权流程对于普通用户来说可能过于繁琐，尤其是在涉及 Profile 选择、凭证填写和 OAuth 跳转时。对于 GitHub 这种极其常用的应用，用户期望能有一种“一键式”的顺畅体验，而不需要理解底层复杂的 Profile 概念和挂载边界。

**设计目标：**
- **极简体验**：将复杂的底层逻辑（Profile 创建、OAuth 状态管理）封装在背后，向用户暴露最简单直观的操作界面。
- **状态清晰**：让用户在任何时候都能一眼看出当前的 GitHub 授权状态（未连接、已连接）。
- **粒度控制**：在保持简便的同时，提供必要的授权范围（如授权账户、授权仓库）的展示和管理入口。

## 2. 交互逻辑设计

### 2.1 状态定义与展示

根据用户当前的授权情况，界面分为两种核心状态：

#### 状态 A：未配置/未授权
- **视觉呈现**：
  - 居中展示 GitHub 图标（带轻量级外框）。
  - 标题：“GitHub”。
  - 描述文案：“在系统中直接访问、搜索并组织代码仓库，跟踪问题、审查拉取请求，并自动化工作流程。”
  - **核心行动点 (CTA)**：一个明显的“连接”按钮（带 Plus 图标），位于描述下方居中。
- **用户行为**：点击“连接”按钮，直接触发 GitHub OAuth 流程。后台自动为其创建一个默认的 Profile 并发起授权跳转，无需用户手动填写任何表单。

#### 状态 B：已完成授权
- **视觉呈现**：
  - 同样的图标、标题和描述。
  - **状态指示器**：在描述下方展示一个状态栏，包含：
    - 绿色 Check 图标 + “授权账户” 字样。
    - 分隔线。
    - 灰色 Shield 图标 + “授权仓库” 字样。
  - **操作按钮组**：
    - 次级按钮：“管理”（用于断开连接或进入底层配置页）。
    - 主级/平级按钮：“添加仓库”（用于触发重新授权以更新 GitHub App 的仓库安装范围）。
- **用户行为**：
  - 点击“管理”：目前绑定清除授权逻辑（`handleDisconnect`），后续可扩展为打开高级设置。
  - 点击“添加仓库”：重新触发 OAuth 流程（`handleOAuth`），让用户在 GitHub 页面选择要添加的新仓库。

### 2.2 流程隐喻与自动化

为了让用户简便使用，我们需要在底层做以下自动化处理：

1. **自动 Profile 管理**：
   - 当用户点击“连接”时，如果该用户下没有 GitHub 的 Profile，系统自动创建一个名为 `GitHub Default` 的 Profile，并立即发起 OAuth。
   - 用户不需要看到“新建 Profile”或“选择 Profile”的下拉框。
2. **静默挂载**：
   - 如果是从特定的工作会话（Session）中打开的设置，OAuth 回调成功后，系统不仅保存凭证，还应静默将此 Profile 挂载到目标会话中，并给予轻量级的 Toast 提示（如：“授权成功并已应用到当前会话”）。
3. **错误处理降级**：
   - 如果 OAuth 失败或 token 失效，界面自动退回或显示为“需要重新授权”的状态，并提供明确的错误提示框和重试按钮。

## 3. 边界条件与约束

1. **多账号需求**：
   - **默认行为**：本设计主推单账号极简模式。
   - **扩展性**：如果高级用户确实需要配置多个 GitHub 账号，可以通过点击“显示详情/高级设置”折叠面板来暴露原有的 Profile 选择器，但在默认的主视口中隐藏这些复杂性。
2. **OAuth 回调处理**：
   - 回调页面必须能正确解析 `state` 参数，识别出是哪个 Profile 在请求，并在成功后通过 `window.history.replaceState` 清理 URL 参数，避免用户刷新页面导致重复提交。

## 4. UI 细节对齐

- **卡片风格**：遵循统一的 `rounded-2xl border border-border/60 bg-muted/20` 设计规范。
- **按钮尺寸**：采用 `h-[36px] min-w-[72px] px-[12px] rounded-[8px]` 的标准中小尺寸按钮，确保在弹窗中不显得突兀。
- **图标使用**：统一使用 `lucide-react` 图标库（`Plus`, `CheckCircle2`, `Unplug`, `ArrowUpRight`）。
