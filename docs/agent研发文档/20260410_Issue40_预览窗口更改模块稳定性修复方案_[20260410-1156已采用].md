# 20260410 Issue40 预览窗口更改模块稳定性修复方案 [20260410-1156已采用]

## 1. 背景与目标

Issue #40（关联总 Issue #38）要求修复“预览窗口-更改模块”在以下链路的稳定性问题：

1. 变更列表与 diff 详情联动不稳定。
2. 消息入口点击后，无法稳定定位到对应变更内容。
3. 刷新、历史回放、重进 session 后，变更视图上下文丢失。
4. 多文件变更场景下，定位与切换体验不一致。

本方案只覆盖更改模块（`changes` tab）链路，不混入文件模块/调试模块/部署模块的额外改造。

## 2. 现状链路与根因分析

## 2.1 当前链路（前端）

1. 消息流 -> `buildPreviewItems(messages)` 生成 `diffItems`（`apps/web/client/src/lib/opencode-preview.ts`）。
2. `Home.tsx` 持有 `selectedDiffId`，入口点击通过 `openDiffPreview(...)` 选择目标。
3. `OpencodePreviewPanel.tsx` 的 `DiffPreview` 用 `selectedDiffId` 渲染当前 diff。

## 2.2 已确认根因

1. **变更项 ID 不稳定（核心根因）**
   - `buildPreviewItems` 使用 `messages.forEach((message, index) => ...)` 的 `index` 参与构造 diff id（如 `diff-${index}-...`），并将 `eventIndex/relatedEventIndexes` 作为定位依据。
   - 历史回放、增量合并、消息去重后，数组下标会变化，导致：
     - `selectedDiffId` 失效；
     - 入口定位偏移；
     - 视图跳到错误 diff 或回退到 latest。

2. **入口定位依赖易漂移索引**
   - `openDiffPreview` 会通过 `messageIndex` -> `findDiffIdForMessageIndex` 寻找 diff。
   - `messageIndex` 与上述 index 同源，不具备跨刷新/回放稳定性。

3. **上下文未持久化**
   - `previewTab/selectedDiffId` 仅驻留内存态，刷新或重进 session 后无法恢复更改上下文。

4. **多文件变更缺少“入口目标文件”聚焦语义**
   - 当前能显示多文件 diff，但从消息入口进入后没有稳定的“目标文件聚焦”策略，用户感知为“点击了但没到我要看的那个文件”。

## 3. 修复目标（Issue #40 验收对齐）

1. 更改预览稳定展示并可切换。
2. 消息入口点击后稳定定位到对应变更。
3. 刷新/重进后保留关键变更上下文。
4. 覆盖页面级回归（含消息入口联动）。

## 4. 方案设计（最短路径）

## 4.1 建立稳定 Diff 身份（替换 index-based）

1. `diffItems.id` 改为基于稳定字段拼装，不再使用数组 index：
   - 优先：`message.messageKey` + `partId/turnId` + `blockIndex`。
   - 缺失时退化到 `metadata.messageKey` / `timelineCursor` 组合。
2. `eventIndex/relatedEventIndexes` 改为稳定引用：
   - 新增 `eventMessageKey`、`relatedMessageKeys`。
   - `Home` 侧定位逻辑改为 messageKey 优先，取消对 index 的主依赖。

## 4.2 入口定位改为“稳定键 + 延迟解析”

1. `openDiffPreview` 接收并优先使用：
   - `diffId`（稳定 id）
   - `messageKey`（入口来源消息 key）
   - `filePath`（目标文件提示）
2. 若入口点击时 `diffItems` 尚未生成目标：
   - 记录 `pendingDiffTarget`（一次性）；
   - 在 `diffItems` 更新后自动解析并落位；
   - 解析成功后清空 pending，避免重复跳转。

## 4.3 更改视图上下文持久化（按 session 维度）

1. 在 `Home.tsx` 引入 `changes preview state` 持久化（`sessionStorage`）：
   - `previewOpen`
   - `previewTab`
   - `selectedDiffId`
   - `selectedDiffMessageKey`（兜底恢复键）
2. 恢复顺序：
   - 优先 `selectedDiffId`；
   - 不存在则按 `selectedDiffMessageKey` 解析；
   - 仍失败才回退最新 diff。

## 4.4 多文件变更聚焦语义补齐

1. 消息入口若携带 `filePath`，在 `DiffBlock` 增加初始聚焦文件参数：
   - 自动展开目标文件；
   - 视图滚动到目标文件段落；
   - 其余文件保持可切换。
2. 仅做前端展示层处理，不改后端 diff 数据结构。

## 5. 非目标

1. 不改后端事件生产协议。
2. 不扩展新的 diff 引擎或 patch 解析协议。
3. 不引入“兼容补丁逻辑”长期并存；统一切到稳定 id 方案。

## 6. 实施步骤

1. 重构 `buildPreviewItems` 输出模型：稳定 id、messageKey 关联字段。
2. 重构 `Home.openDiffPreview` 定位流程：`diffId -> messageKey -> filePath -> latest`。
3. 增加 `pendingDiffTarget` 与 `sessionStorage` 恢复流程。
4. `DiffPreview/DiffBlock` 增加目标文件聚焦能力。
5. 回归测试与页面级验证。

## 7. 验证方案

## 7.1 单元/组件

1. `buildPreviewItems`：历史消息 prepend 后，既有 diff id 不变。
2. 入口定位：给定 messageKey/filePath 时，能稳定命中目标 diff。
3. `pendingDiffTarget`：先点入口后到达 diff 数据时能自动落位。

## 7.2 页面级（Playwright）

1. 在消息卡片点击“Diff · 点击查看更改”，确认定位正确。
2. 多文件 diff 场景，入口点到指定文件后自动聚焦。
3. 刷新页面后，保持 `changes` tab 与已选 diff。
4. 重进同 session（history 视图）后恢复同一 diff 上下文。

## 8. 风险与约束

1. 历史消息可能缺少 `messageKey/partId`。
   - 处理：稳定 id 生成采用多级键（messageKey/timelineCursor/hash），确保可落地。
2. `sessionStorage` 中保留过期 diff id。
   - 处理：恢复失败时走 messageKey 再到 latest，不报错阻塞。
