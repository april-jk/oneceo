## 4. 逐步执行顺序

### 步骤 1：做实例安全加固与专用凭据收敛

目的：

- 不再让 OneCEO 平台长期依赖 `admin`

操作：

1. 轮换当前平台集成账号密码
2. 确认平台只使用：
   - `UMAMI_HOST_URL`
   - `UMAMI_USERNAME`
   - `UMAMI_PASSWORD`
   - `UMAMI_TEAM_ID`
3. 把旧密码视为废弃，不再继续使用

当前状态：

- 已得到用户授权开始实施
- 当前代码接入优先使用专用集成账号，不再继续使用 `admin`

### 步骤 2：固化 oneceo 系列域名范围

目的：

- 确定哪些域名要纳入同一套统计治理

操作：

1. 先固定：
   - `oneceo.ai`
   - `dev.oneceo.ai`
2. 再由用户补充是否还包括：
   - `www.oneceo.ai`
   - `preview.oneceo.ai`
   - 其他业务域名

当前状态：

- 已先固定 `oneceo.ai` 与 `dev.oneceo.ai`
- 其他域名后续按用户新增继续接入

### 步骤 3：整理 website 归属规则

目的：

- 为主站、开发站、生成应用建立统一口径

操作：

1. 主站 website 固定绑定 `oneceo.ai`
2. 开发站 website 固定绑定 `dev.oneceo.ai`
3. 后续生成应用不手工预建
4. 生成应用在首次成功部署后由平台自动创建 Umami website

当前状态：

- 已采用“主站/开发站固定 website，生成应用首次部署自动建站”的规则

### 步骤 4：定义模板注入契约

2. 在模板里统一加入 tracker 脚本

- 已进入模板与平台注入实现阶段
