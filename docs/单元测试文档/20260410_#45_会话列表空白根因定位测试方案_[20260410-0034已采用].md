# 2026-04-10 #45 会话列表空白根因定位测试方案 [20260410-0034已采用]

## 1. 测试目标

定位 Issue #45 在“已修复后仍出现刷新/重部署后会话列表空白”的准确根因，避免继续用猜测推进修复。

## 2. 测试单元清单

1. `task_creation_sessions.user_id` 真实存储分布（uuid / legacy / empty）。
2. 最近异常窗口（2026-04-09）坏样本会话的来源特征。
3. `GET /api/task-creation/sessions` 空列表回填分支的触发条件。
4. 前端 legacy 迁移 header（`X-Legacy-User-Id`）是否稳定可用。

## 3. 预期输入/输出与边界

### 3.1 数据库存储分布核验

- 输入：`task_creation_sessions` 最近 30 天数据。
- 预期输出：可量化的 owner 分类（`uuid / legacy / empty`）与消息/run/sandbox 关联证据。
- 边界：如果存在大量 `legacy/empty`，必须继续按日期和样本细分，不能只给总数。

### 3.2 2026-04-09 样本溯源

- 输入：2026-04-09（Asia/Shanghai）当日所有 `legacy/empty` 会话。
- 预期输出：每条样本的 `user_id`、首条消息类型、消息计数、sandbox 关联。
- 边界：必须区分“真实用户会话”与“smoke/test 会话”。

### 3.3 空列表回填触发条件

- 输入：`GET /sessions` 在“当前用户 ownedDbSessions=0”时的逻辑分支。
- 预期输出：明确说明哪些条件会阻断 orphan 回填。
- 边界：必须给可执行证据（测试用例或脚本输出），不能只读代码口述。

### 3.4 legacy header 可用性

- 输入：前端 `X-Legacy-User-Id` 生成链路。
- 预期输出：确认 header 来源是否可靠、是否存在写入入口。
- 边界：如果只有读取没有写入，必须标注“依赖历史残留 localStorage”。

## 4. 验证方式

1. SQL 查询：`task_creation_sessions` + `conversation_messages` + `task_session_runs` + `sandbox_execution_environments` 联查。
2. 路由逻辑验证：`apps/api/tests/task-creation-business-routes.test.ts`。

## 5. 执行结果（2026-04-10）

### 5.1 存储事实

- 最近 30 天坏样本：
  - `empty`: 50
  - `legacy`: 110
- `empty` 会话中 `no_run=50`；`legacy` 会话中 `no_run=61`。
- legacy Top：`local-egf5ug84`(60)、`local-ny9ymcqo`(8)，其余大量 `smoke-*`。

### 5.2 2026-04-09 当日坏样本

- `legacy=5`（全部 `smoke-user-*`）
- `empty=1`（`5d3bac54-a919-48ca-bc44-0282bf0263b1`）
- 该 empty 样本仅有 1 条 `system/session_started`，无 user/agent 消息，但存在 sandbox metadata 绑定。

### 5.3 回填分支行为（可执行证据）

- 运行：`pnpm --filter api exec tsx --test tests/task-creation-business-routes.test.ts`
- 关键用例通过并确认现状：
  - `GET /api/task-creation/sessions does not rebind when foreign owned sessions exist`
- 结论：当库内存在“其他用户已归属会话”时，orphan 回填会被阻断。

### 5.4 legacy header 链路

- `buildClientIdentityHeaders` 仅从 `localStorage.oneceo_client_user_id` 读取并透传 `X-Legacy-User-Id`。
- 全仓未发现该 key 的现行写入逻辑。
- 结论：legacy 迁移依赖“历史残留 localStorage”，新设备/清空存储后不可用。

## 6. 根因结论

1. **数据源头仍存在非 canonical owner（legacy/empty）**，导致用户态 `userId` 过滤后不可见。
2. **orphan 回填策略在多用户库中常被阻断**（存在 foreign owned sessions 即不回填），导致历史空归属会话长期不可恢复。
3. **legacy 定向迁移依赖前端历史本地标识**，而该标识当前无稳定写入链路，导致迁移能力在刷新/重部署后不可靠。

## 7. 后续修复建议（最短路径）

1. 源头封堵：生产主链禁止写入空 `user_id` 与非 canonical owner（脚本链路隔离到测试库/显式 userId）。
2. 迁移收口：建立“legacy id -> app_users.id”可持久映射，不再依赖浏览器本地残留值。
3. 回填策略调整：对已建立映射的 orphan/legacy 会话执行定向回填，避免全局 foreign 检查把恢复链路彻底锁死。
