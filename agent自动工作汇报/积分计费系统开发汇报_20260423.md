# 积分计费系统开发汇报（2026-04-23）

## 一、改动概要

本次完成了一套类 Manus 的积分计费系统，覆盖数据库、API、用户端、管理端四层。

### 已完成模块

1. **数据库层（P0）**
   - 新增 4 张表：`user_credits`、`credit_transactions`、`token_usage_logs`、`model_pricing`
   - 通过 `apps/api/src/db/migrate.ts` 的 raw SQL migration 创建
   - 已补充索引和必要的外键约束

2. **API 服务层（P1）**
   - `billing-service.ts`：积分查询、CAS 扣费、充值/调整、交易记录、会话用量统计
   - `pricing-service.ts`：定价 CRUD、缓存感知积分计算（OpenAI 50% hit / Anthropic 10% hit + 125% creation）
   - `billing-routes.ts`：用户端接口（余额、交易记录、会话用量）
   - `internal-billing-routes.ts`：管理端接口（用户列表、积分调整、定价配置、平台统计、使用明细）
   - `credit-check.ts`：余额检查中间件，挂载于 `POST /api/task-creation/sessions`

3. **计费钩子（P2）**
   - `altus-run-coordinator.ts`：
     - `execute()` 运行前检查余额
     - `chargeForModelCall()` 每次模型调用后扣费并记录 usage log
     - 使用字符长度估算 token 数（当前未接入真实 token 计数）
   - `app-auth-service.ts`：新用户注册自动初始化 500 积分

4. **用户前端（P3）**
   - `CreditBadge.tsx`：Header 右上角积分余额显示
   - `BillingSettingsPanel.tsx`：Settings 对话框新增"积分与消费"标签页
   - `AuthContext.tsx`：扩展 `credits` 状态和 `refreshCredits()`

5. **管理后台（P4）**
   - `BillingManagementSection.tsx`：主页面，含 Users/Pricing/Stats/Logs 四个标签
   - `BillingStatsDashboard.tsx`：统计看板（周期选择、6 张汇总卡片、3 个图表、缓存效果概览）
   - `BillingUsageLogs.tsx`：使用明细表格（多维度筛选、分页）
   - `UserDetailDialog.tsx`：用户详情弹窗（Overview/History/Usage/Trend + 积分调整表单）
   - `App.tsx`：侧边栏新增"计费管理"导航组

6. **测试数据**
   - 已 seed 5 条模型定价、11 个用户的 500 初始积分、3 个用户的 sample transactions/logs

## 二、代码审查风险清单

### P0（Critical）— 必须立即修复

1. **内部计费管理接口未做管理员鉴权**
   - 位置：`internal-billing-routes.ts` 全部路由（14-370 行）
   - 风险：`/api/internal/billing/*` 未挂任何鉴权中间件，外部可直接查看全站账单、修改用户积分和模型定价
   - 修复：router 级强制内部 token/管理员会话校验，`adminId` 必须从服务端身份获取

2. **`deductCredits()` 未校验 amount > 0**
   - 位置：`billing-service.ts:43-85`
   - 风险：负数 amount 会导致 balance 增加、totalConsumed 减少、交易记录记为正数 consume，可被利用刷积分
   - 修复：入口强校验 `Number.isInteger(amount) && amount > 0`，数据库加 `CHECK (balance >= 0)`

3. **Altus 运行中扣费失败后仍继续执行**
   - 位置：`altus-run-coordinator.ts:1816-1833`（启动预检），`297-324`（扣费失败处理）
   - 风险：用户余额 > 0 即可发起整次 managed run，即使每次模型调用都扣费失败也继续消耗资源
   - 修复：按预估最低成本做开跑校验，`deductCredits` 失败时立即停止后续模型调用

### P1（High）— 尽快修复

4. **`initUserCredits()` 不是原子事务**
   - 位置：`billing-service.ts:18-34`
   - 风险：user_credits 插入成功但 credit_transactions 失败时，审计链断裂
   - 修复：两次 insert 放进同一个 `db.transaction(...)`

5. **`addCredits()` 允许负数，且错误更新累计字段**
   - 位置：`billing-service.ts:91-153`
   - 风险：负数调整会让 totalEarned 下降，可能把余额扣成负数
   - 修复：拆成 `credit()` / `debit()` / `adjust()` 明确语义，负向调整走 CAS

6. **`createPricing()` 未校验价格合法性**
   - 位置：`pricing-service.ts:54-85`
   - 风险：可写入负数价格，后续计费变成返利
   - 修复：校验 `Number.isInteger(...) && >= 0`，provider 白名单限制

7. **`credit-check.ts` 中间件只挂在 POST `/sessions`，可被绕过**
   - 位置：`task-creation-routes.ts`（挂载点）
   - 风险：`POST /sessions/draft` 等路径未挂载，前端 managed 流程实际先走 draft
   - 修复：校验前移到所有创建/启动消耗型流程

8. **`billing-routes.ts` 按 sessionId 返回用量未校验归属**
   - 位置：`billing-routes.ts:68-83`
   - 风险：登录用户拿到别人的 sessionId 就能读取其模型、Token 和积分消耗
   - 修复：查询时附加 `userId` 条件

9. **`app-auth-service.ts` 积分初始化失败不回滚**
   - 位置：`app-auth-service.ts:214-233`
   - 风险：用户创建成功但积分初始化失败时，用户处于"已注册但无 credits 记录"状态
   - 修复：验证码消费、用户创建、积分初始化放进同一事务

10. **数据库 `ON DELETE CASCADE` 抹掉账本审计链**
    - 位置：`schema.ts` billing 表的外键定义
    - 风险：删除用户会连带删掉余额、交易和 token 日志
    - 修复：改为 `RESTRICT/NO ACTION` + 软删除/匿名化用户

11. **`model_pricing` 唯一索引设计错误**
    - 位置：`schema.ts:1335-1350`
    - 风险：`(model, isActive)` 唯一索引导致每个模型只能有 1 条 inactive 记录，第二次调价会失败
    - 修复：改成仅对 `is_active=true` 的部分唯一索引

### P2（Medium）— 建议优化

12. `getTransactions()` 的 total 忽略了 type 过滤（分页失真）
13. `calculateCredits()` 未校验 token 输入合法性（负数 token 可能导致负积分）
14. 扣费与 usage 日志分成两个独立调用（易出现账实分离）
15. 缓存比例硬编码但未知 provider 默认 0（新 provider 可能静默少计费）
16. `lastRechargeAt` 字段完全未维护
