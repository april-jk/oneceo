# 06 分支与部署环境简要规范

本文件是给 AI 协作工具的“快速事实卡片”，用于在开始编码前快速建立本仓库的分支、服务架构、部署与环境变量认知。

## 1. 分支职责（强约束）

1. `task-creation-agent`
   - 主开发分支。
   - 日常功能开发、修复先进入该分支。
2. `develop`
   - Railway 开发环境部署分支。
   - 只接收可部署、已通过最小验证的集成改动。
3. `production`
   - 生产部署分支。
   - 仅接收已在 `develop` 验证通过的版本。

## 2. 服务架构（当前主线）

1. `oneceo-web`（`apps/web`）
   - 用户端前端 + Node server（BFF 代理入口）。
2. `oneceo-api`（`apps/api`）
   - 核心业务与任务会话编排、认证、OSAC、Sandbox、连接器、LLM 代理。
3. `oneceo-admin`（`apps/admin_management`）
   - 管理后台前后端。

说明：当前部署按三服务拆分容器，不新增同类第四服务作为主路径。

## 3. 部署拓扑（Railway）

1. `oneceo-web` 对外暴露域名（自定义域名或 Railway 随机域名）。
2. `oneceo-api` 优先使用 Railway 内网域名供 `web/admin` 调用，不建议直接公网暴露。
3. `oneceo-admin` 可先使用 Railway 随机域名。

## 4. Web BFF 与请求路径约束

1. 浏览器应优先走同源路径：
   - `/api/*`
   - `/ws/task-creation`
   - `/socket.io/*`
2. `oneceo-web` 服务端负责反向代理到 API。
3. 禁止在生产前端固定拼接 API 公网地址。

## 5. 本地与云端环境变量规则（必须遵守）

1. 先判断 `.env` 是否存在（门控条件）：
   - 存在：进入 `.env` 模式，仅使用 `.env` 作为业务配置来源。
   - 不存在：进入环境变量模式，仅使用 Railway Variables/进程环境变量。
2. 禁止将 `.env` 与环境变量混用作为业务配置来源。
3. `.env` 是否存在，同时作为“本地开发/云端部署”运行形态识别标志。

## 6. 推进到 develop 的最小门禁

至少满足以下条件再推进 `task-creation-agent -> develop`：

1. 构建通过：
   - `pnpm --filter @oneceo/shared build`
   - `pnpm --filter api build`
   - `pnpm --filter web build`
   - `pnpm --filter oneceo-admin-management build`
2. 核心链路可用：
   - 注册/登录
   - `task-creation` WebSocket
   - 关键 session/skills 接口无回归错误
3. 前端无 Mixed Content、请求路径符合同源/BFF 设计。
4. `WEB_BFF_API_TARGET` / `ONECEO_API_URL` 在当前模式下已正确配置（本地和云端可配置为不同域名）。
