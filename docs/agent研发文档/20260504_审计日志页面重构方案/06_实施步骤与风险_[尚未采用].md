## 2. 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| Middleware 拖慢 API 响应 | 中 | 高 | 写入完全异步，不 await；使用批量写入；性能监控 |
| 敏感信息泄漏 | 低 | 高 | Headers/Body 脱敏白名单明确；Code Review 重点检查脱敏逻辑；上线前做脱敏测试 |
| 数据库写入压力过大 | 低 | 中 | 异步写入 + 批量 flush；保留 30 天自动清理；监控 DB CPU 和 IOPS |
| 索引导致写入变慢 | 低 | 中 | `created_at` 索引是 B-tree，写入开销可控；必要时延迟建索引 |
| 旧数据清理误删 | 低 | 高 | 清理任务的 `deleteOlderThan` 必须带 `created_at` 条件；测试环境先验证 |
| 页面渲染大量 trace 卡顿 | 中 | 中 | L3 时间线分页加载（每次 50 条）；虚拟滚动（trace > 200 条时）|

## 3. 验收标准

- [ ] 用户端发起 API 请求后，管理后台审计日志页面 5 秒内可见新记录
- [ ] 请求详情面板中，authorization、cookie、password 等字段显示为 `***REDACTED***`
- [ ] 从用户索引页点击用户 → 进入 HTTP 请求列表 → 点击请求进入详情 → 有关联会话则跳转会话 → 进入 AI Trace 时间线，全链路可通
- [ ] AI Trace 时间线中，LLM 请求、工具调用、服务 API、连接器 API 以不同颜色区分
- [ ] 点击 trace 节点可展开详情面板，同时展示结构化视图和原始 JSON 视图
- [ ] 30 天前的记录自动清理，数据库无残留
- [ ] TypeScript 类型检查全部通过
