# 20260414 部署工作台平台侧 UI 更新方案 [20260414-1559已采用]

## 1. 背景

当前平台侧“部署”面板已经接入了真实部署链路和数据库链路，但 UI 仍存在三个问题：

1. `站点数据` 视图仍以占位组件为主，容易让用户误以为已经接入真实分析。
2. 面板里存在若干当前不可执行的按钮与伪交互，不符合“只展示真实能力”的要求。
3. 当前布局信息量较大，在中小屏宽度下可读性一般，重点信息不够集中。

本轮先做平台侧 UI 更新，不扩统计后端；2026-04-16 已在此基础上补充一个真实模板基线接口，用于展示当前工作区的部署模板状态。

## 2. 数据范围

2026-04-14 原方案只允许使用当前 `TaskCreationDeploymentInfo` 已提供的真实字段：

- `configured`
- `canDeploy`
- `message`
- `projectId` / `projectName`
- `environmentId` / `environmentName`
- `serviceId` / `serviceName`
- `deploymentId`
- `latestStatus`
- `latestUrl`
- `latestStaticUrl`
- `activeDeploymentPending`
- `domains`
- `deployments`
- `logs`
- `missing`

不伪造访问量、访客数、地区、设备等数据。

2026-04-16 补充允许使用：

- `GET /api/task-creation/sessions/:sessionId/deployment/template`

该接口只返回当前工作区经过真实导出与模板检查后的结构化基线状态，不返回伪造统计值。

## 3. UI 改造目标

### 3.1 发布与访问

- 保持现有操作闭环：
  - 发布
  - 重新发布
  - 回滚
  - 刷新
- 强化首屏摘要、访问入口、版本轨迹与日志可读性。

### 3.2 仪表盘 / 部署数据

- 保持现有真实部署数据视图。
- 强化摘要、当前线上版本和操作判断的层次。

### 3.3 仪表盘 / 站点数据

- 不再显示误导性的固定 `0` 分析指标页。
- 改为展示：
  - 当前网站是否可公开访问
  - 当前平台已经真实拿到哪些站点侧信息
  - 哪些分析能力尚未接入
  - 后续分析能力接入后会出现在哪些位置

### 3.4 响应式要求

- 顶部操作区在移动端垂直堆叠，在桌面端横向分布。
- 所有统计/摘要卡片在移动端单列，平板端双列，宽屏三列或四列。
- 长链接、部署 ID、commit message 允许换行，不得挤爆父容器。

## 4. 设计原则

1. 只展示真实数据，不用假数字填满页面。
2. 只保留当前可执行动作，去掉无效按钮。
3. 用更少的卡片表达更明确的判断，不做装饰性复杂布局。
4. 保持和现有部署工作台信息架构一致：
   - 发布与访问
   - 仪表盘
   - 数据库
   - 存储桶
   - 设置

## 5. 实施范围

本轮只改：

- `apps/web/client/src/components/OpencodePreviewPanel.tsx`

`AltusRunReplayDrawer.tsx` 通过复用 `DeploymentPreview` 自动获得同样的 UI 更新，不单独改造。

## 6. 非目标

本轮不做：

- 新增后端 analytics 接口
- 新增用户统计聚合
- 新增访问权限管理逻辑
- 新增文档按钮跳转逻辑

这些能力后续要等部署基线和统计链路真正接入后再做。

## 7. 验收口径

完成后需要满足：

1. `站点数据` 视图不再出现误导性的假分析页。
2. 页面只保留真实动作和真实状态。
3. 移动端和桌面端布局都保持清晰、稳定、无明显溢出。
4. `AltusRunReplayDrawer` 和主预览面板中的部署视图表现一致。

## 8. 2026-04-16 增补结果

已补齐：

1. `部署数据` 视图新增“模板与平台接入基线”区块
2. 真实展示 manifest、analytics 注入、数据库契约、健康检查、warnings、errors
3. `刷新` 与 `发布 / 重发 / 回滚 / 轮换 token` 后会重新拉取模板基线
4. 站点数据继续保持“只展示真实已接入数据”，模板基线单独承接部署前正确性信息
