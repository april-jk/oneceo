# Manus固定模板收敛部署方案 [20260508-1039已采用]

## 1. 背景

2026-05-07 对 `referance/manus部署模板推演` 下三个样本的拆解，进一步确认了一件事：

1. Manus 面向用户看起来支持多种任务表达，甚至允许用户口头指定 Java 等语言。
2. 但它的真实交付外壳并没有随语言要求自由切换。
3. 它更像是把绝大多数“可部署网页应用”任务收敛进一套固定可部署模板，再让模型只在模板允许范围内产出内容。

当前样本：

1. [2048的网页游戏并部署](/Users/watson/codingProj/oneceo/referance/manus部署模板推演/2048的网页游戏并部署)
2. [game-2048](/Users/watson/codingProj/oneceo/referance/manus部署模板推演/game-2048)
3. [java写个2048网站](/Users/watson/codingProj/oneceo/referance/manus部署模板推演/java写个2048网站)

共同特征非常强：

1. 顶层目录统一为 `client / server / shared / package.json / vite.config.ts / pnpm-lock.yaml`
2. build/start 契约统一为：
   - `vite build`
   - `esbuild server/... --outdir=dist`
   - `node dist/index.js`
3. `client/index.html` 统一预埋 analytics runtime 占位符
4. `vite.config.ts` 统一包含 Manus runtime 与调试采集插件
5. server 层统一是 Node/Express 壳，不是随任务自由切换语言 runtime

这说明 Manus 的真实策略不是“技术栈自由”，而是“需求表达自由 + 模板壳固定”。

## 2. 结论先行

如果 OneCEO 当前目标是：

1. 把部署成功率抬到 Manus 同级
2. 把最终对用户的成功高质量交付作为唯一核心点

那么当前阶段不应继续追求“多语言广泛兼容”，而应直接采用 Manus 同类策略：

1. 暂时放弃 Java、PHP、Python 等非主模板路线的主链承诺
2. 把网页类项目统一收敛到一套固定模板壳
3. 让 Altus 在固定模板内生成内容、页面、数据结构和少量业务代码
4. 让部署链路只服务这套固定模板，而不是服务无限制自由项目

## 3. 当前问题与 Manus 的差异

OneCEO 当前还在试图同时做两件彼此冲突的事：

1. 允许较高自由度的项目结构
2. 又要求 Manus 级稳定部署

这会导致：

1. 部署前需要识别大量 runtime family
2. Fast Lane 要维护越来越多的例外
3. deploy tool 容易进入 repair_required / status 误判 / 反复重试

而 Manus 的样本说明，它几乎没有把运行时自由暴露给最终交付主链。

真正稳定的不是“模型更强”，而是：

1. 模板固定
2. runtime 固定
3. 目录结构固定
4. build/start 固定
5. analytics 固定
6. debug/preview 固定
7. 发布产物形态固定

## 4. 本轮战略收敛

### 4.1 明确放弃项

当前阶段明确放弃主链支持：

1. Java 部署主链
2. PHP 部署主链
3. Python 部署主链
4. 任意 Node 自由结构部署

不是永久放弃，而是：

1. 暂不纳入核心稳定性交付目标
2. 不再作为当前 Fast Lane / 主部署链的优先优化对象

### 4.2 明确保留项

当前阶段只保留一套主模板路线：

1. 前端：Vite + React
2. 服务端：Node + Express
3. 运行壳：`client + server + shared`
4. 构建契约：`vite build + esbuild server + node dist/index.js`
5. analytics 注入：模板预埋
6. healthcheck：模板预埋

### 4.3 交付目标

我们不再把“支持更多语言”作为首要目标，而是把：

1. 用户最终拿到一个稳定上线的网站
2. 页面质量高
3. 部署成功率高
4. 交付时间可预测

作为唯一核心点。

## 5. 对 Manus 的高比例模拟目标

我们不追求 1:1 抄 UI，而追求部署与模板策略层面的高比例仿真。

需要模拟的核心能力：

1. 固定模板壳
2. 固定目录结构
3. 固定 build/start/runtime 契约
4. 固定 analytics/preview/debug 注入
5. 固定最小发布面
6. 固定 deploy tool 判定逻辑

不需要模拟的内容：

1. “名义上支持很多语言”
2. 对外宣称的技术栈自由
3. 部署期 LLM 自修复万能兼容

## 6. OneCEO 需要收敛成的固定模板

### 6.1 顶层结构

统一收敛为：

1. `client/`
2. `server/`
3. `shared/`
4. `package.json`
5. `vite.config.ts`
6. `tsconfig*.json`
7. `oneceo.manifest.json`

### 6.2 build/start 契约

统一收敛为：

1. `build`: `vite build && esbuild server/... --outdir=dist`
2. `start`: `node dist/index.js`
3. public 产物：`dist/public`

### 6.3 server 壳

统一收敛为 Node/Express 壳：

1. dev 模式接 Vite
2. prod 模式托管 `dist/public`
3. 固定 fallback 到 `index.html`
4. 固定 healthcheck 路由

### 6.4 analytics 壳

统一收敛为：

1. `client/index.html` 预埋 analytics 占位符
2. 由平台在模板内注入
3. 不再依赖 deploy 期临时猜入口

## 7. Altus 生成策略要改什么

### 7.1 平台先注入模板 scaffold

Altus 生成网页类项目时：

1. 平台先把官方固定模板 scaffold 直接 materialize 到空工作区
2. 该 scaffold 至少包含：
   - `client/index.html`
   - `client/src/*`
   - `server/index.ts`
   - `shared/`
   - `package.json`
   - `vite.config.ts`
   - `oneceo.manifest.json`
3. 再让 Altus 在这个模板内工作，而不是从零开始拼技术栈

### 7.2 Altus 不再从零拼栈

Altus 收到的网页类项目任务应默认变成：

1. 基于当前已有的官方模板实现网站
2. 保持 build / start / healthcheck / analytics 契约不变
3. 只改这些区域：
   - 页面内容
   - 样式
   - 交互
   - 少量 server 路由
   - 数据模型

### 7.3 语言要求的处理方式

用户说“用 Java / PHP / Python 写”时，当前阶段不按字面切 runtime。

而是：

1. 解释为“按该语言风格/业务语义理解需求”
2. 最终仍交付在固定模板壳上

这条是战略取舍，不是兼容性补丁。

## 8. 部署链要改什么

### 8.1 Fast Lane 不再做 runtime family 广覆盖

当前主链只服务这一套固定模板。

也就是：

1. 不再继续扩 Java/PHP/Python 的 Fast Lane
2. 不再继续扩任意 Node 自由结构 Fast Lane
3. 先把固定模板壳做到接近 Manus 的确定性

### 8.2 预检简化

因为模板固定，preflight 可以收缩成：

1. 模板指纹匹配
2. build/start/healthcheck 完整
3. analytics 注入点存在
4. 最小发布目录可生成

### 8.3 发布面固定

固定模板的发布面也固定：

1. `dist/public`
2. 打包后的 server 入口
3. `package.json`
4. `oneceo.manifest.json`
5. 部署配置文件

## 9. 验收方式

不再按“语言覆盖率”验收，而按“固定模板成功率”验收。

### 9.1 核心指标

1. 首次部署成功率
2. 重复部署成功率
3. P50 部署耗时
4. P95 部署耗时
5. 假成功率
6. analytics tracking 成功率

### 9.2 样本设计

只围绕固定模板做内容变化：

1. 企业官网
2. 营销页
3. 作品集
4. 工具页
5. 含表单的业务站点
6. 含轻量 server API 的互动站点

## 10. 实施顺序

1. 文档上正式确认“当前主链只做固定模板”。
2. 盘点现有 OneCEO 模板与 Manus 模板壳差异。
3. 把 Altus 生成入口改成“先落固定模板，再生成内容”。
4. 把 Fast Lane / deploy tool 改成只服务固定模板。
5. 跑真实 E2E 矩阵，直到稳定性接近目标。

3. 是否同意后续部署主链优化不再以“多语言支持”为第一目标，而只以“用户成功高质量交付”作为唯一核心点。
