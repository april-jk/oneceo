# 激活码管理功能设计 [20260502-1800已采用]

> 文档状态：`[20260502-1800已采用]` - 已审核通过，开始实施

## 1. 需求概述

在管理后台-计费管理中增加"激活码管理"标签卡，用于管理积分激活码。

### 核心功能
- **创建激活码**：选择有效期、积分数量，支持批量生成
- **查看使用情况**：哪些用了哪些没用，用了的用了多少，激活用户是谁
- **激活码生命周期管理**：启用/禁用、删除、导出

## 2. 数据模型设计

### 2.1 激活码表 `credit_activation_codes`

```sql
CREATE TABLE credit_activation_codes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code VARCHAR(32) NOT NULL UNIQUE,           -- 激活码（唯一）
  credits_amount INTEGER NOT NULL,             -- 积分数量
  status VARCHAR(20) NOT NULL DEFAULT 'active', -- 状态: active, disabled, used, expired
  max_uses INTEGER NOT NULL DEFAULT 1,         -- 最大使用次数（支持多次使用）
  current_uses INTEGER NOT NULL DEFAULT 0,     -- 当前已使用次数
  expires_at TIMESTAMP,                        -- 过期时间（null 表示永不过期）
  created_by UUID REFERENCES admin_users(id),  -- 创建者（管理员）
  used_by UUID REFERENCES app_users(id),       -- 使用者（单次使用时）
  used_at TIMESTAMP,                           -- 使用时间
  batch_id VARCHAR(64),                        -- 批次ID（批量创建时）
  description TEXT,                            -- 描述/备注
  metadata_json JSONB NOT NULL DEFAULT '{}',   -- 扩展元数据
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 索引
CREATE UNIQUE INDEX idx_activation_codes_code ON credit_activation_codes(code);
CREATE INDEX idx_activation_codes_status ON credit_activation_codes(status);
CREATE INDEX idx_activation_codes_batch_id ON credit_activation_codes(batch_id);
CREATE INDEX idx_activation_codes_expires_at ON credit_activation_codes(expires_at);
CREATE INDEX idx_activation_codes_used_by ON credit_activation_codes(used_by);
```

### 2.2 激活码使用记录表 `credit_activation_code_uses`

```sql
CREATE TABLE credit_activation_code_uses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  activation_code_id UUID NOT NULL REFERENCES credit_activation_codes(id),
  user_id UUID NOT NULL REFERENCES app_users(id),
  credits_granted INTEGER NOT NULL,            -- 实际授予的积分
  transaction_id UUID REFERENCES credit_transactions(id), -- 关联的积分交易
  used_at TIMESTAMP NOT NULL DEFAULT NOW(),
  metadata_json JSONB NOT NULL DEFAULT '{}'
);

CREATE INDEX idx_activation_code_uses_code_id ON credit_activation_code_uses(activation_code_id);
CREATE INDEX idx_activation_code_uses_user_id ON credit_activation_code_uses(user_id);
```

## 3. API 接口设计

### 3.1 管理端接口（需要管理员权限）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/internal/billing/activation-codes` | 创建激活码（支持批量） |
| GET | `/api/internal/billing/activation-codes` | 获取激活码列表（分页、筛选） |
| GET | `/api/internal/billing/activation-codes/:id` | 获取激活码详情 |
| PUT | `/api/internal/billing/activation-codes/:id` | 更新激活码（启用/禁用） |
| DELETE | `/api/internal/billing/activation-codes/:id` | 删除激活码 |
| GET | `/api/internal/billing/activation-codes/stats` | 获取激活码统计 |

### 3.2 用户端接口（需要用户登录）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/activation-codes/redeem` | 兑换激活码 |

### 3.3 接口详细设计

#### 创建激活码

```typescript
// POST /api/internal/billing/activation-codes
interface CreateActivationCodeRequest {
  creditsAmount: number;        // 积分数量
  quantity?: number;            // 生成数量（默认1，最大100）
  maxUses?: number;             // 每个码最大使用次数（默认1）
  expiresInDays?: number;       // 有效期（天），null 表示永不过期
  description?: string;         // 描述/备注
  prefix?: string;              // 码前缀（可选）
}

interface CreateActivationCodeResponse {
  items: ActivationCode[];      // 创建的激活码列表
  batchId?: string;             // 批次ID（批量创建时）
}
```

## 5. 业务逻辑

### 5.1 激活码生成规则

- 码格式：`PREFIX-XXXX-XXXX-XXXX`（大写字母+数字）
- 默认长度：16位（不含前缀和分隔符）
- 唯一性：数据库唯一索引保证
- 批次ID：批量创建时自动生成，格式 `BATCH-YYYYMMDD-HHMMSS`

### 5.2 激活码状态流转

```
active ──→ used (单次使用码被兑换)
active ──→ disabled (管理员禁用)
active ──→ expired (超过有效期)
disabled ──→ active (管理员重新启用)
```

### 5.3 兑换流程

1. 验证激活码存在且状态为 `active`
2. 验证未过期
3. 验证用户未超过使用次数限制（多次使用码）
4. 验证用户未使用过该码（单次使用码）
5. 在事务中：
   - 更新激活码状态/使用次数
   - 创建使用记录
   - 增加用户积分
   - 记录积分交易

## 6. 安全考虑

- 激活码不可猜测（随机生成）
- 兑换接口需要用户登录
- 管理接口需要管理员权限
- 防止暴力破解：限制兑换频率（每用户每分钟最多5次）
- 操作审计：创建、兑换、删除都记录审计日志
