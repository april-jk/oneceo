# 00 总体边界与验收总表 [20260426-1457已采用]

## 1. 阶段定位

本文件是分阶段实施的总边界。它不定义具体代码实现，而是规定每个阶段进入开发、退出开发、进入下一阶段的共同规则。

核心判断：

> OneCEO 要吸收 ClaudeCode 的上下文管理哲学，但不能另起一套绕过 OneCEO 现有 DB / Redis / SSE / OSAC / managed runtime 的并行系统。

## 2. 术语统一

| 术语 | 含义 |
| --- | --- |
| ledger | managed context 的协议中立事实视图，第一阶段只能 read-only adapter |
| canonical record | DB-backed 权威记录，迁移期来自现有 `conversation_messages`、`task_session_run_events`、metadata |
| projection | 从 canonical record 派生出的 UI、history、Redis、SSE、API messages |
| manifest | 每次上下文编译的证据清单，记录 hash、tool pairing、included context |
| reconciler | 在 compiler 前补齐协议事实的模块，例如 ask_user answer -> tool_result |
| compiler | 只读 ledger + snapshot，输出 provider-specific API messages，不写状态 |
| snapshot | 本轮模型调用前冻结的 tools、MCP、skills、memory、budget、provider 状态 |

## 3. 全局硬边界

所有阶段都必须遵守：

1. DB 是事实来源，Redis 是热状态和恢复 projection。
2. `AltusRunEventWriter.appendRunEvent(...)` 的职责不能被绕过。
3. `task_session_run_events.sequence` 和可映射 cursor 不能出现双源。
4. `conversation_messages.messageKey` 不能在 read-only 阶段被重写。
5. compiler 不写 ledger、不写 run event、不写 lifecycle。
6. LLM 不直接改内部状态，只能通过工具结果和后端工具边界间接影响流程。
7. OSAC 仍是 sandbox 内 MCP Runtime Host。
8. connector guide gating 和 deployment gate 仍是平台能力边界。
9. dynamic skills / MCP / memory / attachment 只能通过 delta 或 typed context block 注入。
10. direct mode 不进入本套 managed context compiler。

## 4. 阶段总表

| 阶段 | 可交付物 | 关键验收 |
| --- | --- | --- |
| 1 | read-only ledger adapter、snapshot、compiler、manifest debug | 不改变 run 行为；能解释真实 session 中 ask_user/tool_result 缺口 |
| 2 | ask_user / clarification pairing 写入链路 | 用户回答补充信息后不重复追问；pending ask_user 不会进入下一次模型调用 |
| 3 | tool result envelope 和失败 tool_result | 工具失败、blocked、invalid args 都能进入下一轮模型上下文 |
| 4 | skills/MCP/memory/attachments typed context blocks | 动态能力不污染 stable prompt，reload 后不丢 |
| 5 | recovery/cache observability | Redis 丢失可重建，cache miss 可解释，retry/reload 不重复旧问题 |

## 5. 全局验收条件

每个阶段完成时都必须满足：

1. `pnpm --filter api test` 或对应更小测试集通过；如果阶段只改 web，则补充 web 检查。
2. 受影响服务的单元测试覆盖新增边界。
3. 至少有一个真实 session 或可复现 fixture 证明行为。
4. 未改变 direct mode 行为。
5. 未改变未声明的 SSE 事件名。
6. 文档中的禁止事项没有被实现绕过。
7. 失败路径有明确 evidence，而不是只验证 happy path。

## 6. 进入下一阶段门槛

进入下一阶段前必须确认：

1. 当前阶段验收条件全部通过；
2. 当前阶段发现的新风险已写入对应阶段文档；
3. 当前阶段实现没有制造新的并行事实源；
4. 当前阶段提交信息记录 `Tested` 和 `Not-tested`；
5. 用户明确同意进入下一阶段。

## 7. 总体非目标

本系列阶段不做：

1. 不重写整个 `AltusRunCoordinator`；
2. 不替换 OSAC；
3. 不把 Redis 升级成事实存储；
4. 不用关键词 reducer 代替上下文协议；
5. 不把 ClaudeCode 的 CLI UI 搬到 OneCEO；
6. 不改变部署、调试、shell 等高风险工具的能力边界。
