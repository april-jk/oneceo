> 创建时间：2026-05-02

## 1. 背景与目标

### 1.1 现状
- 用户端侧边栏已有「通知」入口（`Sidebar.tsx`），但点击无实际功能
- 设置页面有邮件/推送通知开关（`SettingsDialog.tsx`），仅为 UI 占位
- 管理后台无通知管理能力
- 无通知数据存储

### 1.2 目标
1. **用户端**：侧边栏 → 通知中心，查看系统通知、已读/未读状态
2. **管理后台**：通知管理页面，支持创建、编辑、删除、批量下发通知
3. **数据存储**：独立的通知表和用户通知关联表，支持已读状态追踪

## 2. 数据库设计

### 2.1 通知主表 `notifications`

```sql
CREATE TABLE IF NOT EXISTS notifications (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'system',  -- system, billing, task, security
  priority TEXT NOT NULL DEFAULT 'normal',  -- low, normal, high, urgent
  target_type TEXT NOT NULL DEFAULT 'all',  -- all, specific_users, user_group
  target_user_ids JSONB,  -- 当 target_type='specific_users' 时存储用户 ID 列表
  status TEXT NOT NULL DEFAULT 'draft',  -- draft, published, archived
  published_at TIMESTAMP,
  expires_at TIMESTAMP,
  metadata_json JSONB NOT NULL DEFAULT '{}'::jsonb,
  created_by UUID REFERENCES admin_users(id) ON DELETE SET NULL,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_notifications_type ON notifications(type);
CREATE INDEX idx_notifications_status ON notifications(status);
CREATE INDEX idx_notifications_created_at ON notifications(created_at);
```

### 2.2 用户通知关联表 `user_notifications`

```sql
CREATE TABLE IF NOT EXISTS user_notifications (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES app_users(id) ON DELETE CASCADE,
  notification_id UUID NOT NULL REFERENCES notifications(id) ON DELETE CASCADE,
  is_read BOOLEAN NOT NULL DEFAULT FALSE,
  read_at TIMESTAMP,
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  UNIQUE(user_id, notification_id)
);

CREATE INDEX idx_user_notifications_user_id ON user_notifications(user_id);
CREATE INDEX idx_user_notifications_notification_id ON user_notifications(notification_id);
CREATE INDEX idx_user_notifications_user_read ON user_notifications(user_id, is_read);
```

### 2.3 设计说明
- **notifications**：存储通知内容和下发策略
- **user_notifications**：存储每个用户与通知的关联关系及已读状态
- 当通知 `target_type='all'` 时，用户首次查询时动态创建关联记录
- 当通知 `target_type='specific_users'` 时，创建通知时批量插入关联记录

## 3. API 设计

### 3.1 管理后台 API（`/api/internal/notifications`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/internal/notifications` | 获取通知列表（分页、筛选） |
| POST | `/api/internal/notifications` | 创建通知 |
| PUT | `/api/internal/notifications/:id` | 更新通知 |
| DELETE | `/api/internal/notifications/:id` | 删除通知 |
| POST | `/api/internal/notifications/:id/publish` | 发布通知 |
| POST | `/api/internal/notifications/:id/archive` | 归档通知 |
| GET | `/api/internal/notifications/:id/stats` | 获取通知统计（已读/未读人数） |

### 3.2 用户端 API（`/api/notifications`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/notifications` | 获取当前用户的通知列表 |
| GET | `/api/notifications/unread-count` | 获取未读通知数量 |
| PUT | `/api/notifications/:id/read` | 标记单条通知为已读 |
| PUT | `/api/notifications/read-all` | 标记所有通知为已读 |

### 3.3 API 请求/响应示例

#### 创建通知
```json
POST /api/internal/notifications
{
  "title": "系统维护通知",
  "content": "系统将于今晚 22:00-23:00 进行维护升级...",
  "type": "system",

  "target_type": "all",
  "expires_at": "2026-05-10T00:00:00Z"

```

### 4.2 核心服务 `NotificationService`

```typescript
class NotificationService {
  // 管理端
  async createNotification(params: CreateNotificationParams): Promise<Notification>
  async updateNotification(id: string, params: UpdateNotificationParams): Promise<Notification>
  async deleteNotification(id: string): Promise<void>
  async publishNotification(id: string): Promise<void>
  async archiveNotification(id: string): Promise<void>
  async listNotifications(params: ListParams): Promise<PaginatedResult<Notification>>
  async getNotificationStats(id: string): Promise<NotificationStats>

  // 用户端
  async getUserNotifications(userId: string, params: GetUserNotificationsParams): Promise<PaginatedResult<UserNotification>>
  async getUnreadCount(userId: string): Promise<number>
  async markAsRead(userId: string, notificationId: string): Promise<void>
  async markAllAsRead(userId: string): Promise<void>

  // 内部
  async ensureUserNotificationExists(userId: string, notificationId: string): Promise<void>
  async cleanupExpiredNotifications(): Promise<void>
}
```

### 4.3 通知下发逻辑

1. **全员通知**（`target_type='all'`）：
   - 创建通知时只写入 `notifications` 表
   - 用户查询时，检查 `user_notifications` 是否有记录，无则自动创建（`is_read=false`）

2. **指定用户通知**（`target_type='specific_users'`）：
   - 创建通知时批量写入 `user_notifications` 表
   - 支持通过 `target_user_ids` 指定接收用户

3. **通知过期**：
   - 查询时过滤 `expires_at < NOW()` 的通知
   - 后台定时任务清理过期通知

## 7. 边界条件

1. **并发安全**：已读标记使用 UPSERT 避免重复插入
2. **性能考虑**：
   - 未读数量使用缓存（Redis 可选）
   - 大量通知分页加载
   - 过期通知定期清理
3. **数据一致性**：
   - 删除通知时级联删除 user_notifications
   - 用户删除时级联删除关联记录
4. **权限控制**：
   - 管理后台 API 需要 admin 权限
   - 用户端 API 只能访问自己的通知
