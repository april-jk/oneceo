# 03 前端交互与状态模型

## 1. 前端目标

前端要参照 `suna`，形成完整的输入附件体验，而不是只有“添加成功”的一次性动作。

目标覆盖：

- 首页输入框
- 任务创建对话输入框
- managed chat 多轮输入

## 3. 输入方式设计

### 3.1 必须支持

- 本地文件选择
- 拖拽文件进入输入区
- 粘贴图片
- 技能模板附件

### 3.2 建议参照 Suna 补齐

- zip 自动解包
- 本地预览 URL
- 上传中状态
- 明确的错误状态

## 4. 附件状态模型

前端附件状态统一定义为：

- `pending`
- `uploading`
- `ready`
- `error`

建议结构：

```ts
type ChatAttachmentDraft = {
  localId: string;
  sourceName: string;
  displayName: string;
  path?: string;
  size: number;
  mimeType: string;
  file?: File;
  localUrl?: string;
  status: "pending" | "uploading" | "ready" | "error";
  errorMessage?: string;
  uploadedAt?: string;
};
```

### 4.1 状态含义

- `pending`
  - 已加入输入框，尚未提交
- `uploading`
  - 用户已发送，服务端正在处理
- `ready`
  - 服务端已成功写入 Sandbox，消息已提交
- `error`
  - 本次发送失败或解析失败

## 5. 前端行为规则

### 5.1 添加时

前端先完成本地校验：

- 类型白名单
- 单文件大小
- 附件总数量
- zip 解包数量与总大小

不通过的文件直接在输入态提示，不进入待发送列表。

### 5.2 发送时

发送按钮点击后：

1. 文本和附件一起提交。
2. 如果当前页面还没有 `sessionId`，由统一输入接口一次性完成 session 创建并返回 `sessionId`。
3. 所有 `pending` 附件进入 `uploading`。
4. 点击发送后，输入区附件草稿立即清空，由本次发送请求持有附件快照继续提交。
5. 请求成功后该轮消息进入历史，输入区保持空草稿态。
6. 请求失败则把本次发送失败的附件合并恢复到输入区，允许用户重试或移除。

补充约束：

- 已进入会话后的多轮输入必须继续支持添加附件
- `currentQuestion` / 澄清态不能把附件按钮直接禁用
- 回答澄清问题时，文本和附件也必须走同一条提交链路
- 允许“仅附件、无额外文本”的澄清回答

### 5.3 删除时

#### 发送前删除

允许直接从待发送列表移除：

- 删除本地状态
- 释放 `localUrl`

#### 发送后删除

本轮设计不允许对已进入会话历史的附件做“从消息中删除”的编辑式操作。

原因：

- 用户消息已经成为历史事实
- Sandbox 中文件可能已被后续步骤引用

因此发送后删除只做：

- UI 上不提供“从历史消息移除附件”的操作

## 6. 消息展示规则

### 6.1 用户消息卡片

用户消息展示分两层：

1. 文本内容
2. 附件 chips / 附件预览块

展示优先读取：

- `message.metadata.attachments`

不依赖从文本里反向正则解析后再展示。

### 6.2 输入区附件列表

输入区附件列表需要区分状态：

- `pending`: 正常态
- `uploading`: loading 样式
- `ready`: 成功态
- `error`: 错误态

### 6.3 图片类附件

图片类附件在输入区和消息区都可直接显示缩略信息，但不在本次设计中扩展成重型预览器。

## 7. 页面接入策略

### 7.1 首页 `Home.tsx`

改造目标：

- 不再只 stash `File[]`
- 改为 stash 完整附件草稿结构或可重建结构
- 首页首条消息不再要求前端先手动 `ensureSession(...)`
- 已进入 session 后的继续对话与澄清回答都能随时继续添加附件

### 7.2 `TaskCreationChat.tsx`

改造目标：

- 不再先 `uploadTaskCreationAttachment(...)` 后 `sendChatInput(...)`
- 改为调用统一输入接口
- 发送成功后把返回的 `sessionId + message + attachments` 一次性写入本地消息

### 7.3 `useTaskCreationAgent.ts`

改造目标：

- 新增统一的 `sendUserInputWithAttachments(...)`
- 对本地 optimistic user message 支持 attachments 元数据
- 与 managed run 启动状态联动
- 不再让前端同时维护“create session + upload attachment + start run”三段式主链路

## 8. 需要明确废弃的前端逻辑

以下逻辑在实现时应删除或替换：

1. `appendAttachmentsToPrompt(...)`
2. `uploadTaskCreationAttachment(...)` 作为发送前主路径
3. “附件先上传、文本再发送”的前端双阶段主链路

## 9. 前端验收标准

1. 用户可通过本地、拖拽、粘贴添加附件，并可选择技能附件。
2. 输入区能看到明确附件状态。
3. 发送后历史消息能稳定展示附件 chips。
4. 附件发送失败时，用户能明确知道失败项。
5. 多轮对话中，新一轮发送不会污染上一轮附件状态。
