## 1. 页面目标

本模块不是 skill 管理页的扩展，而是 connector guide 的后台治理页。

后台管理员需要能够：

1. 管理某 connector 的 guide policy
2. 编辑 guide 文本
3. 校验
4. 发布
5. 回滚

本轮只覆盖：

1. GitHub
2. Supabase
3. Vercel
4. Notion

补充口径（2026-04-11）：

1. 页面候选 connector 不再前端写死
2. 页面统一通过 `GET /api/connector-guides/catalog-summary` 获取 catalog 与统计信息
3. 后续新增 MCP 时，页面应自动显示可见 connector，无需单独增加按钮代码

## 2. 页面定位

建议在管理后台新增菜单：

`连接器治理 / Connector Guides`

不要挂到现有 skill management 菜单下，避免和平台 skills 产生误解。

## 3. 信息架构

页面拆成三层：

1. policy 列表页
2. policy 详情页
3. revision 编辑页

当前实现补充：

1. 首屏增加 MCP catalog 快照卡片
2. 展示 `MCP 类型数量 / 可用数 / 不可用数 / 可见 connector 列表`
3. 页面进入时拉取一次 catalog，后续通过“刷新列表”手动同步

## 4. 列表页设计

### 4.1 页面目标

快速查看：

1. 哪些 connector 已有 guide
2. 当前 published revision 是什么
3. trigger mode 是什么

### 4.2 表格列

1. `Connector`
2. `Status`
3. `Trigger Mode`
4. `Published Revision`
5. `Updated At`
6. `操作`

### 4.3 操作

1. `查看详情`
2. `新建 Draft`
3. `停用`

### 4.4 候选 connector 来源

页面上的“新建 connector guide policy”按钮与筛选下拉应统一来自：

1. `catalog-summary.items` 中 `visibleInMenu=true` 的 connector
2. 当前已存在的 `policies.connectorKey`
3. 内置候选集合（至少含 `github / supabase / vercel / notion`），用于兼容 catalog 尚未返回前的首屏渲染

要求：

1. 不允许继续在多个前端常量里重复写死同一组 connector keys
2. 后续新增 MCP 时，只要 catalog 能返回该 connector，页面就应自动出现候选项

## 5. Policy 详情页设计

### 5.1 基础信息卡片

展示：

1. connectorKey
2. status
3. triggerMode
4. description
5. published revision

### 5.2 Published Revision 摘要卡片

摘要展示三段文本是否存在：

1. `Server Instructions`
2. `Guide Reminder`
3. `Blocking Rules`

不需要把完整文本全放在详情页，避免过长。

### 5.3 Revision 历史列表

列：

1. `Version`
2. `Status`
3. `Created By`
4. `Created At`
5. `Notes`
6. `操作`

补充要求（2026-04-11）：

1. Revision 历史位于右侧窄栏时，布局必须允许卡片收缩，不能因表格列宽把父容器撑出页面
2. 长时间文本与操作按钮必须可换行或收缩，避免产生横向溢出

操作：

1. `查看`
2. `编辑`
3. `校验`
4. `发布`
5. `回滚`

## 6. Revision 编辑页设计

### 6.1 页面目标

只编辑三段 guide 文本，不引入复杂 item 编排。

### 6.2 页面结构

#### A. Revision Header

展示：

1. connector 名称
2. revision version
3. revision status
4. notes

顶部操作：

1. `保存 Draft`
2. `校验`
3. `发布`

#### B. Server Instructions 编辑区

用于填写高优先级行为规则。

建议编辑器下方固定说明：

1. 写先后顺序
2. 写前置条件
3. 写禁止路径
4. 写失败即停止的规则

#### C. Guide Reminder 编辑区

用于填写 system reminder 风格的短文本。

目标：

1. 主动告诉 Altus 当前有哪些 relevant connector guides
2. 明确提示应优先遵守 guide

#### D. Blocking Rules 编辑区

用于填写连接器使用前的刚性规则。

目标：

1. 对写入类 MCP 调用建立先决规则
2. 强调“未满足条件就停止”

## 7. ClaudeCode 参考逻辑在页面层的体现

为了和参考实现对齐，页面文案必须引导管理员写出三种不同职责的文本，而不是一段大杂烩：

1. `Server Instructions`
   - 对应 ClaudeCode 的 MCP server instructions
2. `Guide Reminder`
   - 对应 ClaudeCode 的 relevant skills surfaced reminder
3. `Blocking Rules`
   - 对应 ClaudeCode 的 blocking requirement

## 8. 校验结果展示

校验抽屉展示：

1. 文本完整性
2. 长度超限
3. 是否误写入 skill 平台语法
4. 是否缺少“停止/确认/前置检查”这类关键规则

## 9. 发布与回滚

### 9.1 发布确认弹窗

展示：

1. connector
2. revision version
3. 三段文本是否齐备
4. 发布后会影响的运行时 connector

### 9.2 回滚确认弹窗

展示：

1. 当前 published revision
2. 将回滚到的 revision
3. 回滚后运行时会使用旧 guide 文本

## 10. 首批页面范围

必须做：

1. 列表页
2. 详情页
3. revision 编辑页
4. validate 抽屉
5. 发布/回滚确认框

不做：

1. skill 资源树
2. item 粒度排序
3. sandbox 文件预览

## 12. 验收标准

1. 后台管理员可管理 GitHub / Supabase / Vercel / Notion guide 文本
2. 页面清晰区分三段文本职责
3. 页面进入时能看到最新 MCP 类型与数量
4. 新增 MCP 后页面候选项来自 `catalog-summary`，不再要求新增前端硬编码
5. 不出现任何“复用 skill revision”交互
6. 不把 connector guide 混入 skill management 页面
