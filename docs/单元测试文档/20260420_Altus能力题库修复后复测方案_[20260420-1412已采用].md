## 4. 关注点

### 4.1 需要重点确认的正向信号

1. 出现明确澄清问题或 `waiting_user` 语义
2. 任务描述不再被改写成“营销计划制定”
3. Python 脚本任务不再被下发为网页应用
4. 不部署约束能阻止部署主链与网页执行模板

### 4.2 失败信号

1. 再次出现 marketing fallback
2. 再次出现“网页应用 + Playwright 验证”注入到脚本任务
3. 高歧义任务仍然直接进入执行层
4. 多轮第一轮任务目标仍然跑偏

## 5. 执行方式

1. 初始化一个新的 eval run
2. 对上述 5 个 case 逐题执行
3. 读取 artifact JSON、会话消息、session detail
4. 按现有评分规则重新判分

## 6. 输出要求

最终输出必须包含：

1. 复测 run 路径
2. 与上次 smoke 的对比结论
3. 已修复项
4. 未修复项
5. 建议下一轮继续修复的优先级
