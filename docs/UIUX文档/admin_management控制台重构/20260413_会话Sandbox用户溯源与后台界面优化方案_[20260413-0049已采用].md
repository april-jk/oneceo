# 会话 Sandbox 用户溯源与后台界面优化方案 [20260413-0049已采用]

## 背景

本轮需求要求后台对话详情能精确关注会话关联 Sandbox，并能清晰看到对话来源用户信息，同时优化 OSAC 版本、技能管理二级菜单、智能体管理 UI、字体与响应式布局。用户已在 2026-04-13 明确授权“不确认任何内容，包括 doc，直接自行迭代”，因此本方案创建后直接进入采用与实现阶段。

## 目标

- 会话详情不再依赖“最近 Sandbox 列表再过滤”，改为按 `taskSessionId` 精确查询 Sandbox 环境记录。
- 会话列表和详情展示来源用户信息：用户 ID、显示名、邮箱、状态、最近登录/活跃、IP、User-Agent。
- 会话详情中的主 Sandbox 卡片要能一眼识别当前主实例、执行器、归档状态、接管关系，并能跳转 Sandbox 管理。
- OSAC 版本页从普通表格升级为更清晰的发布工作台，突出 current/pending/all/upload 语义。
- 技能管理新增二级菜单式信息架构，让列表、内容编辑、版本资源、校验更符合人类操作顺序。
- 智能体管理重排为“总览 + 阶段 + 能力”三段式，减少重复状态和图表噪音，增强移动端响应式表现。
- 字体策略统一为中文界面优先的正文、数字与代码字体组合，避免字号和字重混乱。
- 顶部浮动栏增加主题选择，管理员切换配色后自动写入 `.env` 中的 `ADMIN_MANAGEMENT_THEME`。

## 数据链路设计

### 会话到 Sandbox

现有事实：

- `sandbox_execution_environments.metadata.taskSessionId` 已存在索引。
- `sandboxExecutionEnvironmentDAO.findCanonicalByTaskSessionId()` 已实现 canonical 排序。
- 管理端 `conversation-management-service` 当前通过 `listSandboxEnvironments(200)` 后端过滤，数量超过 200 时可能漏掉目标环境。

改造方案：

1. API 增加内部接口 `GET /api/internal/sandbox/by-task-session/:taskSessionId`。
2. 接口返回：
   - `taskSessionId`
   - `primaryEnvironment`
   - `relatedEnvironments`
3. `primaryEnvironment` 使用 `findCanonicalByTaskSessionId()`。
4. `relatedEnvironments` 使用 `listByTaskSessionId(taskSessionId, 200)`。
5. 管理端 BFF 的 `ConversationManagementService` 改为先请求该内部接口。
6. 当该接口异常时，不做错误降级展示，只把错误写入 `kvm.errors`，避免错误主记录误导管理员。

### 会话来源用户

现有事实：

- `task_creation_sessions.user_id` 已写入当前用户真实 `app_users.id`。
- `app_users` 保存 `email/display_name/status/last_login_at`。
- `app_user_sessions` 保存 `ip_address/user_agent/last_seen_at/created_at`。

改造方案：

1. API 内部管理态会话摘要补充 `user` 对象。
2. 若 `task_creation_sessions.user_id` 是真实 UUID，则查询 `app_users` 与最近一条 `app_user_sessions`。
3. 若不是真实用户 ID，则返回 `source: legacy_user_id`，只展示原始 ID，避免误把匿名或旧 header 当真实账号。
4. 管理端 BFF 透传 `user` 字段给前端。
5. 前端会话列表展示用户显示名/邮箱/IP；详情概览展示完整来源信息。

## UI 设计

### 字体

- 正文：`Noto Sans SC`，保证中文后台阅读稳定。
- 数字与短标签：`IBM Plex Sans`。
- 代码、ID、路径、哈希：`Fira Code`。
- 标题字号不再新增 viewport 缩放，使用稳定尺寸和响应式布局承载信息密度。

### OSAC 版本

- 顶部保留发布状态，但改为更明确的三项发布指标。
- 标签切换改为 segmented control。
- 版本列表突出 current/pending 状态，详情区域用事实网格替代段落堆叠。
- 上传区域保持原表单行为，只优化字段间距与辅助说明。

### 技能管理

- 主界面新增“二级菜单”：全部技能、启用、归档、已发布、待发布。
- 列表上方新增统计条，帮助管理员快速判断平台技能状态。
- 详情弹窗保留“内容与版本、资源明细、沙箱校验”三段式流程。
- “渲染预览”从管理端详情页移除，避免管理员在版本与资源之间重复跳转。
- 版本历史并入“资源明细”，先选版本，再查看该版本资源列表与资源正文。
- “内容与版本”页聚焦基础信息、主说明文档、补充文档与保存为新版本动作。

### 智能体管理

- 首屏只保留一个“智能体总览”，把服务在线状态、会话关键计数和能力可用数收进同一行视线里，避免一类信息重复出现。
- 阶段区域去掉图表，改成横向阶段切换 + 当前阶段详情，优先展示当前阶段的状态构成和最近会话。
- 能力区域保留名称、接入方式和状态，去掉端点正文等低频字段，信息密度更像管理员日常检索习惯。

### 2026-04-17 智能体管理再精简

- 去掉原来的“服务健康 / 会话状态 / KPI / 阶段图表”四层重复结构，收口成 `总览条 + 阶段工作区 + 能力列表` 三段式。
- 阶段切换从左侧纵向卡片改成横向胶囊按钮，选中后只展示当前阶段的状态摘要和最近会话，减少视线来回跳。
- 最近会话卡只保留标题、状态、更新时间和待补充问题，不再显示原始会话 ID 等噪音字段。
- 能力卡改成轻量行列表，默认只显示名称、接入方式和状态；端点保留在 hover title 中，避免占满版面。

### 2026-04-13 二次精修

- 审计日志页顶部只保留一张“审计摘要”卡片，“筛选状态”卡片移除，避免首屏出现重复摘要。
- 审计日志筛选栏改成更紧凑的工具条式布局：标题、结果提示和应用/重置操作集中在同一行，字段改成轻量两行栅格，减少筛选区对首屏高度的占用。
- 对话管理状态流转 `state-timeline-item` 改为编号时间线、双状态快照、流程 chip 与触发摘要的现代布局。
- 对话管理索引摘要横排和筛选横排按容器宽度铺满，保留面板内边距作为页面留白。
- 技能管理移除“渲染预览”页签，版本历史迁入“资源明细”，内容编辑区域增加发布版本、当前编辑版本、资源数量和补充文档的上下文摘要。

### 2026-04-17 技能详情布局细化

- 技能详情弹窗顶部改为“标题 + 状态标签 + 事实摘要 + 居中页签”的稳定层级，先给管理员当前技能的关键信息，再进入编辑。
- “内容与版本”页改成左主编辑区、右版本侧栏；版本列表与编辑动作分层，减少正文编辑时的视觉干扰。
- “资源明细”页保留版本 / 资源 / 详情三栏，但资源项改成更易扫读的标题、路径、类型与加载阶段结构，右侧详情改成摘要头、事实卡和正文预览。
- 技能管理页首屏的“新建技能 / 导入技能文件夹 / 刷新技能”改成带图标块与辅助说明的分层按钮组，主操作更突出，辅助操作更克制。

### 2026-04-13 主题选择

- 顶部浮动栏改为只保留一个“设置”图标按钮，点击后打开二级设置菜单。
- 主题配置来源为管理后台 API `GET /api/theme`，切换时调用 `PUT /api/theme`。
- 后端写入当前管理后台加载的 `.env` 文件；若没有加载到 `.env`，则创建当前工作目录下的 `.env`。
- `.env` key 固定为 `ADMIN_MANAGEMENT_THEME` 与 `ADMIN_MANAGEMENT_THEME_MODE`。
- 主题模型收敛为“主题家族 + 外观模式”两层：
  - 主题家族只保留 `GitHub`、`Nord`、`Rose Pine`
  - 外观模式只保留 `亮色`、`暗色`、`跟随系统`
- 前端在 `跟随系统` 模式下监听系统明暗切换，并自动更新实际使用的亮/暗配色。
- 配色切换时同步切换正文、弱文本、图标、边框、卡片、表格、输入框、状态 chip 与按钮文字色，避免暗色主题出现背景与文字对比不足的问题。
- 前端切换后先即时应用 CSS 变量，再请求后端持久化；持久化失败时回滚到上一个主题与模式。

### 2026-04-14 Sandbox 摘要移除

- Sandbox 管理页移除顶部独立“Sandbox 摘要”面板，首屏直接进入“Sandbox 工作区”，减少重复指标占用。
- Sandbox 工作区页签由“摘要”改为“概览”，保留原概览内容但避免与顶部摘要概念混淆。
- 会话详情中的 `KVM / Sandbox 摘要` 改名为 `Sandbox 绑定信息`，保留主 Sandbox 跳转、编排 ID、归档状态和关联记录数等定位能力。
- Sandbox Runtime 列表移除“风险聚合”按钮区，风险标签仅保留在筛选栏中，避免列表上方出现重复筛选层。

### 2026-04-14 Sandbox 详情工具分栏

- Runtime inspector 页签调整为 `摘要 / 文件 / 进程与端口 / 连通性 / 归档 / 命令调试`，文件、进程、端口不再挤在旧“高级调试”页内。
- `文件` 页签采用 ranger / yazi 类终端文件管理器心智：顶部地址栏和返回/刷新操作，默认进入根目录 `/`，主体仅保留全宽可展开目录树，不再展示快速访问栏、文件内容栏、右侧状态文本块、文件树标题与说明文案；文件管理页使用随主题适配的柔和渐变工作台背景，不使用网格纹理，工具栏和文件树面板采用半透明材质以提升层次；工具栏提供上传、下载、删除操作，上传写入当前目录，下载面向选中的普通文件，删除面向选中的文件或目录；上传和下载过程中展示进度条并模糊文件管理背景，成功反馈统一使用右上角 toast；文件夹与普通文件使用不同强调色区分，文件树行展示 Linux `rwx` 符号权限（如 `drwxr-xr-x`、`-rw-r--r--`），已展开但无子项的目录必须显示“空目录”占位。
- `进程与端口` 页签采用 Windows 任务管理器心智：顶部提供紧凑的 `进程 / 端口` 分段切换，同一时间只全宽展示一个工作卡片；进程卡片保留刷新与结束 PID，端口卡片仅保留刷新监听快照，不再提供端口映射 / Host 查询；数量标签、快照年龄计数器（如“这是 5 秒前的进程列表”）与辅助提示并入标题区，帮助用户判断当前列表新鲜度。
- `命令调试` 页签保留终端回显和运行元数据，命令输入、提示符、输出区统一使用等宽字体。
- 本次仅复用既有 `runSandboxToolAction` 调试通道，不新增 Sandbox 生命周期或直连服务链路。

### 2026-04-17 Sandbox 概览再收口

  - 顶部状态胶囊统一展示运行态、归档态和纳管来源；
  - 中部统计条固定展示 `会话状态 / 最近活跃 / 归档状态`。
- 概览主体改成 `运行摘要卡 + 关联会话卡 + 运行动作卡` 三段式，和用户详情、对话详情形成同一套工作台语言。
- 概览事实区统一收口为事实网格，保留 `Sandbox 标识 / 执行器 / 模板 / 会话标题 / 创建时间 / 最后更新` 这些高频字段。
- `archiveStatus` 为空时不再直接显示 `-`，统一改写为 `未归档`，减少管理员对内部空值语义的猜测。

### 2026-04-17 对话关联 / 状态流转 / 归档页再收口

- `对话详情 > 关联` 页签进一步收口为两张主卡：
  - `会话身份` 只保留来源用户、来源 IP、最近活跃、最近访问来源与 UA；
  - `运行绑定` 只保留主 Sandbox、编排会话、处理方式、归档状态、最近绑定变更与最近 3 条关联实例。
- `关联信息` 页签标题与页签文案同步压缩，页签从 `关联信息 / 详细日志 / 状态流转` 收口为 `关联 / 日志 / 流转`，降低二级菜单高度。
- `对话详情 > 概览` 右侧消息摘要去掉重复统计条，不再和左侧总览重复表达 `状态流转 / 对话消息 / 日志数量`。
- `对话详情 > 流转` 改成 `顶部摘要卡 + 筛选区 + 时间线` 的顺序：
  - 顶部摘要卡先给出筛选后数量、命中阶段、命中状态、命中相位；
  - 高级筛选继续保留，但降成次级展开层；
  - 时间线卡片补充触发标签胶囊与触发内容块，减少长句堆叠。
- `Sandbox 详情 > 归档` 改成 `归档摘要卡 + 历史快照 + 折叠元数据` 三段式：
  - 顶部摘要先给最近归档、快照数量、当前体积、当前快照、最近恢复和元数据键；
  - 历史快照表承担检索职责；
  - 原始元数据默认折叠，避免与摘要和历史表抢视线。
- 深色主题对应补齐这些新卡片的边框、背景和次级文本语义，避免切换主题后信息层次发灰。

### 2026-04-17 日志页与归档详情弹层补充收口

- `对话详情 > 日志` 页签继续改成 `摘要卡 + JSON 正文` 两段式：
  - 先展示导出时间、会话标识和 `消息记录 / LLM 轨迹 / 总载荷 / 最近记录`；

- `Sandbox 详情 > 归档 > 快照详情` 弹层继续收口为 `快照概览 + 事实区 + 标识区 + 动作区`：
  - 顶部摘要统一给出类型、人类可读状态、体积与时间/原因；
  - 中段事实区只保留 `时间 / 类型 / 大小 / 原因`；
  - 下段集中展示 `快照标识 / 哈希`，避免与事实网格混排。
- `快照详情` 关闭按钮和状态胶囊统一放在头部右侧，减少浮层内部重复动作。
- 该补充仅调整管理态展示层级，不改变归档接口、恢复动作或元数据结构。

### 2026-04-17 Sandbox 连通性 / 归档故障修正

- `连通性检查` 不再强依赖数据库里的 tracked 环境记录：
  - 当管理后台打开的是 `live_only` Sandbox 时，接口会回退到 E2B live metadata 继续检查；
  - 返回结果额外标记 `source: tracked | live_only`，便于排障时判断数据来源。
- `连通性` 页签里的工作目录字段补齐旧键位回退：
  - `workspaceRoot` 支持从 `opencodeWorkspaceRoot / altusWorkspaceRoot / workspaceRoot` 取值；
  - `stateRoot` 支持从 `opencodeStateRoot / altusStateRoot / stateRoot` 取值。
- `归档` 页签修正当前快照字段读取：
  - 管理后台详情不再只读旧的 `snapshotKey / metadataKey`；
  - 统一优先读取 `r2ArchiveSnapshotKey / r2ArchiveMetadataKey`，避免已归档实例在详情里显示成“空快照”。
- 归档服务在解析工作区根路径时，改为合并 `DAO metadata + E2B live metadata`：
  - 当数据库记录里暂时缺少 `taskSessionId / workspaceRoot / stateRoot`，但 live metadata 仍在时，归档链路仍可恢复正确前缀与目录。
- `归档历史 / 下载链接` 同样补齐 live metadata 回退：
  - 当 tracked metadata 暂时缺失 `taskSessionId` 时，历史快照列表与下载链接仍可回到正确的 session 前缀。

### 2026-04-15 会话关联信息精简

- `会话管理 > 关联信息` 改为轻量定位栏，只保留 `会话身份` 与 `运行绑定` 两张信息卡。
- `会话身份` 仅展示阶段、来源用户、来源 IP、最近活跃时间，并保留顶部状态标识。
- `运行绑定` 仅展示编排 ID、主 Sandbox、处理方式、归档状态与关联记录数；附加 Sandbox 不再按治理原因和实例组展开，仅保留最近 3 条简表。
- 原 `Sandbox 分组`、`OSAC / OpenCode` 消息流、`KVM / Sandbox 原始状态` 从该栏移除，避免与 `详细日志`、`状态流转` 等重内容页签重复。

### 2026-04-15 OSAC 发布台再整理

- OSAC 页首改为更克制的发布概览，只保留当前版本、全部版本、待处理、失败四项指标与三条发布规则，减少解释性噪音。
- 二级切换统一成四段工作流 tab：`已发布 / 待发布 / 全部版本 / 上传新版本`，每段同时显示数量与辅助提示，便于管理员快速进入正确操作面。
- 版本列表从表格改成左侧可选版本栈，强化“选版本 -> 看详情 -> 执行动作”的顺序，避免表格动作、详情动作和上传表单同时抢注意力。
- 详情区改成摘要卡 + 事实卡 + 发布说明 + 动作栏，发布、切换、校验全部固定在右侧详情收口，降低误操作。
- 上传页改为表单与发布规则侧栏双栏结构，保留当前版本、待处理数量和已选文件提示，让上传前后的上下文始终可见。
- 响应式下将列表、详情、上传侧栏自然折叠为单列，保证中窄屏仍维持单主任务流，不出现横向拥挤。
