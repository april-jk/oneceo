## 6. Actionable Inspector 设计

### 6.1 定位变化

`AdminStickyInspector` 的实现组件可保留名称，但设计语义升级为 `Actionable Inspector`：

| 修正前 | 修正后 |
|---|---|
| 展示当前状态、关联对象、最近操作 | 帮管理员判断风险并执行下一步 |
| 容易重复 Header / Overview 字段 | 只放风险、影响、阻断、推荐动作与快捷动作 |
| 静态信息栏 | 可操作上下文栏 |

### 6.2 统一 section

每个模块 Inspector 优先使用以下 section，不要求全部出现，但命名与语义要统一：

1. `当前风险`：对象当前是否存在风险，风险来自真实字段。
2. `影响范围`：操作会影响哪些业务对象或后续流程。
3. `最近操作`：来自真实时间字段、版本记录、发布记录、归档记录或前端操作上下文。
4. `阻断原因`：当前不能执行某动作的真实原因，例如未选 revision、已归档、未启用、已删除、无变更。
5. `推荐动作`：基于当前状态给出下一步建议，例如先校验、先保存、先发布、查看 diff。
6. `快捷动作`：安全动作或打开 Diff / Raw / 关联对象；危险动作仍进入 DangerConfirmDialog。

### 6.3 禁止内容

Inspector 不应重复：

1. Header 已展示的实体名称、状态、metric。
2. Overview 中的大量字段。
3. Configuration 中的表单字段。
4. Raw Data 的 JSON / manifest / long text。

## 7. RelationTopology 修正规则

### 7.1 真实对象原则

所有节点必须能追溯到当前详情已有真实数据：

1. 用户：`taskSession.user.id`、用户详情数据、账单用户数据。
2. Session / Conversation：`taskSessionId`、`conversationId`、会话详情。
3. Sandbox：`sandboxId`。
4. Runtime：只有存在真实 runtime endpoint / executor / state 时才展示；如果只是概念，不展示。
5. Artifact / Archive：必须存在 `snapshotKey`、`archiveKey`、`manifestKey`、`objectKey` 等真实字段。
6. Connector：`connectorKey`。
7. Revision：`revision.id` 或 `versionNumber`。
8. OSAC Release：`release.id`、`version`、`objectKey`、`manifestKey`。
9. Billing：`pricing.id`、`model`、`usage log id` 等真实字段。

禁止展示纯装饰节点，例如无法定位真实对象的 `Policy`、`Runtime`、`Artifact` 占位节点。

### 7.2 Sandbox 修正

Sandbox 保留 RelationTopology，但移除 Inspector 中的 `关联对象` section，避免重复。

Sandbox 拓扑建议：

```text
User → Session → Sandbox → Archive
```

仅在真实字段存在时展示节点：

1. User：`sandboxRuntimeDetail.taskSession?.user` 存在时展示；否则不展示或显示“用户未知”的空态，不做假节点。
2. Session：`runtime.taskSessionId` 存在时展示。
3. Sandbox：当前真实 sandboxId。
4. Archive：存在 `snapshotKey / archiveKey / archiveStatus` 时展示。

### 7.3 顶层弹窗规则

点击拓扑中的 User / Session 节点后：

1. 打开对应详情窗口。
2. 新弹窗必须在 Sandbox 详情之上显示。
3. 新弹窗 z-index 必须高于 `AdminDetailShell` 与 `DiffDrawer`。
4. 新弹窗关闭后应回到 Sandbox 详情上下文，不丢失当前 Sandbox tab。
5. 不允许被父弹窗遮挡或焦点困在父弹窗内。

实现可选方案：

1. 使用单独的 top-layer detail dialog，z-index 高于当前 shell。
2. 或在 `AdminDetailShell` 增加 `layer="base | top"` / `zIndexTier` 设计，但需要保持兼容。

## 8. DiffDrawer 修正

### 8.1 必填语义

所有 DiffDrawer 需要具备：

1. `impactItems`：影响范围。
2. `rollbackHint`：回滚能力与限制。
3. `syncHint`：是否需要保存、同步、发布、重启、缓存失效或等待。

### 8.2 编辑态 before / after

编辑态打开 Diff 时：

1. before 必须来自打开编辑器或详情时的原始值。
2. after 必须来自当前表单或编辑器值。
3. 无差异时显示“当前没有未保存变更”。
4. 不得将当前值复制成 before/after 后称为 diff。
5. 没有历史版本时，只能叫“保存前差异”，不能叫“历史版本差异”。

### 8.3 模块要求

| 模块 | Diff 来源 | impactItems | rollbackHint | syncHint |
|---|---|---|---|---|
| Skill | detail 原始字段 vs editor 当前字段 | 技能治理、自动加载、资源/版本 | 可通过重新保存版本修正；归档/启用另走确认 | 保存会生成或更新版本，可能影响后续加载 |
| Connector | revision 原文 / policy 原字段 vs editor 当前值 | 新会话 connector guide、发布 revision | 已发布 revision 可通过回滚恢复 | 保存后需校验，发布后新会话生效 |
| OSAC | release notes / artifact metadata；无真实 before 时不称历史 diff | latest 指针、后续 sandbox 下发 | 可切换回旧 release，但不删除 artifact | 发布/切换后后续 sandbox 跟随 latest |
| Billing | selectedPricing vs pricingForm 当前值 | 新请求计费，历史 usage 不回写 | 可再创建新版本，但历史不回写 | 保存后新请求按新价计费 |

## 9. AuditTimeline 修正

### 9.1 真实数据原则

AuditTimeline 只能来自真实数据或明确的前端操作上下文：

1. Sandbox：归档历史、最近活跃、创建/更新时间。
2. Connector：revision 历史、发布/回滚状态、校验结果。
3. OSAC：上传、校验、发布、切换 latest 的 release 字段。
4. Billing：如果没有定价历史时间线，不应宣称已接入完整 AuditTimeline；可展示当前定价创建/生效/删除事件，或明确空态。
5. Skill：如果只有版本列表、资源校验或更新时间，可基于这些真实字段展示；否则明确不使用。

### 9.2 模块要求

| 模块 | 本轮要求 |
|---|---|
| Sandbox | 保留并修正，使用真实归档与活跃字段。 |
| Skill | 补真实版本/资源/校验时间线；若数据不足，明确显示空态。 |
| Connector | 补 revision / publish / validate 时间线。 |
| OSAC | 可保留 release 上传/发布时间线。 |
| Billing | 补定价当前事件或显示“暂无历史审计数据”，不得报告为完整审计。 |
