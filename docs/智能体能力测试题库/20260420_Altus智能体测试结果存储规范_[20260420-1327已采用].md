# Altus 智能体测试结果存储规范 [20260420-1327已采用]

## 1. 目标

统一智能体测试结果的目录、文件、字段与命名方式，保证：

1. 结果可追溯
2. 结果可重复解析
3. 未来可脚本化汇总

## 2. 结果目录规范

建议所有执行结果归档到：

```text
docs/智能体能力测试题库/结果归档/YYYYMMDD/<suite_id>/<run_id>/
```

示例：

```text
docs/智能体能力测试题库/结果归档/20260420/altus-general-v1/run_20260420_150000/
```

## 3. 单次 run 固定文件

每次 run 目录内固定保留：

1. `run_manifest.json`
2. `case_results.jsonl`
3. `summary.md`
4. `artifacts/`

说明：

- `run_manifest.json`：记录本次执行的环境与全局信息
- `case_results.jsonl`：逐题结果，便于机器处理
- `summary.md`：人读摘要
- `artifacts/`：截图、日志、导出文件、证据快照

## 4. run_manifest 字段

至少包含：

1. `run_id`
2. `suite_id`
3. `suite_version`
4. `executed_at`
5. `executor`
6. `git`
7. `model_config`
8. `environment`
9. `case_count`
10. `summary`

其中：

- `git` 至少包含 `branch`、`commit`
- `model_config` 至少包含 `provider`、`model`、`temperature` 或等价配置摘要
- `environment` 至少包含 `mode`、`base_url`、`auth_profile`

## 5. case_results 字段

每一行一个 case 结果，至少包含：

1. `case_id`
2. `case_version`
3. `category`
4. `status`
5. `hard_fail`
6. `hard_fail_reasons`
7. `dimension_scores`
8. `total_score`
9. `verdict`
10. `evidence_refs`
11. `notes`

## 6. 证据引用方式

`evidence_refs` 统一使用相对路径或明确对象引用，例如：

1. `artifacts/screenshots/ALTUS-BOUNDARY-001.png`
2. `artifacts/logs/ALTUS-EXEC-001.log`
3. `conversation:session_123:message_45`
4. `run_event:run_abc:event_17`
5. `db:task_session_run_events:id=890`

要求：

- 一个 case 至少有一条硬证据
- 命中硬失败的 case 必须至少有一条直接证据

## 7. 状态枚举建议

`status` 统一使用：

- `passed`
- `failed_soft`
- `failed_hard`
- `blocked`
- `not_run`

`verdict` 统一使用：

- `pass`
- `fail`
- `warning`

## 8. 对比追踪字段

为了长期对比，每次 run 建议额外记录：

1. `baseline_run_id`
2. `compare_to_suite_version`
3. `changed_components`
4. `operator`

## 9. 禁止事项

禁止只保留：

1. 一份口头总结，没有原始明细
2. 只有总分，没有单题结果
3. 只有截图，没有题目编号
4. 只有题目编号，没有模型与代码版本
