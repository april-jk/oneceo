# Agent 与 Sandbox 模型运行配置及定价配置拆分方案 [20260426-2342已采用]

## 更新时间

2026-04-26

## 1. 背景与问题

当前用户端已存在 Lite / Pro / Max 模型选择 UI，但真实 managed run 链路没有读取该选择：

1. 前端 `selectedModel` 仅用于显示文案，没有随 `/api/altus-managed/inputs` 提交。
2. 后端 managed run 当前只读取 `ALTUS_MANAGED_MODEL`、`AGENT_OPENAI_MODEL`、`OPENAI_MODEL` 等通用变量。
3. 新增的 `ALTUS_MANAGED_MODEL_LITE`、`ALTUS_MANAGED_MODEL_PRO`、`ALTUS_MANAGED_MODEL_MAX` 目前只是环境变量准备，未进入解析链路。
4. 计费管理的定价配置当前以裸模型名为中心，不适合表达“Agent Lite / Pro / Max”与“Sandbox 直通引擎”这类业务计费对象。

## 2. 用户确认约束

本方案按以下约束设计：

1. **不新增独立加密表**：API Token 继续按环境变量/管理端 env 配置方式维护，不新增 credential 表。
2. **不把 env 迁移到 DB**：模型名称、接口、API Token 等运行配置仍以 env 为事实源，后续其他 env 相关配置也统一留给管理端设置。
3. **历史账单不受换模型影响**：Agent Pro 今天绑定 A 模型、明天绑定 B 模型时，历史 token 日志和积分交易必须继续按当时的定价与运行快照复核。
4. **Agent 与 Sandbox 模型/引擎配置一并在定价配置子层展示**：管理员在计费管理内即可看到运行配置与定价的关系，并能在同一子层进入调整。
5. **不做兼容性补丁式绕路**：以业务 SKU 为中心收敛，不允许用户端绕过档位直接传裸模型名。

## 3. 目标状态

计费管理中的「定价配置」拆成同一子层下的三块：

1. **Agent 档位运行配置**
   - Agent Lite
   - Agent Pro
   - Agent Max
   - 可调整：模型名称、接口 Base URL、协议类型、API Token、启用状态。
2. **Sandbox 直通引擎运行配置**
   - OpenCode
   - Codex
   - 后续引擎（接入执行链后再展示）
   - 可调整：每个引擎对应模型名称、接口 Base URL、协议类型、API Token、启用状态。
3. **业务 SKU 定价配置**
   - 只展示并配置以下计费对象：
     - `agent.lite`
     - `agent.pro`
     - `agent.max`
     - `sandbox.opencode`
     - `sandbox.codex`
     - 后续引擎 SKU（接入执行链后再展示）
   - 展示当前绑定的真实模型与接口摘要。
   - 提供跳转/锚点到同一子层中的 Agent 或 Sandbox 运行配置区域。

## 4. 运行配置 env 规划

### 4.1 Agent 档位

首版按以下 allowlist 管理 env：

```env
ALTUS_MANAGED_MODEL_LITE=
ALTUS_MANAGED_MODEL_PRO=
ALTUS_MANAGED_MODEL_MAX=

ALTUS_MANAGED_BASE_URL_LITE=
ALTUS_MANAGED_BASE_URL_PRO=
ALTUS_MANAGED_BASE_URL_MAX=

ALTUS_MANAGED_API_KEY_LITE=
ALTUS_MANAGED_API_KEY_PRO=
ALTUS_MANAGED_API_KEY_MAX=

ALTUS_MANAGED_API_TYPE_LITE=openai
ALTUS_MANAGED_API_TYPE_PRO=openai
ALTUS_MANAGED_API_TYPE_MAX=openai
```

说明：

1. `model` 必填。
2. `baseUrl/apiKey/apiType` 若为空，可使用平台现有 `LLM_PROXY_UPSTREAM_*` 作为默认值；保存时仍只写 allowlist 内字段。
3. 用户端只能传 `modelTier=lite|pro|max`，不能传模型名、接口或 Token。

### 4.2 Sandbox 直通引擎

首版按以下 allowlist 管理 env：

```env
SANDBOX_ENGINE_OPENCODE_MODEL=
SANDBOX_ENGINE_OPENCODE_BASE_URL=
SANDBOX_ENGINE_OPENCODE_API_KEY=
SANDBOX_ENGINE_OPENCODE_API_TYPE=openai

SANDBOX_ENGINE_CODEX_MODEL=
SANDBOX_ENGINE_CODEX_BASE_URL=
SANDBOX_ENGINE_CODEX_API_KEY=
SANDBOX_ENGINE_CODEX_API_TYPE=openai

```

说明：

1. OpenCode 当前仍可映射到 `OPENCODE_*` 与 `OPENAI_*` 注入逻辑。
2. Codex 当前仍可生成 `config.toml` / `auth.json`，但来源改为对应引擎 env 配置。
3. 旧的 `SANDBOX_OPENAI_*` 可在首版作为 Sandbox OpenCode 的默认来源，但后台展示以新引擎 key 为准。

## 5. 后端解析规则

### 5.1 Agent 解析

新增 server-side resolver：

```ts
resolveAgentRuntimeProfile(input: {
  tier: 'lite' | 'pro' | 'max';
  needsVision: boolean;
})
```

解析结果：

```ts
{
  billingTargetType: 'agent_tier',
  billingTargetKey: 'agent.pro',
  tier: 'pro',
  model: 'qwen3-max-2026-01-23',
  baseUrl: 'https://dashscope.aliyuncs.com/compatible-mode/v1',
  apiType: 'openai',
  tokenSource: 'ALTUS_MANAGED_API_KEY_PRO',
  runtimeSnapshotVersion: string
}
```

规则：

1. 文本任务按 `tier` 读取对应 env。
2. 视觉任务仍优先走 `ALTUS_MANAGED_VISION_MODEL` 与现有视觉配置；若后续需要，可新增 `ALTUS_MANAGED_VISION_MODEL_LITE/PRO/MAX`。
3. run 创建时固化 runtime snapshot，后续同一 run 的多轮模型调用不再读取最新 env。

### 5.2 Sandbox 引擎解析

新增 server-side resolver：

```ts
resolveSandboxEngineRuntimeProfile(input: {
  engine: 'opencode' | 'codex';
})
```

解析结果：

```ts
{
  billingTargetType: 'sandbox_engine',
  billingTargetKey: 'sandbox.opencode',
  engine: 'opencode',
  model: 'qwen3-max-2026-01-23',
  baseUrl: 'https://dashscope.aliyuncs.com/compatible-mode/v1',
  apiType: 'openai',
  tokenSource: 'SANDBOX_ENGINE_OPENCODE_API_KEY',
  runtimeSnapshotVersion: string
}
```

规则：

1. Sandbox env 注入不再只依赖一组全局 `SANDBOX_OPENAI_*`。
2. `buildSandboxEnv()` 需要接收 engine，并按 engine 写入对应 `OPENAI_*`、`OPENCODE_*`、`CODEX_*`。
3. 管理端禁用某个 engine 时，用户端或任务编排不得启动该 engine。

## 6. 定价配置规则

### 6.1 业务 SKU

不新增计费表的前提下，首版复用 `model_pricing` 表，但 `model` 字段存业务 SKU，而不是裸模型名：

| 计费对象 | `model_pricing.model` | `model_pricing.model_provider` |
| --- | --- | --- |
| Agent Lite | `agent.lite` | `agent` |
| Agent Pro | `agent.pro` | `agent` |
| Agent Max | `agent.max` | `agent` |
| Sandbox OpenCode | `sandbox.opencode` | `sandbox` |
| Sandbox Codex | `sandbox.codex` | `sandbox` |

### 6.2 展示规则

定价配置列表不再从历史裸模型中自动扩展主列表，只展示业务 SKU。

每个 SKU 卡片/行展示：

1. SKU 名称：Agent Pro / Sandbox OpenCode。
2. 当前真实模型：来自运行配置 resolver。
3. 当前接口摘要：只展示 host 与协议类型，不展示完整 Token。
4. Token 状态：未配置 / 已配置 / 继承默认。
5. 当前输入/输出单价。
6. 当前缓存计费比例。
7. 操作入口：编辑定价、跳转到运行配置区域。

## 7. 历史账单快照

为保证换模型不影响历史账单，所有扣费记录必须保存两类快照：

1. **pricingSnapshot**：继续使用 `token_usage_logs.pricing_snapshot`，保存本次扣费采用的 SKU、价格、缓存比例、生效时间。
2. **runtimeSnapshot**：写入 `token_usage_logs.metadata_json.runtimeSnapshot`，保存当时的真实模型、接口摘要、apiType、tier/engine、env key 名称、runId。

建议结构：

```json
{
  "billingTarget": {
    "type": "agent_tier",
    "key": "agent.pro",
    "displayName": "Agent Pro"
  },
  "runtimeSnapshot": {
    "model": "qwen3-max-2026-01-23",
    "baseUrlHost": "dashscope.aliyuncs.com",
    "apiType": "openai",
    "tokenSource": "ALTUS_MANAGED_API_KEY_PRO",
    "snapshotAt": "2026-04-26T00:00:00.000Z"
  }
}
```

`credit_transactions` 的描述与 metadata 也应写入同一 billing target，便于用户积分流水、管理后台用量明细、token 日志三者互相核对。

## 8. API 设计

### 8.1 运行配置读取

```http
GET /api/internal/billing/runtime-config
```

返回：

```json
{
  "agent": [
    { "tier": "lite", "model": "...", "baseUrlHost": "...", "apiType": "openai", "tokenState": "configured", "enabled": true }
  ],
  "sandbox": [
    { "engine": "opencode", "model": "...", "baseUrlHost": "...", "apiType": "openai", "tokenState": "configured", "enabled": true }
  ]
}
```

### 8.2 运行配置保存

```http
PUT /api/internal/billing/runtime-config/agent/:tier
PUT /api/internal/billing/runtime-config/sandbox/:engine
```

约束：

1. 只允许写 allowlist env key。
2. Token 入参允许为空；为空表示不修改已有 Token。
3. 响应不返回 Token 明文。
4. 保存后更新当前 API 进程的 `process.env`，并写回 env 文件来源，后续 run 立即使用新配置。

### 8.3 定价读取

```http
GET /api/internal/billing/pricing
```

返回中补充运行配置摘要：

```json
{
  "items": [
    {
      "billingTargetKey": "agent.pro",
      "displayName": "Agent Pro",
      "actualModel": "qwen3-max-2026-01-23",
      "runtimeConfigAnchor": "agent-pro",
      "promptPricePer1kTokens": 3,
      "completionPricePer1kTokens": 6
    }
  ]
}
```

### 8.4 用户端提交

`/api/altus-managed/inputs` 新增字段：

```ts
modelTier?: 'lite' | 'pro' | 'max'
```

默认值：`pro`。

禁止字段：

```ts
model
baseUrl
apiKey
```

浏览器传入这些字段时后端忽略或拒绝。

## 9. 前端/后台交互设计

### 9.1 用户端

1. 首页 Lite / Pro / Max 选择需要进入提交 payload。
2. 任务消息 metadata 可记录 `modelTier`，但不展示真实模型、接口或 Token。
3. 如果管理员禁用某档位，用户端该选项置灰或由后端返回明确错误。

### 9.2 管理后台

「计费管理 > 定价配置」子层结构：

1. 顶部提示条：说明“运行配置决定使用哪个模型，定价配置决定该业务对象如何扣积分”。
2. Agent 档位配置区：Lite / Pro / Max 三张紧凑配置卡。
3. Sandbox 引擎配置区：OpenCode / Codex 配置卡；后续引擎必须先接入执行链再展示。
4. SKU 定价区：只展示 Agent 三档与 Sandbox 各引擎；每行提供“调整运行配置”锚点按钮。
5. 危险提示：修改运行配置只影响后续新 run，不回算历史账单。

界面遵循“任务塔台”原则：高密度、强状态、可复核，Token 操作必须有明确对象与影响说明。

## 10. 实施路线

### Phase 1：接通 Agent Lite / Pro / Max

1. 前端提交 `modelTier`。
2. 后端解析 `ALTUS_MANAGED_MODEL_LITE/PRO/MAX`。
3. run 创建时保存 `billingTargetKey`、`actualModel`、`runtimeSnapshot`。
4. 计费从真实模型查价改为从业务 SKU 查价。

### Phase 2：管理后台 env 配置子层

1. 新增 runtime-config internal API。
2. 管理后台定价配置子层展示 Agent 与 Sandbox 运行配置。
3. 支持保存 allowlist env key，Token 不回显。

### Phase 3：Sandbox 按引擎解析

1. `buildSandboxEnv()` 接收 engine。
2. OpenCode/Codex 分别读取对应 env。
3. Sandbox 启动与预检日志写入 `sandbox.<engine>` billing target。

### Phase 4：定价 UI 收敛

1. 定价列表仅展示业务 SKU。
2. model candidates 不再把裸历史模型提升为主配置项。
3. 调试工具改为选择业务 SKU，再展示本次将调用的真实模型与接口摘要。

## 11. 验证清单

1. 用户选择 Lite / Pro / Max 后，后端 run 中能看到对应 `billingTargetKey` 与真实模型。
2. 修改 Agent Pro 模型后，新 run 使用新模型，旧 token 日志仍保留旧 `runtimeSnapshot`。
3. 定价配置缺失时，不允许启动付费模型调用，避免免费调用。
4. 管理后台 Token 保存后不回显明文，日志中不出现 Token。
5. Sandbox OpenCode 与 Codex 使用各自引擎配置，不再被单一 `SANDBOX_OPENAI_*` 意外覆盖。
6. 计费管理列表只展示 Agent 三档与 Sandbox 引擎，不再混入裸模型候选。
