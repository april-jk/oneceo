# 运行配置模型连通性测试方案 [20260427-0132已采用]

## 更新时间

2026-04-27

## 1. 背景

当前「计费管理 > 定价配置」已经展示 Agent Lite / Pro / Max 与 Sandbox OpenCode / Codex 的运行配置，管理员可以调整模型、Base URL、协议类型与 Token 状态。但保存后缺少即时验证入口，管理员无法在同一界面判断配置是否真实可用，只能等待后续任务失败后再排查。

本方案补充“模型测试”能力，用于验证已保存运行配置是否能完成一次最小模型调用。

## 2. 目标

1. 在每个运行配置项上提供“测试”操作，验证当前已保存配置是否生效。
2. 测试结果必须清晰展示：成功/失败、耗时、实际模型、接口 host、错误摘要。
3. 测试调用不写入用户会话、不创建 Sandbox、不扣用户积分。
4. Token 不回显、不进入响应、不进入日志；响应只允许展示 `tokenState`。
5. 复用现有 LLM Proxy 与运行配置 resolver，避免绕过主链。

## 3. 范围

### 3.1 首版支持

支持以下运行配置对象：

| 类型 | Key | 测试方式 |
| --- | --- | --- |
| Agent | `agent.lite` / `agent.pro` / `agent.max` | 按 Agent tier resolver 解析后，经本地 LLM Proxy 发起 OpenAI-compatible chat 测试 |
| Sandbox | `sandbox.opencode` | 按 Sandbox engine env 解析后，经本地 LLM Proxy 发起 OpenAI-compatible chat 测试 |
| Sandbox | `sandbox.codex` | 使用 Codex engine env 解析模型与 Token，Base URL 写入前按 Codex provider-root 规则规范化；测试本身只验证上游模型连通性，不启动 Codex App Server |

### 3.2 首版不做

1. 不测试未保存的表单草稿。管理员需先保存配置，再点击测试，避免在测试接口中传递一次性明文 Token。
2. 不启动 E2B Sandbox，不验证 OpenCode/Codex CLI 本身，只验证对应引擎绑定的模型上游可用。
3. 不记录 token usage，不产生积分扣费记录。
4. 不把测试响应全文写入后台日志；仅保留必要错误摘要。

## 4. 管理端交互

### 4.1 入口

在「运行配置」卡片与编辑弹窗中增加“测试”按钮：

1. 卡片右侧：`测试`，用于测试当前已保存配置。
2. 编辑弹窗底部：`保存` 与 `测试已保存配置` 并列；如果表单有未保存改动，测试按钮旁提示“请先保存后测试”。

### 4.2 状态展示与详情弹窗

测试触发后必须打开详情弹窗，并在当前卡片内同步展示最后一次测试摘要。弹窗是主反馈面，卡片只作为值守摘要。

弹窗内容：

1. 顶部状态：测试中 / 测试通过 / 测试失败。
2. 关键指标：耗时、实际模型、接口 host、协议类型、Token 状态、测试时间。
3. 人类友好说明：
   - 成功：说明“模型已返回有效响应，当前已保存配置可用于后续新任务”。
   - 失败：按错误码给出可操作建议，例如 Token 缺失、鉴权失败、上游超时、接口地址缺失、模型空响应。
4. 原始安全摘要：错误码、脱敏错误摘要、模型返回预览（最多 200 字）。
5. 响应详情：在不泄露 Token / env key / Authorization 的前提下，尽可能展示所有可安全展示的上游响应信息，包括 HTTP 状态、requestId、finishReason、usage、choices 数量、完整脱敏 JSON 响应。
6. 禁止展示：Token、tokenSource、env key、Authorization header、完整请求体。

卡片摘要展示：

- 测试中：`正在测试模型连通性...`
- 成功：`测试通过 · 842ms · gpt-5.3-codex · llmapi.oneceo.ai`
- 失败：`测试失败 · 401 unauthorized` / `测试失败 · timeout`

卡片上的测试摘要点击后应重新打开对应详情弹窗。

### 4.3 UI 原则

遵循“任务塔台”风格：测试结果是运维状态信号，不做营销式成功动效。按钮使用次级按钮样式；成功/失败使用语义色与文本共同表达，颜色不作为唯一状态。

## 5. API 设计

### 5.1 管理端代理路由

管理后台服务新增代理：

```http
POST /admin/api/billing/runtime-config/test
```

请求：

```json
{
  "key": "agent.pro"
}
```

响应：

```json
{
  "success": true,
  "data": {
    "key": "agent.pro",
    "status": "success",
    "latencyMs": 842,
    "model": "gpt-5.3-codex",
    "baseUrlHost": "llmapi.oneceo.ai",
    "apiType": "openai",
    "tokenState": "configured",
    "checkedAt": "2026-04-27T00:00:00.000Z"
  }
}
```

失败响应仍使用 `success: true` 承载业务失败，避免把模型不可用误判为管理端接口不可用：

```json
{
  "success": true,
  "data": {
    "key": "agent.pro",
    "status": "failed",
    "latencyMs": 430,
    "model": "gpt-5.3-codex",
    "baseUrlHost": "llmapi.oneceo.ai",
    "apiType": "openai",
    "tokenState": "configured",
    "errorCode": "upstream_unauthorized",
    "errorMessage": "Upstream returned 401",
    "checkedAt": "2026-04-27T00:00:00.000Z"
  }
}
```

### 5.2 API 内部路由

API 服务新增内部路由：

```http
POST /api/internal/billing/runtime-config/test
```

仅允许管理后台携带现有 internal auth 调用。请求严格只允许 `{ "key": string }`。如果请求体包含 `model/baseUrl/apiKey/token/envKeys/tokenSource` 或任何额外字段，直接返回 400，避免后续维护者误以为该接口支持草稿测试。

## 6. 后端执行规则

1. 根据 `key` 解析运行配置：
   - `agent.*`：复用 `resolveAgentRuntimeProfile()`，并使用进程内 `runtimeTokenSource` 调用本地 LLM Proxy internal override。
   - `sandbox.*`：新增轻量 `resolveSandboxRuntimeTestProfile()`，读取 `SANDBOX_ENGINE_*` 与既有 fallback，但只返回安全摘要与进程内 tokenSource。
2. 调用本地 LLM Proxy：
   - URL：`http://127.0.0.1:${PORT}/api/llm-proxy/v1/chat/completions`
   - 使用已有 internal override token；禁止从请求体传入 Token。
   - internal override 必须允许在没有全局 `LLM_PROXY_UPSTREAM_BASE_URL` 时使用运行配置提供的 baseUrl，避免测试接口被默认代理配置耦合。
3. 固定测试 prompt：
   - system：`You are a health check endpoint. Reply with exactly OK.`
   - user：`OK`
4. 超时默认 15 秒，可通过 `BILLING_RUNTIME_TEST_TIMEOUT_MS` 调整。
5. 成功条件：HTTP 2xx 且模型返回非空内容；首版不强制内容必须等于 OK，避免部分模型自动补充标点导致误报。
6. 测试结果响应可包含 `responsePreview`，但最多 200 字，并经过脱敏处理。
7. 测试结果响应可包含 `responseDetails` 与 `safeRawResponse`：
   - `responseDetails` 只放结构化安全字段，例如 HTTP 状态、requestId、usage、finishReason、choicesCount。
   - `safeRawResponse` 为脱敏后的上游响应 JSON，最多保留 24KB，超出时截断并标记。

## 7. 安全与审计

1. 响应禁止包含：Token、tokenSource、env key、Authorization header、完整上游 URL query。
2. 日志只记录：key、status、latencyMs、baseUrlHost、errorCode。
3. LLM Proxy internal override 继续要求 loopback + internal token，OSAC bridge 仍剥离 `x-oneceo-internal-llm-*`。
4. 测试接口不写 `token_usage_logs` 与 `credit_transactions`，避免测试成本计入用户账单。
5. 测试接口必须拒绝除 `key` 以外的请求字段。

## 8. 验证计划

1. API type-check。
2. 管理后台 type-check。
3. 单元/集成测试：
   - 不存在 key 返回业务失败。
   - 缺 Token 返回 `token_missing`。
   - 成功 mock 返回 `status=success`。
   - 错误响应不包含 `tokenSource/envKeys/apiKey`。
4. 手动验证：在管理端对 Agent Pro 与 Sandbox Codex 分别点击测试，确认状态条展示成功或明确失败。
5. 浏览器验收：使用 agent-browser 检测计费管理页运行配置、SKU 定价、测试弹窗、错误边界与未保存草稿拦截。

## 9. 待确认

首版按“只测试已保存配置”实现。如果需要“测试当前未保存草稿”，需要额外设计一次性 Token 传递与日志脱敏边界，本方案暂不纳入。
