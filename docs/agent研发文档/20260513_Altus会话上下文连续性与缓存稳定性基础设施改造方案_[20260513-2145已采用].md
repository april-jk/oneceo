# 20260513 Altus 会话上下文连续性与缓存稳定性基础设施改造方案 [20260513-2145已采用]

## 1. 背景与问题定义

当前 Altus 在同一任务会话中已经具备“多轮消息持久化 + 每轮重建 API messages”的能力，但从用户感知上仍存在明显不稳定：

1. 同一会话多轮后，模型表现像“新会话重开”，对上一轮约束继承不稳定。
2. 部署/修复场景中，前几轮已经明确的约束在后续轮次被弱化或丢失。
3. 同一类请求 token 成本波动较大，`cached_tokens` 命中率不稳定。

根因不是“HTTP 请求是否独立”，而是上下文连续性基础设施不完整：

1. 每轮仍按固定条数裁剪历史（当前 `limit:24`），不是按 token 预算与语义分层裁剪。
2. 动态运行态信息（如当前时间）与可复用前缀耦合，导致缓存前缀频繁变化。
3. 会话级 LLM 连续性状态没有一等存储结构，provider 能力也未分层利用。

## 2. 现状代码定位（当前主链）

当前 Altus managed 主链关键文件：

1. `apps/api/src/services/altus-managed-run-entry-service.ts`
2. `apps/api/src/services/altus-managed-setup-service.ts`
3. `apps/api/src/services/altus-run-coordinator.ts`
4. `apps/api/src/services/altus-managed-context-service.ts`
5. `apps/api/src/services/altus-managed-context-budget-service.ts`
6. `apps/api/src/connectors/llm-proxy-connector.ts`

关键事实（基于当前代码）：

1. 每轮模型调用走 `/api/llm-proxy/v1/chat/completions`，属于“多次独立 API 请求”模式。
2. `buildConversationMessages` 目前按 `limit:24` 取最近历史消息拼装上下文。
3. 运行态 prompt 中包含 `Current time`，天然是每轮变化字段。
4. Anthropic 适配层当前只做 Chat Completions 到 Messages 的协议转换，未形成会话连续性层。

## 3. 目标与非目标

### 3.1 目标

1. 在不改变现有产品交互语义的前提下，建立可验证的会话连续性基础设施。
2. 提高同一会话多轮执行的上下文稳定性，减少“看起来像新会话”的漂移。
3. 提高缓存命中率与成本可预测性，降低长会话运行成本抖动。
4. 对 OpenAI / Anthropic 上游形成分层策略，不再用单一路径硬套全部 provider。

### 3.2 非目标

1. 不重写 Altus managed run 主循环。
2. 不改变用户侧会话协议和 UI 行为。
3. 不引入“补丁式兜底分支”堆叠；坚持单主链、确定性收敛。
4. 不引入与本目标无关的新依赖。

## 4. 方案总览（最短路径）

本次改造按“会话锚点 -> 上下文编译 -> provider 分层 -> 观测闭环”四层落地。

### 4.1 会话锚点层（Session Context State）

为每个 `taskSessionId` 维护会话级上下文状态（建议先落 `task_creation_sessions.metadata_json`，不新增表）：

1. `provider`: openai | anthropic
2. `llmContextId`: 会话级上下文链 id（平台内部）
3. `openaiPreviousResponseId`（可选）
4. `anthropicLastRequestId`（可选）
5. `prefixHash`: 当前稳定前缀 hash
6. `summaryCursor`: 历史压缩游标
7. `updatedAt`

说明：

1. `llmContextId` 是平台内部会话锚点，不是用户可见字段。
2. 该状态必须随会话持久化，避免 run 重启后链路断裂。

### 4.2 上下文编译层（Context Compiler V2）

替换固定 24 条策略，改为“稳定前缀 + 动态块 + token 预算窗口”：

1. 稳定前缀：
   - 核心系统规则
   - 稳定工具 schema（排序稳定、字段稳定）
2. 动态块（放后部）：
   - 当前时间
   - pending clarification
   - connector guide delta
   - 会话运行态摘要
3. 历史窗口：
   - 近期原文 tail（高保真）
   - 远期摘要块（低成本）
   - 当前轮 user 输入

约束：

1. 禁止把动态字段混入稳定前缀。
2. 上下文裁剪按 token 预算，不再按固定条数。

### 4.3 Provider 分层连续性策略

#### OpenAI upstream

1. 在保持现有兼容前提下，优先切到 Responses 会话连续性能力（`previous_response_id` 链接）。
2. Chat Completions 保留作为回退路径。
3. 引入稳定 `prompt_cache_key` 分桶（按 `taskSessionId` 或 `projectId`）。

#### Anthropic upstream

1. 继续使用 Messages 重放模型。
2. 增加上下文管理透传能力（`context_management`）。
3. 严格控制 cacheable prefix 与动态块边界，降低 cache break。

### 4.4 观测与验收层

新增三组核心指标：

1. `session_chain_break_rate`
   - 同一 `taskSessionId` 连续轮次中上下文链断裂率。
2. `cached_prompt_ratio`
   - `cached_tokens / prompt_tokens`，按会话与模型聚合。
3. `context_projection_drop_rate`
   - 编译阶段被裁剪但未被摘要覆盖的内容比例（应接近 0）。

## 5. 分阶段实施（P0 / P1 / P2）

### P0（先稳定，低风险高收益）

1. 将 `buildConversationMessages` 从固定 `limit:24` 改为 token 预算策略（含远期摘要游标）。
2. 将 `Current time` 从稳定前缀移至动态后缀块。
3. 工具 schema 做稳定排序，禁止无关字段波动。
4. 为每轮请求记录 `prefixHash` 与缓存命中指标。

验收：

1. 连续 10 轮对话中，关键约束不丢失。
2. 相同任务模板重复执行，`cached_prompt_ratio` 明显提升。

### P1（会话锚点落地）

1. 引入 `llmContextId` 会话锚点持久化。
2. 补齐 run 恢复时的上下文状态恢复流程。
3. 打通 `summaryCursor` 与 context compiler 的协作。

验收：

1. run 中断后续跑，同一会话上下文链可连续。
2. 不再出现“同会话多轮变新会话”的高频漂移。

### P2（provider 分层增强）

1. OpenAI 路径试点 Responses 连续性链路，并保留回退。
2. Anthropic 路径补齐 `context_management` 策略透传。
3. 两条路径统一落同一可观测指标体系。

验收：

1. 双 provider 在同一能力测试集下表现收敛。
2. 切换 provider 不改变会话连续性语义。

## 6. 风险与控制

### 6.1 主要风险

1. 历史窗口策略改造可能影响部分长上下文行为。
2. Responses 试点可能与现有工具调用协议存在兼容细节。
3. 摘要游标错误会造成“看似省 token，实则丢事实”。

### 6.2 控制措施

1. 所有新能力走 feature flag，支持会话级灰度。
2. 保留 Chat Completions 全量重放回退路径。
3. 对每次上下文编译产物生成 manifest 与 diff，做回归对比。

## 9. 结论

这次改造不再从提示词层“修补对话表现”，而是把 Altus 会话连续性提升为基础设施能力：

1. 让每轮请求“独立调用但连续语义”；
2. 让缓存命中由偶然变成可工程控制；
3. 让部署等长链路任务具备稳定、可恢复、可验收的上下文表现。

## 10. 20260513 提示拼装去重与缓存友好化补充（已落地）

为解决同一轮请求中 system 上下文重复注入、影响可读性与缓存稳定性的问题，补充实施如下：

1. 在 `AltusRunCoordinator` 组装 turn-state prompt 时，关闭 `buildSkillCatalogPrompt` 与 `buildSkillContextPrompt` 内部的动态 block index 输出，仅保留一份统一的 `dynamicContextPrompt` 索引。
2. `buildSkillCatalogPrompt` / `buildSkillContextPrompt` 增加 `includeBlockIndex` 开关（默认保持兼容），由协调器在组合场景显式关闭，避免重复段落。
3. `buildRuntimeContextPrompt` 将每轮波动的 `Current time` 收敛为更稳定的 `Current date`，降低前缀频繁变化造成的缓存抖动。

本次补充不改变业务语义、工具权限、会话状态机与执行路径，只做提示上下文编排层去重与稳定化。
