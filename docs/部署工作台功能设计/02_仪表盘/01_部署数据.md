# 仪表盘 / 部署数据

## 1. 功能目标

“部署数据”视图用于承接发布运维信息，强调：

- 版本历史
- 发布状态
- 修改与提交摘要
- 回退能力

## 2. 页面结构

建议结构：

1. 顶部摘要卡
2. 指标卡区
3. 版本时间线
4. 当前版本详情
5. 回退操作区

## 3. 核心内容

### 3.1 顶部摘要卡

展示：

- 当前应用名称
- 当前线上访问地址
- 当前发布状态
- 最近一次部署时间

### 3.2 指标卡区

建议字段：

- 发布成功率
- 成功部署数
- 失败部署数
- 当前可回退版本数
- 最近一次成功发布时间

### 3.3 版本时间线

建议按时间倒序展示 Railway 部署历史，并保留：

- deployment id
- status
- createdAt
- commitMessage
- commitAuthor
- url/staticUrl

### 3.4 当前版本详情

用于展开当前选中版本的详细信息：

- 版本标题
- 提交摘要
- 提交人
- 发布时间
- 运行地址
- 静态地址

### 3.5 回退操作区

设计要求：

- 回退按钮只对可回退版本可用
- 回退动作应直接基于 Railway 历史 deployment 执行
- 回退前应提示当前线上版本会被替换

## 4. 数据来源

当前建议直接来源于 Railway 部署历史与现有后端部署接口：

- `deployments`
- `latestStatus`
- `deploymentId`
- `latestUrl`
- `latestStaticUrl`
- 回滚接口

## 5. 计划设计方式

### 当前阶段

- 直接复用 Railway 历史
- 不重新发明版本模型
- UI 上突出“历史版本可查看、可回退”

### 下一阶段

- 增加按状态筛选
- 增加按部署来源筛选
- 增加版本对比摘要

## 6. 审核点

- 部署数据是否应当直接以 Railway 历史为唯一可信来源。
- 版本回退是否放在时间线内部，还是固定在详情面板中。
