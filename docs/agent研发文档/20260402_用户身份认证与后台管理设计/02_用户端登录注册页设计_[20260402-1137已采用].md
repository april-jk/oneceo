# 02 用户端登录注册页设计 [20260402-1137已采用]

## 1. 现状问题

当前用户端存在两个明显问题：

1. [AuthDialog.tsx](/Users/watson/codingProj/oneceo/apps/web/client/src/components/AuthDialog.tsx) 只是一个占位弹窗，不承载真实认证流程
2. [UserMenu.tsx](/Users/watson/codingProj/oneceo/apps/web/client/src/components/UserMenu.tsx) 里的用户头像、姓名、邮箱都是静态假数据

这意味着当前 UI 还没有真实用户概念。

此外，当前用户态 API 层 [task-creation-client.ts](/Users/watson/codingProj/oneceo/apps/web/client/src/lib/task-creation-client.ts) 与 [connectors-client.ts](/Users/watson/codingProj/oneceo/apps/web/client/src/lib/connectors-client.ts) 大量依赖 `buildClientIdentityHeaders()` 注入本地 `X-User-Id`，这条链也必须整体替换。

## 2. 页面目标

### 2.1 登录页

路由：

`/login`

用途：

1. 让已有用户进入主站
2. 建立正式登录态
3. 登录成功后跳回原目标页面

页面结构：

1. 品牌区
2. 登录表单区
3. 账号密码输入
4. 登录按钮
5. 跳转注册入口

### 2.2 注册页

路由：

`/register`

用途：

1. 创建新用户
2. 初始化个人身份
3. 注册成功后自动登录并进入主站

页面结构：

1. 品牌区
2. 注册表单区
3. 用户名
4. 邮箱
5. 密码
6. 确认密码
7. 注册按钮
8. 跳转登录入口

## 3. 交互规则

### 3.1 未登录访问主站

规则：

1. 访问需要身份的页面时，直接跳转 `/login`
2. 不再弹当前的占位 `AuthDialog`
3. 保留 `redirect` 参数，登录后返回原页面

需要守卫的用户态页面至少包括：

1. `/home`
2. `/session/:sessionId`
3. `/new-task`
4. `/library`
5. `/ai-workspace`
6. `/agent-project`
7. `/task/:projectId/:managerId/:taskId`

是否把 `/projects`、`/manager-view`、`/ceo-view` 也纳入用户登录态守卫，首批建议一并纳入，避免继续保留匿名产品入口。

### 3.2 登录成功

规则：

1. 写入正式会话 cookie
2. 拉取 `/auth/me`
3. 刷新全局用户上下文
4. 清理匿名 `client-identity` 兼容逻辑

### 3.3 注册成功

规则：

1. 自动创建用户
2. 自动进入已登录状态
3. 跳回首页或原目标页面

## 4. 页面视觉方向

### 4.1 视觉原则

1. 不做通用表单模板感
2. 与主站现有产品语言保持一致
3. 页面应体现“个人工作台入口”，不是传统企业 OA 登录页

### 4.2 建议布局

1. 左侧或上方为品牌价值说明
2. 右侧或中心为认证表单
3. 移动端改为单列堆叠

## 5. 主站改造点

### 5.1 全局用户上下文

新增：

1. `AuthProvider`
2. `useCurrentUser()`
3. `RequireUserAuth`

用途：

1. 提供 `me`
2. 提供登录态加载状态
3. 提供登出能力

### 5.2 现有组件改造

需要改：

1. `AuthDialog`
2. `UserMenu`
3. `Header`
4. 依赖 `buildClientIdentityHeaders()` 的 API 调用层
5. `App.tsx` 的路由守卫

### 5.3 会话创建入口

规则：

1. 新建 session 时不再依赖浏览器本地随机 ID 表达用户身份
2. 服务端直接从登录态得到 `userId`

## 6. 首批 API

1. `POST /auth/register`
2. `POST /auth/login`
3. `POST /auth/logout`
4. `GET /auth/me`

需要影响的现有用户态请求面包括：

1. `task-creation-client.ts` 中所有会话、消息、workspace、runtime、Altus、交付物相关请求
2. `connectors-client.ts`
3. 任何直接调用 `fetch()` 且目前依赖 `X-User-Id` 的组件或 hook

请求失败时：

1. 在表单内显示错误
2. 不使用全局 toast 替代表单错误

## 7. 验收标准

1. 注册成功后，主页右上角用户信息显示真实用户数据
2. 登录后创建的对话 session 自动归属于当前用户
3. 用户刷新页面后仍能恢复登录态
4. 登出后再次访问对话/skills/connector 页时必须重新登录
5. `client-identity.ts` 不再承担正式身份主链职责
