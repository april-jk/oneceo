# 20260422 积分计费系统设计 [20260422-2332已采用]

## 更新时间

2026-04-22

## 关联背景

1. 当前 oneceo 无任何计费基础设施，LLM 调用仅透传 usage 信息不做持久化
2. 用户端无余额/积分概念，管理后台无计费管理能力
3. 需求来源：对标 Manus，使用积分进行计费

## 1. 目标

建立一套基于积分的计费系统，覆盖：

1. **用户端**：会话界面显示当前会话积分消耗与剩余积分，设置菜单显示历史消费明细
2. **管理后台**：新增「计费管理」页面，支持手动调整用户积分、配置模型积分单价、查看平台统计
3. **API 层**：LLM 调用前后拦截，按 token 消耗换算积分并扣减，余额不足时阻止发起新会话

## 2. 采用边界

本组设计默认：

1. 积分仅通过充值购买获得（首批），后续可扩展签到/任务等获取方式
2. 计费粒度为按 token 消耗换算积分（输入/输出可不同价），后续可扩展按请求/会话固定计费
3. 余额不足时**禁止**发起新会话，后续可改为降级/欠费模式
4. 积分消费记录按会话聚合展示，明细级 token 日志保留在管理后台

## 4. 当前结论

这组文档的核心落点：

1. 新增 `user_credits`、`credit_transactions`、`token_usage_logs`、`model_pricing` 四张核心表
2. LLM Proxy 层在请求前后增加计费拦截与记录钩子
3. 会话创建前强制校验余额，不足时返回明确错误码
4. 用户端 Header 显示剩余积分，会话界面显示本次消耗，设置页显示消费历史
5. 管理后台新增「计费管理」独立页面，含用户积分调整、模型定价配置、平台统计看板
6. P2 补强：管理端定价页只读展示积分/RMB 兑换比例与缓存计费比例，并补充计费 smoke 与 migration/index 回归测试
