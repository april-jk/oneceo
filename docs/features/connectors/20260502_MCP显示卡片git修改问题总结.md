# 2026-05-02 MCP 显示卡片 git 修改问题总结

## 背景

本轮修改围绕连接器中心的 MCP 显示卡片展开，主要处理两个用户可见问题：

1. VercelMcp 已授权卡片不应显示 `team_mGcDixrMSgZ5EN1BzoNrAHhT` 这类 Vercel 原始团队 ID，应显示统一的产品名。
2. MCP 连接器列表存在中英文混用：中文界面中部分卡片仍展示英文描述，英文界面中也可能受到后端 catalog 固定文案影响。

- `apps/web/client/src/components/ConnectorCenterPanel.tsx`
- `apps/web/client/src/locales/zh.json`

其中 `ConnectorCenterPanel.tsx` 和 locale 文件是本轮界面问题的直接修复点；设计文档与自动汇报用于记录方案依据和工作过程。

## 修改问题 1：Vercel 已授权标签显示团队 ID

### 问题表现

VercelMcp 卡片授权成功后，账号标签区域会显示类似：

```text
team_mGcDixrMSgZ5EN1BzoNrAHhT
```

这属于外部平台返回的原始团队标识，不适合直接展示在连接器卡片中，也与其他卡片的统一展示风格不一致。

### 修复方式

在 `ConnectorCenterPanel.tsx` 中新增 `resolveAuthorizedAccountLabel(...)` 展示层函数：

- 当连接器是 `vercel` 时，固定返回 `Vercel`。
- 其他连接器继续使用 `profile.displayName`、`profile.profileName` 或通用授权账号文案。

这样可以避免 Vercel 团队 ID、i18n key 或底层 profile 名称直接泄漏到卡片主展示区域。

## 修改问题 2：i18n key 误显示

### 问题表现

初次尝试把 Vercel 标签放入 locale 后，页面显示：

```text
connectors.vercel.connectedLabel
```

原因是文案被添加到了 `connectors.guides.vercel.connectedLabel` 层级，但代码读取的是 `connectors.vercel.connectedLabel`。

### 修复方式

最终不再让 Vercel 已授权账号标签依赖 locale key，而是在展示层直接返回 `Vercel`。

这样避免后续因为 locale 层级调整再次出现 key 直出。

## 修改问题 3：MCP 卡片中英文混用

### 问题表现

连接器目录卡片直接使用后端 catalog 返回的 `item.name` 和 `item.description`：

- GitHub、Slack、Figma、Vercel 定义中描述多为英文。
- Notion、Supabase 定义中描述多为中文。

所以同一个界面会出现中文和英文描述混在一起的情况。

### 修复方式

在前端新增 `connectors.catalog.*` 文案命名空间，并新增 `resolveConnectorDisplayText(...)` 展示层函数：

- `zh.json` 提供中文卡片名和中文描述。
- `en.json` 提供英文卡片名和英文描述。
- 列表卡片、详情弹窗、搜索索引、连接按钮均统一使用当前语言下的展示文案。
- 如果未来新增连接器但未补 locale，则回退到后端 catalog 文案，避免页面空白。

## 相关行为变化

1. 中文界面：
   - 卡片描述统一展示中文。
   - 品牌名如 `GitHub`、`Slack`、`Vercel` 保持专有名词写法。

2. 英文界面：
   - 卡片描述统一展示英文。
   - 不再受后端中文 catalog 描述影响。

3. 搜索：
   - 搜索索引也改为使用当前语言下的展示文案。
   - 中文界面可按中文描述搜索，英文界面可按英文描述搜索。

## 顺手修正的类型问题

运行 `pnpm --filter web check` 时发现 `ConnectorCenterPanel.tsx` 中 Vercel/GitHub OAuth 回调路径分支存在 TypeScript 不可达判断：

```text
This comparison appears to be unintentional because the types ... have no overlap.
```

原因是上层分支已经处理了 `detailItem.key === "github"`，后续 fallback 分支中再次判断 `github` 已不可达。

处理方式：移除 fallback 分支内重复的 `github` 判断，不改变实际 GitHub 回调路径行为。

## 后续注意点

1. 后续新增连接器时，需要同步补齐：
   - `apps/web/client/src/locales/zh.json` 的 `connectors.catalog.<connectorKey>`
   - `apps/web/client/src/locales/en.json` 的 `connectors.catalog.<connectorKey>`

2. 后端 connector definition 中的 `name` / `description` 仍可作为 fallback，但不应作为用户界面的最终多语言展示来源。

3. Vercel 已授权状态下的主账号标签应继续固定为 `Vercel`，不要回退成 `team_xxx`、profileName 或底层团队 ID。
