# 20260401 连接器隐式 Skills 挂载与后台管理设计 [20260401-1037已采用]

## 1. 本次修正背景

上一版方案把 connector implicit skills 建模成了对现有 `platform skill` 体系的复用层，这和当前要求冲突。

当前要求已经明确：

1. 不影响现有 skills 模块
2. 不复用现有 platform skill / revision / resource / sandbox skill sync 体系
3. 连接器中的“skills”本质上是连接器域内的纯文本引导文档
4. 这些文档只用于指导 Altus 如何正确使用某个连接器与其 MCP 工具，避免盲目试错

因此本方案在此正式收敛为：

> 连接器隐式 skills = 连接器域内的 guide documents，不进入现有 skills 平台。

## 2. 目标

本次设计只解决下面这件事：

1. 当会话 attach 某个连接器时，系统自动把该连接器对应的 guide 文本注入 Altus 的提示上下文
2. Altus 在真正调用该连接器 MCP 工具前，优先遵守 guide 中定义的使用顺序与限制
3. 管理后台可以管理这些 guide 文本的版本、发布、停用与回滚
4. 用户态完全无感，不展示 guide 列表，不让用户配置

## 3. 非目标

本次不做：

1. 不进入现有 `platform_skills` 模块
2. 不复用现有 `sandbox-skill-sync-service.ts`
3. 不把 connector guide 写成 skill file 下发到 sandbox
4. 不让用户显式选择 connector guide
5. 不做复杂的多层编排 DSL

## 4. 对 ClaudeCode 参考实现的吸收方式

本方案吸收 ClaudeCode 的三条关键逻辑，但只保留与当前需求直接相关的部分。

### 4.1 吸收一：MCP server instructions 是高优先级行为规则

ClaudeCode 的做法是：

1. MCP client 建连后读取 server `instructions`
2. 在系统提示中以高优先级片段注入
3. 让模型先理解“应该怎么使用这个 MCP server”

我们对应实现为：

1. 每个 connector guide revision 都包含一段 `serverInstructionsMarkdown`
2. 当 session attach connector 时，这段文本进入 Altus system prompt 的 `# Connector MCP Instructions`
3. 这段文本优先定义：
   - 先做什么再做什么
   - 哪些工具只能在满足前置条件后调用
   - 哪些场景必须先询问用户
   - 哪些失败要立即停止

### 4.2 吸收二：相关 guide 要被主动 surfaced，而不是让模型自己想

ClaudeCode 的做法是：

1. 系统主动提示当前 relevant skills
2. 不让模型在海量 skill 里盲选

我们对应实现为：

1. Altus prompt 在 connector attach 后主动加入 `Relevant connector guides` 提示块
2. 告诉 Altus：
   - 当前可用的 connector guides 是哪些
   - 哪个 connector 对应哪个 guide
   - 使用该 connector 前必须先遵守 guide

### 4.3 吸收三：guide 命中时是 blocking requirement

ClaudeCode 的 SkillTool prompt 明确规定：

1. 有匹配 skill 时，先调用 skill 是 blocking requirement

我们对应实现为：

1. 当某 connector 已 attach 且存在 published guide 时
2. 若 Altus 准备调用该 connector 的 MCP tool
3. 必须先读取并遵守该 connector guide

这不是“建议优先”，而是系统规则。

## 5. 核心结论

本次建议引入的新内部对象不再是 `Connector Skill Bundle`，而是：

1. `Connector Guide Policy`
2. `Connector Guide Revision`
3. `Connector Guide Document`

其中：

1. policy 负责绑定某个 connectorKey 的当前 guide 策略
2. revision 负责版本化文本与发布状态
3. document 只是纯文本 markdown，不属于现有 skills 平台

## 6. 设计原则

### 6.1 完全独立于 skills 模块

必须做到：

1. 不读写 `platform_skills`
2. 不读写 `platform_skill_revisions`
3. 不走 `sandbox-skill-sync-service`
4. 不把 connector guide 记为 active skill

### 6.2 内容必须是纯文本 guide

guide 文本应只描述：

1. connector 的正确使用顺序
2. 前置检查
3. 常见风险
4. 禁止路径
5. 用户确认点
6. 失败处理

### 6.3 注入点必须在 Altus prompt 层

guide 的生效点不在 sandbox 文件系统，而在：

1. `altus-managed-prompt-service.ts`
2. 必要时的 MCP 工具调用前置检查

### 6.4 对用户无感

用户侧不展示：

1. guide 名称
2. guide 文本
3. guide 版本
4. guide 来源

## 7. 新对象模型

### 7.1 Connector Guide Policy

定义：

一个 connector 当前应该挂载哪份 guide revision。

建议字段：

1. `id`
2. `connectorKey`
3. `status`
   - `active`
   - `draft`
   - `archived`
4. `triggerMode`
   - `on_attach`
   - `on_active_use`
   - `on_attach_and_active_use`
5. `description`
6. `publishedRevisionId`
7. `createdAt`
8. `updatedAt`

### 7.2 Connector Guide Revision

定义：

某个 connector guide policy 的一版纯文本实现。

建议字段：

1. `id`
2. `policyId`
3. `versionNumber`
4. `status`
   - `draft`
   - `published`
   - `archived`
5. `serverInstructionsMarkdown`
6. `guideReminderMarkdown`
7. `blockingRulesMarkdown`
8. `notes`
9. `createdBy`
10. `createdAt`
11. `publishedAt`

说明：

1. `serverInstructionsMarkdown` 用于高优先级系统提示
2. `guideReminderMarkdown` 用于 relevant guides 主动提醒
3. `blockingRulesMarkdown` 用于工具调用前的强规则

## 8. 首批范围

首批只覆盖：

1. `github`
2. `supabase`
3. `vercel`

且用户态完全不展示 guide 列表。

补充口径（2026-04-03）：

1. Vercel connector 运行时固定使用官方 MCP 地址 `https://mcp.vercel.com`
2. guide 规则继续作用于该官方 remote MCP
3. 授权优先走官方 OAuth；若部署尚未配置 Vercel OAuth client，则允许先以手动 Personal Access Token 方式接入

## 9. 运行时模型

### 9.1 attach 时

当某 connector attach 到 session：

1. 解析该 connector 是否存在 published guide
2. 将该 guide 记入 session connector guide context
3. 在 Altus prompt 中注入 guide 相关文本

### 9.2 prompt 注入结构

建议在 `altus-managed-prompt-service.ts` 中新增两个段落：

1. `# Connector MCP Instructions`
2. `# Relevant Connector Guides`

示例结构：

```md
# Connector MCP Instructions
## github
<serverInstructionsMarkdown>

# Relevant Connector Guides
- github: A GitHub guide is active for this session.
- Before using any GitHub MCP write tool, follow the GitHub guide first.
```

### 9.3 MCP 调用前强约束

对于已 attach 且存在 guide 的 connector：

1. 写入类 MCP 工具调用前
2. Altus 必须先遵守 guide 里的 blocking rules

本轮已落地 runtime 强约束：

1. `altus-managed-shared.ts` 暴露内建工具 `load_connector_guide`
2. `altus-managed-tool-runtime.ts` 在首次命中带 active guide 的 connector MCP tool 时先阻断
3. Altus 必须先调用 `load_connector_guide(connectorKey)` 读取 guide 文本
4. 同一 run 内该 connector guide 加载成功后，后续同 connector MCP tool 才放行

## 10. 为什么这次不再走 skills 平台

因为当前目标不是“给用户新增一种可选 skill”，而是：

1. 给连接器增加内部行为指引
2. 只影响 Altus 的 connector 使用方式
3. 不改变现有 skill 平台边界

所以最短路径实现就是：

1. connector 内部 guide 文本
2. 后台可管理
3. prompt 级注入
4. MCP 使用前 blocking requirement

## 11. 管理后台职责

管理后台负责：

1. 管理 connector guide policy
2. 编辑 guide revision 文本
3. validate
4. publish
5. rollback

管理后台不负责：

1. 让用户看 guide
2. 让用户选择 guide

## 12. 验收标准

本方案验收必须满足：

1. GitHub / Supabase / Vercel 三个 connector 均可配置 guide 文本
2. attach 后 Altus prompt 能看到对应 guide 注入内容
3. 连接器 MCP 使用规则明确成为高优先级上下文
4. guide 文本不进入现有 skills 平台
5. 用户态完全无感
