# 转发端口不稳定问题联调记录（交付给 KVM 团队）

## 目标
聚焦转发端口不稳定：同一端口在不同时间段出现“可达/不可达”波动。

## 关键测试环境
- kvm-orchestrator: 192.168.10.172:8500
- session_id: sess_e747d935d97549bb
- VM: sandbox_sess_e747d935d97549bb
- VM IP: 172.28.0.172
- 映射端口（测试用）: 20002、21399、21963

## 测试动作与失败时机
1) 创建端口映射
- POST /v1/sandboxes/sess_e747d935d97549bb/ports
  - 20002 -> 172.28.0.172:18080
  - 21399 -> 172.28.0.172:18080
  - 21963 -> 172.28.0.172:18080

2) 映射查询（确认规则存在）
- GET /v1/sandboxes/sess_e747d935d97549bb/ports
  - 返回 items 含上述端口与 vm_ip=172.28.0.172

3) 连接失败（不稳定阶段）
- Test-NetConnection 192.168.10.172:21399 -> False（TCP connect fail）
- Test-NetConnection 192.168.10.172:20002 -> False
- Test-NetConnection 192.168.10.172:21963 -> False

4) 连接成功（同一端口随时间恢复）
- 重新测试后，Test-NetConnection 192.168.10.172:21399 -> True（连续 8 次成功）

## 观察到的现象
- 端口映射查询显示“规则存在”，但 TCP 连接仍会失败（同一端口时好时坏）。
- 失败/恢复不与 OSAC/VM 状态强绑定：VM 内 18080 持续监听。
- 说明问题更可能在 KVM host 侧端口映射/iptables 规则生效与持久化上。

## 可能原因（请 KVM 侧核查）
1) iptables 规则没有持久化或被刷新/重写（服务重启或定时刷新导致丢失）。
2) refresh 逻辑未覆盖 OUTPUT/PREROUTING/FORWARD/POSTROUTING 的完整链路。
3) host 防火墙/安全策略对新端口段限流或间歇阻断。
4) 端口映射的 DNAT 目标在 VM IP 更新后未及时修正。

## 建议 KVM 侧提供/核实
- 端口映射的规则落地位置与链路（iptables/nftables 的具体 chain 及规则样例）。
- 服务重启后是否自动重建规则。
- refresh 触发后是否重写 OUTPUT/PREROUTING 规则，并记录是否成功。
- 是否存在端口段黑名单或策略限速。

## 编排端临时规避建议（可选）
- 连接前调用 GET /v1/sandboxes/{session_id}/ports 触发 refresh。
- 连接失败时，重建端口映射并重试。
