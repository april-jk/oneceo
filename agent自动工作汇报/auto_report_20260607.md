## PPT 结构化澄清卡重复确认修复

- 做了什么：为确认动作增加同步提交锁与成功闭合状态，并把原澄清消息标识随回答持久化；历史重建时依据关联标识隐藏已回答卡片。
- 遇到什么：原实现既不等待回答提交，也不记录回答对应的卡片；重复点击会进入通用“运行中先中止”逻辑，刷新后旧卡片也会再次出现。
- 计划如何解决：确认期间禁用所有交互，提交成功后移除卡片、失败时恢复；存储和客户端元数据白名单保留闭合字段，并以 Web/API 定向测试覆盖重复提交和刷新恢复。

## PPT 结构化澄清卡首次加载修复

- 做了什么：把 managed run 的 SSE 事件游标绑定到具体 run；同一 run 重连保留游标，新 run 订阅前清空旧游标。
- 遇到什么：旧实现跨 run 复用 `afterSequence`，新 run 从 1 开始的澄清事件会被服务端误判为已消费，因此只有刷新重建历史后才显示卡片。
- 计划如何解决：已补充游标归属逻辑和定向测试，确保实时卡片首屏出现，同时保持同一 run 的断线续传能力。

## PPT 澄清卡实时消息被历史覆盖修复

- 做了什么：使用专用测试账号通过浏览器真实发起 PPT 工作流，确认服务端 SSE、recent cache 和 canonical messages 均已包含完整卡片；修正前端历史快照直接覆盖实时消息的问题。
- 遇到什么：新会话初始历史请求早于澄清事件发出、晚于澄清事件返回，旧历史快照会把已经进入内存的卡片移除，所以刷新后才恢复。
- 计划如何解决：历史响应按 `messageKey` 与当前实时消息合并，managed SSE 同步更新消息引用，并增加旧历史响应晚到时仍保留卡片的竞态测试。

## PPT 澄清卡首次加载最终根因修复

- 遇到什么：连续步骤会不断中断并重启平滑滚动动画，且 `scrollIntoView` 可能联动祖先滚动容器，表现为对话区瞬间上跳后再回到底部。
