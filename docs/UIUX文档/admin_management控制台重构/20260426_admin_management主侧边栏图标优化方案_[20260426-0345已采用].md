# 2026-04-26 admin_management 主侧边栏图标优化方案 [20260426-0345已采用]

## 1. 状态

- 当前状态：`[20260426-0345已采用]`
- 目标分支：`feature/admin-detail-ui-unification`
- 方案定位：优化 `apps/admin_management` 管理后台左侧主侧边栏导航图标，让展开态和收起态都更易懂、更容易区分。
- 执行门槛：用户已确认继续，允许进入代码实现；实现阶段仍需遵守“不改导航语义、不新增图标库、不扩范围”的边界。

## 2. 背景与当前事实

当前主侧边栏实现位于：

1. `apps/admin_management/web/src/App.tsx:351-466`：`NAV_GROUPS` 与 `NAV_ITEMS`。
2. `apps/admin_management/web/src/App.tsx:11980-12014`：侧边栏导航渲染。
3. `apps/admin_management/web/src/styles.css:1360-1474`：`.nav-item-tag` 与收起态样式。
4. `apps/admin_management/web/src/components/admin-ui/adminDetailIcons.tsx`：现有 `lucide-react` 受控图标体系。

当前侧边栏没有真正的图形图标，而是用三字母缩写 `tag` 作为视觉锚点：

| 模块 | 当前 tag |
|---|---:|
| Sandbox 管理 | `SBX` |
| 部署管理 | `DEP` |
| 对话管理 | `MSG` |
| 用户管理 | `USR` |
| 审计日志 | `LOG` |
| KVM 管理 | `KVM` |
| 智能体管理 | `AGT` |
| 技能管理 | `SKL` |
| 连接器 Guide | `CGD` |
| OSAC 版本 | `OSA` |
| 计费管理 | `BIL` |

问题：

1. 收起态只显示英文缩写，中文后台用户需要记忆缩写含义。
2. 所有 tag 外形一致，视觉轮廓弱，扫视效率低。
3. `Sandbox / KVM`、`部署 / OSAC`、`对话 / 审计`、`Agent / Skill / Connector Guide` 容易在收起态混淆。
4. 项目已存在 `adminDetailIcons.tsx`，但主侧边栏未复用这套受控图标体系。

## 3. 设计目标

1. 将主侧边栏从三字母缩写升级为语义化 SVG 图标。
2. 展开态保持“图标 + 模块名称”，不让图标替代文字。
3. 收起态只保留图标时，仍可通过图标轮廓识别模块。
4. 复用现有 `lucide-react` 与 `adminDetailIcons.tsx`，不新增图标库。
5. 提高相邻模块的可区分度：
   - Sandbox：容器/沙箱。
   - KVM：宿主机/虚拟机。
   - Deployment：发布/上线。
   - OSAC：工件/版本校验。
   - Conversation：多轮消息。
   - Audit：审计记录。
6. 保持管理后台专业、克制、可操作，不做装饰化图标堆砌。

## 4. 非目标

1. 不新增后端 API。
2. 不修改导航分组、模块顺序、路由 key 或权限语义。
3. 不新增图标库。
4. 不做侧边栏整体布局重构。
5. 不移除文字标签；展开态仍显示模块名称。
6. 不用彩色插画或营销化图标替代产品导航图标。
7. 不为普通说明文字批量增加图标。

## 5. 图标策略

### 5.1 原则

1. 图标必须表达模块主任务，而不是英文缩写。
2. 同一分组内的图标轮廓要明显不同，避免连续使用相似方块、文本或齿轮图标。
3. 图标来源集中在 `adminDetailIcons.tsx`，禁止在 `App.tsx` 分散 import 大量 lucide 图标。
4. `NAV_ITEMS` 增加受控 `iconKey`，渲染时通过 `getAdminModuleIcon(iconKey)` 输出图标。
5. 保留 `tag` 字段作为搜索、兼容或后续辅助文案，不再作为主视觉图标显示。

### 5.2 推荐映射

| key | 模块 | 当前 tag | 推荐 iconKey / 图标 | 语义说明 |
|---|---|---:|---|---|
| `sandbox` | Sandbox 管理 | `SBX` | `sandbox` / `Container` | 容器、沙箱、隔离运行环境。 |
| `deployment` | 部署管理 | `DEP` | `deployment` / `Rocket` | 发布、上线、部署动作。 |
| `conversation` | 对话管理 | `MSG` | `conversation` / `MessagesSquare` | 多轮消息与会话。 |
| `user` | 用户管理 | `USR` | `user` / `UserRound` | 普通用户账号。 |
| `audit` | 审计日志 | `LOG` | `audit` / `ScrollText` | 审计记录、时间线、操作日志。 |
| `kvm` | KVM 管理 | `KVM` | 新增 `kvm` / `Server` 或 `ServerCog` | 宿主机、虚拟机、基础资源。 |
| `agent` | 智能体管理 | `AGT` | `agent` / `Bot` | 智能体服务与能力。 |
| `skill` | 技能管理 | `SKL` | `skill` / `Sparkles` | 技能、能力增强。 |
| `connectorGuide` | 连接器 Guide | `CGD` | 新增 `connectorGuide` / `BookOpenText`，或复用 `connector` / `Cable` | 若强调 Guide，用书本文档；若强调连接器，用线缆。推荐新增 `connectorGuide`。 |
| `osacRelease` | OSAC 版本 | `OSA` | `osac` / `PackageCheck` | 工件、版本包、校验发布。 |
| `billing` | 计费管理 | `BIL` | `billing` / `Receipt` | 账单、消费、定价。 |

## 6. 实施方案

### 6.1 数据结构

在 `NAV_ITEMS` 中新增：

```ts
iconKey: AdminModuleIconKey;
```

如果需要区分 KVM 与 Connector Guide，则在 `adminDetailIcons.tsx` 扩展：

```ts
export type AdminModuleIconKey =
  | ...
  | 'kvm'
  | 'connectorGuide';
```

并补充受控映射：

```ts
case 'kvm': return <Server {...props} />;
case 'connectorGuide': return <BookOpenText {...props} />;
```

### 6.2 渲染结构

将侧边栏导航的：

```tsx
<span className="nav-item-tag">{item.tag}</span>
```

改为：

```tsx
<span className="nav-item-icon" aria-hidden="true">
  {getAdminModuleIcon(item.iconKey, { size: 17 })}
</span>
```

展开态继续显示：

```tsx
<span className="nav-item-body">
  <span>{item.label}</span>
</span>
```

### 6.3 样式

1. `.nav-item-icon` 继承 `.nav-item-tag` 的尺寸、圆角、边框和 active 状态。
2. 图标颜色使用当前侧边栏文字色，不使用多彩图标。
3. active 状态通过背景、边框、图标颜色增强，不额外增加装饰条以外的新视觉噪音。
4. 收起态下图标居中，hover/active 点击区域不缩小。
5. 保持暗色与浅色主题可读性。

## 7. 验收标准

1. 11 个主导航模块均显示语义化 SVG 图标。
2. 侧边栏收起态不再只显示 `SBX / DEP / MSG` 等缩写。
3. `Sandbox / KVM`、`部署 / OSAC`、`对话 / 审计` 的图标轮廓可明显区分。
4. 图标来源集中在 `adminDetailIcons.tsx`，不在 `App.tsx` 分散 import 大量 lucide 图标。
5. 不新增外部图标库。
6. 展开态仍显示模块名称，图标只辅助识别。
7. 浅色、暗色、收起态、窄屏浮层下图标可见、对齐稳定、active 状态清晰。
8. `npm --prefix apps/admin_management run type-check` 通过。
9. `npm --prefix apps/admin_management run build` 通过。

|---|---|

| 误改导航语义 | 不修改 `key/group/label/route`。 |
