# 01 目标与范围 [20260402-1137已采用]

## 1. 背景

当前 oneceo 的身份体系存在三个明显缺口：

1. 用户端没有正式登录页和注册页
2. 用户身份主要依赖前端本地 `X-User-Id`
3. 管理后台没有管理员认证边界

同时，身份数据模型还缺一条明确边界：

1. 用户态和管理端不能共用同一张用户表

这会直接影响：

1. 对话 session 的真实归属
2. skills 的个人可见范围
3. connector profile 与 OAuth 授权的归属
4. 后台查看与治理操作的审计可信度

## 2. 本次目标

### 2.1 必须实现

1. 新增用户注册页
2. 新增用户登录页
3. 新增管理后台登录页
4. 主站与后台分别接入独立身份表与独立登录态
5. session、skills、connector profile、OAuth token、run stream 都明确绑定到真实用户表 `app_users.id`
6. 前端请求从“本地伪身份头”切换为“真实登录态 + 服务端解析”

### 2.2 本次不做

1. 不做社交登录首批接入
2. 不做组织/团队/多成员协作权限体系
3. 不做复杂 RBAC 矩阵
4. 不做计费与订阅系统

## 3. 角色定义

### 3.1 普通用户

能力：

1. 注册与登录 oneceo 主站
2. 查看和操作自己的对话、skills、connector profile
3. 发起连接器授权
4. 订阅自己的 run stream

### 3.2 管理员

能力：

1. 登录后台管理系统
2. 查看平台级 skills、connector guides、sandbox、会话治理信息
3. 查看审计日志

限制：

1. 管理员身份不自动拥有普通用户会话的业务操作权
2. 后台查看用户数据必须带审计记录
3. 管理员账户不写入普通用户表

## 4. 页面范围

### 4.1 用户端

新增：

1. `/login`
2. `/register`

调整：

1. `UserMenu`
2. `AuthDialog`
3. 需要用户身份的入口页和会话页

### 4.2 后台端

新增：

1. `/login`

调整：

1. `App.tsx` 的主导航入口
2. 各个管理区块的进入守卫

## 5. 技术边界

### 5.1 独立身份源

建议拆成两套：

1. 用户态：
   - `POST /auth/register`
   - `POST /auth/login`
   - `POST /auth/logout`
   - `GET /auth/me`
2. 管理端：
   - `POST /admin/auth/login`
   - `POST /admin/auth/logout`
   - `GET /admin/auth/me`

### 5.2 登录态

首批统一使用：

1. HttpOnly session cookie
2. 服务端解析当前身份
3. 用户态和管理端 cookie 分离

不再把 `X-User-Id` 作为正式产品身份主链。

## 6. 用户态鉴权覆盖范围

本轮检查后，用户态需要鉴权的范围不只你已经点名的对话、skills、连接器，还至少包括：

1. 会话创建与列表
2. 会话详情
3. 最近消息与历史消息
4. workspace tree / dir / file / raw
5. Altus managed input / run / stop / stream
6. Codex runtime config
7. 交付物下载
8. 附件抓取与上传
9. 会话标题、收藏、分享、删除
10. connector OAuth 启动与回调后的 profile 归属

## 7. 管理端鉴权覆盖范围

后台端需要鉴权的范围基本覆盖全部现有管理 API：

1. dashboard
2. audit
3. conversations
4. skill-management
5. connector-guides
6. osac-releases
7. sandbox-management
8. agent-management
9. kvm / hosts

## 8. 验收口径

1. 未登录用户访问主站关键能力时，进入登录页，而不是继续拿匿名 ID
2. 已登录用户只能看到自己的会话、skills、connector 授权
3. 未登录管理员无法进入后台
4. 后台操作可以明确记录管理员身份
5. 用户态和管理端数据库层不存在共用同一张身份表的路径
