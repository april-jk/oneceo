# 08 用户端账户设置页重设计 [20260418-0125已采用]

更新时间：2026-04-18 01:42

## 1. 背景

当前 `SettingsDialog` 的“账户”页仍是默认表单堆叠：

1. 视觉层级弱，和当前用户资料区、连接器设置区风格不一致
2. 账户身份信息没有形成稳定的顶部概览
3. 用户只能看到占位输入框，缺少真实邮箱、用户 ID、登录方式等关键信息

本次改动以用户提供的两段参考结构为直接依据，目标不是增加新业务流程，而是把账户页重构成更清晰的资料页结构。

## 2. 设计目标

1. 一级页先展示“当前是谁”
2. 一级页只保留账户状态摘要，不堆叠详细资料
3. 详细资料移动到二级页，由编辑按钮进入
4. 在现有接口能力未补齐前，优先保证信息结构、视觉层级和可扩展性正确

## 3. 页面结构

### 3.1 顶部资料区

组成：

1. 头像
2. 显示名
3. 邮箱
4. 右侧快捷操作

要求：

1. 头像、显示名、邮箱必须直接取自当前登录用户态 `app_users`
2. 右侧保留“编辑资料”和“退出登录”两个轻量动作入口
3. 移动端改为上下排布，桌面端保持单行概览

### 3.2 账户摘要区

组成：

1. 套餐层级（当前先固定展示免费）
2. 账户状态
3. 登录方式
4. 会话隔离状态

要求：

1. 摘要区只展示当前系统已有真实语义，不能伪造积分、套餐配额等未接入数据
2. 允许保留“升级”按钮位置，但若后端能力未接入，必须明确提示暂不可用

### 3.3 二级详情页

条目顺序：

1. 头像 + 显示名编辑
2. 邮箱
3. 用户 ID
4. 密码
5. 删除账户

要求：

1. 一级页和二级页不能同时出现两份头像概览
2. 编辑按钮进入二级页，二级页提供返回一级页的能力
3. 每个条目独立成行，信息在左、操作在右
4. 用户 ID 需要支持复制
5. 密码行显示掩码态，不暴露真实密码信息
6. 删除账户维持危险动作视觉语义

## 4. 交互约束

1. 退出登录必须接入现有 `useAuth().logout()` 主链
2. 当前未接入后端的能力，包括头像上传、资料更新、密码修改、删除账户，必须明确提示“暂未接入”，不能伪装成已生效
3. 显示名输入保留可扩展编辑结构，为后续接正式接口做准备
4. 一级页必须收敛成概览视图，不再堆叠完整资料表单
5. 账户页必须使用真实登录用户数据，不能再展示占位邮箱和占位用户名

## 5. 实现落点

文件：

1. `apps/web/client/src/components/SettingsDialog.tsx`
2. `apps/web/client/src/locales/zh.json`
3. `apps/web/client/src/locales/en.json`

## 6. 验收标准

1. 打开设置后，账户一级页顶部能看到真实头像、显示名、邮箱
2. 账户一级页中部存在明确的账户状态摘要区
3. 一级页不再同时出现第二个用户头像
4. 点击编辑按钮后进入账户二级详情页
5. 用户 ID 可以复制并得到反馈
6. 退出登录按钮可直接生效
7. 未接入的账户编辑类能力会明确提示，而不是静默无响应
8. 页面在桌面和移动宽度下都保持稳定排版
