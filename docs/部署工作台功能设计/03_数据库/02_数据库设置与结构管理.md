# 数据库 / 数据库设置与结构管理

## 1. 功能目标

这一页承接数据库控制台中的设置与结构能力，不和数据浏览混在一个面板里。

目标能力：

- 查看数据库基础信息
- 查看表结构
- 管理字段、索引、约束
- 查看连接与权限信息
- 复制连接信息到外部数据库管理工具
- 后续扩展迁移、备份、恢复

## 2. 入口设计

入口位于数据库页左侧底部 `设置` 按钮。

原因：

- 用户先浏览和修改数据，再进入结构与设置。
- 把高频操作和低频设置拆开，降低主工作区复杂度。

## 3. 页面结构

建议结构：

- 数据库概览卡
- 连接信息区
- 表结构区
- 连接与权限区
- 高级操作区

### 3.1 数据库概览卡

建议展示：

- 数据库名称
- 当前环境
- 连接状态
- 最近同步或最近迁移时间

### 3.2 连接信息区

这是左下 `设置` 按钮进入后的核心区块之一。

必须展示：

- 连接 URL
- 主机
- 端口
- 用户名
- 密码
- 数据库名

每一项都必须提供独立复制按钮，允许用户直接复制到自己的数据库管理软件中使用。

交互要求：

- 每个字段右侧提供 `复制` 按钮
- 支持一键复制单个值
- 复制成功后给出轻量反馈
- 不要求用户额外展开二次确认后才能复制

产品要求：

- 这里展示的是可直接使用的真实连接信息
- 目标是支持用户直接粘贴到 DBeaver、TablePlus、DataGrip、Postico 等数据库工具

### 3.3 表结构区

建议支持：

- 表列表
- 字段名
- 字段类型
- 是否主键
- 是否可空
- 默认值
- 索引 / 约束信息

### 3.4 连接与权限区

建议支持：

- 连接方式说明
- 角色与权限概览
- 读写范围说明

说明：

- 这一块偏说明与权限，不替代上面的“连接信息区”
- “连接信息区”解决复制使用问题
- “连接与权限区”解决理解连接方式和权限范围问题

### 3.5 高级操作区

后续能力建议放在这里：

- 迁移
- 备份
- 恢复
- 审计

## 4. 计划设计方式

### 第一阶段

- 先做数据库概览
- 先做连接信息展示与复制
- 先做表结构只读页

### 第二阶段

- 支持字段层级查看和索引/约束展示
- 支持部分结构变更入口

### 第三阶段

- 支持迁移、备份、恢复和审计

## 5. 数据模型建议

后续建议至少提供：

- `databaseSummary`
- `databaseConnection`
- `tables`
- `tableColumns`
- `tableIndexes`
- `tableConstraints`
- `databasePermissions`
- `databaseOperations`

`databaseConnection` 至少包含：

- `url`
- `host`
- `port`
- `username`
- `password`
- `database`
- `provider`
- `source`

其中：

- `provider` 当前固定为 `postgres`
- `source` 当前固定为 `railway`

## 6. 审核点

- `设置` 是否作为数据库页左下固定入口。
- 结构管理是否与数据编辑彻底分屏。
- 连接信息是否按“逐项可复制”的形式直接展示。
