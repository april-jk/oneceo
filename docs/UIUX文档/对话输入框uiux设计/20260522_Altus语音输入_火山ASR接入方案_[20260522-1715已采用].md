# 20260522 Altus语音输入 火山ASR接入方案 [20260522-1715已采用]

## 背景

当前 `oneceo` 在对话输入框右下角已经有麦克风按钮占位，但没有真正实现语音输入能力。  
这次目标不是做完整的“语音秘书系统”，而是给 Altus / task-creation 主输入框补齐一条最短、稳定、可直接上线迭代的语音转文字链路。

用户明确要求：

1. 使用字节跳动 / 火山引擎语音识别 API。
2. 参照 `AgentLine` 项目里已经实现过的语音转文字逻辑。
3. 在 `oneceo` 中实现“通过语音输入直接安排任务”。

## 设计原则

1. 不把 `AgentLine` 整套 Voice Secretary 搬进来。
2. 只复用已经验证过的“录音 + 火山 ASR”实现方式。
3. 不新造第二套任务编排入口。
4. 语音输入的最终结果必须回到 `oneceo` 现有发送链路。
5. 配置方式遵循 `oneceo` 现有规则，优先走 `.env` / `process.env`，不引入 `AgentLine` 的 server settings 页面依赖。

## 最终采用方案

### 1. 前端录音方式

沿用 `AgentLine` 的思路：

- 浏览器点击麦克风后请求麦克风权限
- 使用 `AudioContext + ScriptProcessorNode` 采集音频
- 前端直接转为 `16k / mono / wav`
- 停止录音后将 blob 上传给 `oneceo` API

原因：

- 这是 `AgentLine` 已验证的链路
- 后端转发给火山 ASR 更稳定
- 避免浏览器端厂商兼容差异直接影响识别主结果

### 2. 后端转写方式

新增一条 task-creation 域内接口：

- `POST /api/task-creation/voice/transcribe`

职责：

- 接收前端上传的 `audio` 文件
- 使用火山引擎 ASR 转写
- 返回最终文本与置信度

### 3. 火山引擎接入方式

后端直接参照 `AgentLine/packages/server/src/voice-secretary/volcengine-speech.ts`：

- 支持 HTTP flash endpoint
- 支持 WebSocket `bigmodel_nostream`
- 先保留 `AgentLine` 中已经验证过的鉴权与协议处理方式

### 4. oneceo 里的发送行为

语音转写成功后：

- 将识别文本作为本次用户输入
- 直接复用 `Home.tsx` 现有发送逻辑
- 对普通任务输入走 `submitPrompt`
- 对澄清问题回答走 `submitQuestionAnswer`

也就是说：

- 语音输入只是“文本输入来源”发生变化
- Altus / task creation 主流程本身不改语义

## 风险与边界

1. 浏览器录音权限会受到用户系统权限影响
2. WebSocket ASR endpoint 依赖当前火山鉴权配置可用
3. 语音输入属于直接发任务能力，误识别会直接进入任务链路，因此 UI 上必须保持“点击开始，再点击结束发送”的明确交互

## 验证方式

1. 本地登录后进入 `/new-task`
2. 点击输入框右下角麦克风
3. 说一句完整任务，例如“帮我做一个产品发布页”
4. 再点一次麦克风结束录音
5. 观察是否：
   - 成功调用后端转写
   - 输入内容被送入现有任务链路
   - 会话正常进入 Altus 处理状态

## 采用结论

采用该方案进入实现。核心原则是：

> 复用 `AgentLine` 已验证的火山 ASR 接入方式，但只在 `oneceo` 中接入“语音转文字并直接发任务”这一条最小必要链路。
