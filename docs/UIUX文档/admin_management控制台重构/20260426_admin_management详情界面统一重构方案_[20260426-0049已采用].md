# 2026-04-26 admin_management 详情界面统一重构方案 [20260426-0049已采用]

## 1. 状态

- 当前状态：`[20260426-0049已采用]`
- 分支：`feature/admin-detail-ui-unification`
- 设计目标：在不重写业务 API 的前提下，统一 OneCEO 管理后台详情类界面的外壳、控件、状态展示、代码/JSON 展示、危险操作确认与移动端可用性。
- 执行门槛：用户已确认采用，并允许在前端引入新增 UI 组件库；本轮进入代码实现。

## 2. 背景

管理后台已经经过整站重构、治理二期、用户管理、计费管理与界面收敛等多轮建设，但详情类界面仍由各模块各自实现：

1. `Sandbox`、对话、用户、技能、连接器、OSAC、计费详情的弹窗/抽屉外壳不统一；
2. 技能和连接器页面存在偏原生按钮或弱一致性的按钮观感；
3. 禁用用户、归档技能、发布连接器、发布/切换 OSAC、删除/更新定价、Sandbox 关机/重启/归档等高风险操作缺少统一确认模式；
4. 部分操作仍使用 `window.confirm` / `confirm`，不符合长期治理要求；
5. 移动端主要是桌面表格压缩，390px 下不可用或信息密度失控。

本轮定位为 `Clean SaaS Admin 2.0 + Guided Change Control`：保留现有后台信息密度，但把详情页改成统一、可审计、移动端可用的管理控制台体验。

## 5. 目标

1. 建立统一组件：`AdminDetailShell`、`AdminTabs`、`AdminButton`、`StatusBadge`、`IdToken`、`DangerConfirmDialog`、`CodePanel`。
2. 先改详情类界面，不重写业务 API，不改变后端路由语义。
3. 禁止继续把 `window.confirm` / `confirm` 作为长期确认方案。
4. 所有危险操作确认必须展示：对象、操作、影响范围、不可逆程度、审计说明、原因输入或确认词。
5. 统一关闭按钮、Tab、badge、按钮尺寸、边距、圆角、阴影。
6. 390px 移动端使用卡片列表和全屏详情，不直接压缩桌面表格。
7. 完成后提供截图验证清单与最小可行验证命令。

## 6. 非目标

1. 不重写 `apps/admin_management/server/*` 的业务 API。
2. 不重构 `apps/api/*` 主链业务逻辑。
3. 不新增 UI 组件库、路由库或状态管理库。
4. 不改变 Sandbox / OSAC / Connector / Skill / Billing 的业务状态机。
5. 不引入兼容旧视觉的双轨弹窗；本轮只保留统一详情组件作为后续长期方案。
6. 不把列表页全部重做成新信息架构；只处理详情入口、详情内容承载、高风险操作与 390px 可用性。

## 7. 总体方案

### 7.1 统一详情骨架

所有详情弹窗、抽屉、详情编辑器统一迁移到 `AdminDetailShell`：

```text
┌──────────────────────────────────────────────┐
│ Header: 标题 / 来源路径 / 状态 / 关闭按钮       │  sticky
├──────────────────────────────────────────────┤
│ Summary: 核心 ID / 状态 / 关键指标 / 时间       │
├──────────────────────────────────────────────┤
│ Tabs: 概览 / 配置 / 日志 / 审计 / 原始数据       │  sticky
├──────────────────────────────────────────────┤
│ Body: 主内容 + 右侧上下文栏                    │
│                                              │
├──────────────────────────────────────────────┤
│ Footer: 安全操作 / Danger Zone 入口            │  sticky
└──────────────────────────────────────────────┘
```

桌面端默认宽度：`min(1240px, calc(100vw - 48px))`；高度：`max-height: calc(100dvh - 32px)`。

390px 下转为全屏详情：`width: 100vw; height: 100dvh; border-radius: 0`。

### 7.2 Guided Change Control

所有会改变运行态、发布状态、计费规则、归档状态、文件系统或用户可用性的操作统一进入 `DangerConfirmDialog`：

1. Review：展示对象、当前状态、目标动作；
2. Impact：列出直接影响、旁路影响、不会发生的影响；
3. Confirm：输入确认词或对象 ID；
4. Execute：提交按钮 loading，禁止重复提交；
5. Audit：填写原因，成功后 toast + 详情内保留最近操作结果，失败时保留弹窗并显示错误。

### 7.3 移动端列表策略

390px 下列表区不得直接压缩桌面表格。详情相关索引列表改为：

1. 表格外层保持桌面端；
2. 小屏隐藏表头，将每行渲染为 `admin-mobile-card`；
3. 每张卡片展示主标题、状态、关键 ID、更新时间、主操作；
4. 次级字段通过两列 key-value 或纵向栈展示；
5. 点开详情后使用全屏 `AdminDetailShell`。

## 8. 组件设计

### 8.1 `AdminDetailShell`

建议位置：`apps/admin_management/web/src/components/admin-ui/AdminDetailShell.tsx`

职责：统一详情弹窗/抽屉/编辑器外壳。

建议 props：

```typescript
type AdminDetailShellProps = {
  open: boolean;
  title: string;
  subtitle?: string;
  originTrail?: Array<{ label: string; value?: string }>;
  status?: React.ReactNode;
  summary?: React.ReactNode;
  tabs?: React.ReactNode;
  actions?: React.ReactNode;
  dangerZone?: React.ReactNode;
  children: React.ReactNode;
  size?: 'md' | 'lg' | 'xl' | 'fullscreen';
  onClose: () => void;
};
```

要求：

1. 使用 `role="dialog"`、`aria-modal="true"`、`aria-labelledby`；
2. 关闭按钮尺寸、圆角、hover、focus ring 统一；
3. Header / tabs / footer 支持 sticky；
4. Body 独立滚动，避免页面底层滚动；
5. 支持桌面居中、侧向抽屉视觉与移动端全屏三种布局，但 DOM 结构保持一致。

### 8.2 `AdminTabs`

建议位置：`apps/admin_management/web/src/components/admin-ui/AdminTabs.tsx`

要求：

1. pill tabs；active tab 有清晰边框、浅色背景与 focus ring；
2. 支持 `count`、`warning`、`dirty` 标识；
3. 使用 `role="tablist"`、`role="tab"`、`aria-selected`；
4. 390px 下横向滚动，不换行挤压；
5. tabs 内禁止放危险操作。

### 8.3 `AdminButton`

建议位置：`apps/admin_management/web/src/components/admin-ui/AdminButton.tsx`

variants：

1. `primary`
2. `secondary`
3. `ghost`
4. `danger`
5. `dangerSoft`
6. `link`

要求：

1. 统一 `sm / md / lg / icon` 尺寸；
2. 支持 loading、disabled、busy、iconOnly；
3. danger 按钮不得混入普通主操作区，必须和 `DangerConfirmDialog` 或明确二次确认绑定；
4. 替换技能、连接器、OSAC、计费详情中的原生感按钮。

### 8.4 `StatusBadge`

建议位置：`apps/admin_management/web/src/components/admin-ui/StatusBadge.tsx`

tones：`success`、`info`、`warning`、`danger`、`neutral`、`processing`。

要求：

1. 不仅靠颜色表达，保留 dot 或 icon 与中文短文案；
2. 统一圆角、内边距、字号、边框透明度；
3. 覆盖运行中、已暂停、失败、已归档、草稿、已发布、当前版本、生效中、禁用等状态。

### 8.5 `IdToken`

建议位置：`apps/admin_management/web/src/components/admin-ui/IdToken.tsx`

用于展示：`userId`、`sandboxId`、`sessionId`、`snapshotKey`、`connectorKey`、`model`、`revisionId`。

要求：

1. 默认中间截断，`title` 展示完整值；
2. 右侧固定复制按钮；
3. 复制成功使用现有 toast，不新增通知库；
4. 390px 下最大宽度约 `calc(100vw - 120px)`，不撑破布局。

### 8.6 `DangerConfirmDialog`

建议位置：`apps/admin_management/web/src/components/admin-ui/DangerConfirmDialog.tsx`

必备内容：

1. 对象：类型、名称、ID、当前状态；
2. 操作：当前动作与目标状态；
3. 影响范围：会影响什么、不会影响什么；
4. 不可逆程度：可恢复、部分可恢复、不可逆；
5. 审计说明：原因输入，危险操作默认必填；
6. 确认词：输入对象 ID、`DELETE`、`ARCHIVE`、`PUBLISH`、`SWITCH` 等；
7. 执行反馈：loading、错误、成功关闭。

建议 props：

```typescript
type DangerConfirmDialogProps = {
  open: boolean;
  title: string;
  objectLabel: string;
  objectId?: string;
  objectMeta?: Array<{ label: string; value: React.ReactNode }>;
  actionLabel: string;
  impactItems: string[];
  nonImpactItems?: string[];
  reversibility: 'reversible' | 'partially_reversible' | 'irreversible';
  confirmText?: string;
  reasonRequired?: boolean;
  loading?: boolean;
  error?: string | null;
  onCancel: () => void;
  onConfirm: (payload: { reason: string }) => void | Promise<void>;
};
```

### 8.7 `CodePanel`

建议位置：`apps/admin_management/web/src/components/admin-ui/CodePanel.tsx`

要求：

1. Header 展示标题、语言、复制、下载、自动换行开关；
2. JSON 默认 pretty print；解析失败显示错误提示；
3. 长日志使用内部滚动，不撑破 `AdminDetailShell`；
4. 390px 下默认横向滚动，可手动开启换行。

## 9. 危险操作确认矩阵

| 模块 | 操作 | 确认词 | 原因 | 不可逆程度 | 影响说明要点 |
|---|---|---|---|---|---|
| 用户管理 | 禁用用户 | 输入用户邮箱或用户 ID | 必填 | 部分可恢复 | 用户无法登录；现有会话可能失效；不删除历史会话/账单。 |
| 用户管理 | 启用用户 | 输入用户邮箱或用户 ID | 必填 | 可恢复 | 用户恢复登录能力；不自动重建历史会话。 |
| 技能管理 | 归档技能 | `ARCHIVE` 或 skill key | 必填 | 部分可恢复 | 技能从可用列表移除；历史记录保留；恢复需重新启用。 |
| 技能管理 | 重新启用技能 | skill key | 必填 | 可恢复 | 技能重新进入可用治理范围；不修改版本内容。 |
| Connector Guide | 发布 revision | `PUBLISH` 或 revision id | 必填 | 部分可恢复 | 新会话将使用发布内容；旧 revision 保留；可后续回滚。 |
| Connector Guide | 回滚 revision | `ROLLBACK` 或 revision id | 必填 | 部分可恢复 | published revision 切回目标版本；不删除其他 revision。 |
| OSAC 版本 | 发布版本 | `PUBLISH` 或 version | 必填 | 部分可恢复 | 版本进入可切换范围；不自动切换当前运行版本。 |
| OSAC 版本 | 切换当前版本 | `SWITCH` 或 version | 必填 | 部分可恢复 | 新下发链路使用目标版本；已运行实例不强制改写。 |
| 计费管理 | 删除定价 | `DELETE` | 必填 | 不可逆 | 新请求不再使用该规则；历史账单不回写；恢复需重新创建。 |
| 计费管理 | 更新定价 | 输入 model/provider | 必填 | 部分可恢复 | 新请求按新价格计费；历史消费不回算。 |
| Sandbox 管理 | 关机/关闭 | sandbox id | 必填 | 部分可恢复 | 当前实例停止；不保证原实例可继续；工作区恢复依赖既有归档/恢复链路。 |
| Sandbox 管理 | 重启 | `RESTART` 或 sandbox id | 必填 | 部分可恢复 | 按既有重启语义归档、关闭、恢复/重建；运行中任务可能短暂不可用。 |
| Sandbox 管理 | 归档 | `ARCHIVE` 或 sandbox id | 必填 | 可恢复 | 生成/更新工作区快照；不删除历史会话；可能占用归档资源。 |
| Sandbox 管理 | 删除文件 | `DELETE <path>` | 必填 | 不可逆 | 文件从当前工作区移除；不会自动重启 Sandbox。 |

说明：如当前后端接口尚不接收 `reason`，前端仍必须收集并在本地 UI/日志上下文中保留；不因 API 暂不支持而退回原生确认。

## 10. 各详情界面迁移方案

### 10.1 Sandbox 详情

1. 将 `runtime-inspector-modal` 迁移到 `AdminDetailShell`。
2. Summary 展示 Sandbox ID、Task Session ID、运行状态、归档状态、最近活跃时间。
3. Tab 建议：概览、运行态、文件/命令、归档、审计/原始数据。
4. 关机、重启、归档、删除文件统一进入 `DangerConfirmDialog`。
5. 代码、JSON、日志使用 `CodePanel`。

### 10.2 对话详情

1. 将 `conversation-dialog-modal` 迁移到 `AdminDetailShell`。
2. Summary 展示会话 ID、用户、状态、阶段、处理方式、更新时间。
3. Tab 建议：概览、消息、Sandbox、事件、原始数据。
4. 消息 JSON、事件 payload 使用 `CodePanel`。
5. 移动端消息列表使用卡片，不压缩表格。

### 10.3 用户详情与计费用户详情

1. `UserManagementSection` 用户详情抽屉与 `UserDetailDialog` 计费用户详情都使用 `AdminDetailShell`。
2. 用户治理操作禁用/启用进入 `DangerConfirmDialog`。
3. 用户 ID、legacy ID、session ID 使用 `IdToken`。
4. 390px 下用户列表、会话列表、Sandbox 列表使用卡片列表。

### 10.4 技能详情

1. `skill-detail-modal` 迁移到 `AdminDetailShell`。
2. 技能状态使用 `StatusBadge`。
3. 归档/重新启用进入 `DangerConfirmDialog`。
4. 技能内容、配置片段、错误日志使用 `CodePanel`。
5. 替换 `ghost-btn` 等原生感按钮为 `AdminButton`。

### 10.5 Connector Guide 详情/编辑器

1. `connector-guide-editor-modal` 迁移到 `AdminDetailShell`。
2. policy 详情、revision 编辑器共享同一 shell；编辑区在 body 内呈现。
3. 发布/回滚进入 `DangerConfirmDialog`。
4. connector key、revision ID 使用 `IdToken`。
5. guide 文本、blocking rules 使用 `CodePanel` 或统一 editor panel 样式。

### 10.6 OSAC 版本详情

1. `osac-release-modal` 迁移到 `AdminDetailShell`。
2. 发布、切换当前版本进入 `DangerConfirmDialog`。
3. 版本号、checksum、artifact key 使用 `IdToken`。
4. 验证结果、manifest、日志使用 `CodePanel`。

### 10.7 计费/定价详情

1. pricing 表单与详情统一用 `AdminDetailShell`。
2. 删除定价移除 `confirm`，改为 `DangerConfirmDialog`。
3. 更新定价如会影响生效价格，进入 change-control 确认，展示新旧价格差异。
4. 使用明细表 390px 下改卡片列表。

## 11. CSS 与视觉 token

本轮不引入新设计系统库，只在 `apps/admin_management/web/src/styles.css` 中建立 `admin-ui-*` 命名空间，避免继续叠加模块专有弹窗类。

建议 token：

```text
radius: 8px 默认；12px 用于 shell/dialog
space: 4 / 8 / 12 / 16 / 24
font: 正文 14px；元信息 12px；mono 使用现有等宽字体
surface: page / card / elevated 复用现有变量
border: default / strong 复用现有变量
shadow: card / dialog 复用现有变量
status: success / info / warning / danger / neutral / processing
```

统一要求：

1. 关闭按钮：32px，圆角 8px，统一 hover/focus。
2. Tab：高度 34-36px，圆角 999px，active 有边框与浅底。
3. Badge：高度 22-24px，12px 字号，dot + 文案。
4. Button：`sm` 28px、`md` 34px、`lg` 40px；圆角 8px。
5. Shell：桌面圆角 12px，阴影统一，移动端无圆角。
6. CodePanel：暗色代码面板和浅色标题栏统一。

## 12. 移动端 390px 规则

1. `AdminDetailShell` 全屏：`100vw * 100dvh`，无外边距、无圆角。
2. Header sticky 顶部，footer sticky 底部。
3. Tabs 横向滚动、单行 snap，不多行挤压。
