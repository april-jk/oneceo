# 用户侧蒙层引导设计方案 [20260507-1143已采用]

创建时间：2026-05-07 11:25  
适用范围：`apps/web` 用户侧工作台  
当前状态：已通过方案评审，第一阶段、第二阶段已实现；第三阶段高级能力与总经理视图引导已完成实现验证

## 1. 背景与目标

本方案基于 2026-05-07 在 Chrome 中对 oneceo 用户侧 UI 的实机巡检，以及仓库根目录 `PRODUCT.md` / `DESIGN.md` 的“任务塔台”原则整理。用户侧不是营销页，也不是单纯聊天框；它承担任务创建、Agent 协作、项目治理、连接器授权、Skills 注入、交付物复核和部署推进。

蒙层引导的目标是：

- 让新用户在 30 秒内知道“先从哪里开始”：新建任务、输入需求、选择附件 / Skills / 连接器 / 模型。
- 让用户理解 oneceo 的核心工作结构：会话产生任务，任务可归属项目，项目下有经理、员工、交付文档。
- 让复杂能力按需出现：连接器、Skills、项目默认连接器、设置项不在首屏一次性压给用户。
- 保持指挥台气质：引导文案直接、短、可行动，不做营销式欢迎语。

## 2. 实机巡检范围

已查看的用户侧主路径：

- `/home` / `/new-task`：主任务输入区、侧栏、通知、设置、附件菜单、Skills 子菜单、连接器菜单、模型选择。
- `/search`：全局会话搜索。
- `/library`：资料库空态。
- `/projects`：项目总览、自组织项目、创建项目弹窗、默认连接器下拉。
- `/project/1`：项目详情、经理、任务、协作员工、查看交付文档。
- `/ceo-view`：总经理视图、指标卡、CEO 对话输入区。
- 设置弹窗：个性化、账户、模型设置、语言 / 主题 / 通知、Skills 管理、Connectors、积分与消费。
- Connectors 二层：应用连接器、连接器详情、Custom API 占位、Custom MCP、MCP 直接配置弹窗。

## 3. 引导设计原则

### 3.1 分层，不一次讲完

引导分为三层：

1. 首次任务闭环：只解释“输入需求 -> 补充上下文 -> 选择能力 -> 发送”。
2. 项目组织闭环：用户进入项目页时解释“项目 / 经理 / 员工 / 任务 / 交付文档”。
3. 高级能力闭环：用户主动打开设置、连接器、Skills、积分时再解释。

### 3.2 以用户动作触发，而不是按页面硬弹

触发点优先级：

- 第一次进入 `/home`：显示 4 步主流程引导。
- 第一次点击附件、连接器、模型选择：显示对应局部解释。
- 第一次进入 `/projects`：显示项目结构导览。
- 第一次打开设置：仅高亮设置左侧分区，不逐项展开。
- 第一次进入 `/ceo-view`：解释这是跨项目调度视角，不替代普通任务输入。

### 3.3 允许跳过，允许回看

每个引导都必须有：

- `跳过`
- `下一步`
- `完成`
- `稍后再看`
- 设置内的“重新查看引导”入口

不建议设置不可关闭的强制引导。

## 4. 推荐引导体系

### 4.1 首次进入工作台：核心任务引导

触发条件：

- 用户已登录。
- 本地或服务端未记录 `home_core_tour_completed`。
- 当前页面为 `/home` 或 `/new-task`。

建议步骤：

1. 侧栏「新建任务」
   - 标题：新建任务
   - 文案：从这里开启一个新的 Agent 会话。每个会话都会记录上下文、产出和后续操作。
   - 目标：建立“会话是工作单元”的认知。

2. 中央输入框
   - 标题：描述你要完成的事
   - 文案：直接写目标、约束和交付物。越接近真实需求，Altus 越容易给出可复核产出。
   - 目标：避免用户把它当普通问答框。

3. 附件按钮
   - 标题：补充资料和 Skills
   - 文案：这里可以添加本地文件、云端资料，或选择已启用的 Skills 进入本次任务。
   - 目标：解释 `+` 背后的三层菜单。

4. 连接器按钮
   - 标题：授权外部工具
   - 文案：GitHub、Notion、Slack、Supabase、Figma、Vercel 可按任务启用；未授权时先去管理连接器。
   - 目标：解释连接器既有“开关”也有“授权配置”。

5. 模型选择
   - 标题：选择执行强度
   - 文案：Lite 更快，Pro 均衡，Max 适合复杂任务。默认 Pro 可以覆盖多数工作。
   - 目标：减少用户对 Agent Lite / Pro / Max 的猜测。

6. 发送按钮
   - 标题：开始执行
   - 文案：发送后会进入会话执行链路，产出、文件、部署和调试信息会跟随会话保存。
   - 目标：形成闭环。

建议控制：

- 首次只展示 4 步：新建任务、输入框、附件 / Skills、发送。
- 连接器和模型可以作为“更多能力”二段引导，避免第一轮过重。

### 4.2 附件与 Skills 局部引导

触发条件：

- 用户第一次点击附件按钮。

锚点与文案：

- 从云端添加：适合把已有资料作为上下文。
- 使用技能：选择平台或自定义 Skills，给本次任务注入专门方法和资源。
- 从本地文件添加：适合文档、图片、代码文件。

Skills 子菜单特殊处理：

- 因为当前列表很长，首次展开时建议只显示一个小提示：`Skills 会进入本次任务上下文，不等于全局开启。可在设置里管理可用 Skills。`
- 不逐个解释每个 Skill。

### 4.3 连接器局部引导

触发条件：

- 用户第一次点击任务输入区的连接器按钮。

锚点与文案：

- 单个连接器开关：`为本次任务启用这个工具。未授权时需要先完成连接。`
- 管理连接器：`在这里配置授权、默认 profile、自定义 MCP。`

打开 Connectors 设置页后的二层引导：

- 应用：`常用集成，适合 GitHub、Notion、Slack、Supabase、Figma、Vercel。`
- 自定义 API：`当前是预留入口，不作为首轮推荐动作。`
- 自定义 MCP：`只支持远程 HTTP / Streamable HTTP / SSE；本地命令型配置不会保存。`
- MCP 配置弹窗：高亮服务器名称、传输类型、服务器 URL、Headers、编辑 JSON、保存。

### 4.4 项目页结构引导

触发条件：

- 用户第一次进入 `/projects`。

建议步骤：

1. 项目页标题与创建项目
   - 文案：项目用于把多个会话和任务收拢到同一个目标下。

2. 普通项目空态
   - 文案：普通项目由你创建，可以配置项目指令和默认连接器。

3. 自组织项目
   - 文案：这里展示系统示例或已形成组织结构的项目，适合查看经理和员工分工。

4. 项目卡片
   - 文案：进度、经理数、员工数帮助你快速判断执行状态。

5. 查看详情
   - 文案：进入后可以查看经理、任务、协作员工和交付文档。

创建项目弹窗引导：

- 项目名称：`给目标一个可复用的工作空间。`
- 项目指令：`写长期约束，例如技术栈、部署要求、语气和验收标准。`
- 默认连接器：`项目内任务可优先使用这些授权工具。`

### 4.5 项目详情引导

触发条件：

- 用户第一次进入 `/project/:id`。

建议步骤：

- 经理卡片：`经理负责一个方向的任务拆分和协调。`
- 任务卡片：`任务展示优先级、状态、截止日期和参与员工。`
- 展开任务：`展开后可以看协作员工与各自交付状态。`
- 查看交付文档：`这里是验收证据，不只是聊天记录。`
- 创建经理：`需要新增职责线时再使用。`

### 4.6 总经理视图引导

触发条件：

- 用户第一次进入 `/ceo-view`。

建议步骤：

- 指标卡：`这里用于跨项目判断规模、完成率和整体进度。`
- CEO 对话：`适合问资源调度、项目优先级、团队绩效，不替代单任务执行。`
- 输入区能力：沿用任务输入区的附件、连接器、模型说明，但不重复全流程。

### 4.7 设置弹窗引导

触发条件：

- 用户第一次打开设置。

建议只做“分区说明”，不进入每个字段：

- 个性化：长期身份、背景和回应偏好。
- 账户：账号、登录方式、会话隔离和退出登录。
- 模型设置：Altus 接管模式和 sandbox 直通切换。
- 设置：语言、主题、通知偏好。
- Skills 管理：启用平台模板和维护自定义 Skills。
- Connectors：授权、默认项、自定义 API / MCP。
- 积分与消费：余额、充值、激活码和消费记录。

高风险提示：

- 模型设置里的 `sandbox 直通` / `Altus 接管对话` 会影响执行链路，应使用解释型提示，不应做成普通装饰 tooltip。
- Skills 的“移出我的 skills”需要二次确认或至少清晰表达影响范围。
- 连接器断开、删除 profile、自定义 MCP 保存失败需要明确对象与后果。

## 5. 引导状态与触发建议

建议记录以下状态键：

- `tour.home_core.completed`
- `tour.home_attachment.seen`
- `tour.home_connectors.seen`
- `tour.home_model.seen`
- `tour.projects.overview.completed`
- `tour.project_detail.completed`
- `tour.ceo_view.completed`
- `tour.settings.overview.completed`
- `tour.connectors.custom_mcp.seen`

存储建议：

- 首期可使用用户级本地状态 + 账号级服务端状态组合。
- 同账号跨设备应尽量不重复展示完整引导。
- 如果服务端暂未准备好，可先使用 localStorage，但后续需要迁移到账号偏好，避免浏览器清理后频繁打扰。

## 6. 视觉与交互规范

蒙层风格：

- 背景遮罩：低饱和深灰，透明度约 45%-55%，不要使用强 blur。
- 高亮区域：1px `command-blue` 描边 + 轻量蓝色 ring，保持任务塔台的克制感。
- 气泡：8px 圆角，标题 14px/800，正文 13px，按钮 28px 或 32px 高。
- 箭头：仅在空间足够时显示；移动端可以省略箭头。
- 不使用大面积渐变、插画、庆祝动效。

交互：

- `Esc` 关闭当前引导。
- 点击遮罩不直接完成，只弹出“跳过 / 继续”轻提示或关闭当前步。
- 被引导元素应保持可见，但默认不允许触发破坏性动作。
- 页面滚动时自动把目标元素滚入视口，避免气泡悬空。
- 移动端气泡固定底部，目标元素只高亮，不强行塞在元素旁。

## 7. 文案基调

推荐语气：

- 短句。
- 面向动作。
- 告诉用户后果。
- 少说“智能”“强大”“领先”，多说“会保存什么”“会影响什么”“下一步做什么”。

示例：

- 好：`把项目长期约束写在这里，后续任务会优先遵守。`
- 避免：`在这里释放 AI Agent 的无限潜能。`

## 8. 分阶段落地建议

第一阶段：低风险主流程

- `/home` 首次任务引导。
- 附件 / Skills / 连接器 / 模型局部提示。
- 设置分区说明。

第二阶段：项目结构

- `/projects` 项目结构引导。
- 创建项目弹窗提示。
- `/project/:id` 经理 / 任务 / 交付文档引导。

第三阶段：高级能力与复看

- Connectors 自定义 MCP 引导。
- 积分消费说明。
- 总经理视图引导。
- 设置中增加“重新查看引导”入口。

## 9. 验收标准

- 新用户首次进入 `/home` 能在不阅读文档的情况下理解如何开始一个任务。
- 用户第一次打开附件菜单时能区分本地文件、云端资料、Skills 的用途。
- 用户第一次打开连接器菜单时能理解“启用本次任务”和“管理授权”的区别。
- 用户第一次进入项目页时能理解项目、经理、员工、任务、交付文档的层级关系。
- 引导可跳过、可关闭、可回看，不阻断核心任务执行。
- 所有气泡文案在 1440px 桌面和移动端都不遮挡主要操作。
- 不出现营销式欢迎页、全屏大插画、不可关闭弹窗。

## 10. 暂不纳入本方案

- 不设计代码实现细节。
- 不改动现有页面布局。
- 不设计新手任务模板库。
- 不设计后端埋点表结构。
- 不处理管理后台蒙层引导。
