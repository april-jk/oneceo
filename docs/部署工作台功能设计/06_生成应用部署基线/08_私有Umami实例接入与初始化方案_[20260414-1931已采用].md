# 08 私有 Umami 实例接入与初始化方案 [20260414-1931已采用]

## 1. 目标

把 `https://analytics.oneceo.ai` 这套自托管 Umami 纳入 OneCEO 的平台标准能力，并满足以下要求：

1. 主站生产流量和开发流量分开。
2. 生成应用后可以由平台自动创建统计站点，不需要 agent 自己管理统计后台。
3. OneCEO 平台只保存一组受控的 Umami 集成配置，不把统计供应商选择权下放到每个项目。
4. 后续可以在部署工作台直接展示真实的网站访问数据。

## 2. 当前实例盘点

基于 2026-04-14 对 `analytics.oneceo.ai` 的实际检查：

1. 当前只有 1 个 Umami 用户：`admin`
2. 当前还没有 team
3. 当前已有 1 个 website：
   - 名称：`oneceo`
   - 域名：`oneceo.ai`
   - 挂在 `admin` 名下
4. 当前该 website 没有历史统计数据：
   - `pageviews = 0`
   - `visitors = 0`
   - `visits = 0`

因此当前实例处于可整理状态，适合直接收敛成 OneCEO 的标准组织结构。

## 3. 推荐组织结构

### 3.1 Team

创建两个平台级 team：

1. `OneCEO Platform`
2. `OneCEO Deployment`

组织边界固定如下：

1. `OneCEO Platform`
   - 只承载 OneCEO 自身系列网站
   - 当前至少包括：
     - `oneceo.ai`
     - `dev.oneceo.ai`
2. `OneCEO Deployment`
   - 只承载平台为用户生成并发布的部署网站
   - 包括 Railway 随机域名、自定义绑定域名和后续正式发布域名
   - 不承载 OneCEO 自身站点

### 3.2 平台集成用户

创建一个专门给 OneCEO 平台后端使用的 Umami 用户：

- Username：`oneceo-analytics`
- Role：`user`

再把该用户加入两个 team，角色都设为：

- `team-manager`

原因：

1. 平台后端不应长期直接使用 `admin`
2. `admin` 只保留为实例管理账户
3. 日常 website 创建、查询、统计读取都走 `oneceo-analytics`

## 4. Website 分层规则

### 4.1 现在就落地的 website

当前实例应至少在 `OneCEO Platform` team 下保留两个 website：

1. `OneCEO Main`
   - domain: `oneceo.ai`
   - 用途：主站生产环境

2. `OneCEO Dev`
   - domain: `dev.oneceo.ai`
   - 用途：开发环境 / 预发布主环境

### 4.2 暂时不预创建的网站

以下 website 不建议现在人工批量预建：

1. 各个生成应用的网站
2. 各个预览部署的网站

正确方式是：

- 由平台在“首次成功部署”时自动创建对应 Umami website
- 再把返回的 `websiteId` 回写到 OneCEO 自己的部署记录和环境变量注入链路里
- 创建位置固定为 `OneCEO Deployment` team

### 4.3 不建议创建的 website

不建议把以下域名作为业务 website 创建：

1. `analytics.oneceo.ai`

原因：

- 它是 Umami 自己的后台域名，不是 OneCEO 产品本身的业务站点
- 跟踪它没有业务价值，反而会污染统计

## 5. 生成应用的自动创建规则

平台后端在首次成功部署时执行：

1. 判断该应用是否已绑定 `umamiWebsiteId`
2. 如果没有：
   - 调 Umami API `POST /api/websites`
   - name 按平台规则生成
   - domain 使用该应用最终公开域名
   - teamId 固定指向 `OneCEO Deployment`
3. 创建成功后保存：
   - `umamiWebsiteId`
   - `umamiHost`
   - `boundDomain`
   - `createdAt`
4. 在环境变量注入阶段写入：
   - `VITE_ANALYTICS_ENABLED=true`
   - `VITE_ANALYTICS_HOST=https://analytics.oneceo.ai`
   - `VITE_ANALYTICS_WEBSITE_ID=<websiteId>`
   - `VITE_ANALYTICS_TAG=prod`

## 6. OneCEO 平台应该保存的配置

平台级配置应保存：

- `UMAMI_HOST_URL=https://analytics.oneceo.ai`
- `UMAMI_USERNAME=oneceo-analytics`
- `UMAMI_PASSWORD=<由平台安全存储>`
- `UMAMI_PLATFORM_TEAM_ID=<OneCEO Platform 的 teamId>`
- `UMAMI_DEPLOYMENT_TEAM_ID=<OneCEO Deployment 的 teamId>`

注意：

1. 不建议在代码仓库保存密码
2. 不建议把 `admin` 账号写入平台生产配置
3. 平台不再使用单一 `UMAMI_TEAM_ID` 混挂所有 website
4. 平台应在运行时获取 token，而不是长期缓存 bearer token

## 7. 前端模板如何使用

生成应用前端统一使用平台注入，不让 agent 自己决定：

```html
<script
  defer
  src="%VITE_ANALYTICS_HOST%/script.js"
  data-website-id="%VITE_ANALYTICS_WEBSITE_ID%"
  data-domains="%VITE_PUBLIC_DOMAIN%"
  data-tag="%VITE_ANALYTICS_TAG%"
  data-do-not-track="true"
  data-exclude-search="true"
  data-performance="true"
></script>
```

规则：

1. `websiteId` 来自平台绑定结果
2. `domains` 来自当前实际部署域名
3. 开发环境和生产环境使用不同 websiteId
4. 生成应用不允许硬编码 Umami 地址

## 8. 平台后端如何使用

平台后端至少需要三类能力：

### 8.1 鉴权

- `POST /api/auth/login`
- 获取 bearer token

### 8.2 Website 管理

- `GET /api/websites`
- `POST /api/websites`
- `POST /api/websites/:websiteId`

### 8.3 统计读取

- `GET /api/websites/:websiteId/stats`
- `GET /api/websites/:websiteId/pageviews`
- `GET /api/websites/:websiteId/metrics`
- `GET /api/realtime/:websiteId`

## 9. 部署工作台的展示边界

部署工作台未来接入 Umami 后，建议这样分层：

### 9.1 站点数据

显示：

- pageviews
- visits
- visitors
- top pages
- referrers
- countries
- devices
- realtime

### 9.2 用户统计

不要完全依赖 Umami。

平台自己的“用户统计”仍应保留在 OneCEO 自己的数据库模型里，包括：

- app user 身份
- 登录用户行为
- agent 会话归属
- 任务创建与部署归属

Umami 只负责“网站被访问了什么”，不负责“平台内部业务主数据”。

## 10. 本次初始化的目标状态

本次在 `analytics.oneceo.ai` 上完成以下目标：

1. 创建 team：`OneCEO Platform`
2. 创建 team：`OneCEO Deployment`
3. 创建集成用户：`oneceo-analytics`
4. 把该用户加入两个 team，角色都为 `team-manager`
5. 清理空的旧 website `oneceo.ai`
6. 在 `OneCEO Platform` team 下创建：
   - `OneCEO Main` -> `oneceo.ai`
   - `OneCEO Dev` -> `dev.oneceo.ai`
7. 后续生成应用 website 统一进入 `OneCEO Deployment`
8. 记录返回的 `teamId`、`websiteId`

## 11. 后续代码接入顺序

推荐按这个顺序做：

1. 先在 OneCEO 后端加 Umami connector
2. 再在部署成功后自动创建 website
3. 再把 `websiteId` 注入生成应用模板
4. 最后把部署工作台“站点数据”接到 Umami API

## 12. 验收标准

满足以下条件才算接入完成：

1. `analytics.oneceo.ai` 上已有 `OneCEO Platform` team
2. `analytics.oneceo.ai` 上已有 `OneCEO Deployment` team
3. `oneceo-analytics` 可单独登录
4. `OneCEO Main` / `OneCEO Dev` 已存在，并且只归属 `OneCEO Platform`
5. 平台可以用非 admin 账号读取两个 team 下网站统计
6. 生成应用后可自动拿到 `websiteId`，并且 website 只创建在 `OneCEO Deployment`
