# 会话标题首条消息锁定设计

## 1. 背景

task creation / sandbox 直通会话的标题需要同时满足两个要求：

- 用户发送消息时即可确定标题，不能等到智能体回复后才更新。
- 标题一旦确定，后续多轮对话不能频繁改名。

旧方案只在“首次明确对话”时锁定标题，会导致“你好”“在吗”等非明确指令会话继续显示占位标题。当前采用的新规则是：首条有效用户消息立即确定标题；如果没有明确指令，则使用首条消息前 24 个字符作为稳定标题。

## 2. 目标

- 任意非空首条用户消息都会在发送阶段得到稳定标题。
- 明确任务类消息继续走规则提炼，例如 `帮我开发2048小游戏，使用html实现` 提炼为 `HTML 2048 小游戏`。
- 非明确消息直接取归一化文本前 24 个字符，例如 `你好` 标题即为 `你好`。
- 标题锁定后，后续自动逻辑不再覆盖。
- OpenCode / Codex / Altus 统一遵守同一套后端标题策略。

## 3. 数据模型

标题状态继续保存在 file memory session，并同步到 DB `task_creation_sessions.metadata_json`：

- `title`
- `titleLocked`
- `titleSource`
- `titleState`
- `titleResolvedAt`

`titleSource` 当前含义：

- `placeholder`：占位标题。
- `first_user_input`：由首条有效用户消息锁定。
- `first_explicit_user_input`：旧数据兼容来源。
- `task_description` / `clarification_summary`：由任务描述或澄清摘要产生。
- `manual`：用户手动重命名。

## 4. 行为流程

### 4.1 新建会话

- 新会话先以占位标题创建，避免创建阶段把未处理的原文误当最终标题。
- 如果创建接口携带首条消息，后端立即用统一标题策略生成标题并锁定。
- 创建接口返回的 session summary 必须已经包含最新标题，前端收到后立即派发 `task-creation-session-updated` 更新侧边栏。

### 4.2 发送用户消息

每次发送用户消息时：

1. 后端读取当前 session 标题状态。
2. 如果 `titleLocked=true`，跳过自动标题更新。
3. 如果仍是占位标题，用当前用户消息生成标题。
4. 明确任务类消息走规则提炼；非明确消息取前 24 个字符。
5. 更新 `title/titleLocked/titleSource/titleState/titleResolvedAt`，并同步 DB metadata。

### 4.3 展示与列表

- `toSessionSummary`、会话列表、搜索、轻量 DB session 构造统一调用 `resolveDisplaySessionTitle()`。
- DB metadata 与 file memory 均保存标题状态，避免刷新、缓存命中、列表查询出现标题状态分叉。
- 前端只负责展示和派发更新事件，不再自行判断标题业务规则。

## 5. 实现落点

- `apps/api/src/services/task-session-title-service.ts`
  - 统一标题策略、占位识别、标题展示解析。
- `apps/api/src/routes/task-creation-routes.ts`
  - `POST /sessions/draft`、`POST /sessions`、`POST /sessions/:sessionId/title/resolve` 使用统一策略。
- `apps/api/src/agents/task-creation/websocket-service.ts`
  - WebSocket `user_input` 持久化后立即锁定标题。
- `apps/api/src/agents/task-creation/file-memory-store.ts`
  - `updateSessionTitle()` 同步写入 DB metadata 的完整标题状态。
- `apps/api/src/db/dao/task-creation-session.dao.ts`
  - 从 DB metadata 装饰出 `title/titleLocked/titleSource/titleState/titleResolvedAt`。
- `apps/web/client/src/hooks/useTaskCreationAgent.ts`
  - 创建接口返回标题后立即更新侧边栏。
  - 非空消息均允许调用标题 resolve。

## 6. 验收用例

### 用例 1

输入：

- `你好`

预期：

- 发送后立即锁定标题为 `你好`。
- 不等待智能体回复。

### 用例 2

输入：

- `帮我开发2048小游戏，使用html实现`

预期：

- 发送后立即锁定标题为 `HTML 2048 小游戏`。

### 用例 3

输入：

- `你好`
- `帮我开发2048小游戏，使用html实现`

预期：

- 第一轮标题为 `你好`。
- 第二轮不会自动改成 `HTML 2048 小游戏`，除非用户手动重命名。
