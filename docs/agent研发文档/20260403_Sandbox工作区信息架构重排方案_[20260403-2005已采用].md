# 20260403 Sandbox 工作区信息架构重排方案 [20260403-2005已采用]

更新时间：2026-04-03

## 1. 背景

当前 `apps/admin_management` 的 Sandbox 工作区已经具备运行态总览、风险队列、Runtime 列表和手工创建入口，但实际首屏存在以下问题：

1. Sandbox 同时出现在 `KVM 管理` 和 `执行环境管理` 两个入口下，导航边界不清
2. 总览指标、工作区切换、主表、风险队列、新建 Runtime 同屏堆叠，首屏优先级混乱
3. 风险队列按实例平铺，重复项过多，管理员无法先判断“哪类问题最值得处理”
4. 主表缺少面向排障的筛选、搜索和排序，长 ID 与长模板名导致扫读成本高

## 2. 重排目标

本轮只做 Sandbox 工作区的信息架构重排，不扩展新的业务动作。

目标：

1. 让管理员进入首屏后先判断“系统是否健康”
2. 再判断“哪类风险最紧急”
3. 最后进入具体 Runtime 列表和详情处理
4. 降低重复信息和长文本对首屏注意力的争抢

## 3. 页面结构

### 3.1 一级定位

建议把 Sandbox 工作区从 `KVM 管理` 的二级切换中移出，归入独立的 `执行环境管理`。

原因：

1. Sandbox 的治理维度已经不只是 VM/KVM 资源，还包括 task session、archive、OSAC、executor connectivity
2. 把 Sandbox 挂在 KVM 下，会误导管理员把它理解成 KVM 的附属资源页
3. 当前侧边栏已存在 `执行环境管理`，继续保留 `KVM > Sandbox` 属于重复入口

## 4. 首屏布局

建议首屏改成三段式：

### 4.1 健康总览区

展示：

1. 总环境
2. 运行中
3. 待归档
4. 风险项
5. 当前服务状态

当前实现要求：

1. 只放健康判断所需的聚合指标
2. 不在该区域混入工作区说明文案和次级操作

### 4.2 风险聚合区

把当前“风险队列”从实例平铺改成按风险类型聚合：

1. `inactive_but_running`
2. `missing_osac_endpoint`
3. `missing_opencode_base_url`
4. 其他风险

每类展示：

1. 风险名
2. 受影响实例数
3. 最近出现时间
4. 进入实例列表按钮

这样管理员先判断“处理哪一类”，再进入具体实例。

### 4.3 Runtime 列表区

主表保留，但首屏只承担“定位目标实例”的职责。

建议默认列：

1. Task Session
2. Sandbox
3. Executor
4. 状态
5. 风险摘要
6. 最近活跃
7. 操作

以下信息降级到详情或次级行：

1. 模板全名
2. archive 文本枚举
3. 事件来源文案

## 5. 交互规则

### 5.1 风险优先

列表默认排序：

1. 有风险优先
2. 风险数量多优先
3. 最近活跃优先

### 5.2 首屏筛选

首屏必须补齐：

1. `sessionId / sandboxId` 搜索
2. executor 筛选
3. 状态筛选
4. 风险标签筛选
5. 明确显示“已加载 N 条 / 当前筛选命中 M 条”，避免管理员误判列表是否已完整展开

首屏列表加载约束：

1. 首屏默认只加载当前工作区排障所需的 Runtime 数量
2. 不允许为了“可能的后续浏览”在首屏默认放大到明显高于当前展示需求的取数规模
3. 需要查看更多历史 Runtime 时，使用显式“查看更多 Runtime”二段加载，而不是回退到隐式首屏大批量加载
4. “查看更多 Runtime”是否显示，必须由服务端明确返回是否仍有更多记录，前端不允许仅依赖 `当前条数 >= limit` 推断

### 5.3 长文本处理

1. 长 ID 默认截断显示
2. 提供复制按钮
3. 风险标签默认只展示前 2 个，剩余显示 `+N`
4. 模板名放次级行，避免主信息列被模板名挤占

### 5.4 工作区切换加载

`执行环境管理` 的一级工作区切换必须遵循“进入即加载当前工作区数据”的规则：

1. 切到 `总览` 或 `运行环境` 时，立即加载 Sandbox 概览与 Runtime Registry
2. 切到 `模板` 时，立即加载模板列表与模板治理所需数据
3. 不允许切到 `模板` 后继续沿用 Runtime 列表请求，导致页面先空白再依赖自动刷新补数据
4. 自动刷新只作为兜底更新机制，不能替代首次进入工作区时的即时加载

## 6. 次级操作区

“新建 Runtime”不再和风险区并列占首屏主注意力，当前实现为：

1. `Sandbox 工作区` 顶部右侧提供 `新建 Runtime` 主按钮
2. 点击后从右侧拉出抽屉承载创建表单
3. 创建成功后自动关闭抽屉并刷新 Runtime 列表

这样处理的原因：

1. 新建是低频动作
2. 风险排障和运行态观测是高频动作
3. 低频动作不应与高频决策区抢首屏位置

## 7. 详情面板要求

详情面板打开后，信息顺序建议固定为：

1. 基本身份信息
2. 当前运行状态
3. 风险与恢复建议
4. 连接性检查
5. 文件/进程/端口等调试能力

禁止在详情首屏混入过多原始 JSON，原始数据应折叠到调试区。

## 8. 验收标准

1. 管理员在 5 秒内能判断平台当前是否健康
2. 管理员在 10 秒内能确定最优先处理的风险类型
3. 管理员在 15 秒内能通过筛选或搜索定位到指定 Runtime
4. 首屏不再同时出现重复导航语义和低频创建操作抢占主视觉
