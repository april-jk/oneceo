# 20260418_部署工具模板修复循环终止测试方案 [20260418-1558已采用]

## 1. 目标

验证 `public/index.html` 形态项目在完成 OneCEO analytics bootstrap 注入后，模板合规检查能够正确识别注入结果，不再持续返回 `missing_analytics_entry`。

## 2. 覆盖范围

- `apps/api/src/services/deployment-template-bootstrap-service.ts`
- `apps/api/src/services/template-compliance-service.ts`
- `apps/api/src/services/task-creation-deployment-source-service.ts`

## 3. 用例

### 用例 1：`public/index.html` 项目注入后应判定为合规

构造工作区：

- `package.json`
- `server.js`
- `oneceo.manifest.json`
- `public/index.html`

执行：

1. `ensureDeploymentTemplateBootstrap(workspace)`
2. `ensureTemplateCompliance(workspace)`
3. `buildDeploymentTemplateBaseline(...)`

断言：

- `bootstrap.analyticsInjected === true`
- `compliance.checks.analyticsEntryDetected === true`
- `compliance.ok === true`
- `baseline.status === "ready"`

### 用例 2：根静态项目基线不回归

继续保留已有 `index.html` 根静态项目测试，确认本次入口收敛不会破坏原有路径。

### 用例 3：`client/index.html` 项目基线不回归

继续保留已有 `client/index.html` 项目测试，确认 Vite 风格入口仍能正常通过。

## 4. 执行命令

```bash
pnpm --filter api exec tsx --test tests/deployment-template-bootstrap-service.test.ts tests/deployment-template-baseline-service.test.ts
pnpm --filter api type-check
```

## 5. 通过标准

满足以下条件即可通过：

1. 新增 `public/index.html` 回归测试通过
2. 原有部署基线测试全部通过
3. API type-check 通过
