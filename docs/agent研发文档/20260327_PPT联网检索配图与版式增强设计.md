# 20260327 PPT 联网检索、配图与版式增强设计

## 1. 背景

用户反馈当前生成的 PPT 存在两个明显问题：

- 只有文字，没有图片
- 页面结构接近普通提纲，不像正式商务演示文稿

这说明问题不在单一 skill 文案，而在执行链路本身缺少“联网检索 -> 内容抽取 -> 图片落盘 -> 受控版式生成”的能力。

## 2. 根因

### 2.1 原有 PPT skill 只是 brief

`apps/web/client/src/lib/skill-attachment-templates.ts` 中的 `PPT 办公` 本质上是一个 skill brief，能约束模型思路，但不能直接提供联网检索、图片下载和版式生成能力。

### 2.2 Altus managed 工具集缺少联网能力

在本设计提出时，Altus managed 只有：

- `shell_execute`
- `read_file`
- `write_file`
- `list_directory`
- `search_code`
- `ask_user`
- `complete_task`

没有 `web_search`、`web_extract` 这类联网工具，因此模型无法稳定补外部事实和候选图片。

### 2.3 文档类任务默认被约束为“简单且正确”

此前为了保证办公文件可交付，prompt 已明确偏向“先做出正确文件”。这对稳定性是必要的，但如果没有补上联网和视觉素材能力，结果就会自然退化为纯文本 PPT。

## 3. 最短正确方案

### 3.1 新增 Tavily connector

新增：

- `apps/api/src/connectors/tavily-connector.ts`

职责：

- 封装 Tavily Search API
- 封装 Tavily Extract API
- 统一管理超时、错误和结果归一化

### 3.2 给 Altus managed 暴露联网工具

新增 managed tools：

- `web_search`
- `web_extract`

并在 runtime 中接入 Tavily connector，让 run 内可以直接检索和抽取外部资料。

### 3.3 图片下载不新增专用工具

本轮不新增独立下载工具，继续复用 `shell_execute`：

1. `web_search` 找候选结果和图片 URL
2. `web_extract` 获取正文和可用图片
3. `shell_execute` 在 sandbox 内把选中的图片下载到 workspace
4. `python-pptx` 或其他本地脚本将图片插入 `.pptx`

### 3.4 强制使用受控页面原型

PPT 页面不允许自由堆字，必须优先使用固定原型，例如：

- `cover_hero`
- `agenda`
- `section_divider`
- `two_column_text_image`
- `three_card_comparison`
- `chart_focus`
- `summary_next_step`

并至少满足：

- 1 页封面视觉页
- 2 页以上带图片、图表或卡片结构的内容页

### 3.5 收紧 completion 约束

文件生成并完成一次验证后，应立刻 `complete_task`，避免把轮次浪费在可选检查和重复试错上。

## 4. 不做什么

- 不新增 Connector Center UI
- 不引入通用浏览器自动化或 computer tool
- 不做 AI 绘图服务接入
- 不做 Office 模板市场
- 不做兼容性补丁或降级方案

## 5. 验证标准

### 5.1 功能验证

输入：

- `帮我生成一份职业规划 PPT`

预期：

- run 中出现 `web_search`
- 至少有 1 张封面图下载到 workspace
- 生成的 `.pptx` 可下载
- PPT 不再是纯文本页

### 5.2 结构验证

最终 PPT 至少满足：

- 1 页封面图
- 1 页目录
- 2 页以上图文或图表页
- 1 页总结

- Tavily connector 接入

- PPT skill 模板新增联网短链路与稳定导入约束
- managed prompt 收紧为 bounded workflow
- managed 默认轮次预算提升到 `32`
