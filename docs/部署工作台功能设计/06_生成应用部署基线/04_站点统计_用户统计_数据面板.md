# 站点统计、用户统计与数据面板设计 [尚未采用]

## 1. 目标

这份文档专门回答：

- 站点统计看什么
- 用户统计看什么
- 这些数据如何支撑部署工作台

它直接服务于现有文档 [../02_仪表盘/02_站点数据.md](../02_仪表盘/02_站点数据.md)。

## 2. 数据分层

建议把工作台里看到的数据拆成三层：

1. 站点流量数据
2. 用户行为数据
3. 运行质量数据

## 3. 站点流量数据

站点流量数据用于回答“网站有没有被访问、怎么被访问”。

第一阶段建议默认支持：

- 页面浏览量 `pageViews`
- 访问次数 `visits`
- 唯一访客 `uniqueVisitors`
- 平均会话时长 `avgSessionDuration`
- 跳出率 `bounceRate`
- 热门页面 `topPages`
- 引荐来源 `topReferrers`
- 地区分布 `geoBreakdown`
- 设备分布 `deviceBreakdown`

这与当前“站点数据”页签里的占位结构完全对齐。

## 4. 用户统计

用户统计用于回答“这个应用有没有真实用户、用户有没有持续使用”。

第一阶段建议默认支持：

- 新注册用户数 `newUsers`
- 登录用户数 `signedInUsers`
- 日活 `dau`
- 周活 `wau`
- 月活 `mau`
- 回访用户数 `returningUsers`
- 注册转化率 `signupConversionRate`
- 登录转化率 `signinConversionRate`

注意：

- 只有应用启用 OneCEO 用户态身份时，才展示这些指标。
- 未启用身份体系的应用，不伪造用户统计，明确显示“不适用”。

## 5. 运行质量数据

运行质量数据用于回答“网站上线后是不是稳定”。

建议第一阶段默认支持：

- 客户端错误次数
- API 错误次数
- 失败请求率
- 最近错误事件

它们可以不必直接放在“站点数据”主视图中，但应作为后续仪表盘扩展接口预留。

## 6. 事件模型

## 6.1 站点事件

默认事件：

- `page_view`
- `route_change`
- `cta_click`
- `form_submit`

## 6.2 用户事件

默认事件：

- `identify_user`
- `signup_success`
- `login_success`
- `logout`

## 6.3 业务事件

保留一个统一通道：

- `business_event`

要求：

- 业务事件名必须是稳定字符串
- 业务字段必须可序列化
- 不允许直接写入敏感原文

## 7. 建议的数据表

第一阶段建议至少有以下聚合模型：

### 7.1 原始事件表

- `app_analytics_events`

字段建议：

- `id`
- `site_id`
- `deployment_id`
- `visitor_id`
- `session_id`
- `user_id`
- `event_name`
- `path`
- `properties_json`
- `occurred_at`

### 7.2 会话表

- `app_analytics_sessions`

字段建议：

- `session_id`
- `site_id`
- `visitor_id`
- `started_at`
- `ended_at`
- `entry_path`
- `exit_path`
- `page_view_count`
- `duration_seconds`
- `bounce`

### 7.3 日聚合表

- `app_site_daily_metrics`
- `app_user_daily_metrics`

作用：

- 工作台优先读聚合表
- 只有明细钻取时再回查原始事件

## 8. 部署工作台接口建议

## 8.1 站点统计总览接口

建议新增：

- `GET /api/task-creation/sessions/:sessionId/deployment/site-analytics`

返回：

- `siteSummary`
- `trafficMetrics`
- `topPages`
- `topReferrers`
- `geoBreakdown`
- `deviceBreakdown`
- `accessPolicy`

## 8.2 用户统计接口

建议新增：

- `GET /api/task-creation/sessions/:sessionId/deployment/user-stats`

返回：

- `newUsers`
- `signedInUsers`
- `dau`
- `wau`
- `mau`
- `returningUsers`
- `conversion`

## 8.3 时间范围

第一阶段只需要支持：

- `24h`
- `7d`
- `30d`

不在第一阶段引入更复杂的 cohort、漏斗、对比分析。

## 9. UI 映射

## 9.1 仪表盘 / 站点数据

直接使用：

- 顶部站点头部信息
- 公开状态卡
- 时间范围选择
- 指标卡
- 热门页面
- 引荐来源
- 地区
- 设备

## 9.2 发布与访问

建议补两个轻量指标：

- 最近 24 小时访问数
- 最近 24 小时错误数

作用：

- 让用户在“发布成功”之后立即知道这个版本有没有被真实访问、有没有明显异常。

## 10. 空态与真实性规则

必须遵守：

- 没有数据就显示“没有数据”
- 没启用用户态就显示“不适用”
- 不允许用 deployment 次数充当访问数
- 不允许用匿名 visitor 伪装成真实 user

## 11. 当前建议的审查点

- 是否同意把“站点统计”和“用户统计”拆成两类数据模型。
- 是否同意第一阶段只做天级聚合，不做更重的分析产品能力。
- 是否同意工作台先补两个只读接口，而不是先做复杂配置页。
