## 4. 测试单元清单

### 单元 A：评测 run 初始化

- 输入：采用的题库 seed + smoke 模式
- 预期输出：生成标准 run 目录与 manifest
- 验证方式：检查 `run_manifest.json`、`case_results.jsonl`、`summary.md`

### 单元 B：当前 Altus 服务可连接

- 输入：`http://localhost:4000`
- 预期输出：健康检查可用，WebSocket 可建立
- 验证方式：`/health` 返回 200，实际执行至少一题

### 单元 C：单题执行证据可回收

- 输入：某个 smoke case
- 预期输出：能获得 session/run/messages/workspace 等至少一种硬证据
- 验证方式：结果目录写入 `evidence_refs`

### 单元 D：评分结果可回写

- 输入：case 原始证据
- 预期输出：`case_results.jsonl` 中写入状态、分数、判定
- 验证方式：finalize 后 summary 与明细一致

## 5. 边界与失败条件

### 5.1 阻塞条件

以下情况允许记为 `blocked`：

1. 当前 Altus 服务未启动
2. 题目依赖真实外部部署，但当前环境不具备安全执行条件
3. 当前接口无法稳定拿到评分所需的最小证据

### 5.2 硬失败条件

按照 adopted 评分标准执行，不在本文件重复定义。

## 6. 执行方式

1. 用 `apps/api/scripts/altus-eval/init-run.ts` 初始化 smoke run
2. 逐题调用当前 Altus 服务
3. 收集消息、run、workspace、tool call 等证据
4. 人工按评分标准写入 `case_results.jsonl`
5. 用 `apps/api/scripts/altus-eval/finalize-run.ts` 生成最终汇总

## 7. 输出要求

最终输出必须包含：

1. 实际 run 目录
2. smoke 总分
3. 通过/失败/阻塞数量
4. 每题简要结论
5. 主要风险与阻塞项
