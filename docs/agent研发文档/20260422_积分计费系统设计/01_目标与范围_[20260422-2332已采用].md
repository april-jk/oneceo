# 01 目标与范围 [20260422-2332已采用]

## 1. 背景

当前 oneceo 的身份体系已完善（app_users），但存在计费缺口：

1. LLM 调用仅透传 usage 信息，不做持久化记录
2. 用户端无任何余额/积分概念
3. 管理后台无计费管理能力
4. 需求：对标 Manus 的积分计费模式

## 2. 本次目标

### 2.1 必须实现

1. 新增用户积分余额表与交易记录表
2. 新增 Token 使用明细表
3. 新增模型定价配置表
4. 会话创建前强制校验余额
5. LLM 调用后按 token 消耗扣减积分
6. 用户端 Header 显示剩余积分
7. 会话界面显示当前会话积分消耗
8. 设置菜单中显示历史消费明细
9. 管理后台新增「计费管理」页面

### 2.2 本次不做

1. 不做充值支付流程（仅预留接口与手动调整）
2. 不做订阅制/会员等级
3. 不做欠费运行模式
4. 不做自动充值提醒
5. 不做除 token 外的其他计费维度（如 sandbox 时长、存储空间）

## 3. 角色定义

### 3.1 普通用户

能力：

1. 查看当前积分余额
2. 查看历史消费记录
3. 查看单个会话的积分消耗
4. 余额充足时发起新会话

限制：

1. 余额不足时无法创建新会话
2. 消费记录只读，不可删除

### 3.2 管理员

能力：

1. 查看所有用户积分余额
2. 手动增加用户积分（当前仅支持大于 0 的整数增加；直接扣减需单独设计交易类型与审计规则）
3. 配置模型定价（输入/输出单价）
4. 查看平台级统计（总消耗、Top 用户等）
5. 查看 Token 使用明细日志

## 4. 技术边界

### 4.1 积分精度

- 使用整数积分，避免浮点精度问题
- 最小单位：1 积分
- 换算：按每 1k tokens 定价，不足 1k 按实际比例计算后向上取整

### 4.2 并发安全

- 积分扣减使用数据库原子操作（行锁或 CAS）
- 不允许并发扣费导致余额为负

### 4.3 定价变更

- 新定价生效后，后续调用使用新价格
- 历史记录保留定价快照，确保数据一致性
