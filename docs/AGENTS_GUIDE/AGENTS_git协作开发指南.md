# AGENTS Git 协作开发指南

本文用于指导协作成员在 `oneceo/` 仓库内进行稳定、可追溯的 Git 协作开发。

## 基本约定

- 每次功能阶段完成或关键测试通过后必须提交代码。

- 不要在未确认归属的目录中跨系统修改（遵循 `oneceo/AGENTS.md` 目录边界）。

- 大范围改动请分阶段提交，避免一次性混入多个主题。

- 提交时，必须使用中文，禁止使用仅英文或无法体现语义的提交描述。

- 提交信息必须明确写清本次做了什么修复或修改，不能只写笼统词语。

- 提交信息必须说明本次修改的目的，确保后续可以追溯“为什么做这次变更”。

- 提交信息必须注明提交类型，至少包含以下类型之一：`新功能`、`修复`、`重构`、`文档`、`测试`、`构建`、`杂项`。

- 推荐提交格式：`[提交类型] 修改内容；修改目的`。

- 提交示例：
  - `[修复] 修正 task creation 接口重复写入问题；避免任务创建后出现重复消息`
  - `[新功能] 新增 sandbox 生命周期状态上报；便于前端展示运行中的真实状态`
  - `[文档] 更新 Git 提交约束说明；统一团队提交信息规范`

  

## 常用分支策略

- 默认使用当前团队约定分支（如 `task-creation-agent`）。
- 功能开发建议新建主题分支：`feature/<topic>`。
- 修复问题建议使用：`fix/<issue>`。

## 提交规范

- 提交类型使用中文语义标签，不使用 `feat:`、`fix:`、`docs:` 这类英文前缀作为最终提交信息格式。
- 单条提交信息至少应包含三部分：提交类型、修改内容、修改目的。
- 推荐统一写法：`[提交类型] 修改内容；修改目的`。

示例：
- `[修复] 修复 SSE 调试预览状态未持久化问题；避免页面刷新后丢失调试上下文`
- `[文档] 更新 AGENTS Git 协作开发指南；统一仓库提交说明格式`

## 审查与合并

- 合并前优先自测（本地 + 基本流程）。
- 如涉及 sandbox / opencode / sse 等链路，请附上验证步骤或日志位置。

## 与 AGENTS.md 的关系

- 详细项目结构、服务启动方式、E2B 规则等请参见 `AGENTS.md`。
- 新成员进场必读：`AGENTS.md` + `docs/AGENTS_GUIDE/*`。
