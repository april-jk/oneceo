# 20260418 Altus 默认接管设置修复方案 [20260418-0148已采用]

更新时间：2026-04-18 01:48

## 1. 背景

当前 `设置 -> 模型设置` 中虽然提供了：

1. `sandbox 直通`
2. `Altus 接管对话`

但前端多处代码对 `localStorage.altus_mode` 的缺省值处理并不一致：

1. `SettingsDialog.tsx` 初始状态默认成了 `sandbox`
2. `Home.tsx` 在本地没有设置值时回落到 `sandbox`
3. `TaskCreationChat.tsx` 在本地没有设置值时回落到 `sandbox`
4. `useTaskCreationAgent.ts` 在读不到值时甚至会主动写回 `sandbox`

这会导致“新用户未显式设置过模式”时，实际默认链路不是 Altus 接管，而是直通模式。

## 2. 修复目标

1. 新用户首次进入时，默认模式必须是 `Altus 接管对话`
2. 缺省值逻辑必须统一，不能在不同页面各自回退到不同模式
3. 已明确切到 `sandbox` 的用户，行为必须保留
4. 非法值、空值、缺省值都统一纠正为 `managed`

## 3. 修复方案

### 3.1 统一读取入口

新增前端共享模块：

1. `apps/web/client/src/lib/altus-settings.ts`

模块职责：

1. 统一声明 `ALTUS_MODE_STORAGE_KEY`
2. 统一声明默认值 `managed`
3. 统一处理：
   - 无值
   - 非法值
   - 读写异常兜底

### 3.2 统一消费点

以下位置全部改为复用共享读取逻辑：

1. `apps/web/client/src/components/SettingsDialog.tsx`
2. `apps/web/client/src/pages/Home.tsx`
3. `apps/web/client/src/components/TaskCreationChat.tsx`
4. `apps/web/client/src/hooks/useTaskCreationAgent.ts`

要求：

1. 任何新入口都不能再手写 `altus_mode === managed ? managed : sandbox`
2. 任何缺省初始化都不能再把值写成 `sandbox`

## 4. 验收标准

1. 浏览器本地不存在 `altus_mode` 时，首次读取结果为 `managed`
2. 首次读取后，`localStorage.altus_mode` 会被规范化写成 `managed`
3. 已显式设置为 `sandbox` 的用户仍保持 `sandbox`
4. `SettingsDialog` 初次打开时，“Altus 接管对话”为默认选中项
5. 首页和任务创建对话发送消息时，缺省链路按 `managed` 执行

## 5. 测试

新增单测：

1. `apps/web/client/src/tests/altus-settings.test.ts`

覆盖：

1. 缺省值写入 `managed`
2. 非法值纠正为 `managed`
3. 显式 `sandbox` 保持不变
