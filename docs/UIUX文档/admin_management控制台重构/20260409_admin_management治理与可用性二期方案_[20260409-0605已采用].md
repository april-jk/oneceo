# 2026-04-09 admin_management 治理与可用性二期方案 [20260409-0605已采用]

## 1. 背景

在 `20260405_admin_management控制台整站重构方案_[20260405-2329已采用].md` 与 `20260406_5174对话管理UI优化方案_[20260406-1836已采用].md` 落地后，`apps/admin_management` 已具备统一控制台骨架，但当前仍存在以下问题：

1. `Sandbox 模板` 缺少模板别名设置闭环。
2. `别名检测` 以独立卡片存在，脱离模板主工作流。
3. 全局缺少统一的等待遮罩、失败弹窗与稳定的异步反馈。
4. 默认首页仍落在 `KVM 管理`，与当前实际值班重点不符。
5. 页面与导航中仍残留 `水位` 等抽象词。
6. `对话管理`、`审计日志`、`智能体管理`、`技能管理` 仍存在信息架构与可用性优化空间。

## 2. 本轮目标

1. 管理后台默认进入 `Sandbox 管理`。
2. 所有关键异步动作具备统一加载遮罩与右上角 toast 反馈。
3. `Sandbox 模板` 支持在详情中设置别名，并把别名检测收敛为辅助校验动作。
4. `审计日志` 支持详细筛选与详情查看。
5. `智能体管理` 的任务阶段分布中文化，并能输出更细信息。
6. `技能管理` 的二级菜单与工作区尽量中文化，并让二级菜单保持居中、紧凑、可扫读。
7. 对 `对话管理` 做真实可用性审阅后收敛无效项、补强高价值项，并改善响应。

## 3. 范围

### 3.1 包含

1. `apps/admin_management/web`
2. `apps/admin_management/server`
3. `docs/UIUX文档/admin_management控制台重构`
4. `docs/单元测试文档`
5. `.note/` 本轮工作日志

### 3.2 不包含

1. `apps/web`
2. `apps/api` 主业务实现（仅依赖现有管理端可访问接口）
3. KVM 主流程协议改造

## 4. 方案总览

### 4.1 全局交互壳

1. 增加全局阻塞遮罩：用于 `查看`、`刷新`、`保存` 等需要等待的动作。
2. 增加右上角 `ToastStack`：统一展示错误、成功、提醒信息。
3. 页面顶部 `error-banner` 保留为长错误兜底，但不再承担即时反馈主职责。

### 4.2 导航与默认入口

1. `activeSection` 默认值改为 `sandbox`。
2. 运行管理导航顺序改为：`Sandbox 管理 -> 对话管理 -> 审计日志 -> KVM 管理`。
3. 统一清理虚词：如 `资源水位 -> 资源占用`、`结果回溯 -> 操作记录`。

### 4.3 Sandbox 模板

1. 删除独立的 `别名检测` 卡片。
2. 在模板详情中新增：
   - 当前别名
   - 待设置别名输入框
   - `检查是否可用`
   - `保存别名`
3. 保存后刷新模板详情与模板列表。

### 4.4 审计日志

1. 后端 `GET /api/audit` 增加 `query / operator / action / result / sessionId / targetVmId / from / to / limit / offset`。
2. 新增 `GET /api/audit/:auditId` 返回详情与关联记录。
3. 前端增加筛选条、结果表格、详情弹窗。
4. 审计日志中的 `sessionId` 与 `targetVmId` 不再只是纯文本，管理员可以直接就地打开对应的对话详情或 Sandbox 详情。
5. 从审计日志打开关联详情后，关闭时要回到原审计上下文。

### 4.5 智能体管理

1. 阶段分布由后端直接输出中文标签。
2. 每个阶段增加状态摘要、最近会话列表等更详细输出。
3. 前端通过二级信息块或折叠菜单展示，而不是只给一张图。

### 4.6 技能管理

1. 二级菜单与关键工作区文案尽量中文化。
2. 仍保留必要的英文技术标识（如 `slug`、`sessionId`），但以中文解释包裹。
3. 二级菜单默认采用居中对齐，避免左重右空的悬浮感。

### 4.7 对话管理

1. 先由 Playwright 审阅当前真实可用性并出截图。
2. 基于截图与设计建议收敛低价值功能，补强高价值功能。
3. 优先处理：布局响应、默认信息层级、无效功能入口。

## 5. 执行顺序

1. 基线启动与 Playwright 审阅。
2. 设计师子代理给出问题清单与修复纲要。
3. 主代理与程序员子代理并行改代码。
4. 复测关键页面。
5. git 工程师子代理基于变更规模与验证结果决定是否提交、何时提交、如何写提交文档。
6. 汇总总结文档。

## 6. 验收标准

1. 登录后默认落在 `Sandbox 管理`。
2. 模板详情可设置别名并完成可用性检查。
3. 别名检测不再以低价值独立卡片形式占据首页。
4. 关键异步动作出现背景虚化与明确加载文案；失败时右上角出现具体错误。
5. 审计日志可筛选、可查看详情。
6. 智能体阶段与技能管理二级结构中文表达显著改善。
7. 对话管理完成至少一轮真实浏览器审阅和针对性优化。
