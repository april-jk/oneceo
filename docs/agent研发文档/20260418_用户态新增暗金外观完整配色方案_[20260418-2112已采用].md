# 20260418 用户态新增暗金外观完整配色方案 [20260418-2112已采用]

更新时间：2026-04-18 14:08

## 1. 背景

当前用户态已经具备：

1. `light`
2. `dark`
3. `system`

三种外观模式，但还没有品牌感更强的深色高端主题。你提出新增一个新的外观“暗金”，并且不是只做一个按钮高亮，而是要把整站配色系统设计完整，覆盖页面主体、卡片、弹窗、抽屉、输入区、预览区、状态色和交互态。

这属于新增外观能力，不是简单修色，因此需要先给出完整设计，再进入代码实施。

## 2. 本次目标

本次方案只解决“新增暗金外观并形成完整网站配色系统”：

1. 在现有主题体系内新增第四种用户可选外观：`dark-gold`
2. 让 `设置 -> 设置 -> 外观` 增加“暗金”选项
3. 为全站用户态页面定义完整的暗金语义色板
4. 保证常用组件在暗金模式下的层级、可读性和状态区分清晰
5. 保持现有浅色、深色、系统模式逻辑不被破坏

## 3. 不做的内容

为了避免过度设计，本次明确不做：

1. 不新增服务端主题存储
2. 不新增“跟随系统 -> 暗金”的自动解析逻辑
3. 不改管理后台 `apps/admin_management`
4. 不修改 AI 实时生成消息、用户消息、业务数据文本内容本身
5. 不把整站做成纯金色页面，避免失去信息层级与可读性

## 4. 设计原则

暗金不是“黑底 + 大量亮金”，而是：

1. 以石墨黑、深炭灰作为主体背景
2. 以低饱和金色作为强调色、焦点色、品牌色
3. 用暖灰和浅金白承担主要正文可读性
4. 用少量铜棕作为次级装饰和分层

目标视觉感受：

1. 沉稳
2. 高级
3. 不刺眼
4. 不影响长时间阅读
5. 不破坏工作台类页面的效率感

## 7. 全站组件配色规范

### 7.1 页面主体

1. 页面主背景使用 `background`
2. 二级工作区使用 `background-elevated`
3. 主工作卡片使用 `card`
4. 悬浮层、弹窗、下拉、抽屉使用 `popover` / `dialog`

### 7.2 按钮

主按钮：

1. 背景 `primary`
2. 文本 `primary-foreground`
3. hover 使用 `primary-hover`
4. active 使用 `primary-active`

次按钮：

1. 背景透明或 `accent`
2. 边框 `border`
3. 文本 `foreground`
4. hover 使用 `accent-hover`

危险按钮：

1. 背景使用 `destructive-bg`
2. 文本使用 `destructive-fg`
3. 边框使用 `destructive-border`

### 7.3 输入框 / 文本域

1. 背景 `card-elevated`
2. 边框 `border`
3. 文本 `foreground`
4. placeholder `muted-foreground`
5. focus ring `ring`
6. 禁用态降低不透明度，不额外改为灰白

### 7.4 卡片 / 表格 / 列表

1. 常规卡片 `card`
2. 选中卡片 `card-muted + border-strong`
3. hover 卡片 `card-elevated`
4. 表头可用 `background-elevated`
5. 行 hover 不用亮金底，只做深暖灰提亮

### 7.5 弹窗 / 抽屉 / 预览面板

1. 主容器统一使用 `dialog` 或 `popover`
2. 标题和主要操作使用 `foreground`
3. 分隔线使用 `separator`
4. 高亮 tab 用金色文字或细边框，不使用整块亮金底
5. 文件预览、部署面板、设置页左右栏要有明确层级差

### 7.6 侧边栏

1. 背景使用 `sidebar`
2. 当前项使用 `accent`
3. 当前项边框或左侧高亮可用 `border-strong` / `primary`
4. 数字徽标和状态胶囊使用低饱和金或暖灰，不要纯白高亮

### 7.7 对话区工具调用卡片与悬浮详情

对话区中的工具调用卡片、状态徽标和 hover 详情不应在深色主题下继续沿用浅色模式的整块浅红、浅绿底色，否则会在 `dark` 与 `dark-gold` 下形成刺眼的大片高亮。

本次补充规范如下：

1. 工具调用卡片主体保持中性底色，沿用 `card/popover` 体系，不把整张卡片刷成状态色
2. `失败 / 成功 / 进行中` 的语义主要落在：
   - 状态 badge
   - 工具图标底
   - hover 详情页顶部状态头部
   - 结果摘要块
3. 深色与暗金模式下，失败态使用更深的暖红 / 灰红面，不使用浅粉底
4. 深色与暗金模式下，成功态使用更深的灰绿 / 鼠尾草绿面，不使用亮薄荷底
5. hover 详情页正文文本保持正常正文色，状态色只承担提示，不主导整页阅读
6. `结果摘要` 可以使用状态浅底，但正文仍保持高可读性，避免整段红字/绿字

建议新增以下变量组用于工具调用状态：

1. `--tool-success-surface`
2. `--tool-success-surface-strong`
3. `--tool-success-foreground`
4. `--tool-success-border`
5. `--tool-error-surface`
6. `--tool-error-surface-strong`
7. `--tool-error-foreground`
8. `--tool-error-border`

## 10. 技术实现建议

### 10.1 主题值

建议将 `ThemePreference` 扩展为：

1. `light`
2. `dark`
3. `dark-gold`
4. `system`

### 10.2 根节点标记

建议根节点同时输出：

1. `html.dark` 仅保留给传统深色分支
2. `data-theme="light|dark|dark-gold"`
3. `data-theme-preference="light|dark|dark-gold|system"`

原因：

1. 现有大量样式可能仍依赖 `.dark`
2. 暗金不能硬塞进 `.dark` 的同一份变量，否则普通深色会被污染
3. 通过 `data-theme="dark-gold"` 可以精确覆盖变量

### 10.3 变量实现方式

建议在全局样式中做三套主题变量块：

1. `:root`
2. `.dark`
3. `[data-theme="dark-gold"]`

暗金主题的优先级必须高于 `.dark`，避免系统类名覆盖暗金变量。

## 11. 验证要求

代码实施后，至少完成以下验证：

1. `pnpm --dir apps/web check`
2. 设置页可切换到“暗金”
3. 刷新页面后暗金选择可保持
4. 首页、会话页、设置页、预览面板、CEO View 在暗金模式下没有亮白残留
5. Playwright 逐页截图覆盖主页面和已展开子态
6. 不影响 `light` / `dark` / `system`

## 12. 验收标准

你确认方案时，重点看下面三点：

1. 暗金是否足够“深”，而不是棕黄页面
2. 金色是否只承担品牌强调，而不是破坏信息密度
3. 全站是否统一，而不是只有设置页和首页换色

## 13. 实施顺序

确认采用后，按以下顺序开发：

1. 扩展 `ThemeContext` 的主题值
2. 补全全局 CSS 变量的暗金映射
3. 增加设置页“暗金”预览卡和文案
4. 逐页修正用户态页面中的固定色
5. 使用 Playwright 做全站暗金模式验收
