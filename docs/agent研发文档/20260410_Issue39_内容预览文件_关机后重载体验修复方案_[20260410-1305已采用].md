# 20260410 Issue39 内容预览-文件 关机后重载体验修复方案 [20260410-1305已采用]

## 1. 背景

当前「内容预览-文件」链路在 sandbox 关闭后会出现以下问题：

1. 文件预览面板（`OpencodePreviewPanel`）点击 HTML 文件时，iframe 直接展示后端原始错误文本：`获取工作区原始文件失败，请稍后重试`。
2. 对话区 `Task complete` 网页交付卡片（`AltusArtifactPreviewCard`）同样直接展示该文本。
3. 用户缺少就地恢复入口，只能离开当前上下文重试。

该问题归并到 Issue #39（预览窗口-文件模块）继续修复。

## 2. 根因

### 2.1 现有实现行为

1. 前端直接把 `workspace/raw` URL 喂给 iframe：
   - `apps/web/client/src/components/OpencodePreviewPanel.tsx`
   - `apps/web/client/src/components/AltusArtifactPreviewCard.tsx`
2. 后端 `GET /api/task-creation/sessions/:sessionId/workspace/raw/*` 在 runtime 未就绪/关闭/读取失败时返回纯文本错误。
3. iframe 不做状态分层，后端返回的错误文本会直接成为页面内容。

### 2.2 体验问题本质

并非“文件本身不可预览”，而是“预览运行环境暂不可用”。当前 UI 将运行态错误直接暴露为内容错误，导致突兀且不可恢复。

## 3. 修复目标

1. 不再直接向用户展示 `workspace/raw` 的底层错误文本。
2. 在同一位置提供明确的「重新加载预览」入口。
3. 重载动作可触发 runtime 恢复并重新拉起预览。
4. 失败时展示分层文案（环境未启动/读取失败/网络错误），而不是统一生硬报错。

## 4. 方案设计（最短路径）

## 4.1 预览加载改为“两阶段”

在所有 HTML iframe 预览前增加 `HEAD` 预检查：

1. 第一步：请求 `HEAD /workspace/raw/*`（同 URL）。
2. 第二步：仅当状态为 200 时再挂载 iframe。

这样可避免 iframe直接渲染后端错误文本页面。

> 说明：后端新增 `HEAD` 路由与 `GET` 共享同一鉴权和 runtime 判断逻辑，仅返回状态码与必要头，不返回正文。

## 4.2 前端统一状态机

对 HTML 预览引入统一状态：

- `loading`：检查预览可用性
- `ready`：展示 iframe
- `runtime_unavailable`：环境未启动/已关闭
- `fetch_failed`：读取失败或网络异常

在 `runtime_unavailable` 与 `fetch_failed` 状态展示统一占位卡片，不渲染 iframe。

## 4.3 「重新加载预览」接口（用户入口）

在占位卡片提供主操作按钮：`重新加载预览`。

点击行为：

1. 调用现有 runtime 启动接口：
   - `POST /api/task-creation/sessions/:sessionId/runtime/start`
2. 启动成功后重新执行 `HEAD` 检查。
3. 检查通过后重新挂载 iframe（附带 cache bust 参数，避免浏览器使用失败缓存）。

附加次操作：

- `查看源码`（切换到 Code 标签/打开文件查看），避免用户阻塞。

## 4.4 覆盖范围

本次仅覆盖 HTML 预览路径：

1. `OpencodePreviewPanel`（文件面板内 HTML Preview）
2. `AltusArtifactPreviewCard`（Task complete 网页交付卡片）

不扩展到图片/音频/PDF 的预览链路。

## 5. 具体改动点

## 5.1 API

文件：`apps/api/src/routes/task-creation-routes.ts`

1. 新增 `HEAD /sessions/:sessionId/workspace/raw/*`。
2. 复用 `GET workspace/raw` 的鉴权、路径校验、runtime 状态判断。
3. 返回：
   - 200：可预览
   - 409：环境未就绪/已关闭
   - 4xx/5xx：按现有语义返回

## 5.2 Web

文件：

1. `apps/web/client/src/components/OpencodePreviewPanel.tsx`
2. `apps/web/client/src/components/AltusArtifactPreviewCard.tsx`
3. `apps/web/client/src/lib/task-creation-client.ts`（新增 `headWorkspaceRawFile` 封装）

改动：

1. 抽取共享预览可用性检查逻辑（hook 或 util）。
2. 使用状态机驱动 UI，占位态显示友好文案与操作按钮。
3. 「重新加载预览」调用 runtime/start 后重试。

## 6. 验收标准

1. sandbox 关闭后点击 HTML 文件，不再显示“获取工作区原始文件失败，请稍后重试”原文。
2. 页面显示“预览环境不可用”样式，并提供 `重新加载预览`。
3. 点击 `重新加载预览` 后可自动恢复预览（环境恢复成功时）。
4. 对话区网页交付卡片与文件预览面板行为一致。

## 7. 测试计划

## 7.1 单元/组件

1. 预览状态机：`loading -> runtime_unavailable -> reloading -> ready`。
2. `headWorkspaceRawFile` 状态码映射。

## 7.2 Playwright 页面回归

1. 制造 runtime 关闭场景后进入 HTML 预览。
2. 断言展示占位卡片而非原始错误文本。
3. 点击 `重新加载预览`，断言预览恢复。
4. 在 `Task complete` 卡片重复上述流程。

## 8. 约束

1. 不做兼容补丁分支，不引入双轨逻辑。
2. 不修改业务会话模型，仅修正预览链路与交互。
3. 优先复用现有 `runtime/start` 接口，不新增多余恢复 API。
