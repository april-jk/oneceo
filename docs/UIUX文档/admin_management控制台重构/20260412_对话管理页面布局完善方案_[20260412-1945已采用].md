# 2026-04-12 对话管理页面布局完善方案 [20260412-1945已采用]

## 1. 背景

本方案用于 `apps/admin_management` 的 `对话管理` 页面布局完善。当前已采用方案已经把页面从“三栏常驻工作台”收敛为“全宽会话索引 + 统一会话详情 popup”：

1. 主页面只保留会话索引，服务管理员快速定位会话。
2. 会话详情、交互回放、关联信息、详细日志、状态流转统一进入同一个 popup。
3. `core / infra` 分层加载、自动刷新、状态筛选和消息开发者视图均已具备。

同时，后台跨模块查看逐步收敛为“相关对象优先在当前上下文之上叠层打开详情”，避免管理员点进会话后丢失来源页状态。

本轮不改变该主方向，只在已采用结构内完善布局信息层级和响应式稳定性。

## 2. 现状观察

### 2.1 代码入口

1. 导航入口：`apps/admin_management/web/src/App.tsx` 中 `conversation` 对应 `对话管理`。
2. 当前实际渲染入口：`renderConversationOpsSection()`。
3. 旧版 `renderConversationSection()` 仍在文件中保留，但当前不走该入口，后续实现不能误改旧入口作为主方案依据。
4. 当前样式集中在 `apps/admin_management/web/src/styles.css` 的 `.conversation-*` 区块。

### 2.2 当前布局

1. 主页面是单列全宽会话索引。
2. 面板内包含：
   - 标题与自动刷新开关；
   - 状态快捷筛选；
   - 搜索 / 状态阶段 / 用户 / 处理方式 / 日期 / 重置工具条；
   - 会话表格。
3. 会话表格列为：
   - 会话；
   - 当前进度；
   - 最近活跃；
   - 操作。
4. 详情 popup 内包含：
   - 概览；
   - 交互回放；
   - 关联信息；
   - 详细日志；
   - 状态流转。

### 2.3 当前问题

1. 页面进入后直接展示索引表，缺少一层轻量摘要，管理员难以快速判断当前列表的治理重点。
2. 表格列宽固定为 `46% / 24% / 16% / 14%`，长标题、长待确认问题、长会话 ID 容易挤压操作列。
3. 行点击会触发详情加载，但主页面不展示详情，选中态语义不够直观。
4. popup 内容较重，交互回放、详细日志、状态筛选都可能形成长内容，需要更稳定的内部滚动边界。
5. 窄屏下表格 `min-width` 带来横向滚动，需明确哪些字段优先保留、哪些字段降级为次级信息。
6. 已废弃的三栏常驻样式和 JSX 仍存在，容易在后续布局迭代中造成误改。

## 3. 目标与非目标

### 3.1 目标

1. 保持“全宽会话索引 + 统一详情 popup”的已采用方向。
2. 提升管理员进入页面后的第一眼判断能力。
3. 稳定会话表格的列宽、操作列和长文本换行/截断行为。
4. 明确行点击与详情按钮的交互语义。
5. 强化 popup 的滚动层级，使概览、回放、日志和状态流转在大屏和窄屏下都可读。
6. 保持现有接口、数据结构、状态模型不变。

### 3.2 非目标

1. 不恢复“三栏常驻详情工作台”。
2. 不新增管理端对话 API。
3. 不修改 `ConversationManagementService` 聚合语义。
4. 不改 `apps/api` 主链。
5. 不引入新 UI 框架。
6. 不进行整站视觉重构。

## 4. 布局方案

### 4.1 主页面信息架构

主页面维持单个功能边界：`conversation-index-panel`。在该面板内部形成三层：

1. 顶部摘要层
   - 总会话数；
   - 进行中；
   - 待确认；
   - 失败；
   - 最近更新时间。
2. 筛选层
   - 搜索；
   - 状态 / 阶段合一下拉；
   - 用户；
   - 处理方式；
   - 重置。
3. 索引表格层
   - 主体列表；
   - 空状态；
   - 当前筛选命中说明；
   - 行点击直接进入详情，不再保留行内复制按钮。

这样保持页面只有一个主面板，不额外新增外层装饰容器。

### 4.2 顶部摘要层

在 `conversation-index-panel` 的标题区下方增加紧凑摘要条：

1. `全部`：当前已加载会话数。
2. `进行中`：正在推进的会话数。
3. `待确认`：需要用户补充或确认的会话数。
4. `失败`：需要人工介入的会话数。
5. `最近活跃`：列表中最新 `updatedAt`。

摘要条只使用现有 `summary-card` / `session-status` / `state-*` 语义，不创建新的视觉系统；五个摘要项在常规后台视口保持同一行，窄视口允许摘要条横向滚动，避免把索引区首屏撑高。

### 4.3 筛选层

筛选层继续保持单层，不展开成复杂表单：

1. 不再保留独立状态 chips。
2. 搜索框继续匹配：
   - 会话 ID；
   - 标题；
   - 用户；
   - 处理方式；
   - 阶段；
   - 状态；
   - 待确认问题。
3. 原阶段筛选 select 调整为“状态 / 阶段”合一下拉：
   - 先展示 `进行中 / 待确认 / 失败 / 已完成` 等状态项；
   - 再展示真实阶段项；
   - 选择状态时清空阶段筛选，选择阶段时清空状态筛选。
4. 增加“更新开始日期 / 更新结束日期”两个日期筛选项，按会话 `updatedAt` 做包含式范围筛选。
5. 增加 `用户` 与 `处理方式` 两个本地筛选项：
   - 用户按 `app_users.id` 聚合，标签可展示用户名 / 邮箱；
   - 处理方式按会话 runtime 中的 `executor` 聚合，支持 Altus、OpenCode、Codex 以及未来新增值。
6. 重置按钮作为同一组筛选字段的最后一列展示，并和搜索、状态 / 阶段、用户、处理方式、日期筛选保持同一行；搜索栏使用较短的固定上限宽度，状态、用户、处理方式、日期和按钮保留足够宽度避免文字与控件重叠，窄视口允许筛选条横向滚动，但不把这些控件拆成两行。
7. 筛选命中说明移动到筛选层尾部，避免夹在表格主体里影响扫读。

### 4.4 表格列结构

表格采用三列，但调整信息职责：

1. `会话`
   - 标题；
   - 待确认 / 失败 / 完成摘要；
   - `用户 / 处理方式 / 会话 ID` 的轻量元信息行。
2. `状态`
   - 状态标签；
   - 阶段标签；
   - 当前进度说明。
3. `时间`
   - 最近更新时间；
   - 创建时间。

列宽建议调整为：

1. 会话：`minmax(360px, 1.6fr)`。
2. 状态：`minmax(220px, 0.9fr)`。
3. 时间：`minmax(170px, 0.7fr)`。

实现时如果继续使用 table，需通过 `colgroup` 与最小宽度保持三列稳定；如果改为 CSS grid 行，必须保持表头、行高、键盘可读性与横向滚动一致。

### 4.5 行点击语义

1. 点击行：直接打开统一详情 popup，并同步当前选中会话。
2. 列表中不再保留复制按钮或单独的“查看详情”动作。
3. 自动刷新时不清除当前选中行。

该规则避免重复动作堆叠，让管理员保持“一眼扫列表，一次点击进详情”的节奏。

### 4.6 统一详情 popup

popup 仍保持五个 Tab，不拆出第二弹窗：

1. `概览`：摘要信息与当前待确认问题。
2. `交互回放`：类用户态回放。
3. `关联信息`：运行绑定、Sandbox 分组、OSAC / OpenCode 信息。
4. `详细日志`：统一 JSON 载荷。
5. `状态流转`：状态机 timeline / list。

布局完善点：

1. modal 最大高度继续受视口约束。
2. tab 区固定在 modal 内容顶部。
3. 只有 `conversation-dialog-body` 内部滚动。
4. `交互回放` 保留自身滚动容器，但不能与外层产生双重滚动冲突。
5. `详细日志` 使用 JSON block，保持横向滚动，不让长字段撑破 modal；JSON 展示栏需要使用更高的专用高度，并在左侧显示稳定行号，优先让管理员少滚动弹窗外层。
6. `状态流转` 的筛选区保留高级筛选折叠，不默认占满首屏。
7. 当会话详情由 `用户管理`、`Sandbox 管理` 等其他主栏目打开时，popup 头部要明确显示来源；默认关闭后应回到原上下文，而不是强制切到 `对话管理` 主页面。
8. 当管理员在 popup 中点击“在对话管理中查看”进入整页工作台时，页头继续显示来源路径，帮助管理员确认自己是从哪里跳过来的。
9. 若来源是 `用户管理` 的详情窗，关闭当前详情后必须恢复原来的用户详情窗与原分页，不允许只回到用户索引表。

### 4.7 响应式规则

1. `> 1320px`
   - 摘要、筛选、表格完整展示。
   - 表格操作列稳定显示。
2. `920px - 1320px`
   - 筛选区降为两列或单列。
   - 表格保留横向滚动，不压缩操作按钮。
3. `< 920px`
   - 页面恢复自然流。
   - popup 宽度贴近视口。
   - tab 允许换行。
4. `< 640px`
   - 操作按钮保持整宽或稳定最小宽度。
   - 表格横向滚动优先，不把长文本硬挤进窄列。
   - 会话标题和待确认摘要最多展示两行。

## 6. 全链路逻辑验证

本方案的数据链路保持不变：

1. 页面进入 `对话管理`。
2. 前端调用 `listConversationSessions(200)` 获取会话索引。
3. 前端本地派生摘要、状态 counts、阶段选项和筛选结果。
4. 点击会话行后选择目标 session，并直接打开详情 popup。
   - 会话列表保留标题、待确认摘要、状态和时间；
   - `用户 / 处理方式 / 会话 ID` 收为轻量元信息行。
5. 前端调用 `getConversationSessionCore(sessionId)` 加载核心详情。
6. 前端调用 `getConversationSessionInfra(sessionId)` 异步补充运行关联信息。
7. popup 各 Tab 共享同一份详情状态。
8. 自动刷新只更新列表和当前详情，不改变接口语义。

该链路不新增后端依赖，因此不会影响用户态会话、Sandbox 生命周期、OSAC 或 LLM 代理主流程。

## 7. 验收标准

1. 管理员进入页面后，能在首屏看到总量、进行中、待确认、失败和最近活跃摘要。
2. 搜索、状态筛选、阶段筛选、用户筛选、处理方式筛选和重置仍可用。
3. 会话标题、待确认问题、会话 ID、状态、阶段和时间不互相挤压。
4. 点击表格行可直接打开 popup，且不会触发额外冗余动作。
5. popup 五个 Tab 均可正常切换。
6. `交互回放`、`详细日志`、`状态流转` 不出现内容撑破 modal 或无法滚动。
7. 在 `>1320px`、`1200px`、`920px`、`640px` 四档宽度下布局不重叠、不遮挡、不出现按钮被压缩到不可用。
