# AGENTS Git 操作与提交指南

本文用于指导 `oneceo/` 仓库内的 Git 基本操作、同步动作、提交准备与提交说明编写。

## 基本操作约定

- 修改前先执行：
  - `git branch --show-current`
  - `git status --short`
- 提交前再次执行：
  - `git status --short`
  - `git diff --stat`
- 不要跨系统误改，遵循目录边界。
- 大范围改动请拆分提交，避免把多个主题混在一个提交里。
- 改文档时要同时清理过时引用、失效接口和错误路径。
- 若本次修改依赖已采用设计文档，应在提交说明或文档里体现依据。

## 拉取与同步原则

- 开始开发前，先确认当前分支是否需要同步最新远端。
- 如果需要拉取最新改动，优先做法是：
  1. 先看 `git status --short` 是否干净
  2. 再决定 `fetch`、`rebase` 或 `merge`
  3. 发生冲突时逐块理解，不允许机械选择 `ours` 或 `theirs`
- 如果当前工作区已经有未提交改动，不要直接执行会改写工作树的大动作。

## 提交规范

- 提交信息必须使用中文。
- 提交信息要清楚说明“做了什么”和“为什么做”。
- 如果本次修改对应明确的 `issue`、`PR`、任务单或其他带编号事项，提交信息中必须显式写出对应编号，禁止只写“相关问题”或“对应需求”这类模糊表述。
- 如果一次提交同时完成多个带编号事项，提交信息中必须把实际完成的编号逐个写清，不得省略。
- 如果本次提交只完成某个编号事项中的一部分，提交信息必须明确写出“完成的是哪一部分”，不能让编号看起来像整项已经全部完成。
- 推荐格式：`[提交类型] 修改内容；修改目的`
- 涉及编号事项时，推荐格式：`[提交类型] 编号 + 修改内容；修改目的`。

## 提交信息生成规则

- 提交 Git 时，不能只参照“当前这一轮对话最后一句要求”来写提交信息。
- 提交信息必须参照以下两个维度共同归纳：
  1. 最近几次对话中，实际连续完成了什么
  2. 从“上一次 commit”到“这一次 commit”之间，代码和文档真实发生了什么变更
- 如果一个提交里包含的是连续几轮对话共同完成的结果，提交信息必须覆盖这些连续变更的共同主题，不能只写最后一次对话的表面动作。
- 如果用户在几轮对话中逐步补充要求，而你一直没有提交，那么提交信息必须按“这整个未提交区间的最终结果”来写。
- 判断提交信息时，优先级应是：
  1. `git diff --stat`
  2. `git diff --cached`
  3. 相关文件实际内容
  4. 最近几次对话上下文
  5. 最后一句用户消息
- 最后一句用户消息只能帮助你理解“当前收口动作”，不能替代对实际改动内容的归纳。
- 如果存在 `issue`、`PR`、任务单编号，还必须核对“本次实际提交内容”与“编号对应事项”是否一致；不能因为用户提到过某个编号，就把未完成的编号写进提交信息。

## 提交前的提交说明检查

- 写提交信息前，至少回答这几个问题：
  1. 这次暂存区里一共改了哪些主题
  2. 这些改动是一次对话完成的，还是几次对话累计完成的
  3. 自上次提交以来，最主要的结果是什么
  4. 提交信息是否遗漏了暂存区里已经存在的重要改动
- 如果暂存区包含多个不应混在一起的主题，不要靠一个模糊提交信息硬包住，应该拆分提交。
- 如果提交信息只能描述“最后一次对话做了什么”，但不能准确描述暂存区全部改动，说明你还不应该提交。
- 如果提交信息写了编号，还要额外检查：
  1. 这个编号是不是本次提交真实完成的事项
  2. 提交内容是否足以支撑“已完成”这几个字
  3. 是否把无关编号错误带入提交说明
  4. 是否遗漏了同一提交里已经实际完成的其他编号

提交类型至少包含以下之一：

- `新功能`
- `修复`
- `重构`
- `文档`
- `测试`
- `构建`
- `杂项`

示例：

- `[修复] 修正 task session 恢复后连接器绑定未重建；避免恢复后 MCP 工具缺失`
- `[文档] 更新 AGENTS_GUIDE 执行链路说明；清理旧三智能体接口描述`
- `[重构] 统一 Altus managed run 状态写入链路；避免最近几轮调整后事件状态不一致`
- `[文档] 更新 AGENTS 与 Git 协作规范；反映当前架构并约束多人协作提交流程`
- `[修复] Issue #128 修复 task creation 重复写入；避免同一任务生成重复消息`
- `[新功能] PR #342 对应联调项：新增 sandbox 生命周期状态上报；支撑前端展示真实运行状态`
- `[修复] Issue #128 与 Issue #131 修复任务恢复和连接器重绑；解决恢复后消息缺失与工具不可用问题`

## 合并前检查

- 至少做一次最小可行验证。
- 确认 `git diff` 里没有混入无关改动。
- 确认不会覆盖别人已在当前文件中做出的未合并调整。
- 涉及 Sandbox / OSAC / MCP / 连接器 / 认证时，优先附上：
  - 本地验证命令
  - 请求路径
  - 日志关键词
  - 是否依赖外部环境
