# 20260409 Altus记忆与日志持久化架构评审 [尚未采用]

## 1. 背景与评审目标

当前 Altus 会话链路已经包含数据库、Redis、本地文件、R2 多种存储介质。近期暴露的问题集中在：

- 会话续聊时，部分状态在无状态部署环境下无法稳定恢复。
- 运行机本地文件（memory/log）在实例重启或切换后不可持续。
- 记忆读取链路存在“主链 + 侧车”的混合形态，职责边界不够清晰。

本评审文档目标：

- 明确当前“主记忆/热缓存/日志/工作区归档”的真实存储事实。
- 给出可对比的存储架构选型，明确推荐方向与不推荐方向。
- 为后续专项方案（DB 持久化 + Redis 读取）提供上位决策依据。

## 2. 当前实现事实（基于代码现状）

### 2.1 会话消息主链路

- 会话消息主存储：`conversation_messages`。
- 最近消息热窗口：`task_session_recent_messages`。
- 运行事件：`task_session_run_events`。

说明：消息与事件已具备数据库持久化基础能力。

### 2.2 文件侧车记忆

- 本地文件：`data/task-creation-memory.json`。
- 由 `taskCreationFileMemoryStore` 维护会话标题、阶段、runtime 绑定等侧车状态。

说明：该侧车在“单机连续运行”场景可用，但在无状态多实例部署中天然不可靠。

### 2.3 本地调试日志

- 本地文件：`data/connector-debug.log`。
- 属于 best-effort append 模式，不保证跨实例聚合和长期持久。

### 2.4 工作区与状态文件

- Sandbox 工作区/状态归档通过 R2（`workspace.tar.gz` + snapshot + metadata）。
- 归档恢复由 `sandbox-archive-service` 执行，依赖 `E2B_ARCHIVE_ENABLED` 与 R2 配置。

说明：工作区文件已有“对象存储持久化”路径，但受归档触发与成功率影响。

## 3. 问题归纳

### 3.1 无状态部署与本地文件冲突

当服务实例重启、扩缩容或切换节点时：

- `task-creation-memory.json` 不具备全局可见性。
- `connector-debug.log` 不具备统一检索能力。

结果是：会话元数据可恢复性与排障可观测性依赖“命中同一台机器”，不满足生产稳定性要求。

### 3.2 混合存储职责不清

当前“消息在 DB、部分会话元数据在文件、热数据部分在 Redis/DB”的状态，增加了：

- 读路径复杂度。
- 状态不一致窗口。
- 故障定位成本。

### 3.3 高可用边界未闭环

数据库连接层有重试与健康检查，但业务层并未形成完整的“降级一致性策略”定义（例如 DB 短暂失败时消息处理语义）。

## 4. 选型对比（架构层）

### 方案 A：全文件存储（本地或共享文件系统）

优点：

- 实现简单，写入直观。

缺点：

- 在无状态服务中不可作为主存储。
- 多实例并发下一致性与锁竞争问题明显。
- 备份、审计、查询能力弱。

结论：不建议作为 Altus 主链路。

### 方案 B：数据库为真相源 + Redis 作为热读取层 + R2 管文件归档

优点：

- 持久化、查询、审计能力明确（DB）。
- 低延迟读取与高并发抗压（Redis）。
- 大对象与工作区文件独立管理（R2）。

缺点：

- 需要清晰定义缓存一致性与失效策略。
- 需要治理当前本地文件侧车迁移。

结论：推荐作为目标架构。

### 方案 C：事件溯源全面重构（Event Store + Projection）

优点：

- 理论一致性与可追溯性最强。

缺点：

- 重构成本高，迁移复杂，短期风险大。

结论：当前阶段不建议。

## 5. 评审结论

推荐采用方案 B，并进一步收敛为以下原则：

- `DB`：唯一真相源（会话、消息、事件、关键元数据）。
- `Redis`：仅承担热数据读取与短期状态加速，不承载唯一事实。
- `R2`：工作区归档、可下载产物与快照。
- `本地文件`：仅临时缓存与开发调试，禁止作为生产恢复依赖。

## 6. 迁移边界与验收标准（架构级）

### 6.1 边界

- 不改变业务语义（会话状态流转、消息顺序、runtime generation 语义不变）。
- 不引入“多真相源”。
- Redis 必须继续遵守显式开关：`ONECEO_REDIS_ENABLED=true` 且 `REDIS_URL` 同时存在。

### 6.2 验收标准

- 实例重启后，任一会话在新实例读取到的状态与旧实例一致。
- 关闭 Redis 时，系统可完全回退 DB 读路径，功能正确。
- 断开单实例本地磁盘后，不影响线上会话恢复与消息读取。

## 7. 待决策项

- 是否为“Redis 未命中率、回源耗时、消息一致性”建立固定观测面板（建议是）。
