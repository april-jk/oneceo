## 1. 背景

当前后台登录页已经满足“管理员身份独立于普通用户身份”的功能目标，但页面文案与视觉信息结构存在以下问题：

1. Hero 区主标题使用“管理员后台与用户态彻底分离”这类内部设计语言，更像架构说明，不像正式产品官网
2. 辅助文案直接暴露 `admin_users`、`admin_user_sessions`、Cookie 等实现细节，技术感过重
3. 徽标词使用“独立管理员表”“独立 Cookie”“统一治理入口”，表述偏口号化，缺少企业官网常见的克制感
4. 左侧强视觉区和右侧登录卡的角色边界不清，导致页面像“宣传页 + 演示页”的混合体，而不是稳定的企业控制台入口

用户反馈为“AI 味太浓”，本质上不是单句文案问题，而是整页在信息取舍、语气和视觉重心上都没有对齐成熟企业软件站点。

## 2. 目标

本方案只解决后台登录页的“表达方式”，不改动身份体系、不改动登录接口、不扩展额外业务功能。

目标只有三条：

1. 文案语气对齐 AWS 这类企业级产品站点，克制、明确、少宣言式表达
2. 页面只展示管理员登录真正需要知道的信息，不把内部实现细节放在首屏中心
3. 保留后台作为正式治理入口的专业感，但避免“AI 生成式营销文案”的痕迹

## 3. 对标原则

这里的“对标 AWS”不是照搬视觉皮肤，而是对齐其表达纪律。

### 3.1 文案原则

1. 优先说“这是什么入口”，不要先说“底层如何实现”
2. 优先说“面向谁、做什么”，不要用夸张语气做概念宣告
3. 每段文案只承载一个信息点，禁止一段里同时塞身份边界、数据表、Cookie、统一入口等多个概念
4. 首屏避免出现工程实现名词，除非该名词本身就是用户必须理解的产品术语

### 3.2 视觉原则

1. 左侧 Hero 是品牌与场景说明，不是架构海报
2. 右侧卡片是操作入口，应当成为第一交互焦点
3. 大标题控制在 1 到 2 行，避免超大字堆叠造成“海报感”和不稳定换行
4. 颜色与装饰应服务于秩序感，而不是服务于“高级感”

### 3.3 信息边界

登录页允许展示：

1. 后台名称
2. 后台职责
3. 管理员身份入口说明
4. 必要的安全与权限提示

登录页不再展示：

1. `admin_users`
2. `admin_user_sessions`
3. Cookie 实现细节
4. “彻底分离”“统一治理入口”这类偏内部视角的口号

## 4. 当前页面问题拆解

对应当前实现：

1. 左侧标题“管理员后台与用户态彻底分离。”属于技术结论，不属于首屏产品标题
2. 底部说明“后台使用独立的 admin_users 和 admin_user_sessions”是实现说明，应该下沉到文档或审计说明，不应放在登录 Hero 核心区域
3. 徽标词“独立管理员表 / 独立 Cookie / 统一治理入口”读起来像系统特性枚举，不像企业控制台的稳定特征
4. 右侧标题“进入治理控制台”偏虚，不如直接说“管理员登录”或“登录管理控制台”

## 5. 目标页面信息架构

调整后首屏只保留两层结构：

### 5.1 左侧 Hero

承载三项内容：

1. 产品识别：`ONECEO 管理控制台`
2. 简洁标题：说明后台的职责范围
3. 一段辅助说明：点出“仅供授权管理员使用”

建议结构：

1. eyebrow：`ONECEO 管理控制台`
2. heading：`平台管理与运维控制台`
3. copy：`用于访问平台治理、运行状态与配置管理能力。仅限已授权管理员登录。`

左侧底部不再放技术徽标词，可改为 2 到 3 个业务向短标签：

1. `平台治理`
2. `运行监控`
3. `配置管理`

### 5.2 右侧登录卡

承载三项内容：

1. 卡片标题：`管理员登录`
2. 表单字段：`登录名`、`密码`
3. 错误提示与登录按钮

按钮文案建议统一为：

1. 默认：`登录`
2. 提交中：`登录中...`

不建议继续使用“登录后台”“进入治理控制台”这类一会儿偏动作、一会儿偏口号的混合表达。

## 6. 推荐文案

以下为本轮推荐的一版正式文案。

### 6.1 加载态

1. eyebrow：`ONECEO 管理控制台`
2. title：`正在验证管理员会话`
3. copy：`请稍候，系统正在检查当前登录状态。`

### 6.2 未登录页左侧 Hero

1. eyebrow：`ONECEO 管理控制台`
2. title：`平台管理与运维控制台`
3. copy：`用于访问平台治理、运行状态与配置管理能力。仅限已授权管理员登录。`
4. tags：`平台治理`、`运行监控`、`配置管理`

### 6.3 未登录页右侧卡片

1. eyebrow：`管理员入口`
2. title：`管理员登录`
3. 无辅助说明正文
4. field 1：`登录名`
5. field 2：`密码`
6. button default：`登录`
7. button pending：`登录中...`

## 7. 明确不采用的表达

以下表达本轮明确不采用：

1. “管理员后台与用户态彻底分离”
2. “统一治理入口”
3. “进入治理控制台”
4. “独立管理员表”
5. “独立 Cookie”
6. 首屏直接展示 `admin_users`、`admin_user_sessions`

原因一致：

1. 都偏内部实现或概念口号
2. 会提高陌生感，不利于形成正规控制台的稳定预期
3. 容易让页面看起来像 AI 自动生成的“高概念描述”

## 8. 视觉收敛要求

在不改动整体双栏结构的前提下，视觉需同步收敛：

1. 左侧标题字号下降一级，控制最大宽度，避免 3 到 4 行超大换行
2. 左侧背景保留深色专业感，但减少强烈蓝绿渐变的“展板感”
3. 徽标标签改成更轻、更扁平的业务标签，不再强化透明发光效果
4. 右侧卡片取消标题下方辅助说明，直接进入表单，保持控制台入口的干净感
5. 按钮与字段文案统一短句，不叠加宣传性词汇

### 8.1 本轮细化校正

在上述基础上，补充以下落地约束：

1. 左右两栏各自建立稳定的垂直节奏，避免标题、正文、表单之间距离忽紧忽松
2. 表单标签、输入框、错误提示和提交按钮采用单独的登录页节奏，不直接复用后台内容页的常规控件密度
3. 提交按钮必须具备清晰的默认态、悬停态和禁用态，避免“加载中”时仍显得可点击
4. 输入框聚焦态要有明确边框与焦点环，体现正式控制台的可用性
5. 920px 以下切为单栏时，Hero 和登录卡都要重新收紧内边距与标题字号，不能简单沿用桌面布局

## 10. 验收标准

采用后应满足以下标准：

1. 首屏不再出现数据表名、Cookie 等实现词汇
2. 页面标题与按钮文案均可被非研发角色快速理解
3. 左侧 Hero 阅读感受接近正式企业控制台，而不是概念海报
4. 右侧登录卡一眼可知是“管理员登录入口”，不存在多余口号
5. 页面整体气质与 AWS、Azure、Cloudflare Dashboard 这类正规控制台保持同类秩序感
