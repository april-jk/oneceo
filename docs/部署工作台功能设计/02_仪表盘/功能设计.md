# 仪表盘功能设计

## 1. 功能定位

“仪表盘”是一个双视图模块，用同一个页面承载两类信息：

- 部署数据
- 站点数据

它回答的问题是：

- 最近发布是否稳定
- 历史版本如何变化
- 站点当前是否公开
- 站点访问和来源表现如何

## 2. 页面结构

建议结构：

- 顶部站点摘要区
- 右上角视图切换按钮
- 主内容区

右上角切换按钮：

- `部署数据`
- `站点数据`

交互要求：

- 默认进入 `部署数据`
- 切换后只替换主内容区，不刷新整个部署工作台导航
- 切换状态应保持到当前会话级页面生命周期内

## 3. 视图拆分

### 3.1 部署数据

部署数据面向发布运维，主要包含：

- 发布成功率
- 成功/失败版本数
- 当前可回退版本
- 最近部署轨迹
- 从 Railway 获取的部署历史
- 基于部署历史执行回退

详见：

- [01_部署数据.md](/Users/eunice/codingProject/oneceo/docs/部署工作台功能设计/02_仪表盘/01_部署数据.md)

### 3.2 站点数据

站点数据面向应用运营，布局参考 Manus 的站点分析页，主要包含：

- 站点头部信息
- 公开状态卡
- 时间范围与筛选区
- 分析指标卡
- 页面、引荐来源、地区、设备等分析块

详见：

- [02_站点数据.md](/Users/eunice/codingProject/oneceo/docs/部署工作台功能设计/02_仪表盘/02_站点数据.md)

## 4. 数据原则

部署数据：

- 优先复用现有部署记录与 Railway 历史
- 回退动作直接基于真实部署记录

站点数据：

- 不允许伪造统计值
- 没有真实埋点或分析管道时，要明确展示“没有数据”
- 允许先把结构和空态设计完整

## 5. 计划设计方式

### 当前阶段

- 先完成双视图结构文档
- 部署数据优先接真实数据
- 站点数据先设计完整信息架构与空态

### 下一阶段

- 为站点数据接入真实分析采集
- 补时间筛选和过滤维度
- 支持地区、设备等明细切换

## 6. 审核点

- 仪表盘拆成“部署数据 / 站点数据”两个视图是否符合你的预期。
- 右上角切换按钮是否是你想要的交互位置。
- 站点数据是否按 Manus 的分析页结构继续推进。
