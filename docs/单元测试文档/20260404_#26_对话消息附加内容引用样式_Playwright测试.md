# 2026-04-04 #26 对话消息附加内容引用样式 Playwright 测试

## 1. 测试目标

验证对话消息中的附加内容引用样式在真实浏览器链路中满足以下要求：

1. 仅附加 `skill` 时，消息内出现明确的引用块
2. 仅附加文件附件时，消息内出现明确的引用块
3. 同时附加 `skills + 附件` 时，消息内出现统一引用块并按分组展示
4. 引用块与消息正文属于同一条消息，而不是脱离消息单独悬浮
5. 消息在刷新或历史恢复后，附加内容引用关系仍可见

## 3. 测试单元清单

1. 打开主对话页并进入可发送消息状态
2. 仅附加 `skill` 后发送消息
3. 仅附加文件附件后发送消息
4. 同时附加 `skills + 附件` 后发送消息
5. 分别检查三类消息中的引用块结构与正文归属
6. 刷新当前会话后，检查引用块仍可见

## 4. 预期输入与预期输出

### 4.1 仅附加 skill

输入：

1. 在输入区只选择一个已可用 `skill`
2. 不选择文件附件
3. 发送最小消息

预期输出：

1. 用户消息气泡内出现引用块
2. 引用块头部显示 `已附加`
3. 引用块中存在 `Skills` 分组
4. 引用块中不存在 `附件` 分组

### 4.2 仅附加文件附件

输入：

1. 在输入区只选择一个本地文本附件
2. 不选择 `skill`
3. 发送最小消息

预期输出：

1. 用户消息气泡内出现引用块
2. 引用块中存在 `附件` 分组
3. 引用块中不存在 `Skills` 分组
4. 引用块中能看到文件名和格式化后的大小

### 4.3 同时附加 skills 与附件

输入：

1. 在输入区选择一个 `skill`
2. 再附加一个本地文件
3. 发送最小消息

预期输出：

1. 用户消息气泡内只出现一个引用块
2. 引用块头部显示 `Skills 与附件`
3. 引用块中同时存在 `Skills` 与 `附件` 两个分组
4. 两组内容都在同一条消息气泡内

### 4.4 刷新恢复

输入：

1. 在包含上述消息的会话页面执行刷新

预期输出：

1. 三类消息的引用块仍可见
2. 不需要重新发送消息才能恢复附加内容展示

## 5. 边界条件与失败条件

边界条件：

1. 使用当前可用 `skill`，避免因为 skill 列表为空导致场景失效
2. 附件使用最小文本文件，避免上传链路波动
3. 三类消息均发送在同一会话中，便于横向比较

失败条件：

1. 引用块只在输入区可见，发送后消息内不可见
2. `skills` 仍然不显示，只显示附件
3. 同时附加两类内容时出现两个分离容器，或布局混乱
4. 刷新后引用块消失

## 6. 验证方式

1. Playwright 浏览器自动化逐场景发送消息并截图
2. 对页面做可见性与文本断言
3. 刷新同一会话后复查消息引用块
