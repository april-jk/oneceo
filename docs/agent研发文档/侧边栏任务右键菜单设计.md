# 侧边栏任务右键菜单设计

## 1. 背景

当前侧边栏中的任务会话项只支持：

- 点击进入会话
- 在“全部任务”弹窗中浏览会话

缺少面向会话级管理的快捷操作。用户希望在侧边栏任务项上通过右键直接完成以下动作：

- 分享
- 重命名
- 添加到收藏 / 取消收藏
- 移动到项目
- 删除

仓库现状已具备可复用基础：

- 前端已有通用 [context-menu.tsx](/Users/watson/codingProj/oneceo/apps/web/client/src/components/ui/context-menu.tsx)
- 侧边栏会话项集中在 [Sidebar.tsx](/Users/watson/codingProj/oneceo/apps/web/client/src/components/Sidebar.tsx)
- 后端当前仅已有删除会话接口 [task-creation-routes.ts](/Users/watson/codingProj/oneceo/apps/api/src/routes/task-creation-routes.ts)

因此本次设计的重点不是菜单 UI 本身，而是：

- 会话元数据扩展
- 五个动作的能力边界
- 哪些先做真实落库，哪些先做占位或二阶段能力

## 2. 目标

为侧边栏任务会话新增右键菜单，覆盖以下操作：

1. 分享
2. 重命名
3. 添加到收藏 / 取消收藏
4. 移动到项目
5. 删除

要求：

- 侧边栏预览区和“全部任务”弹窗中的任务项行为一致
- 操作后侧边栏状态即时更新
- 不影响现有点击进入会话的主行为

## 3. 非目标

- 不在本轮实现完整权限分享系统
- 不在本轮实现真实项目域模型重构
- 不在本轮增加多选批量操作
- 不改现有会话主路由结构

## 4. 交互方案

## 4.1 触发方式

每个任务会话项增加右键菜单：

- 右键点击打开菜单
- 未来可补 `...` 溢出按钮复用同一菜单逻辑，但第一版不是必须

菜单适用范围：

- 侧边栏预览列表中的会话项
- “全部任务”弹窗中的会话项

## 4.2 菜单项顺序

建议顺序：

1. 分享
2. 重命名
3. 收藏 / 取消收藏
4. 移动到项目
5. 分隔线
6. 删除

原因：

- 分享、重命名属于高频轻操作
- 收藏、项目归档属于管理动作
- 删除放底部并使用危险样式

## 4.3 每个动作的交互

### 分享

第一版建议：

- 打开“分享会话”对话框
- 先只提供“复制会话链接”
- 后续再扩展公开分享、团队分享、权限控制

第一版不直接做复杂分享权限，避免把需求拖入账号系统。

### 重命名

交互：

- 打开小型重命名对话框或 inline input
- 提交后即时更新 sidebar 标题
- 与“自动标题锁定”兼容：手动重命名后，`titleSource = manual`

### 添加到收藏 / 取消收藏

交互：

- 菜单项文案随状态切换：
  - 未收藏：`添加到收藏`
  - 已收藏：`取消收藏`
- 更新后可将收藏会话排序提升

### 移动到项目

交互：

- 打开子菜单或对话框
- 列出可选项目
- 允许“移出项目 / 不归属任何项目”

注意：

- 当前仓库里 task session 尚未和真实 project 建立正式归属关系
- 所以这项需要新增轻量 `projectId/projectName` 归属字段

### 删除

交互：

- 弹确认框
- 删除成功后从 sidebar 中移除
- 若删除的是当前正在查看的 session，需要跳回首页或空白页

## 5. 数据模型

需要为 task session 增加轻量管理字段。

## 5.1 session summary/detail 扩展

建议增加：

- `isFavorite?: boolean`
- `projectId?: string | null`
- `projectName?: string | null`
- `shareEnabled?: boolean`
- `shareToken?: string | null`

说明：

- `isFavorite` 用于收藏显示与排序
- `projectId/projectName` 用于“移动到项目”
- `shareToken` 只作为第一版复制链接的轻量能力

## 5.2 标题来源兼容

已有标题锁定字段：

- `titleLocked`
- `titleSource`
- `titleResolvedAt`

右键重命名后：

- `titleLocked = true`
- `titleSource = manual`

后续自动标题逻辑不可再覆盖。

## 6. API 设计

## 6.1 重命名

新增：

- `POST /api/task-creation/sessions/:sessionId/title/rename`

请求：

```json
{
  "title": "新的标题"
}
```

行为：

- 更新 session.title
- 写入 `titleLocked=true`
- 写入 `titleSource=manual`

## 6.2 收藏切换

新增：

- `POST /api/task-creation/sessions/:sessionId/favorite`

请求：

```json
{
  "favorite": true
}
```

## 6.3 移动到项目

新增：

- `POST /api/task-creation/sessions/:sessionId/project`

请求：

```json
{
  "projectId": "xxx",
  "projectName": "oneceo.ai"
}
```

支持移出：

```json
{
  "projectId": null,
  "projectName": null
}
```

## 6.4 分享

第一版建议：

- `POST /api/task-creation/sessions/:sessionId/share`

返回：

```json
{
  "shareUrl": "https://.../shared/session/xxx",
  "shareToken": "xxx"
}
```

第一版允许只做“生成或复用 share token + 复制链接”，不做复杂权限页面。

## 6.5 删除

复用已有：

- `DELETE /api/task-creation/sessions/:sessionId`

## 8. 排序策略

新增收藏后，建议侧边栏排序调整为：

1. 收藏优先
2. 再按 `updatedAt` 倒序
3. 同时间保持原顺序

如果不想让收藏改变排序，也可以只加图标标记。  
建议第一版就做“收藏优先”，这样收藏才有真实价值。

## 9. 分阶段建议

为避免一次引入太多后端能力，建议分两阶段：

### 阶段 1

真实实现：

- 重命名
- 收藏 / 取消收藏
- 删除
- 右键菜单骨架

原因：

- 这三项都能在现有 session 模型上直接落地
- 风险低、用户价值高

### 阶段 2

扩展实现：

- 分享
- 移动到项目

原因：

- 当前仓库尚无 task session 级分享与项目归属的现成能力
- 如果强行一次做完，后端边界会扩散

## 10. 风险

### 10.1 分享能力过度设计

如果第一版直接做复杂分享权限，会把需求拖进认证/鉴权系统。

结论：

- 第一版只做复制链接

### 10.2 项目归属与现有 mock project 混用

当前 sidebar/project 体系有一部分仍偏前端 mock 结构。

结论：

- `移动到项目` 第一版只做轻量 session metadata 归属
- 不做深层项目系统联动

### 10.3 菜单与点击导航冲突

右键菜单不能破坏左键进入会话。

结论：

- item 主区域保留 left click 导航
- context menu 仅拦截右键

## 11. 验收标准

### 用例 1

右键某任务项，菜单中能看到：

- 分享
- 重命名
- 添加到收藏 / 取消收藏
- 移动到项目
- 删除

### 用例 2

重命名后：

- sidebar 即时显示新标题
- 刷新后标题仍存在
- 自动标题逻辑不再覆盖

### 用例 3

收藏后：

- 菜单文案切为“取消收藏”
- 列表顺序或样式变化符合设计

### 用例 4

删除当前会话后：

- sidebar 移除该项
- 当前页面跳出已删除会话

## 12. 当前建议

建议按“两阶段”推进：

第一阶段先做：

- 右键菜单骨架
- 重命名
- 收藏/取消收藏
- 删除

第二阶段再做：

- 分享
- 移动到项目

如果要一次性全做，也可以，但需要接受后端接口范围会显著扩大。
