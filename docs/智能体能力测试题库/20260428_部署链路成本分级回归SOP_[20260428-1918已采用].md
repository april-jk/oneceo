# 部署链路成本分级回归 SOP [20260428-1918已采用]

## 1. 目的

部署链路验证必须同时控制两个目标：

- 稳定性：部署工具、模板适配、Umami 继承、状态 reducer 的改动必须有证据。
- 成本：真实 Railway 部署有资源成本，不能把全量真实部署矩阵作为每次小改动的默认动作。

因此部署相关改动按风险分级执行回归。

## 2. 风险分级

### 低风险

范围：

- 只改文档。
- 只改展示文案。
- 只改不影响工具调用的 prompt 描述。

必跑：

- `git diff --check`
- 相关文档或 prompt 单测，若没有对应单测则说明未跑原因。

不默认跑：

- 真实 Railway 部署。

### 中风险

范围：

- 模板归一化。
- `oneceo.manifest.json` / `railway.json` 生成逻辑。
- Umami bootstrap 注入。
- template compliance 检查。
- project profile 扫描。

必跑：

- `pnpm --filter api exec tsx --test tests/deployment-template-baseline-service.test.ts tests/task-session-project-profile-service.test.ts tests/deployment-flow-reducer-service.test.ts`
- `pnpm --filter api exec tsc --noEmit`
- `git diff --check`

可选：

- 本地 preview / Playwright 检查一个代表形态。

不默认跑：

- 真实 Railway 部署，除非改动影响 public URL 可达性或 Railway config 主链。

### 高风险

范围：

- `deploy_application` / `redeploy_application` / `rollback_application_deployment` 工具行为。
- Railway 发布动作。
- 部署状态同步。
- 部署 reducer 完成判定。
- analytics binding 写入环境变量。

必跑：

- 中风险全部项目。
- 部署工具单测：`tests/altus-managed-deployment-tool-service.test.ts`
- 运行协调器部署完成判定相关单测：`tests/altus-run-coordinator.test.ts`
- 一个真实部署 smoke。选择本次改动影响最大的 runtime，不跑全矩阵。

### 重大发布

范围：

- 部署资源模型调整。
- Railway provider 层大改。
- 多 runtime 判断边界重构。
- Umami binding 主链重构。

必跑：

- 高风险全部项目。
- 多形态真实部署矩阵，至少覆盖：
  - static HTML
  - frontend dist
  - Node HTTP
  - Python Web
  - PHP 站点

## 3. 输出格式

每次部署链路回归结果必须记录：

```json
{
  "riskLevel": "low | medium | high | release",
  "selectedCases": [],
  "realDeployExecuted": false,
  "skippedRealDeployReason": "本次为中风险模板归一化改动，真实部署成本较高且未触及 Railway 发布动作",
  "commands": [],
  "failures": [],
  "evidence": []
}
```

## 4. 判定规则

- 如果真实部署没有跑，必须写明成本理由。
- 如果部署工具或 reducer 被改动，不能只跑模板测试。
- 如果 Railway 发布或 analytics binding 被改动，至少跑一个真实部署 smoke。
- 如果 public URL 未验证 200，不能宣称线上部署成功。
