# 2026-04-07 #36 Altus 澄清补充信息重复显示回归测试

## 1. 测试目标

验证 Altus managed 模式下，assistant 文本与 `clarification_request` 文本仅存在中英文边界空格差异时，前端能够判定为同一语义并去重，仅保留一条澄清卡片。

## 2. 测试依据

1. `docs/agent研发文档/20260406_Altus澄清问题重复发送修复方案_[20260406-1931已采用].md`
2. Issue `#36`

## 3. 测试单元清单

1. `mergeRealtimeMessage(...)` 在 `clarification_request` 到达时触发同 run 去重
2. `normalizeClarificationComparableText(...)` 与“空白无关语义键”生成逻辑
3. `stripDuplicateManagedAssistantForClarification(...)` 对空格差异文本的匹配行为
4. `Sidebar` 会话条目的 `waiting_user` 视觉状态（文案颜色与左侧图标）

## 4. 预期输入与预期输出

### 单元 1

- 输入：
  - 先收到 `agent_message`：`Supabase连接器`（无空格）
  - 后收到 `clarification_request`：`Supabase 连接器`（有空格）
  - 两条消息 `runId` 相同
- 预期输出：
  - 合并后只保留 `clarification_request`
  - 重复 assistant 文本被移除

### 单元 2

- 输入：
  - 文本 A：`通过Supabase 项目控制台`
  - 文本 B：`通过 Supabase 项目控制台`
- 预期输出：
  - 比较语义键一致
  - 命中去重条件

### 单元 3

- 输入：
  - 文本语义不同（非仅空格差异）
- 预期输出：
  - 不触发误去重
  - 原有消息保留

### 单元 4

- 输入：
  - 侧边栏会话状态为 `waiting_user`
  - 随后状态切回 `in_progress`
- 预期输出：
  - `waiting_user` 时显示 warning 色“待补充”+ 虚线圆图标
  - 切回 `in_progress` 后恢复默认文案颜色和默认图标

## 5. 边界条件与失败条件

### 边界条件

1. 中文+英文混排，空格仅出现在英文词与中文之间
2. 同一个 run 内存在多条 assistant 段消息
3. `clarification_request` 与 assistant 文本前后到达

### 失败条件

1. 空格差异场景仍出现两条重复提示
2. 非同义文本被误删
3. 去重后保留了 assistant 文本而丢失 `clarification_request`

  - `pnpm --filter web exec vitest run client/src/tests/sidebar-session-status-visual.test.ts`
2. 判定规则：
