# 2026-03-20 管理后台界面与布局优化设计

## 目标

对 `apps/admin_management/web` 现有管理后台进行一次完整的界面与布局优化，重点解决以下问题：

- 页面信息密度高但层级弱，用户进入页面后难以快速判断“先看哪里、先做什么”。
- 五个主页面共用一套近似平铺卡片布局，缺少页面级别的结构差异，导致不同业务场景辨识度低。
- 操作入口、状态摘要、图表和明细表经常混排在同一视觉层，缺少主次关系。
- 会话详情、Sandbox 详情等复杂页面缺少稳定的二级导航与分区机制，浏览成本高。
- 当前前端实现几乎集中在 `apps/admin_management/web/src/App.tsx`，样式集中在 `apps/admin_management/web/src/styles.css`，UI 规则未文档化，后续维护容易失真。

本次优化只调整管理后台 Web 的信息架构、视觉表达、交互密度和页面布局，不改后端接口语义，不新增业务能力。

## 现状范围

当前管理后台主页面如下：

- `KVM 管理`
- `对话管理`
- `智能体管理`
- `执行环境管理`
- `审计日志`

当前主要实现文件：

- `apps/admin_management/web/src/App.tsx`
- `apps/admin_management/web/src/styles.css`
- `apps/admin_management/web/src/components/KvmControlCenter.tsx`

## 设计原则

### 1. 保持“运维控制台”而不是“通用后台模板”

本后台承载的是运行态观测和操作，不适合做成普通 CRM 风格。界面方向采用“亮色商务控制台 + 清晰信息层级”：

- 亮色底板与弱对比层次并存
- 状态色强语义
- 指标、列表、时间线各自有独立视觉区块
- 保留专业感，但避免过重装饰和炫技

### 2. 统一页面骨架

所有一级页面统一为三层结构：

1. 全局导航层：左侧导航栏，承载主模块切换
2. 页面上下文层：顶部页面头部，展示标题、说明、刷新动作、页面级切换器
3. 页面内容层：按“摘要 -> 主工作区 -> 次级明细”展开

### 3. 强化视觉语义

- 指标卡只承载“摘要结果”，不混入复杂操作
- 图表区只承载趋势和分布，不承担主操作
- 表格区只承载批量浏览、筛选、进入详情
- 危险动作统一使用显著 danger 语义，并和主 CTA 分离

### 4. 响应式与可读性

- 桌面优先，但在中窄屏下必须能自然降为单列
- 避免大面积横向滚动；必要时只在数据表内部横滚
- 所有表单、按钮、切换器保持稳定高度和焦点态

## 统一视觉系统

### 颜色

- 页面底色改为高亮度冷灰与浅蓝层次，保持商务感和阅读效率
- 主强调色：青绿，用于在线、主按钮、关键高亮
- 次强调色：蓝色，用于链接、筛选激活、辅助图表
- 警告色：琥珀
- 危险色：红
- 卡片表面分成三级：页面背景、普通面板、强调面板

### 字体

- 标题使用更紧凑、更有控制台气质的无衬线字重
- 技术字段、ID、时间戳继续使用等宽字体
- 页面标题、区块标题、字段标题、辅助说明建立固定字号层级

### 阴影与圆角

- 减少当前偏“营销页”式的漂浮阴影
- 统一为低位移、低模糊的结构性阴影
- 外层容器圆角大于内层模块，形成稳定嵌套层级

### 动效

- 保留轻量淡入和悬浮反馈
- 禁止造成布局抖动的过度位移动画
- 页面切换只保留 150-220ms 的透明度/轻位移动画

## 信息架构调整

### 全局导航

- 左侧导航保留，但增强品牌区、环境标识、当前模块高亮
- 导航项从“纯按钮列表”调整为“图标 + 标题 + 功能摘要”的稳定导航块
- 当前激活态增加左侧强调条和更明确的背景对比

### 顶部页面头部

统一包含：

- 面包屑/模块归属
- 页面标题
- 页面说明
- 服务在线状态
- 页面级切换器
- 刷新按钮
- 最后更新时间

其中“页面级切换器”只在相关页面出现，如 KVM/Sandbox 双模式切换。

## 各页面布局方案

### 1. KVM 管理

目标：先看整体资源，再看宿主机，再看 VM 操作。

布局顺序：

1. 摘要指标条
2. 宿主机容量卡片网格
3. 趋势/分布图表区
4. VM 明细表
5. 控制中心

调整重点：

- 宿主机卡片改为更强的信息模块化布局，状态、容量、心跳、趋势分区明确
- KPI 区从“均质四卡”改为“主指标 + 次指标”层级
- VM 表格增加更清晰的行状态和操作区，不再与摘要区抢主视觉

### 2. 对话管理

目标：左侧选会话，右侧先掌握会话状态，再深入全链路信息。

布局顺序：

1. 左侧会话索引列
2. 右侧详情工作区
3. 详情内部分区：
   - 会话摘要
   - 状态流转
   - 时间线
   - 消息
   - LLM 调用
   - KVM / Sandbox 状态

调整重点：

- 右侧详情顶部新增摘要卡区，先显示会话状态、阶段、运行绑定和关键阻塞信息
- 复杂筛选区与状态流转区独立成一个“分析面板”，避免与消息流混在一起
- 时间线、消息、调用轨迹采用更稳定的区块标题和内容边界
- 下载会话详情按钮放在详情页头部操作区，不再与正文混排

### 3. 智能体管理

目标：先看服务可用性，再看能力分布。

布局顺序：

1. 服务健康摘要
2. 能力覆盖卡片
3. 关键图表

调整重点：

- 让 KPI 和能力卡视觉上明显区分
- 能力状态使用统一徽标体系，避免页面显得像临时拼装

### 4. 执行环境管理

目标：运行中 Sandbox 与模板管理分离，详情查看更聚焦。

布局顺序：

1. 顶部模式切换（运行实例 / 模板）
2. 摘要指标
3. 当前主工作区
4. 明细详情弹层

调整重点：

- 运行实例页强调“在线状态、容量、可操作项”
- 模板页强调“模板列表、构建记录、模板动作”
- 详情弹层改为更明确的 inspector 风格，头部固定摘要，正文分 tab 浏览
- 工具执行区、构建日志区使用代码面板风格，减少普通表单感

### 5. 审计日志

目标：快速浏览最近操作，并能一眼识别成功/失败。

布局顺序：

1. 日志摘要
2. 日志列表

调整重点：

- 列表项按时间和结果强化视觉对比
- 成功/失败状态采用统一结果标签
- 后续如果需要扩展筛选，此页面保留顶部筛选条插槽

## 组件级约束

### 指标卡

- 分为 `summary`, `status`, `warning` 三种视觉变体
- 指标数字与说明文字层级固定
- 不在指标卡内放超过一个主操作

### 面板

- 面板头部统一：标题、说明、动作区
- 面板正文统一内边距和栅格
- 同一页面内的面板间距固定，不允许局部自定义漂移

### 表格

- 表头吸附风格保持轻量，不做重边框
- 行 hover 与选中态分离
- 操作按钮尺寸统一，危险操作和普通操作颜色分离

### 状态标签

- 统一 pill 样式规则
- 同一语义状态在不同页面保持同色，不允许重复定义

## 实现策略

本轮实现遵循最短路径，不做过度拆分重构，但会进行必要的前端结构整理：

1. 保留现有接口调用与页面功能
2. 优先整理 `styles.css` 的设计 token、布局层和通用组件样式
3. 在 `App.tsx` 内按页面区块重组 DOM 结构
4. 仅在必要时抽取少量通用展示组件，避免一次性大拆文件引入额外回归风险

## 不在本次范围

- 不改后端 API
- 不新增新的业务页面
- 不改 KVM / Sandbox / Agent 具体业务逻辑
- 不引入新的大型 UI 框架
- 不做兼容旧视觉与新视觉并存的双轨方案

## 验收标准

- 一级页面均具备明确的“摘要 -> 主内容 -> 明细”层级
- KVM、对话、Sandbox 三个复杂页面的阅读成本明显下降
- 页面在 1280px 以上桌面宽度下层级稳定，在中等宽度下不会出现主布局崩坏
- 所有按钮、输入框、切换器、标签风格统一
- 不改变现有业务接口和核心交互能力
