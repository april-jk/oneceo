# 20260522 Altus语音输入 火山ASR接入方案 [20260522-1715已采用]

## 背景

当前 `oneceo` 在对话输入框右下角已经有麦克风按钮占位，但没有真正实现语音输入能力。  
这次目标不是做完整的“语音秘书系统”，而是给 Altus / task-creation 主输入框补齐一条最短、稳定、可直接上线迭代的语音转文字链路。

用户明确要求：

1. 使用字节跳动 / 火山引擎语音识别 API。
2. 参照 `AgentLine` 项目里已经实现过的语音转文字逻辑。
3. 在 `oneceo` 中实现“通过语音输入快速生成任务输入”。

## 设计原则

1. 不把 `AgentLine` 整套 Voice Secretary 搬进来。
2. 只复用已经验证过的“录音 + 火山 ASR”实现方式。
3. 不新造第二套任务编排入口。
4. 语音输入的最终结果必须回到 `oneceo` 现有输入框与发送链路。
5. 配置方式遵循 `oneceo` 现有规则，优先走 `.env` / `process.env`，不引入 `AgentLine` 的 server settings 页面依赖。

## 最终采用方案

### 1. 前端录音方式

沿用 `AgentLine` 的思路：

- 浏览器点击麦克风后请求麦克风权限
- 使用 `AudioContext + ScriptProcessorNode` 采集音频
- 前端直接转为 `16k / mono / wav`
- 同时使用 Web Speech API 做实时转写上屏
- 同时通过 `/ws/task-creation/voice/asr` API WebSocket 代理把 PCM 小包送入服务端流式识别接口
- 停止录音后将 wav blob 和实时转写文本一起交给 `oneceo` API，并把最终文本回填到输入框

原因：

- 这是 `AgentLine` 已验证的链路
- 用户说话时可以立即看到输入框内容变化，符合 AgentLine 的实时语音体验
- 浏览器不能直接给上游 WebSocket 加鉴权 header，因此由 API 层验证当前用户会话后再代理并注入鉴权头
- 后端仍保留服务端 ASR 最终确认链路
- 当服务端最终确认暂时失败时，本次任务输入不能因为上游错误直接 502

### 2. 后端转写方式

新增一条 task-creation 域内接口：

- `POST /api/task-creation/voice/transcribe`

职责：

- 接收前端上传的 `audio` 文件
- 使用火山引擎 ASR 转写
- 接收前端实时转写得到的 `clientTranscript`
- 服务端最终确认成功时返回服务端识别文本与置信度
- 服务端最终确认失败但已有实时转写文本时，返回实时转写文本，避免用户侧出现 502
- 结束识别后只回填文本，不自动发送，由用户手动确认后点击发送

### 3. 火山引擎接入方式

后端直接参照 `AgentLine/packages/server/src/voice-secretary/volcengine-speech.ts`：

- 支持 HTTP flash endpoint
- 支持 WebSocket `bigmodel_nostream`
- 保留 `AgentLine` 中已经验证过的鉴权与协议处理方式
- WebSocket 音频发送按流式协议拆成约 200ms PCM 包，并在最后一包标记结束
- 服务端错误只进入日志与通用错误处理，不在用户界面暴露供应商名称
- `/api/task-creation/voice/transcribe` 不再把上游最终确认失败直接暴露为 502；已有实时文本时返回实时文本，没有实时文本时返回空文本给前端做通用提示

### 4. oneceo 里的发送行为

语音转写成功后：

- 将识别文本作为当前输入框内容回填
- 用户可以继续手动修改
- 最终仍由用户点击发送按钮进入现有发送逻辑

也就是说：

- 语音输入只是“文本输入来源”发生变化
- Altus / task creation 主流程本身不改语义

### 5. 实时转写与最终确认的关系

本轮按 AgentLine 的实际交互拆成两层：

- 实时层：浏览器 Web Speech API 负责录音过程中的实时上屏，让用户看到正在说出的任务内容。
- 流式层：浏览器把 PCM 小包通过 `/ws/task-creation/voice/asr` 代理送入流式识别接口，API 先验证当前用户会话，再转发到上游并把实时文本返回输入框。
- 最终层：后端服务端 ASR 负责停止录音后的最终确认；如果该层暂时失败且实时层已有文本，则本次任务仍使用实时层文本完成回填。

这样可以同时满足“点击录音后有状态、说话时实时出现文字、结束后得到可编辑文本”和“服务端保留正式 ASR 接入”的要求。

## 环境变量方案

`oneceo` 本次采用专用环境变量：

- `ONECEO_VOLCENGINE_ASR_APP_ID`
- `ONECEO_VOLCENGINE_ASR_ACCESS_TOKEN`
- `ONECEO_VOLCENGINE_ASR_SECRET_KEY`
- `ONECEO_VOLCENGINE_ASR_ENDPOINT`

原因：

- 与 `oneceo` 现有 `.env` 体系保持一致
- 不把 `AgentLine` 的后台设置系统移植进来
- 本地 / staging / product 可以按 `oneceo` 现有环境分层加载

## 风险与边界

1. 浏览器录音权限会受到用户系统权限影响
2. WebSocket ASR endpoint 依赖当前火山鉴权配置可用
3. 语音输入会影响待发送文本，因此 UI 上必须保持“点击开始录音，点击结束识别，手动确认后发送”的明确交互

## 验证方式

1. 本地登录后进入 `/new-task`
2. 点击输入框右下角麦克风
3. 说一句完整任务，例如“帮我做一个产品发布页”
4. 再点一次麦克风结束录音
5. 观察是否：
   - 成功调用后端转写
   - 输入内容被送入现有任务链路
   - 会话正常进入 Altus 处理状态

## 采用结论

采用该方案进入实现。核心原则是：

> 复用 `AgentLine` 已验证的火山 ASR 接入方式，但只在 `oneceo` 中接入“语音转文字并直接发任务”这一条最小必要链路。
