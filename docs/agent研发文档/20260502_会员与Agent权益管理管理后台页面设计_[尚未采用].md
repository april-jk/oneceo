# 20260502 会员与Agent权益管理管理后台页面设计 [尚未采用]

## 1. 设计目标

本文件定义管理后台的会员管理页面布局、操作流和交互状态，目标是让管理员能快速维护会员类型、分配用户会员并复核变更记录。

## 2. 导航位置

建议在管理后台新增独立导航组：

- 会员管理

建议下挂四个入口：

1. 会员类型
2. 用户会员
3. 权益矩阵
4. 变更记录

## 3. 页面结构

### 3.1 会员类型页

内容：

- 会员类型表格
- 创建按钮
- 编辑/停用操作
- 默认积分展示
- Agent tier 展示

### 3.2 用户会员页

内容：

- 用户搜索
- 当前会员类型
- 到期时间
- 可用 Agent
- 分配/变更按钮

### 3.3 权益矩阵页

内容：

- 会员类型行
- Agent tier 列
- 默认积分列
- 其他权益列

### 3.4 变更记录页

内容：

- 操作人
- 动作类型
- 目标对象
- 变更前后
- 时间戳

## 4. 关键交互

### 4.1 创建会员类型

弹窗字段：

- code
- name
- 默认积分
- 可用 Agent tiers
- 权益项
- 状态
- 生效时间

### 4.2 编辑会员类型

编辑时建议采用“新记录 + 旧记录停用”的方式，保留历史版本。

### 4.3 分配用户会员

操作流：

1. 搜索用户
2. 选择会员类型
3. 选择有效期
4. 确认是否补发默认积分
5. 提交后显示审计结果

### 4.4 到期处理

到期用户应在列表里明确标记为：

- 已到期
- 已降级
- 待处理

## 5. 状态展示

建议使用以下状态标签：

- `active`
- `inactive`
- `expired`
- `pending`
- `manual_override`

## 6. 错误与反馈

1. 创建失败：显示后端错误码对应文案
2. 分配失败：突出冲突原因
3. 默认积分发放失败：提示可重试
4. 审计查询失败：提示只读数据加载失败

## 7. 与现有后台的整合

建议和现有计费管理并列，不嵌套在计费页面里。

原因：

1. 会员是权限层
2. 计费是账务层
3. 两者联动但职责不同
