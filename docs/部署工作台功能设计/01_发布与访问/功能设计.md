# 发布与访问功能设计

## 1. 功能定位

“发布与访问”是部署工作台的默认二级页，承担最核心的闭环：

- 发布新版本
- 查看当前状态
- 打开网站
- 查看历史版本
- 查看发布日志

## 2. 页面结构

建议保持以下信息块：

- 顶部发布摘要卡
- 当前访问地址
- 快速操作区
- 版本时间线
- 当前版本详情
- 资源状态
- 发布日志

## 2.1 2026-04-17 排版调整补充

本轮针对“发布与访问”标签卡补充以下 UI 约束：

- `overview` 首屏优先保证一页展示完成，避免在同一视图内依赖上下滚动阅读主信息。
- 页面主结构调整为“访问卡 + 发布卡”纵向堆叠布局：
  - 顶层不使用并排双列，避免在预览面板等窄容器中出现横向溢出与遮挡。
  - 访问卡负责状态、主地址、快捷动作、访问入口。
  - 状态标题右侧内联放置 `发布 / 重发 / 回滚` 三个紧凑按钮，不再单独占一整行，并优先保证同行展示不换行。
  - 发布卡负责当前版本、发布记录、发布日志。
- `资源状态` 从 `overview` 中移除，不再占用首屏空间；相关资源信息保留在其它部署视图中展示。
- `发布记录` 默认只展示精简摘要，允许用户手动展开查看更多历史记录，但展开后的每条记录仍只保留状态、时间、版本说明等必要信息。
- `发布日志` 保持简洁，优先展示当前版本相关内容，不与资源说明混排。

## 3. 数据依赖

当前可复用的数据：

- `configured`
- `canDeploy`
- `latestStatus`
- `deployments`
- `domains`
- `logs`
- `project/service/environment`

补充约束：

- 当前页如果持有已失效的历史 `deploymentId`，接口层需要自动回退到当前仍存在的最新有效版本，不能因为旧选择失效直接返回 500。

后续建议新增的数据：

- 明确的阶段态字段
- 最近一次成功发布时间
- 部署来源摘要
- 回滚可用性标记

## 4. 计划设计方式

### 当前阶段

- 保持“发布工作台”作为默认页。
- 继续强调主访问地址与主操作按钮。
- 版本历史改为卡片式而不是纯下拉选择。

### 下一阶段

- 增加分步骤状态条：准备资源、同步源码、构建、发布成功。
- 增加发布完成后的成功反馈区。
- 为首次发布和更新发布区分不同文案。

## 5. 审核点

- 默认页是否继续叫“发布”，还是改回“概览”。
- 日志和版本详情是否应该继续同屏显示。
