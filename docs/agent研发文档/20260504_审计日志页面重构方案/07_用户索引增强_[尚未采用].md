# 审计日志用户索引增强方案 [20260505-补充]

## 更新时间

2026-05-05

## 背景

当前审计日志页面的 L1 用户索引仅为简单表格，一次性拉取 200 条用户，无搜索、筛选、排序、分页能力。随着用户量增长，管理员难以快速定位目标用户。

## 目标

为用户索引页增加完整的检索与导航能力，使其能支撑千级用户规模的高效治理。

## 功能范围

### 1. 搜索

- 按邮箱、用户名称、用户 ID 关键词实时搜索
- 输入防抖（300ms），即时刷新列表

### 2. 筛选

- **状态**：全部 / 正常 / 已禁用
- **时间范围**：全部 / 最近 24 小时 / 最近 7 天 / 最近 30 天（筛选有审计记录的用户）

### 3. 排序

- 注册时间（默认倒序）
- 用户名称（字母序）
- 最近活动（倒序）

### 4. 分页

- 每页 20 条
- 底部页码导航 + 上一页/下一页
- 总条数显示

### 5. 统计摘要

- 总用户数
- 正常/禁用用户数
- 今日新增用户数

### 6. 列表字段增强

| 列 | 说明 |
|---|---|
| 用户 | 名称 + 邮箱 |
| 状态 | active / disabled 彩色标签 |
| 注册时间 | `createdAt` 格式化 |
| 最近活动 | 最后请求时间（如有） |
| 操作 | 「查看审计日志」按钮 |

## 技术方案

### 前端

复用现有 `api.listAppUsers()`，该接口已支持：
- `query`: 关键词搜索
- `status`: 状态筛选
- `sortKey` / `sortDirection`: 排序
- `limit`: 分页限制（但缺少 `offset`，需要前端分页或后端补充）

由于现有 API 返回全部匹配结果（limit 默认 200），前端在结果量较小时做内存分页；若用户量超过 200，再升级后端支持 `offset` 参数。

### 样式

复用现有审计日志设计系统：
- `.audit-filter-grid` 筛选栏
- `.audit-table` 表格
- `.status-pill` 状态标签
- 保持与用户管理页面一致的紧凑高密度布局
