# 20260418 用户态主题外观设置功能方案 [20260418-1835已采用]

更新时间：2026-04-18 18:35

## 1. 背景

当前用户态前端虽然存在 `ThemeContext` 与“设置 -> 设置 -> 主题”入口，但两者并未接通：

1. `ThemeContext` 只支持 `light/dark`
2. `App.tsx` 未开启 `switchable`
3. `SettingsDialog.tsx` 内部维护了一份独立的本地 `theme` 状态
4. Toast 组件仍从 `next-themes` 读取主题，和当前项目的自定义主题上下文不是同一条链路

这会导致用户在设置页切换主题后，页面外观并不会真实变化，属于假功能。

## 2. 本次目标

本次只做用户态页面主题能力收口，不做额外扩展：

1. 支持 `light`、`dark`、`system` 三种主题模式
2. 让 `设置 -> 设置` 成为真实可用的主题切换入口
3. 将主题选择持久化到浏览器本地存储
4. 保证全局页面、弹窗、Toast 跟随同一主题源

## 3. 不做的内容

为了避免过度设计，本次明确不做：

1. 不新增服务端用户级主题配置
2. 不新增更多主题配色方案
3. 不改动 AI 实时生成内容本身
4. 不对管理后台 `apps/admin_management` 做主题改造

## 4. 设计方案

### 4.1 单一主题源

统一以 `apps/web/client/src/contexts/ThemeContext.tsx` 作为唯一主题状态源，提供：

1. `theme: light | dark | system`
2. `resolvedTheme: light | dark`
3. `setTheme()`
4. `toggleTheme()`

其中：

1. `theme` 表示用户选择
2. `resolvedTheme` 表示系统解析后的实际渲染主题

### 4.2 系统主题跟随

当用户选择 `system` 时：

1. 监听 `prefers-color-scheme: dark`
2. 动态计算 `resolvedTheme`
3. 将 `html.dark` 与 `color-scheme` 保持同步

### 4.3 持久化策略

继续使用本地存储键 `theme`：

1. 已存在旧值 `light/dark` 时继续兼容
2. 新增 `system`
3. 当本地无值时使用应用默认值

### 4.4 设置页样式

`设置 -> 设置` 中的主题入口改为“外观”卡片选择器，提供：

1. 浅色
2. 深色
3. 跟随系统

样式参考用户给出的三张外观预览卡，但实现上采用项目内原生 JSX/CSS 预览，不依赖外部图片资源，避免远程资源失效影响设置页可用性。

### 4.5 统一下游消费

需要同时切换到同一主题源的用户态组件：

1. `App.tsx`
2. `SettingsDialog.tsx`
3. `components/ui/sonner.tsx`

## 5. 影响范围

文件范围：

1. `apps/web/client/src/contexts/ThemeContext.tsx`
2. `apps/web/client/src/App.tsx`
3. `apps/web/client/src/components/SettingsDialog.tsx`
4. `apps/web/client/src/components/ui/sonner.tsx`
5. `apps/web/client/src/locales/zh.json`
6. `apps/web/client/src/locales/en.json`

至少完成以下验证：

3. 页面根节点 `html.dark` 会跟随切换

## 7. 深色模式逐页整改补充

在主题切换能力接通后，需要继续做一次用户态页面级深色模式收口，避免出现“主题已切换，但页面局部仍保留浅色卡片/浅色文字”的问题。

### 7.1 巡检方式

必须使用 Playwright 逐页检查用户态路由，包括但不限于：

1. `/`
2. `/login`
3. `/register`
4. `/home`
5. `/search`
6. `/library`
7. `/projects`
8. `/project/:id`
9. `/manager-node`
10. `/manager-view`
11. `/ai-workspace`
12. `/agent-project`
13. `/ceo-view`
14. `/task/:projectId/:managerId/:taskId`
15. `/404`

### 7.2 整改边界

本轮只修正“用户态界面配色不合理”的问题，重点包括：

1. 深色模式下仍然固定 `bg-white` / `text-slate-900` / `bg-slate-50`
2. 浅色警告色在深色背景下对比过强或失衡
3. 面板、表格、预览器、抽屉、空态、加载态在深色模式下层级不清
4. 局部组件未使用主题变量，导致页面出现亮块

不做的内容：

1. 不改变 AI 生成消息、会话内容、业务数据文本本身
2. 不重新设计页面结构
3. 不扩展到管理后台

### 7.3 优先级

优先处理以下直接影响用户主流程的区域：

1. 登录 / 注册 / 鉴权加载页
2. `Home` 主工作区
3. `TaskCreationChat`
4. `OpencodePreviewPanel`
5. `ConnectorCenterPanel`
6. `TaskRuntimeDrawer`
7. 404 与其他独立页面

### 7.4 验证标准

每个页面至少满足：

1. 没有明显浅色底块残留在深色页面主体中
2. 主要文本在深色背景上保持足够对比度
3. 面板边界、分组层级和交互 hover/selected 态仍可识别
4. Playwright 截图可作为逐页验收依据

### 7.5 2026-04-18 会话态补充修复

本轮真实登录态验收中，额外发现并修复了两个高优先级会话态问题：

1. `/session/:id` 底部“继续对话”输入区仍使用固定白底与浅色边框
2. `OpencodePreviewPanel` 的 Files / Changes / Deployment / Debug 主容器和多数组块仍保留浅色表面

对应修复策略：

1. 会话态输入区统一切到 `bg-card`、`border-border`、`text-foreground`、`text-muted-foreground`
2. 预览面板主容器、文件树、空态、文件详情、部署工作台等改为主题变量，移除深色模式下显眼的白底卡片
3. 使用真实 `app_session_id` 登录态对会话页执行 Playwright 回归，覆盖：
   - 附件菜单
   - 连接器菜单
   - 模型下拉
   - 预览面板默认态
   - Files / Changes / Debug / Deployment 四个主 tab
   - Deployment 下的 Publish & access / Dashboard / Database / Storage / Settings 子态

说明：

1. `Runtime logs` 抽屉是否可点击依赖当前会话的编排运行时状态
2. 本次验收使用的真实会话在页面初始态按钮为禁用，仅在预览链路挂载后显示 runtime 已连接标记，但抽屉入口仍未开放，因此该项以产品现状记录，不做越权改造
