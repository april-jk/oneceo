# 20260328 内容感知型 Office 生成实现与验证

## 1. 背景

用户反馈当前 `PPT / Word` 结果存在明显同质化问题：

- 不同主题容易落成相似结构
- 风格变化弱，缺少内容驱动的差异化表达
- 更像“同一个模板换标题”，而不是“根据内容选择生成策略”

根据设计文档 [20260328_内容感知型Office生成设计.md](/D:/oneceo-task-creation-agent-fresh/docs/agent研发文档/20260328_内容感知型Office生成设计.md)，本轮按最短路径只修改 `skill + prompt` 两层，不改 UI、不增 connector、不换生成引擎。

## 2. 实现范围

本次仅修改两个核心文件：

- `apps/web/client/src/lib/skill-attachment-templates.ts`
- `apps/api/src/services/altus-managed-prompt-service.ts`

未改动：

- 交付物闭环
- Tavily 联网能力
- managed run 工具集合
- 前端交互入口

## 3. 具体改动

### 3.1 升级 `PPT 办公` skill

在 `office-ppt` 中新增了显式的内容感知规则：

- 生成前必须先识别 `content_archetype`
- 允许的内容原型被限制为：
  - `pitch_deck`
  - `consulting_report`
  - `roadmap_plan`
  - `training_material`
  - `proposal_solution`
  - `research_summary`
  - `product_story`
- 生成前必须先形成 `generation_brief`
- `generation_brief` 至少包含：
  - `artifactType`
  - `contentArchetype`
  - `audience`
  - `goal`
  - `tone`
  - `structureStrategy`
  - `visualStrategy`
  - `evidenceMode`
- 强制从有限 `style_pack` 中选择：
  - `consulting_clean`
  - `executive_formal`
  - `vision_bold`
  - `training_friendly`
- 强制要求页面结构、视觉密度、标题写法、图表类型随原型变化，而不是复用默认 deck

### 3.2 升级 `Word 文档` skill

在 `office-docx` 中新增了显式的内容感知规则：

- 生成前必须先识别 `content_archetype`
- 允许的内容原型被限制为：
  - `business_plan`
  - `formal_report`
  - `proposal`
  - `policy_process`
  - `meeting_memo`
  - `research_brief`
  - `external_statement`
- 生成前必须先形成 `generation_brief`
- 强制从有限 `style_pack` 中选择：
  - `formal_executive`
  - `proposal_professional`
  - `policy_precise`
  - `research_structured`
- 强制不同文档原型使用不同章节顺序、语气和证据模式，而不是统一写成报告体

### 3.3 升级 Altus system prompt

在 `altus-managed-prompt-service.ts` 中新增 Office 专项约束：

- `PPT / DOCX` 任务不得直接跳到文件生成
- 生成前必须先选择唯一 `contentArchetype`
- 生成前必须先形成内部策略 brief
- `PPT` 必须同时选择受限 `style pack`
- `DOCX` 必须同时选择受限 `style pack`
- 明确要求不同 archetype 带来不同结构决策、语气决策和证据组织方式
- 明确禁止把所有 `PPT` 都写成同一种标题加 bullets 页面，也禁止把所有 `Word` 都写成同一种通用汇报体

## 6. 结果判断

这次改动的价值不在于“让模型更自由”，而在于：

- 让 `PPT / Word` 在生成前先做受限决策
- 用有限原型和有限风格包替代单一默认模板
- 在不破坏现有稳定交付链路的前提下，增加内容驱动的差异化

也就是说，本轮解决的是：

- 为什么不同主题总长得像一份文档
- 为什么 skill 明明很多规则，但结果还是同质化

而不是去新增新的生成工具或复杂模板系统。

## 7. 后续建议

下一步最值得观察的不是“能不能生成”，而是“不同主题之间是否已经明显分流”。建议优先对比：

- `职业规划 PPT`
- `商业计划书路演 PPT`
- `内部培训课件`

以及：

- `商业计划书 DOCX`
- `会议纪要 DOCX`
- `制度流程 DOCX`

如果这几类结果的结构、语气和视觉组织仍然过于相似，再继续精修 archetype 到 slide/section 的映射，而不是回退到增加更多泛化规则。
