# 20260418 部署状态后台同步与多形态模板发布支持测试方案

## 测试目标

验证两件事：

1. 部署面板状态由后台同步任务推进，而不是由读请求实时向 Railway 拉取。
2. 部署模板基线可覆盖 HTML / JS / Node / Python 等形态，并能产出稳定的部署契约。

## 测试单元

### 1. 部署状态后台同步

#### 单元 1.1 `buildTaskSessionDeploymentResponse()`

- 预期输入：
  - 环境 metadata 内已有 `deploymentPanel` / `deploymentState`
- 预期输出：
  - 直接返回快照
  - 不依赖读请求同步 Railway
- 失败条件：
  - 无快照时仍触发 provider 实时查询
- 验证方式：
  - 代码级检查
  - 类型检查与调用链核对

#### 单元 1.2 `enqueueTaskSessionDeploymentSync()`

- 预期输入：
  - `taskSessionId`
  - `orchestratorSessionId`
  - `selectedDeploymentId`
- 预期输出：
  - 会话进入后台同步队列
- 失败条件：
  - 队列未写入
  - 更早的同步请求被更晚时间覆盖
- 验证方式：
  - 代码级检查

#### 单元 1.3 `startTaskSessionDeploymentSyncJob()`

- 预期输入：
  - API 启动
- 预期输出：
  - 定时任务启动
  - backlog 可恢复
- 失败条件：
  - API 启动后无同步任务
- 验证方式：
  - 代码级检查
  - type-check

### 2. 模板基线与归一化

#### 单元 2.1 纯静态 HTML 基线

- 预期输入：
  - 只有 `index.html`
- 预期输出：
  - 自动补 `package.json`、`server.js`、`oneceo.manifest.json`、`railway.json`
- 失败条件：
  - 缺少 start command 或 healthcheck 配置
- 验证方式：
  - 单元测试脚本

#### 单元 2.2 Node.js 脚本基线

- 预期输入：
  - 无 `package.json`
  - 存在 `server.js`
  - 模板 HTML 在 `templates/index.html`
- 预期输出：
  - 自动补 Node baseline
  - manifest/runtime/framework 为 `node_script`
- 失败条件：
  - 仍要求原始 `package.json`
- 验证方式：
  - 单元测试脚本

#### 单元 2.3 Python FastAPI 基线

- 预期输入：
  - `requirements.txt`
  - `main.py`
  - `templates/index.html`
- 预期输出：
  - 自动补 `oneceo.manifest.json`
  - 自动补 `railway.json`
  - start command 为 `uvicorn main:app --host 0.0.0.0 --port $PORT`
- 失败条件：
  - 缺少 start command
  - Bootstrap 不注入模板入口
- 验证方式：
  - 单元测试脚本

#### 单元 2.4 HTML 模板入口扩展

- 预期输入：
  - `templates/index.html`
- 预期输出：
  - `ensureDeploymentTemplateBootstrap()` 能成功注入 analytics bootstrap
- 失败条件：
  - 只支持根目录 `index.html`
- 验证方式：
  - 单元测试脚本

## 验证方式

本轮验证只做：

1. `pnpm --filter api type-check`
2. `pnpm --filter api exec tsx --test tests/deployment-template-bootstrap-service.test.ts tests/deployment-template-baseline-service.test.ts`

若 type-check 或模板基线测试失败，则本轮实现视为未完成。
