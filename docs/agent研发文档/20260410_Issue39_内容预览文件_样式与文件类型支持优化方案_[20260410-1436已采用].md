# 20260410 Issue39 内容预览-文件 样式与文件类型支持优化方案 [20260410-1436已采用]

## 1. 背景

在 Issue #39 已完成“稳定性修复”后，当前「内容预览-文件」仍有两类体验缺口：

1. **样式层**：文件树与右侧预览区布局较朴素，缺少可拖拽宽度、清晰层级图标、路径面包屑和文件动作区，不符合你给出的参考交互密度。
2. **类型层**：目录文件应“全部可见”，但预览范围需明确收敛，避免不同文件类型处理不一致。

本方案作为 Issue #39 的第二阶段优化文档，先确定方向，再进入代码实现。

## 2. 现状核验（代码事实）

1. 前端主实现位于 `apps/web/client/src/components/OpencodePreviewPanel.tsx`，当前 `FilePreview` 为固定左右布局，左栏不可拖拽。
2. 文件树节点目前仅用文本 + 简单符号（`▾/▸`），未按文件类型显示专属图标，也缺少 hover 快捷动作。
3. 右侧顶部信息栏已有基础信息，但缺少“路径分段面包屑 + 统一文件操作按钮组（复制/下载/外链）”的结构化展示。
4. 预览类型目前主要覆盖：
   - `html / markdown / image / video / audio / pdf / text / binary`
5. 后端 `detectPreviewType`（`apps/api/src/routes/task-creation-routes.ts`）已具备基础分类，但前后端仍需统一“仅支持指定类型预览”的边界。
6. 文件列表数据源涉及实时目录与 diff 推导目录，若不做合并会出现“只剩 html”的回归风险（当前分支已在修复中）。

## 3. 优化目标

1. 左侧文件树样式与交互对齐参考实现：可拖拽宽度、层级缩进、展开态、图标与 hover 动作。
2. 右侧预览头部结构化：路径面包屑、文件基本信息、复制/下载/新窗口等操作一致化。
3. 目录内所有文档都可展示，但预览只支持：`html / markdown / image / video / audio / pdf / text / binary`。
4. 二进制文件仅展示文件信息（大小、MIME、路径、下载），不渲染正文内容。
5. 保持文件列表完整展示，不因单一来源缺失导致文件“消失”。

## 4. 非目标

1. 不引入新的独立预览后端服务。
2. 不新增 Office 文档渲染引擎（docx/xlsx/pptx）与复杂三方解析器。
3. 不改会话权限模型与用户归属链路。

## 5. 方案设计（最短路径）

## 5.1 布局与样式重构（参照你给出的结构）

1. 将 `files` 视图改为可拖拽分栏（左树 + 右预览）：
   - 左栏默认 `240px`，最小 `180px`，最大 `420px`
   - 使用现有依赖 `react-resizable-panels`，避免新增库
   - 分隔条做成细线可 hover 高亮样式（与示例的窄拖拽条一致）
2. 左侧树节点结构对齐参考：
   - 统一行高、缩进与圆角 hover 背景
   - 目录节点使用 `ChevronRight/ChevronDown`
   - 文件节点使用扩展名映射图标
   - 行内保留 `group-hover` 右侧快捷动作位（复制路径/外链）
3. 保留移动端降级：
   - `md` 以下改为上下布局，避免水平拖拽交互在小屏失效

## 5.2 文件树交互增强

1. 节点交互：
   - 单击目录展开/收起
   - 单击文件打开预览
   - 当前文件高亮与 hover 态分离
2. 节点 hover 动作：
   - 复制相对路径
   - 在新标签打开 raw（可预览文件）
3. 根目录与分页提示：
   - 保留“加载更多”能力
   - 将提示位置并入目录节点下方，避免打断树层级

## 5.3 右侧预览头部改造

1. 头部显示“路径面包屑”（目录分段 + 当前文件）。
2. 右上统一操作区：
   - 复制内容
   - 下载文件
   - 新窗口打开（支持 raw/preview）
3. 头部副信息：
   - 行数/大小/MIME
   - 当前渲染模式标签（如 `Preview`、`Source`、`Markdown`、`Binary Info`）

## 5.7 样式对齐清单（按你给的示例代码）

实现时必须按以下视觉与交互约束对齐，不做“近似实现”：

1. 左侧文件树区域
   - 节点为紧凑行高（接近示例的 13px 字号 + 紧凑 vertical rhythm）
   - 目录/文件统一使用行内图标槽位，避免文本跳动
   - 选中态为浅底高亮，hover 态弱于选中态
2. 分栏拖拽体验
   - 拖拽条常态细线，hover 明显着色
   - 支持实时拖拽反馈，不做点击后跳变
3. 顶部路径栏
   - 使用分段面包屑（目录段 + `/` 分隔 + 当前文件高亮）
   - 固定高度工具栏，右侧按钮组与面包屑同一水平线
4. 文件操作按钮
   - 图标按钮统一尺寸、圆角和 hover 背景
   - 保持“复制/下载/新窗口”三类动作的一致位置
5. 代码预览区
   - 视觉上保持编辑器风格（独立背景、边界、滚动区）
   - 文本区域与头部工具栏分层清晰，避免样式混叠

## 5.4 文件类型支持矩阵（前后端闭环）

统一渲染矩阵（严格限定在以下类型）：

1. 网页类：`html/htm`
   - `Preview` + `Source` 双视图（保留现有能力）
2. Markdown：`md/markdown/mdx`
   - `Rendered` + `Source` 双视图
3. 文本类：`text`（含常见源码/配置/数据文件统一按文本展示）
   - 纯文本预览（源码视图）
4. 媒体类：`image/video/audio/pdf`
   - 维持现有内嵌预览
5. 二进制类：`binary`
   - 仅展示元数据卡片（路径、MIME、大小、编码状态）+ 下载入口
   - 不显示二进制内容正文，不尝试文本化渲染

## 5.5 API/类型定义同步

1. 后端与前端统一保持现有类型集合：
   - `html / markdown / image / video / audio / pdf / text / binary`
2. `detectPreviewType` 规则收口：
   - 不新增额外 previewType
   - 未命中媒体/markdown/html 的可读文本统一归并为 `text`
   - 无法文本化或超阈值文件归并为 `binary`
3. 前端 `WorkspaceFile.previewType` 渲染分支与上述集合严格一致。

## 5.6 文件列表完整性收口

1. 文件树来源采用“实时目录 + diff 推导目录”合并去重策略，禁止二选一覆盖。
2. 合并后统一排序：目录在前、文件在后、同级按路径字典序。
3. 刷新时保留当前选中文件；若文件确实不存在，再回退到首个可读文件。

## 6. 验收标准

1. 左侧文件树可拖拽宽度，展开/选择/hover 动作稳定可用。
2. 文件树不再出现“只显示 html，其它文件消失”的回归。
3. 预览类型仅限：`html`、`markdown`、`image`、`video`、`audio`、`pdf`、`text`、`binary`。
4. 二进制文件预览只显示信息卡片，不展示二进制正文。
5. 右侧头部具备面包屑与统一操作按钮，移动端不出现布局错位。
6. 异常场景不直接暴露底层技术错误，统一以可恢复文案与操作呈现。

## 7. 测试计划

## 7.1 单元/组件

1. `previewType` 识别映射测试（后端）。
2. 前端渲染矩阵测试：不同 `previewType` 命中正确组件。
3. 树合并函数测试：主树缺失时仍保留 diff 文件，且去重正确。
4. `binary` 分支测试：仅输出信息卡片，不渲染正文。

## 7.2 Playwright 回归

1. 打开内容预览 -> 验证左栏可拖拽、节点展开/收起、文件切换。
2. 分别验证 `html/markdown/image/video/audio/pdf/text/binary` 预览行为。
3. sandbox 关闭后重载预览，验证不出现生硬技术报错文案。
4. 刷新页面与重进 session，验证文件树与当前选中文件恢复行为。

## 8. 实施步骤

1. 重构 `OpencodePreviewPanel` 的 files 布局与树节点样式。
2. 落地文件类型渲染矩阵与右侧头部动作区。
3. 同步后端 `detectPreviewType` 与前端类型定义。
4. 补齐单元测试与 Playwright 回归。
5. 用户验收通过后，将文档状态改为 `[yyyymmdd-hhmm已采用]` 并进入提交阶段。

## 9. 风险与控制

1. 风险：类型判断扩展后误判文本文件。
   - 控制：先按 MIME，再按扩展名，最后回退 `text`。
2. 风险：大二进制文件误进入正文渲染导致卡顿。
   - 控制：二进制统一走信息卡片，禁止正文渲染。
3. 风险：样式改造引入移动端断点问题。
   - 控制：强制保留 `md` 以下纵向布局，并做 Playwright 视口回归。
