# blog 子站建设方案 [20260530-1813已采用]

## 背景

主站 `oneceo.ai` 需要继续保持简洁、产品化，不适合承载持续增长型内容。

为了做工作流案例、使用教程、行业资讯与品牌宣传，需要单独建设博客子站，并与主站保持清晰边界。

## 目标

1. 在 `apps/` 下新增独立的 `blog` 应用目录。
2. 使用成熟现成方案，不从零造博客系统。
3. 支持 `blog.oneceo.ai` 子域名部署。
4. 便于后续直接新增 Markdown/MDX 内容。
5. 对 SEO 友好，但不影响主域名整洁性。

## 技术选择

### 最终选择

- 框架：`Astro`
- 内容格式：`MDX`
- 输出模式：静态站点
- 部署目标：`GitHub Pages`
- 域名：`blog.oneceo.ai`

### 选择理由

- `Astro` 原生适合内容站与博客站。
- 自带良好的静态 SEO 基础能力，适合文章页索引。
- `content collections` 适合后续按 frontmatter 管理文章元数据。
- 和 `GitHub Pages` 配合简单，不需要额外服务端。
- 可以和主站彻底隔离，避免把主站做成内容门户。

## 目录规划

新增：

- `apps/blog/`

建议内部结构：

- `src/content/blog/`：文章内容
- `src/layouts/`：站点布局
- `src/pages/`：首页、列表页、详情页、RSS
- `src/components/`：复用组件
- `public/`：静态资源、`CNAME`

## 信息架构

### 首页

- 最近文章列表
- 子站简介
- 指向主站入口

### 文章列表页

- `/blog`

### 文章详情页

- `/blog/<slug>`

### RSS

- `/rss.xml`

## SEO 规划

### 子站级

- 独立 `robots.txt`
- 独立 `sitemap.xml`
- 子站级 canonical
- `WebSite` 基础结构化数据

### 文章级

- `title`
- `description`
- `published time`
- `tags`
- Open Graph
- Article 结构化数据

### 主站关系

- blog 页面 header / footer 链回 `https://oneceo.ai`
- 主站后续可从页脚或导航挂 `Blog`
- 文章正文可自然链接到主站产品页，但不做硬塞营销区块

## 内容模型

每篇文章 frontmatter 至少包含：

- `title`
- `description`
- `pubDate`
- `updatedDate`
- `tags`
- `heroImage`
- `draft`

## 部署规划

### 第一阶段

- `GitHub Pages`
- `public/CNAME` 写 `blog.oneceo.ai`
- 通过 GitHub Actions 自动构建并发布

### 域名配置

- DNS 中给 `blog.oneceo.ai` 配置到 GitHub Pages
- 同时做 GitHub Pages 自定义域名校验

## 本次落地范围

1. 创建 `apps/blog` 脚手架
2. 补齐 Astro 基础配置
3. 建立 MDX 内容目录
4. 建立示例文章
5. 建立列表页、详情页、RSS、SEO 基础布局
6. 放置 `CNAME` 与部署说明

## 本次非目标

- 不接入在线 CMS
- 不做评论系统
- 不做搜索
- 不做复杂主题系统
- 不把 blog 并入主站应用

## 后续建议

1. 首批优先写工作流和教程类内容
2. 每篇文章都要有明确关键词与目标受众
3. Search Console 中单独观察 `blog.oneceo.ai` 表现
