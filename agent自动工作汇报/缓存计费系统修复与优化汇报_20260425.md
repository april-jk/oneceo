# 缓存计费系统修复与优化汇报（2026-04-25）

## 一、改动概要

本次完成四项计费系统优化，覆盖**管理后台可配置化**、**LLM 缓存 token 真实解析计费**、**数据完整性修复**和**用户端会话积分展示**。

### 功能 1：缓存计费比例后台可调

将原本硬编码在 `pricing-service.ts` 中的缓存计费比例逻辑，改造为管理后台可动态配置，支持即时生效与向后兼容。

**核心改动：**

1. **数据层**：新增 `cache_pricing_config` 表，以千分比整数存储各 provider 的缓存计费比例
2. **服务层**：`pricing-service.ts` 的 `calculateCredits()` 优先读取数据库配置，无配置时回退默认值
3. **API 层**：`internal-billing-routes.ts` 新增缓存比例 CRUD 接口
4. **管理后台**：「定价配置」Tab 新增缓存比例配置卡片

### 功能 2：LLM 缓存 token 解析与计费修复

修复了 LLM Proxy 层 Anthropic 响应类型定义缺失缓存字段的问题，实现从请求到计费的全链路缓存 token 识别。

**核心改动：**

1. **请求构造**：Anthropic 请求自动注入 `cache_control: { type: "ephemeral" }`，触发上游缓存机制
2. **响应解析**：正确提取 `cache_read_input_tokens` 和 `cache_creation_input_tokens` 字段
3. **流式响应**：SSE 流式响应中也支持传递缓存 token 信息
4. **计费层**：`chargeForModelCall` 正确解析 usage 中的缓存字段，按缓存比例计算积分消耗
5. **数据记录**：`token_usage_logs` 正确记录 `cachedPromptTokens` / `nonCachedPromptTokens` / `cacheCreationTokens`

### 功能 3：数据完整性修复（3 个 Bug）

| Bug | 修复内容 | 文件 |
|-----|---------|------|
| 缺少 `CHECK (balance >= 0)` 约束 | 迁移 SQL 追加约束，防止负余额 | `migrate.ts` |
| `lastRechargeAt` 字段未维护 | `initUserCredits` 和 `addCredits` 中设置 `lastRechargeAt` | `billing-service.ts` |
| `getTransactions` count 未过滤 type | count 查询改用 `and(...conditions)` 包含 type 过滤 | `billing-service.ts` |

### 功能 4：用户端会话积分显示

新增 `SessionCreditBar` 组件，在会话页面消息输入框上方显示当前会话的积分消耗、token 数和模型调用次数。

**核心改动：**

1. **新增组件**：`SessionCreditBar.tsx`，调用 `/api/billing/session/:sessionId/usage` API
2. **集成到会话页面**：在 `Home.tsx` 的 Main Input Area 上方渲染
3. **数据展示**：显示已消耗积分、总 tokens、模型调用次数

## 四、技术要点

### 4.1 缓存比例配置存储格式

采用**千分比整数**存储，避免浮点精度问题：

| 字段含义 | 数据库存储 | 业务含义 |
|---------|-----------|---------|
| OpenAI hit rate | `500` | 50.0%（缓存命中按 50% 计费） |
| Anthropic hit rate | `100` | 10.0%（缓存命中按 10% 计费） |
| Anthropic creation rate | `1250` | 125.0%（缓存写入按 125% 计费） |

计算时统一除以 1000 还原为实际比例，确保计费精度。

### 4.2 向后兼容策略

`pricing-service.ts` 中 `calculateCredits()` 的行为：

1. 优先查询 `cache_pricing_config` 表，按 provider 获取对应配置
2. 若表中无该 provider 记录，则回退至硬编码默认值
3. 新增 provider 时，若未配置则默认缓存比例为 0（不享受缓存优惠）

### 4.3 Anthropic 缓存触发机制

在 `llm-proxy-connector.ts` 中，Anthropic 请求的消息体自动追加 `cache_control: { type: "ephemeral" }`，触发上游 prompt caching 机制。

### 4.4 缓存 token 全链路传递

```
Anthropic API 响应
  ├── usage.cache_read_input_tokens      → llm-proxy-connector.ts 解析
  ├── usage.cache_creation_input_tokens  → llm-proxy-connector.ts 解析
  └── SSE 流中逐 chunk 传递缓存信息
            ↓
altus-run-coordinator.ts chargeForModelCall()
  ├── 按 provider 读取 cache_pricing_config
  ├── cachedPromptTokens × hitRate ÷ 1000
  ├── nonCachedPromptTokens × 1.0
  ├── cacheCreationTokens × creationRate ÷ 1000
  └── 汇总为 totalCredits
            ↓
token_usage_logs 表记录三类 token 明细
```

### 4.5 数据库约束增强

```sql
ALTER TABLE user_credits ADD CONSTRAINT check_balance_non_negative CHECK (balance >= 0);
```

此约束作为 CAS 更新的最终防线，即使并发扣费竞争条件突破应用层检查，数据库也会拒绝负余额写入。

### 4.6 用户端会话积分展示

`SessionCreditBar` 组件：
- 进入会话页面时自动获取 `/api/billing/session/:sessionId/usage`
- 展示已消耗积分、总 tokens、模型调用次数
- 无消耗时自动隐藏，避免空状态干扰
