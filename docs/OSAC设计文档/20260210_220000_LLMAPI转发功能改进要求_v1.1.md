# OSAC LLM API 转发功能改进要求（v1）

> 目的：解决 sandbox 内无法访问内网 LLM 网关的问题。OSAC 在 sandbox 内提供本地 LLM 代理（127.0.0.1），将 OpenAI 兼容请求转发到编排服务的 LLM API 代理模块。

## 1. 背景与问题
- 现有 sandbox 安全策略禁止访问内网（如 192.168.x.x）。
- opencode 需要访问 OpenAI 兼容 API 才能运行。
- 因无法访问内网 LLM 服务，opencode CLI 调用会阻塞/超时。

## 2. 核心目标
1) OSAC 在 sandbox 内启动一个本地代理服务（HTTP），供 opencode 访问。
2) OSAC 将请求转发到编排服务的 LLM 代理模块（由编排服务统一对接外部/内网模型服务）。
3) 请求/响应保持 OpenAI 兼容，不增加额外适配成本。
4) 不引入 OSAC 与编排服务的强耦合，实现最小依赖。

## 3. 工作流程（端到端）
1) 编排服务创建 sandbox -> 下发 OSAC + opencode。
2) 编排服务向 OSAC 注入代理配置（环境变量）。
3) OSAC 启动本地 LLM 代理，监听 `127.0.0.1:<proxy_port>`。
4) opencode 设置 `OPENAI_BASE_URL=http://127.0.0.1:<proxy_port>/v1`。
5) opencode 发起 OpenAI 兼容请求 -> OSAC 本地代理接收 -> 转发到编排服务 LLM 代理。
6) OSAC 原样返回响应给 opencode。

## 4. OSAC 必须实现的能力

### 4.1 本地 HTTP 代理服务
- 监听地址：`127.0.0.1:<OSAC_LLM_PROXY_PORT>`
- 默认端口：`18111`
- 支持路由（OpenAI 兼容）：
  - `GET /v1/models`
  - `POST /v1/chat/completions`
  - `POST /v1/completions`
  - `POST /v1/embeddings`（可选但建议支持）
- 需完整支持 `stream=true` 的 SSE 流式响应。

### 4.2 上游转发规则
- OSAC 使用环境变量确定上游目标：
  - `OSAC_LLM_UPSTREAM_BASE_URL`（如 `http://<orchestrator-host>:4000/api/llm-proxy`）
  - `OSAC_LLM_UPSTREAM_TOKEN`（可选，Bearer Token）
- 路径映射：
  - `/v1/*` -> `${OSAC_LLM_UPSTREAM_BASE_URL}/v1/*`
- 必须转发请求头：
  - `Content-Type`
  - `Accept`
  - `Authorization`（如有）
  - `OpenAI-Organization`（如有）
  - `OpenAI-Project`（如有）
- OSAC 必须追加/覆盖上游鉴权头（若配置）：
  - `Authorization: Bearer <OSAC_LLM_UPSTREAM_TOKEN>`

### 4.3 SSE 转发要求（stream=true）
- OSAC 必须透传 SSE 数据，不能缓冲到结束后再返回。
- 必须保持 SSE 数据行结构，包含 `data:` 前缀。
- 必须支持 `[DONE]` 结束标记透传。

### 4.4 错误处理规范
- OSAC 遇到上游超时/连接失败时，需返回 OpenAI 风格错误：

```json
{
  "error": {
    "message": "Upstream timeout",
    "type": "upstream_timeout",
    "code": "upstream_timeout"
  }
}
```

- HTTP 状态码建议：
  - 上游不可达：`503`
  - 请求超时：`504`
  - 认证失败：`401`

### 4.5 日志与可观测性
- 记录字段：
  - method、path、status
  - latency
  - upstream_status
- 不记录敏感信息（API Key、请求体内容）。
- 允许配置日志级别：`OSAC_LOG_LEVEL`（例如 info/debug/error）。

## 5. OSAC 新增环境变量（建议）
```bash
OSAC_LLM_PROXY_PORT=18111
OSAC_LLM_UPSTREAM_BASE_URL=http://<orchestrator-host>:4000/api/llm-proxy
OSAC_LLM_UPSTREAM_TOKEN=<optional-token>
OSAC_LLM_PROXY_TIMEOUT_MS=60000
```

## 6. 编排服务侧要求（OSAC 调用接口）
OSAC 只需调用以下接口（均为 OpenAI 兼容）：
- `GET  {UPSTREAM_BASE_URL}/v1/models`
- `POST {UPSTREAM_BASE_URL}/v1/chat/completions`
- `POST {UPSTREAM_BASE_URL}/v1/completions`
- `POST {UPSTREAM_BASE_URL}/v1/embeddings`

请求/响应字段与 OpenAI 规范一致，OSAC 不做字段重写。

## 7. opencode 侧配置（由编排服务注入到 sandbox）
```bash
OPENAI_BASE_URL=http://127.0.0.1:18111/v1
OPENAI_API_KEY=anystring   # 仅占位，真实鉴权由 OSAC->编排服务完成
OPENCODE_MODEL=<模型名>
```

## 8. 验收标准
1) sandbox 内 `opencode session list --format json` 可在 5 秒内返回。
2) sandbox 内 `opencode run "Hello"` 可正常返回且无超时。
3) OSAC 本地代理日志显示请求被正确转发到编排服务。

## 9. 兼容与扩展要求
- 代理逻辑必须独立模块化，便于后续拆分为独立服务。
- 新增接口（如 `/v1/images/generations`）应可通过配置/路由扩展，而无需改动核心逻辑。
