# 20260328 Office 技能联网联动扩展 设计与实现

## 1. 背景

此前已经完成 `PPT 办公` 与 Tavily 联网检索链路的打通，但 `Word 文档` 与 `Excel 表格` 仍主要停留在 skill brief 约束层，没有像 `PPT` 一样显式地把 `web_search / web_extract` 纳入默认执行路径。

因此当前状态是：

- 平台层已经具备联网工具
- `PPT` 已明确联动这些工具
- `Word` / `Excel` 仍缺少显式联网工作流约束

## 2. 目标

本轮目标是把 Office 能力从“只有 PPT 明确联网”扩展成“PPT / Word / Excel 三者都能显式联动联网检索能力”。

需要满足：

- `Word 文档` 在需要外部事实、政策、案例、引用时，会主动使用 `web_search / web_extract`
- `Excel 表格` 在需要公开数据、基准数据、来源链接时，会主动使用 `web_search / web_extract`
- 生成结果保留来源信息，而不是把外部事实混成无来源内容
- 最终仍通过现有 deliverable 闭环输出可下载文件

## 3. 最短实现方案

### 3.1 Prompt 层扩展为 Office 通用约束

在 `altus-managed-prompt-service.ts` 中新增两类规则：

- `docx` 任务需要事实、政策、案例、引用时，优先联网检索，不要凭空编写
- `xlsx` 任务需要公开数据、行业基准或当前指标时，优先联网检索，并保留来源与日期

同时补充：

- `docx` 应把引用来源保留在参考资料、脚注、附录或交付说明中
- `xlsx` 应把来源保留在独立 source sheet、备注列或说明区域

### 3.2 Skill 模板层扩展为显式联网 brief

更新 `Word 文档` 模板：

- 明确研究型文档、政策说明、行业分析、建议书等任务在素材不足时应优先联网补材
- 约束使用“搜索 -> 抽取 -> 引用”的短链路
- 要求保留 URL 和来源说明
- `.docx` 生成并验证后立刻作为最终交付物完成

更新 `Excel 表格` 模板：

- 明确外部数据型表格在素材不足时应优先联网补数据
- 约束使用“搜索 -> 抽取 -> 整理数据 -> 建工作簿”的短链路
- 要求保留来源 URL、日期、口径与单位
- `.xlsx` 生成并验证后立刻作为最终交付物完成

## 9. 结论

现在不只是 `PPT 办公`，`Word 文档` 和 `Excel 表格` 也已经显式联动到了 `web_search / web_extract`。

当前结果可以总结为：

- `PPT`：联网检索、配图、下载交付已打通
- `Word`：联网检索、引用保留、`.docx` 交付已打通
- `Excel`：联网检索、来源 sheet、`.xlsx` 交付已打通

也就是说，Office 三件套现在都不再只是“文字提示模板”，而是已经能显式触发外部检索并走到最终文件交付。
