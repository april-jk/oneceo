# 10 部署链路验收、回归与清理手册 [20260415-1245已采用]

## 1. 目的

本文件用于沉淀三类操作：

1. 如何验证 OneCEO 当前部署链路真实可用
2. 如何在回归时复跑完整烟测
3. 如何在验证后回收 Railway / GitHub / Umami 资源，避免长期堆积

## 2. 当前已经验证通过的链路

截至 2026-04-15，下面这条链路已做过真实烟测并通过：

1. 平台为同一用户复用固定 Railway Project
2. 平台为每个会话创建独立 Railway Environment / Service / GitHub Repo / Project Token
3. 平台在首次部署前自动创建或绑定 Umami website
4. 平台把 `VITE_ANALYTICS_*` 注入 Railway 服务变量
5. 导出工作区时强制补入 analytics bootstrap
6. GitHub 仓库同步成功后触发 Railway 部署
7. Railway 部署状态变为 `SUCCESS` 后继续等待公网 URL 真正返回 2xx/3xx
8. 根路径和 `/api/system/health` 返回 `200`

## 3. 必备环境变量

最少需要在 [apps/.env](/Users/watson/codingProj/oneceo/apps/.env) 配置：

- `RAILWAY_ADMIN_TOKEN`
- `RAILWAY_WORKSPACE_ID`
- `GITHUB_DEPLOYMENT_OWNER`
- `GITHUB_DEPLOYMENT_APP_ID`
- `GITHUB_DEPLOYMENT_INSTALLATION_ID`
- `GITHUB_DEPLOYMENT_APP_PRIVATE_KEY`
- `UMAMI_ENABLED=true`
- `UMAMI_HOST_URL`
- `UMAMI_USERNAME`
- `UMAMI_PASSWORD`
- `UMAMI_TEAM_ID`

额外约束：

1. `UMAMI_PASSWORD` 如果包含 `#`、空格或其他特殊字符，必须加引号。
2. `RAILWAY_DEPLOYMENT_TARGET_PORT` 默认应为 `8080`，必须与应用真实监听端口一致。
3. `RAILWAY_DEPLOYMENT_HEALTHCHECK_PATH` 当前统一为 `/api/system/health`。
4. `GITHUB_DEPLOYMENT_APP_PRIVATE_KEY` 推荐写成单行，并使用 `\n` 表示 PEM 中的换行。
5. Railway 账号必须已绑定 GitHub，并在 `General Settings -> Account Integrations -> GitHub -> Edit Scope` 中授予目标仓库访问范围；若仓库位于组织下，还需在 GitHub 为 Railway 安装其 GitHub App：`https://github.com/apps/railway-app/installations/new`。

示例值以 [apps/.env.example](/Users/watson/codingProj/oneceo/apps/.env.example) 为准。

## 4. 回归前检查

执行完整烟测前，先跑：

```bash
pnpm --filter api type-check
pnpm --filter web check
pnpm --filter api exec tsx --test tests/deployment-template-bootstrap-service.test.ts
```

目的：

- 先确认部署链路代码与前端展示没有类型回归
- 先确认 analytics bootstrap 注入仍然只发生一次

## 5. 完整烟测命令

在 [apps/api](/Users/watson/codingProj/oneceo/apps/api) 执行：

```bash
pnpm exec tsx scripts/_tmp/_tmp_deployment_e2e_smoke.ts
```

成功判定：

1. 输出 JSON 中 `ok=true`
2. `sessionA.projectId === userProject.projectId`
3. `sessionA.environmentId !== sessionB.environmentId`
4. `sessionA.serviceId !== sessionB.serviceId`
5. `analytics.websiteId` 非空
6. `bootstrapInjected=true`
7. 输出的最终 `url` 可手工访问

建议在烟测完成后再补两次外部校验：

```bash
curl -I <烟测输出url>
curl -I <烟测输出url>/api/system/health
```

预期都是 `200`。

## 6. 已修复的真实故障点

这次链路打通过程中，已经确认并修复以下问题：

### 6.1 Umami 密码被 dotenv 截断

原因：

- 密码中带 `#`
- `.env` 未加引号

结果：

- 登录接口始终 `401`
- 平台误判 Umami 不可用

处理：

- 对密码值加引号
- 在示例环境文件中补充明确说明

### 6.2 Railway service domain 指向了错误端口

原因：

- `serviceDomainCreate` 默认 `targetPort` 之前写成了 `3000`
- 实际模板应用监听 `8080`

结果：

- Railway deployment 显示 `SUCCESS`
- 公网域名长期返回 `502`

处理：

- 默认 `RAILWAY_DEPLOYMENT_TARGET_PORT` 调整为 `8080`
- 现有 domain 若端口不一致，自动执行 `serviceDomainUpdate`

### 6.3 Railway 状态成功不等于公网已就绪

原因：

- 边缘层和路由传播存在延迟

结果：

- 平台过早返回“部署成功”
- 用户立即访问时可能仍然看到 `502`

处理：

- 部署 / 重部署 / 回滚统一增加公网可达等待
- 只有 URL 真正返回 2xx/3xx 才向上游返回成功

### 6.4 Umami website 列表分页导致去重失效

原因：

- 之前只读首屏 20 条

结果：

- website 数量变多后，可能重复建站或在校验时找不到旧站点

处理：

- `listWebsites()` 补全分页
- 清理脚本优先从 Railway 变量读取 `VITE_ANALYTICS_WEBSITE_ID`

### 6.5 GitHub 部署凭据已切换为 GitHub App

原因：

- 经典 PAT 很难同时做到最小权限和长期可维护
- GitHub App installation token 更适合平台托管部署

处理：

- 部署链路改为读取 `GITHUB_DEPLOYMENT_APP_ID` / `GITHUB_DEPLOYMENT_INSTALLATION_ID` / `GITHUB_DEPLOYMENT_APP_PRIVATE_KEY`
- `GITHUB_DEPLOYMENT_APP_PRIVATE_KEY` 支持单行 `\n` 转义格式

## 7. 资源清理命令

### 7.1 先看 dry-run

在 [apps/api](/Users/watson/codingProj/oneceo/apps/api) 执行：

```bash
pnpm exec tsx scripts/deployment-smoke-cleanup.ts --dryRun
```

默认行为：

- 用户：`oneceo-deployment-smoke-user`
- 只匹配 `projectKey` 以 `smoke-` 开头的部署记录

### 7.2 实际清理 smoke 资源

```bash
pnpm exec tsx scripts/deployment-smoke-cleanup.ts --deleteUserProject
```

脚本会按顺序处理：

1. 删除 Railway service domain
2. 吊销 Railway project token
3. 删除 Railway service / database service
4. 删除 Railway environment
5. 删除 GitHub 托管仓库
6. 删除 Umami website
7. 删除本地部署账号记录
8. 当没有剩余 smoke 账号记录时，再删除固定 smoke Project

### 7.3 当前 GitHub 部署凭据无法删仓库时的清理方式

如果当前 GitHub App installation token 对目标仓库没有删除所需权限，脚本会保守地保留 DB 记录。

这种情况下，先执行：

```bash
pnpm exec tsx scripts/deployment-smoke-cleanup.ts --skipGithub --deleteUserProject
```

效果：

- Railway / Umami / DB / 固定 smoke Project 会被清理
- GitHub 仓库会保留，后续需要用具备删除权限的账号手工回收

### 7.4 只清指定前缀

```bash
pnpm exec tsx scripts/deployment-smoke-cleanup.ts --prefix smoke-1776228
```

适合只回收一批最近烟测资源，而不动更早记录。

## 8. 当前操作建议

默认建议：

1. 开发改动后先跑类型检查和 bootstrap 单测
2. 涉及部署链路时再跑完整烟测
3. 烟测通过后执行一次清理
4. 只有需要保留现场时，才不立即清理 smoke 资源
