# 03 前端选择协议与消息模型

## 1. 前端必须从“文件附件模型”切换到“技能引用模型”

当前前端把 skill 伪装成 `File`，这是这次必须移除的结构问题。

应改为真正的 union 模型：

1. `uploaded_file`
2. `user_skill_reference`

也就是说，attachment 区域仍然可以展示 skill，但 skill 不再拥有 `File` 实体。

## 2. 建议的数据结构

### 2.1 `PendingUserSkill`

建议字段：

1. `id`
2. `sourceType`
2. `skillId`
3. `revisionId`
4. `slug`
5. `name`
6. `description`
7. `category`
8. `revisionNumber`
9. `attachmentKind: "user_skill_reference"`

### 2.2 `PendingAttachment`

改为：

1. `PendingUploadAttachment`
2. `PendingUserSkill`

而不是所有项都默认有 `file`

## 3. 消息发送协议

发送消息时不再把 skill 正文拼进 prompt。

消息 metadata 改为传：

1. `attachments` 继续只表示真实文件
2. `skills` 专门表示当前选择的 skill 引用

建议结构：

```json
{
  "skills": [
    {
      "sourceType": "platform",
      "skillId": "uuid",
      "revisionId": "uuid",
      "slug": "office-ppt",
      "name": "PPT 办公"
    }
  ]
}
```

## 4. 前端改造点

### 4.1 Skill Picker

`AttachmentPickerButton.tsx` 改为：

1. 从 `/api/task-creation/skills` 拉取“当前用户已配置可用”的列表
2. 选择 skill 后加入 `PendingUserSkill`
3. 不再构造 `skill-*.md` 文件
4. 每次打开加号菜单时重新拉取一次 skills，不能只在页面初次挂载时缓存
5. 设置页 `Skills 管理` 变更后，需要触发前台 picker 刷新，避免“设置已变更但菜单仍显示旧列表”

### 4.2 发送前拆分

`task-attachments.ts` 改为：

1. `uploadableAttachments`
2. `selectedSkills`

取消以下逻辑：

1. `inlineContent`
2. `inline-skill:*`
3. `appendAttachmentsToPrompt()` 中对 skill 内容的拼接

### 4.3 UI 展示

消息卡片和输入框附件区仍然显示用户已选 skill，但只显示：

1. 名称
2. 描述
3. 版本号或 revision 标识
4. 来源类型：平台模板 / 自定义

不再显示“这是一个本地 markdown 文件”。

## 5. 为什么不能继续把 skill 内联到 prompt

继续内联会保留以下旧问题：

1. skill 内容每次重复传输
2. prompt 越来越大
3. sandbox 内仍然没有真实 skill
4. 后续无法利用 OpenCode 原生 `skill` 工具按需加载

因此这次方案必须让消息只传 `引用`，实际内容改由后端和 sandbox 处理。

## 6. 设置页新增要求

业务前端设置页不再只有通用设置和 connectors。

必须新增 `Skills 管理` 分区，负责：

1. 展示平台全局模板目录
2. 允许用户把平台模板加入或移出“我的 skills”
3. 允许用户创建、编辑、归档自己的自定义 skill
4. 让 attachment picker 只消费这个分区配置后的可用 skill 集

## 7. 跨页面草稿传递要求

从首页、AI Agent 落地页、新任务弹窗跳转到正式任务创建页时，不能只暂存真实文件。

必须把待发送的 `PendingAttachment` 整体暂存并恢复，包括：

1. `file`
2. `user_skill_reference`

否则用户在入口页通过左下角加号选择的 skills，会在进入正式对话页时丢失。
