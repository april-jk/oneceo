# 2026-03-13 直通模式消息一致性回归测试计划

## 测试目标

- 验证直通模式下，用户发送消息后，到任务执行完成时，对话区消息数据稳定。
- 验证同一会话在页面刷新后，对话区消息与刷新前一致。
- 验证关闭当前页面上下文并重新进入会话页面后，对话区消息仍与任务完成时一致。
- 验证上述一致性检查覆盖“页面可见内容”和“历史消息数据结构”两个层面。

## 测试范围

- 模式：直通模式（`altus_mode=sandbox`，执行器 `opencode`）
- 页面场景：
  - 首次发送消息后的实时对话页面
  - 任务完成后的当前页面
  - 浏览器刷新后的同一会话页面
  - 重新打开页面后的同一会话页面
- 一致性对象：
  - 主对话区渲染消息
  - 会话对应的历史消息列表
  - 当前会话在侧栏中的预览位置与标题

## 测试步骤

1. 进入首页并强制设置直通模式。
2. 新建会话并发送测试消息。
3. 等待任务执行完成。
4. 记录完成时页面状态与历史消息快照。
5. 刷新当前页面并再次记录页面状态与历史消息快照。
6. 使用会话 URL 重新进入页面，并第三次记录页面状态与历史消息快照。
7. 比较三次快照，确认消息文本、消息顺序、消息类型与页面渲染一致。
8. 若存在差异，定位是前端历史重建、侧栏列表、还是后端会话落盘问题，并修复后重测。

## 判定标准

- 任务完成时、刷新后、重新进入页面后：
  - 对话消息数量一致
  - 对话消息顺序一致
  - 每条消息的 `type/content` 一致
  - 主对话区文本一致
  - 页面截图一致
- 如执行器链路未完成，应明确记录阻塞点，不得将其误判为通过。

## 本轮优先测试消息

- 平台能力链路：`帮我查看当前部署状态`
- 执行器直通链路：`帮我开发一个简单的待办清单网页`
