# 开源发布仓库整理

## 背景

当前仓库准备面向 GitHub 公开，但存在三类直接阻碍：

1. 最小静态验证链路不稳定，外部协作者无法快速确认仓库是否可用。
2. 根 README 与当前工作区事实不一致，包含错误目录、错误环境文件路径与过时的启动说明。
3. 缺少面向开源协作的基础治理文件，且存在仅适合内部流程的 PR 来源分支限制。

## 本次采用范围

1. 以“外部开发者首次打开仓库后的最小闭环”作为整理目标。
2. 不改变主业务架构，不引入新依赖，不做与开源准备无关的功能重构。
3. 仅修正以下内容：
   - 最小验证与工作区配置噪音
   - README 事实对齐
   - 开源治理文件补齐
   - 内部专用分支校验对外部贡献的误伤

## 方案

### 1. 最小验证链路

- 以当前仓库实际可执行命令为准：
  - `pnpm --filter api type-check`
  - `pnpm --filter web check`
  - `npm --prefix apps/admin_management run type-check`
- 将 `apps/web/package.json` 中不会在 workspace 生效的 `pnpm.overrides` / `pnpm.patchedDependencies` 上移到根 `package.json`，消除误导性警告。
- 新增 GitHub Actions 校验工作流，保证外部 PR 至少经过安装与三项静态检查。

### 2. README 对齐

- 删除与当前仓库不符的目录描述，例如不存在的 `packages/database`、`packages/config`。
- 环境说明改为当前真实入口 `apps/.env.example`，并补充 `apps/admin_management/.env` 的本地用途。
- 快速开始仅保留当前可执行的最短路径，并明确 `web / api / admin_management / blog` 的实际启动命令。

### 3. 开源治理

- 补齐：
  - `CONTRIBUTING.md`
  - `CODE_OF_CONDUCT.md`
  - `SECURITY.md`
  - `SUPPORT.md`
- 内容坚持最短路径，不引入与当前仓库事实不符的流程承诺。

### 4. 内部流程与外部贡献隔离

- 保留 `staging` / `product` 的内部保护意图。
- 将来源分支限制收窄到“仅同仓库内部 PR 生效”，避免 fork PR 因必须来自 `task-creation-agent` 而被误伤。

## 验证标准

1. 根目录执行最小静态检查通过。
2. 新 README 中所有关键路径均与仓库实际存在路径一致。
3. GitHub 新协作者可以从根 README 找到：
   - 环境文件入口
   - 启动命令
   - 验证命令
   - 贡献与安全入口
4. 对 fork PR，不再强制要求来源分支名为 `task-creation-agent`。
