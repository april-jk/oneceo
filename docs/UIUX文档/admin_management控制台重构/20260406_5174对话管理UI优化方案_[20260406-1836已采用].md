# 2026-04-06 5174 管理后台对话管理 UI 优化方案 [20260406-1836已采用]

## 1. 背景

`apps/admin_management` 已在整站重构中采用三栏排障结构，但 `对话管理` 仍存在以下可优化点：

1. 左栏会话索引仅有基础展示，定位目标会话时需要大量滚动。
2. 中栏状态流转筛选占据较大空间，影响首屏有效信息密度。
3. 右栏 inspector 信息价值层级不够清晰，高频信息与低频调试信息混排。
4. 会话切换时会出现“清空后再加载”的视觉跳变，影响持续排查体验。

本方案仅针对 `5174` 管理后台中的 `对话管理` 模块 UI 与交互，不改后端接口语义。

## 2. 目标与范围

### 2.1 目标

1. 缩短“找会话 -> 看状态 -> 跳转关联 Sandbox”的排障路径。
2. 在不改接口契约的前提下，提升信息密度和稳定性。
3. 保持已采用的 `Editorial Ops Console` 视觉方向，不引入新 UI 框架。

### 2.2 范围

- 前端目录：
  - `apps/admin_management/web/src/App.tsx`
  - `apps/admin_management/web/src/styles.css`
  - 拆分后新增的 `web/src/pages/*`、`web/src/components/*`（如本轮进入实现）。

### 2.3 非范围

1. 不新增对话管理后端 API。
2. 不改 `ConversationManagementService` 数据结构。
3. 不做新旧 UI 双轨并存。

## 3. 现状问题

## 3.1 左栏索引

- 当前仅展示标题、更新时间和状态，缺少 `stage`、待确认信息摘要和快速筛选入口。
- 当会话数量达到 30 条上限时，定位成本明显上升。

## 3.2 中栏工作区

- 状态流转筛选默认全展开，导致首屏内容被筛选控件挤占。
- LLM 调用默认展开完整 JSON，长会话下阅读负担较重。
- 切换会话时先置空详情再加载，会产生明显闪烁。

## 3.3 右栏 inspector

- 运行绑定、Sandbox 分组、OSAC 消息、原始状态都在同一密度层级。
- 高价值信息与低频调试信息之间缺少主次分区。

## 4. 优化总览

保持三栏布局不变，按“索引效率、主工作区稳定性、inspector 层级”做优化：

1. 左栏升级为可筛可搜索引列。
2. 中栏升级为“常用信息优先”的工作台。
3. 右栏升级为“高频默认展开、低频折叠”的 inspector。
4. 会话切换改为局部 loading 覆盖，不再全量清空正文。

## 5. 详细方案

### 5.1 左栏：会话索引列

新增能力：

1. 顶部搜索框
   - 关键词匹配：`session.id`、`session.title`、`pendingQuestion`。
2. 状态快捷筛选
   - `全部`、`进行中`、`待用户确认`、`失败`、`已完成`。
3. 会话项信息增强
   - 标题 + 会话 ID 截断展示；
   - `stage` 标签；
   - 待确认问题摘要（最多 1 行）；
   - 更新时间。
4. 自动刷新控制
   - 增加“自动刷新中/已暂停”开关，默认开启。
   - 排障时可暂停，避免列表重排干扰阅读。

### 5.2 中栏：会话主工作区

1. 顶部摘要区保留并压缩高度，优先保留会话 ID、状态、阶段、OpenCode ID、绑定更新时间。
2. Tab 改为带计数标签：
   - `状态流转 (N)`、`消息 (N)`、`详细日志 (N)`。
3. 状态流转筛选分级：
   - 常用筛选常驻：搜索、时间范围、重置；
   - 高级筛选折叠：stage/status/phase/role/agent/tone。
4. LLM 列表默认折叠 request/response JSON，仅显示阶段、来源、时间与摘要；按条目展开详情。
5. 会话切换 loading 策略：
   - 切换会话时保留旧内容并显示局部 loading mask；
   - 新数据完成后整体替换，减少闪烁。

### 5.3 右栏：运行绑定 inspector

分为四个区块：

1. 当前会话（默认展开）
2. KVM / Sandbox 摘要（默认展开）
3. Sandbox 分组（默认展开）
4. OSAC / OpenCode 消息（默认折叠，仅显示计数与最近时间）

并将 `KVM / Sandbox 原始状态 JSON` 统一归入“调试数据”折叠区，避免常态干扰。

### 5.4 响应式规则

1. `>= 1360px`：三栏（索引 / 工作区 / inspector）。
2. `1100px - 1359px`：两栏（索引 / 工作区），inspector 改右侧抽屉。
3. `< 1100px`：单栏，索引与 inspector 分别改可收起区块。

## 6. 实施步骤（最短路径）

1. 结构拆分
   - 从 `App.tsx` 抽离：
     - `ConversationIndexPanel`
     - `ConversationWorkspacePanel`
     - `ConversationInspectorPanel`
2. 状态收敛
   - 增加 `conversationSearchQuery`、`conversationStatusFilter`、`conversationAutoRefreshEnabled`。
   - 新增“切换会话局部 loading”状态。
3. 样式调整
   - 在 `styles.css` 增加对话页专用区块样式，保持现有 token 体系。
4. 清理遗留
   - 删除未使用的旧版 `renderConversationSection` JSX，避免后续维护误导。
5. 验证
   - `npm --prefix apps/admin_management run type-check`
   - 手动验证：会话筛选、会话切换、四个 Tab、关联跳转、响应式断点。

## 7. 验收标准

1. 左栏支持搜索与状态筛选，且筛选结果可立即反馈。
2. 会话切换不再出现“先清空再加载”的大幅闪烁。
3. 中栏四个 Tab 支持计数展示，状态流转筛选信息分层明确。
4. 右栏信息分区清晰，低频调试数据默认折叠。
5. 1200px 左右宽度下布局不挤压、不重叠。

## 8. 风险与约束

1. 当前接口只返回最近 `30` 条会话，若后续需要深度检索需新增后端分页/搜索接口（本轮不做）。
2. `App.tsx` 仍为中心文件，若不进行适度拆分，后续 UI 迭代复杂度会继续上升。

## 10. 会话详情超时优化补充（2026-04-06）

为解决“切换会话详情偶发请求超时”的问题，实施以下分层加载策略：

1. 管理后台会话详情接口拆分为：
   - `GET /api/conversations/sessions/:sessionId/core`
   - `GET /api/conversations/sessions/:sessionId/infra`
2. `core` 仅返回首屏核心数据（会话主体、消息、状态流转、基础 trace），用于快速渲染主工作区。
3. `infra` 异步返回运行关联信息（Sandbox/KVM/OSAC），用于补全右侧 inspector。
4. 前端改为“先 core 后 infra 合并”的加载链路，`infra` 失败不再阻断主工作区展示。
5. 前端请求超时分层：
   - `core`：10 秒
   - `infra`：20 秒

该补充属于同一主题下的实现细化，不新增候选方案文档。

## 11. 页头窄顶栏固定化补充（2026-04-09）

针对管理后台当前“对话管理”页头区域，再补充以下已采用的视觉与布局约束：

1. 原 `page-header-shell` 大标题区不再保留独立大卡片形态：
   - 直接压缩并替换为固定顶部栏；
   - 继续展示原有信息：所属分组、页面标题、页面说明、刷新操作、退出操作。
2. 顶部栏需同时容纳原页头与状态信息：
   - 保留模块标签、最后更新时间、服务在线状态、管理员身份；
   - 与页面主标题信息合并在同一紧凑栏内，而不是拆成上下两层。
3. 顶部栏固定在页面顶部可视区域：
   - 页面纵向滚动时持续可见；
   - 不允许随内容区一起滚出视口；
   - 主内容区需要预留顶部安全间距，避免遮挡错误提示与正文面板。
4. 视觉目标：
   - 以更小垂直空间保留原有信息语义；
   - 让管理员首屏看到更多实际工作区内容，而不是被页头占高。
5. 响应式下保持相同语义：
   - 桌面端固定于主内容列顶部；
   - 小屏下允许换行，但仍维持单个紧凑顶部栏，不恢复成大标题卡片。
6. 页面骨架采用固定分区布局：
   - 顶部栏贯穿页面顶部全宽，并始终占据真实布局高度；
   - 左侧边栏固定在顶部栏下方的剩余高度内；
   - 中间内容区也固定在顶部栏下方的剩余高度内。
7. 滚动行为约束：
   - 页面外层不再依赖整页纵向滚动；
   - 左侧边栏仅内部导航区域可滚动；
   - 中间内容区仅自身内部滚动，外层框架保持静止。
8. 中间内容区需要补齐可视高度：
   - 即使内部内容较少，也必须占满剩余区域；
   - 避免页面底部或布局外层暴露留白。
9. 对话管理三栏（会话索引 / 会话内容 / 关联信息）采用等高固定容器：
   - 三个区域高度以顶部栏下的剩余可视高度为准；
   - 不因单侧内容较少而出现断裂或底部留白。
10. 三栏滚动策略：
   - `会话索引` 仅索引列表区域内部滚动；
   - `会话内容` 仅工作区主体内部滚动；
   - `关联信息` 仅 inspector 主体内部滚动；
   - 不允许三栏外层再参与页面纵向滚动。
11. 桌面端高度分配遵循“先顶部、后摘要、余量给三栏”：
   - 先扣除固定顶部栏高度；
   - 再扣除“总会话 / 最近 200 条会话索引”等摘要区高度；
   - 下三栏只占用剩余可视高度，并在各自卡片内部滚动。
12. 桌面端三栏断点需保持稳定：
   - 常见桌面宽度（如 `1440px`）默认仍保持三栏；
   - 仅在更窄宽度下才允许将 `关联信息` 收折为下沉区域或单列布局。

该补充仅调整前端布局与样式，不改变任何接口、状态模型或页面行为语义。

   - 不再保留任何常驻的 `关联信息 / 运行绑定与排障信息` 侧栏；
   - 顶部摘要信息若需保留，也应收敛进索引卡片面板内部，而不是额外占用独立主布局区域。
6. 视觉目标：
   - 首屏只优先服务“索引定位”；
   - 会话索引需在桌面端保持视觉主导并充满主工作区，不能退化成狭窄侧栏；
   - 会话索引主体采用类似 `Sandbox 列表` 的详细列表布局，优先支持按状态、阶段、更新时间和待确认内容快速扫读；
   - 状态筛选收敛为轻量 chip 线，搜索 / 阶段 / 重置收敛为单层工具条，不允许让筛选器抢走列表主体注意力；
   - 会话重内容阅读与关联排障均进入 popup 后完成，避免常驻工作区长期被单一会话占满。

针对 `对话详情` 的 `概览 / 计费 / 关联` 三个页签，再补充以下已采用约束：

1. 三个页签统一取消多卡片拼接，改为单块工作台式布局，用顶部摘要、横向指标行、分隔区块和表格式行承载信息，避免视觉碎片化。
2. `概览` 页签中：
   - 顶部保留会话总览，并将 `来源用户` 整合进会话与来源区块，形成“会话是什么 → 谁发起 → 最近发生什么 → 部署到哪里”的纵向阅读顺序；
   - `来源用户` 在会话总览内展示用户、邮箱、IP、最近访问与设备摘要；当来源为真实用户账号时，用户名必须能跳转到用户详情窗口；
   - `消息摘要` 与 `部署摘要` 不再作为右侧独立卡片，而是作为同一工作台内的连续分隔区块；
   - `消息摘要` 不使用横向小格子承载长文本，改为阻塞/待确认提示优先、用户输入与主回复纵向展示、统计信息轻量 pill 化；
   - `待确认问题` 只在消息摘要内高亮展示，避免和总览事实项重复。
   - `概览` 内容使用独立滚动区域，避免长摘要、部署信息或来源设备信息撑开详情弹窗。
3. `计费` 页签中：
   - 不再使用多卡片拼接布局，改为单块账单式布局；
   - 顶部展示会话与积分消耗，中部用横向指标行展示 tokens 与调用次数；
   - 缓存构成与调用明细使用分隔线和表格式行展示，避免卡片堆叠造成视觉碎片化。
4. `关联` 页签中：
   - 顶部放置操作价值更高的 `运行绑定`，主 Sandbox、编排会话和最近关联记录作为主排障入口；
   - `会话身份` 改为同一工作台内的分隔区块，承载来源用户、IP、最近活跃和来源类型；当来源为真实用户账号时，来源用户必须可跳转到用户详情窗口；
   - 最近关联实例使用紧凑表格式行展示，不再使用卡片网格；Sandbox ID 自身作为跳转入口，不再额外重复显示“打开”按钮；
   - 无主 Sandbox 时只使用轻量空状态文字，不保留大面积空占位。
5. 响应式规则：
   - 中宽屏先将指标、事实、消息摘要退为两列；
   - 小屏再退为单列，保证卡片边缘、标题和操作按钮不挤压换行。
