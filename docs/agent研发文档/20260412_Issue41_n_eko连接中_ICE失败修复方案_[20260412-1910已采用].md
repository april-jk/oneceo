# 20260412 Issue41 n.eko连接中 ICE失败修复方案 [20260412-1910已采用]

## 1. 背景

在调试页访问 `http://oneceo.ai:3000/session/fedd010d-4e0d-4af7-9705-e73c6c9ce328` 时，用户持续看到“连接中”。

已确认事实（来自当前链路真实日志）：

1. sandbox 已 ready，n.eko 进程在运行，`8081/8082` 端口监听正常。
2. `/tmp/oneceo/neko.yml` 为 mux 模式（`tcpmux: 8082`，`epr` 已关闭）。
3. `/tmp/neko.log` 持续出现：
   - `Failed to ping without candidate pairs`
   - `Failed to read from candidate tcp4 host 8.229.30.245:8082: io: read/write on closed pipe`
   - `ICE connection state changed: failed`

结论：不是“服务没启动”，而是 WebRTC ICE 候选配对失败，媒体链路未建立。

## 2. 修复目标

1. 彻底消除“服务已启动但前端无限连接中”的假成功状态。
2. 把调试链路改为可明确判定成功/失败，并返回可操作的失败原因。
3. 提供稳定可复现的测试与验收步骤，保证后续不会回归。

## 3. 非目标

1. 不新增第二套调试架构（继续使用现有 E2B + OSAC + n.eko 链路）。
2. 不引入旧 KVM 主链路。
3. 不做“静默降级到不可靠直连”的兼容性补丁。

## 4. 完整 TODO 清单（审阅版）

### T0. 建立可复现诊断基线

1. 固化诊断脚本，统一采集：
   - `/tmp/oneceo/neko.yml`
   - `/tmp/neko.log`（最近 200 行）
   - `ss -ltnup`（8081/8082/18080）
2. 把“判定失败”关键词标准化为可机读规则：
   - `Failed to ping without candidate pairs`
   - `ICE connection state changed: failed`
   - `Failed to read from candidate tcp4 host`

验收标准：同一 session 连续两次采集结果一致，可稳定复现“连接中”根因。

### T1. 后端新增 ICE 配置输入（显式 TURN）

1. 在 `apps/api/src/services/sandbox-debug-service.ts` 增加 `NEKO_ICE_SERVERS_JSON` 解析。
2. 仅接受结构化数组（`[{ urls, username?, credential? }]`），并做严格校验。
3. 将解析结果写入 `neko.yml -> webrtc.iceservers` 与 metadata（用于可观测性）。

验收标准：

1. 无效 JSON/无效字段会直接报错，不进入启动流程。
2. 有效配置能正确落到 `neko.yml`。

### T2. 调试启动强约束：无 TURN 时显式失败

1. 在远程调试场景下，若 `NEKO_ICE_SERVERS_JSON` 中不存在 TURN 项（`turn:`/`turns:`），直接返回失败状态。
2. 不再把“仅 STUN”当作可用链路继续返回“启动中/连接中”。
3. 失败信息明确返回“缺少 TURN，无法建立远程媒体链路”。

验收标准：前端不会再出现无限“连接中”，而是收到明确失败态和原因。

### T3. 启动后健康检查与失败收敛

1. `ensureNekoDebug` 在启动后增加短窗口日志探测（例如 10~20 秒）。
2. 命中 ICE 失败规则时，立刻将 debug 状态写为 `failed`，并携带 `reasonCode`。
3. 对成功链路只返回 `running/ready`，避免“假成功”。

验收标准：同一 session 中，ICE 失败可在一次调用内被后端识别并返回 `failed`。

### T4. 调试信息 API 协议扩展

1. 扩展 `GET /sessions/:sessionId/debug` 与 `POST /sessions/:sessionId/debug/start` 返回结构：
   - `status` 支持 `failed`
   - 新增 `reasonCode`（如 `missing_turn`, `ice_failed`）
   - `message` 给出用户可操作提示
2. 保持兼容现有字段，不破坏前端调用。

验收标准：接口能稳定区分 `running` 与 `failed`，不再以“ready 布尔值”掩盖失败。

### T5. 前端调试页状态改造

1. 在 `apps/web/client/src/lib/task-creation-client.ts` 补齐 `TaskCreationDebugInfo` 新字段类型。
2. 在 `apps/web/client/src/components/OpencodePreviewPanel.tsx` 中：
   - 对 `status=failed` 显示失败态文案，不显示“连接中”。
   - 保留“发送消息触发启动调试”按钮，但文案改为“重新触发远程调试”。
   - 展示后端返回的 `message`（例如缺少 TURN）。

验收标准：用户可在 UI 一眼判断是“未启动”还是“ICE失败”，并可重试。

### T6. Altus 调试工具链路一致性修复

1. 在 `apps/api/src/services/altus-managed-tool-runtime.ts` 的 `debug_open_page` 路径中，透传 `ensureNekoDebug` 的失败态与原因。
2. 当 debug 处于 `failed` 时，工具调用返回结构化失败，不继续伪装页面打开成功。

验收标准：run 事件流里能看到调试工具真实失败原因，不再误判工具成功。

### T7. 单元测试与类型验证

1. 新增 `apps/api/tests/sandbox-debug-service.test.ts`，覆盖：
   - ICE servers 解析与校验

   - 日志命中 ICE 失败后状态收敛
2. 更新/新增 `apps/api/tests/altus-managed-tool-runtime.test.ts` 用例，验证 `debug_open_page` 失败透传。
3. 前端类型与渲染分支验证（最小范围）。
4. 执行：
   - `pnpm --filter api test -- sandbox-debug-service.test.ts altus-managed-tool-runtime.test.ts`

验收标准：新增/变更测试全部通过，类型检查通过。

### T8. 真机链路回归验证（你实际可见）

1. 使用你提供的会话进行复测：
   - 先在“无 TURN”配置下验证 UI 显示明确失败，不再“连接中”。
2. 配置 TURN 后再测：
   - 验证可进入 `ready/running` 并显示画面。
3. 同步输出一份最小证据集（接口返回 + sandbox 原始日志关键词）。

验收标准：

1. 无 TURN：明确失败可见。

## 8. 补充修复（2026-04-12 晚）

问题：调试面板在请求超时后会停留在“无显示/错误态”，即便远程浏览器后续已可访问也不能自动恢复。

修复：
1. 调试面板改为分层轮询策略：`starting` 高频轮询、`ready` 低频心跳轮询。
2. `timeout/network/abort` 等瞬时错误自动重试，不再一次超时后停轮询。
3. 轮询异常时保留最近一次可用 `debugInfo`，避免短暂异常把 iframe 直接清空。
4. 新增 effect cleanup，确保切页/卸载时清理 `debugPollRef`，避免轮询泄漏。

## 9. TURN 用户级签发改造（2026-04-12 夜）

目标：替换“固定写死 `NEKO_ICE_SERVERS_JSON`”方案，改为后端按用户动态签发 TURN 临时凭据，以支持后续按用户计费归集。

2. `ensureNekoDebug` 支持调用方注入 `iceServers`，优先使用动态签发结果。
3. `/debug/start` 与 `debug_open_page` 统一接入用户级动态 TURN 签发链路。
4. 新增环境变量：
   - `CLOUDFLARE_TURN_MANAGEMENT_API_TOKEN`
   - `CLOUDFLARE_ACCOUNT_ID`
   - `CLOUDFLARE_TURN_KEY_PREFIX`
   - `NEKO_TURN_CREDENTIAL_TTL_SECONDS`

当前状态说明：
