# 20260421 会话 session 项目归属能力方案 [20260421-0932已采用]

更新时间：2026-04-21

## 1. 背景

当前用户态里已经出现了两层与“项目”相关但尚未闭环的能力：

1. 侧边栏项目区展示了一组示例项目结构；
2. 会话 summary 类型、侧边栏会话映射、file memory 中都已经出现了 `projectId/projectName` 字段；
3. 右键菜单设计文档里也已经把“移动到项目”列为目标能力；
4. 但数据库主表 `task_creation_sessions` 还没有把“会话归属项目”作为正式持久化字段接住；
5. 当前用户无法真实地把一个会话归属到某个项目，也无法稳定地从“无项目”切换到“有项目”，或从“有项目”移回“无项目”。

因此这次不是从零发明新能力，而是要把已有半成品收口成正式能力：

- 一个会话只能属于一个项目；
- 默认处于“无项目”状态；
- 能被用户显式归属到某个项目；
- 归属结果能稳定持久化并返回给前端。

## 2. 目标

本次目标聚焦“会话归属 + 前端普通项目入口”：

1. 给 task session 增加正式项目属性；
2. 一个 session 最多归属一个项目；
3. 默认 `无项目`；
4. 支持把 session 归属到某个普通项目；
5. 支持把 session 从项目中移出，回到 `无项目`；
6. 会话列表与会话详情接口都能返回归属信息；
7. 侧边栏等前端消费者可直接消费该字段；
8. 用户态侧边栏支持创建普通项目；
9. 自组织项目与普通项目在交互语义上明确区分；
10. 普通项目点击进入的页面必须是“会话分组页”，不能复用自组织项目的经理-任务树页面。

## 3. 非目标

本次明确不做：

1. 不做完整项目系统重构；
2. 不做完整项目后台管理系统；
3. 不做一个 session 归属多个项目；
4. 不做项目级权限、成员、分享体系；
5. 不做项目排序、拖拽编排等增强交互；
6. 不把“示例项目树”立即升级成真实项目管理产品；
7. 不让自组织项目直接承担普通项目的会话归属职责。

## 4. 现状对齐

基于当前代码，已有以下事实：

### 4.1 前端与内存态已有字段

以下位置已经出现 `projectId/projectName`：

1. [task-creation-client.ts](/Users/watson/codingProj/oneceo/apps/web/client/src/lib/task-creation-client.ts)
2. [Sidebar.tsx](/Users/watson/codingProj/oneceo/apps/web/client/src/components/Sidebar.tsx)
3. [file-memory-store.ts](/Users/watson/codingProj/oneceo/apps/api/src/agents/task-creation/file-memory-store.ts)
4. [task-creation-routes.ts](/Users/watson/codingProj/oneceo/apps/api/src/routes/task-creation-routes.ts)

说明：

1. 这些字段已经作为“会话轻量元数据”被前端和 file memory 理解；
2. 但它们目前没有形成数据库主事实源闭环。

### 4.2 数据库存储仍未正式收口

当前 [schema.ts](/Users/watson/codingProj/oneceo/apps/api/src/db/schema.ts) 中：

- `task_creation_sessions` 只有 `metadata_json`，没有显式项目归属列。

这意味着：

1. 会话项目归属如果只存在于 file memory，就无法作为稳定真相源；
2. 一旦发生服务重启、恢复、补建、跨路径读取，项目归属容易丢失或不一致。

## 5. 设计原则

本次遵守以下原则：

1. 最短路径落地，不新建额外 project relation 表；
2. 会话项目归属先作为 `task_creation_sessions` 的轻量元数据能力收口；
3. 用户态只关心“属于哪个项目 / 不属于任何项目”，不引入额外复杂状态；
4. 数据库为真相源，file memory 仅作运行态镜像；
5. 前后端字段语义保持稳定：`projectId` + `projectName`；
6. 自组织项目是未来 Altus 自主组织能力的预览脚手架，当前不能作为 session 父项目；
7. 普通项目进入后端持久化表，前端不再保留独立真相源。

## 6. 数据设计

### 6.1 会话项目归属存储位置

本次建议继续使用 `task_creation_sessions.metadata_json` 收口会话项目归属，而不是新建列或新建关联表。

建议结构：

```json
{
  "projectId": "1",
  "projectName": "oneceo.ai"
}
```

说明：

1. 现有会话轻量管理字段本就适合放在会话元数据层；
2. `projectId/projectName` 本质上就是会话轻量管理元数据；
3. 用 `metadata_json` 收口，能避免本轮继续扩散数据库列；
4. 后续若项目系统变成正式领域模型，再评估是否拆分到独立列或独立关系表。

### 6.2 普通项目主表

普通项目本轮新增独立主表：

- `app_user_projects`

建议字段：

1. `id`
2. `user_id`
3. `name`
4. `description`
5. `project_type`
6. `status`
7. `metadata_json`
8. `created_at`
9. `updated_at`

约束：

1. 仅当前登录用户自己的项目可见；
2. 当前只持久化 `project_type=standard` 的普通项目；
3. 自组织项目不进入该表；
4. session 归属时只允许归属到该表中的普通项目。

### 6.3 字段规则

`projectId`

1. 可空；
2. 空值表示 `无项目`；
3. 若传入非空，需 `trim`；
4. 当前按字符串处理。

`projectName`

1. 可空；
2. 空值表示 `无项目`；
3. 若传入非空，需 `trim`；
4. 最大 80 字。

### 6.4 归属约束

1. 一个 session 只能有一个 `projectId`；
2. 若 `projectId = null`，则 `projectName` 必须一并置空；
3. 不允许同时挂多个项目；
4. 默认新 session：`projectId = null`、`projectName = null`。

## 7. API 设计

### 7.1 新增会话项目归属更新接口

建议新增：

- `POST /api/task-creation/sessions/:sessionId/project`

请求体：

```json
{
  "projectId": "1",
  "projectName": "oneceo.ai"
}
```

移出项目：

```json
{
  "projectId": null,
  "projectName": null
}
```

规则：

1. 必须要求当前登录用户拥有该 session；
2. 若传 `projectId`，后端必须到 `app_user_projects` 校验该项目归属当前用户且类型为普通项目；
3. `projectName` 由后端根据项目表回填，不再信任前端传值；
4. 返回最新 session summary；
5. 若传空，则表示回到 `无项目` 状态。

### 7.2 新增普通项目接口

本轮新增：

1. `GET /api/task-creation/projects`
2. `POST /api/task-creation/projects`

能力范围：

1. 列出当前用户的普通项目；
2. 创建普通项目；
3. 为侧边栏与 session 归属弹窗提供统一项目源。

### 7.3 会话列表与详情返回

以下接口继续统一返回：

1. `GET /api/task-creation/sessions`
2. `GET /api/task-creation/sessions/:sessionId`

返回中保持：

```json
{
  "projectId": null,
  "projectName": null
}
```

或

```json
{
  "projectId": "1",
  "projectName": "oneceo.ai"
}
```

## 7.4 新建会话页项目提示条

### 背景

当前用户已经可以从项目上下文进入新建会话页，例如：

- `/new-task?projectId=<id>&new=<ts>`

但新建会话输入框区域没有明确提示“当前会话将归属到哪个项目”，导致用户进入后容易丢失项目上下文，也无法一眼确认当前消息是否会创建到目标项目下。

### 目标

当用户通过 `projectId` 进入新建会话页，且当前仍处于输入态主对话框时，需要在输入框下方增加一个项目名称提示条，用来明确当前会话归属项目。

### 展示规则

1. 仅在 `/new-task` 页面且 URL 中存在有效 `projectId` 时展示；
2. 仅在输入态主对话框区域展示，不在历史消息流中额外挂同类提示；
3. 提示条位于主对话框下方，视觉上与主对话框保持一体，但不直接并入输入框边框；
4. 提示条采用“下吊单眼皮”样式：
   - 作为输入框底边下方悬挂的一条窄胶囊/窄条；
   - 总宽度略窄于主对话框；
   - 右侧对齐；
   - 与输入框主体保持 1 个稳定的小间距；
5. 提示内容只展示项目名称，不额外堆叠说明文字，避免输入区噪音过高；
6. 若项目名称尚未拉取完成，可先显示轻量 loading 占位；
7. 若 `projectId` 无效、项目不存在、或接口拉取失败，则不展示错误块，不做兜底文案，直接隐藏该提示条，避免输入区被异常状态污染。

### 数据来源

1. `projectId` 继续来自当前 URL query；
2. `projectName` 不从 query 直接读取，不信任前端拼接值；
3. 前端通过既有 `GET /api/task-creation/projects/:projectId` 拉取项目详情；
4. 拉取成功后使用返回的 `name` 作为提示条文案；
5. 数据获取失败时按“无提示条”处理。

### 交互约束

1. 该提示条只承担“当前项目归属提示”，不是切换器，不承载下拉、编辑、跳转等交互；
2. 用户发送首条消息并进入正式会话后，后续会话归属仍由既有 session `projectId/projectName` 事实源驱动；
3. 该提示条不能替代侧边栏或会话归属能力，只是新建会话入口的上下文提示。

## 7.5 新建会话页项目选择下拉

### 背景

当前新建会话页已经有项目名称底托提示，但它仍是只读的。用户如果想在发送首条消息前切换归属项目，仍需要返回侧边栏或其他入口，路径过长。

### 目标

把新建会话页输入框下方的项目底托升级为“可点击选择”的轻量项目归属入口，使用户在发送首条消息前就能直接决定新会话将归属到哪个普通项目下。

### 展示与默认态

1. 底托区域整体可点击；
2. 默认显示 `无项目`；
3. 若 URL query 已携带 `projectId` 且能成功解析到普通项目，则默认显示对应项目名称；
4. 若 URL query 无 `projectId`，或该项目已不存在/无权限/拉取失败，则回落为 `无项目`；
5. 展示文案最多显示 8 个字符，超出前端截断，避免撑坏布局；
6. 底托右侧保留对齐语义，点击后从底托区域弹出普通项目下拉列表。

### 下拉规则

1. 列表第一项固定为 `无项目`；
2. 其后列出当前登录用户的全部普通项目；
3. 自组织项目不能出现在该下拉中；
4. 当前已选项目需要在列表中有选中态；
5. 若普通项目列表加载中，可显示轻量 loading；
6. 若项目列表加载失败，保留当前选中值，不在输入区展示错误块或 toast 噪音，允许用户继续按当前值发起会话。

### 提交与归属规则

1. 用户在新建会话输入态选择项目后，只更新前端的“待创建会话归属项目”状态；
2. 首条消息触发新 session 创建时，把当前选中的 `projectId` 作为创建参数提交；
3. 选择 `无项目` 时，创建参数中的 `projectId` 必须为 `null`；
4. session 创建成功后，后续会话详情、列表与侧边栏仍以既有后端事实源返回的 `projectId/projectName` 为准；
5. 该下拉只影响“当前尚未创建的会话”，不承担已创建 session 的项目迁移动作；已创建 session 的迁移仍走既有会话项目归属能力。

### 实现约束

1. 优先复用现有 `GET /api/task-creation/projects` 项目列表接口；
2. 不新增新的项目选择专用接口；
3. 不在前端维护独立项目真相源；
4. 不在本轮加入搜索、分组、最近使用、键盘快捷筛选等增强交互；
5. 仍维持“输入框下挂层”的视觉语义，不退回为普通表单字段。

## 9. 前端实现方案

### 9.1 数据消费

前端已存在 `projectId/projectName` 类型定义，原则上不需要重新发明字段。

需要补齐的是：

1. 调用普通项目列表 / 创建接口；
2. 调用会话项目归属接口；
3. 更新侧边栏项目列表与 session 列表本地状态；
4. 让“无项目 / 有项目”状态在 UI 上可被前端直接消费。

### 9.2 交互

本轮建议只做最小可用交互：

1. 在会话项右键菜单中，把现有“移动到项目（待实现）”改成真实能力；
2. 不再打开独立弹窗，而是在右键菜单内展开悬浮二级菜单；
3. 顶部提供 `无项目` 选项；
4. 再列出当前可选普通项目；
5. 若当前没有普通项目，则在二级菜单里直接给出“新建项目”入口；
6. 选择后立即更新会话归属。

### 9.3 项目来源分层

项目来源分为两类：

1. 普通项目：用户通过侧边栏“新建项目”按钮创建；
2. 自组织项目：当前侧边栏中的预览型静态项目树。

说明：

1. 普通项目才可以作为 session 的父项目；
2. 自组织项目只用于未来 Altus 自主组织项目、分配经理、分配 session 的预览交互；
3. 自组织项目必须继续保留，但不能出现在“移动到项目”的可选列表里；
4. 普通项目以服务端列表接口作为唯一真相源。

### 9.4 普通项目创建交互

本轮补齐侧边栏项目区右上角新增按钮能力：

1. 点击后弹出“新建项目”窗口；
2. 至少填写项目名称；
3. 可选填写项目简介；
4. 保存后项目出现在“普通项目”折叠组中；
5. 新建后的普通项目可作为 session 父项目；
6. 普通项目数据当前落在后端项目表中，由前端实时读取。

### 9.5 项目详情页分流

普通项目与自组织项目必须使用不同的详情页语义。

普通项目页：

1. 面向“项目分组 / 会话归档”；
2. 展示项目名称、简介、会话数量、最近活动时间；
3. 展示归属到该普通项目下的 session 列表；
4. 允许用户从这里进入具体 session；
5. 不展示经理、员工、任务树等自组织项目专属结构。

自组织项目页：

1. 继续保留当前预览型经理-任务树页面；
2. 作为未来 Altus 自组织、分配经理和分配 session 的功能预览；
3. 不与普通项目页共享页面语义。

### 9.6 侧边栏项目展开行为

侧边栏中的普通项目与自组织项目，在“展开”后的子列表也必须分流。

普通项目展开态：

1. 展示当前归属到该项目下的 session 会话列表；
2. 点击左侧折叠按钮时，下拉出的就是这些 session；
3. 点击 session 后，URL 与主内容区都必须立即切换到对应会话，不能出现“仅 URL 变化、页面需手动刷新”的情况；
4. 若暂时没有归属会话，则保持为空，不额外显示提示文案；
5. 不展示经理、员工、任务树；
6. 展开后的 session 条目必须继续受侧边栏宽度约束，不能把项目头部、右上角加号按钮或整个侧边栏横向撑坏；
7. 以“项目”标题行为滚动分界线，该标题行以下的项目列表、会话预览与“所有任务”入口必须位于同一个纵向滚动区内，避免条目过多时显示不开。

### 9.7 普通项目右键菜单

普通项目在侧边栏中的项目名按钮，需要支持右键菜单能力。

1. 仅普通项目支持该菜单；自组织项目不开放编辑型菜单；
2. 菜单项固定为：`置顶`、`编辑`、`删除`；当项目已置顶时，首项切换为 `取消置顶`；
3. `置顶 / 取消置顶` 的真实语义是切换项目在普通项目列表中的置顶状态，被置顶的普通项目优先排在其他普通项目之前；
4. `编辑` 用于修改普通项目名称和简介；
5. `删除` 会删除该普通项目，并将原先归属到该项目的 session 清空为 `无项目`；
6. 这些操作都必须持久化到后端，不能只停留在前端本地状态。

自组织项目展开态：

1. 继续展示经理节点与任务树预览；
2. 不改成 session 列表；
3. 保持未来 Altus 自组织项目预览语义；
4. 自组织项目分组只允许在 `VITE_RUNTIME_ENV=dev` 时显示，`staging` 与 `product` 必须隐藏。

## 10. 验证方案
