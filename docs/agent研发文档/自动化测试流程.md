# 自动化测试流程（Altus 端到端）

日期：2026-03-04

本文档说明如何在本地执行 **Altus 端到端自动化测试**，并生成完整的会话日志用于排查状态机问题。

---

## 1. 前置条件

- 后端已启动：`oneceo/apps/api` → `pnpm dev`
  - 2026-03-25 起，`apps/api` 的 `pnpm dev` 会在启动前自动回收同仓库残留的旧 API 监听进程；若 `4000` 被其他程序占用，会直接打印 PID / cwd / command 并退出。
  - 2026-03-26 起，API 启动前会先做一次数据库 schema 快速探测；只有发现缺表、缺列或缺关键索引时才执行整套 `runMigration()`，正常重启不会再无条件全量迁移。
- 前端可选启动：`oneceo/apps/web` → `pnpm dev`
- 本地可访问：`http://localhost:4000`

---

## 2. 自动化测试脚本

测试脚本路径：
- `D:\project\oneceo.ai\.tmp\run_autotest.js`

脚本行为：
1. 通过 WebSocket 发起任务（默认任务：`开发2048小游戏，使用html即可`）
2. 自动响应澄清问题（默认回复：`使用html即可`）
3. 监听 status_update / opencode_event
4. 任务结束后拉取：session detail / messages / intent / task / plan
5. 输出完整日志到 `oneceo/debug/`

运行命令：
```bash
node D:\project\oneceo.ai\.tmp\run_autotest.js
```

---

## 3. 产出日志

日志默认输出：
- `oneceo/debug/conversation-autotest-YYYY-MM-DDTHH-MM-SS-sssZ.json`

包含内容：
- WebSocket 收发记录
- 会话详情
- 全量 messages
- 意图/规划/执行计划

---

## 4. 测试通过判定

满足以下条件即可视为通过：

- 最终 status_update 为 `completed`
- Review 输出显示交付物已生成
- messages 中出现实际文件产出（如 `2048.html`）
- Playwright 测试记录存在（工具事件或测试日志）

---

## 5. 常见异常与定位

### 5.1 卡在 repair / testing
可能原因：
- 未检测到新产物（revision 未增长）
- 测试证据未命中

检查项：
- 日志中是否有 `[File] edited` 事件
- Review 是否识别到文件列表

### 5.2 无法进入 testing
可能原因：
- baseline 未建立
- 实际文件未写入（无产物）

检查项：
- workspace tree 是否有新增文件

---

## 6. 对应状态机要点（简版）

- **development → testing**：有新产物 revision 增长
- **testing → repair**：Review 返回 retry
- **repair → testing**：修复后产生新产物
- **testing → delivery**：Review 通过

---

## 7. 快速检查命令

- 拉取会话详情：
```bash
curl http://localhost:4000/api/task-creation/sessions/<sessionId>
```

- 拉取会话消息：
```bash
curl http://localhost:4000/api/task-creation/sessions/<sessionId>/messages
```

- 拉取工作区树：
```bash
curl http://localhost:4000/api/task-creation/sessions/<sessionId>/workspace/tree
```

---

如需扩展测试场景，请复制脚本并修改输入内容即可。
