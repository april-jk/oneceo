## 6. 对 OSAC Fix3 的明确修复请求
请 OSAC 团队在 Fix3 中至少覆盖以下点：

1. **WS 握手稳定性**
- 消除同 endpoint/token 的偶发 401 抖动。
- 401 返回中增加可机器识别原因码（例如：`token_mismatch` / `session_not_ready` / `mapping_not_ready`）。

2. **LLM_PROXY 请求回流可靠性**
- 对 `LLM_PROXY_REQUEST` 增加桥接确认与超时原因细分。
- 当 bridge 不可用时，需快速返回 `bridge_disconnected`，避免卡满 60s 无响应。

3. **日志可观测性增强**
- 对每个 requestId 输出完整阶段：`recv -> bridge_send -> bridge_ack -> response/error`。
- 401 与桥接断开日志中打印 sessionId、endpoint、requestId（脱敏 token 指纹即可）。

4. **端口映射与会话绑定一致性**
- 确保 hostPort 与 session/token 的绑定一致，不出现“端口可达但鉴权不稳定”。
- 提供就绪信号定义（ready 判定标准）供编排调用。

## 7. Fix3 验收标准（建议）
在同一环境下连续执行 20 次以下用例，成功率应达到 100%：

1. provision 成功后，`GET_SESSION_LIST` 必须稳定成功（无偶发 401）。
2. VM 内执行：
```bash
curl -m 60 http://127.0.0.1:18111/v1/models -H "Authorization: Bearer local-proxy"
```

3. `chat/completions` 流式请求可稳定返回 chunk/end，不出现 bridge 卡死。
