## 3. 背景与问题

Clean SaaS Admin 2.0 完成后，详情类界面已经从“多套弹窗”收敛为“统一弹窗”。但当前体验仍有以下缺口：

1. 桌面端缺少耳目一新的产品级详情工作台感。
2. Skill / Connector / Billing / Sandbox / OSAC 的信息节奏仍不完全统一。
3. 图标体系不足，关键状态和动作主要依赖文字或缩写。
4. Connector Guide 编辑器仍像独立编辑页面，未融入统一详情指挥台。
5. Skill 详情表单虽已统一基础控件，但仍有局部原生编辑器感。
6. 异常、关系、审计、变更差异没有形成可复用的信息层。

本轮需要把详情类界面升级为：

```text
Admin Detail Command Center
管理员详情指挥台
```

其目标不是视觉炫技，而是让管理员在桌面端进入任何详情后，都能快速回答：

1. 这个对象是谁？当前是否健康？
2. 最近发生了什么？哪里异常？
3. 它和哪些用户、会话、运行时、版本、计费规则有关？
4. 可以安全做哪些操作？危险操作会影响什么？
5. 配置变更前后差异是什么？是否可回滚？

## 4. 设计目标

1. 将详情顶部升级为紧凑的状态驾驶舱，而不是普通标题条。
2. 在桌面端增加右侧 Sticky Inspector，承载状态、异常、关联、最近操作与快捷入口。
3. 建立基于 `lucide-react` 的受控图标体系，不新增图标库。
4. 新增轻量可复用组件：`RelationTopology`、`AuditTimeline`、`DiffDrawer`。
5. 统一详情内容分区：`Overview / Runtime / Configuration / Relations / Audit / Raw Data`。
6. 按异常优先排序详情内容：错误、未完成任务、安全风险优先于常规字段。
7. 以 Sandbox 详情为第一试点，再推广到 Skill / Connector / OSAC / Billing。
8. 保持管理后台专业、高密度、可操作，不做营销页化视觉。

## 5. 非目标

本轮明确不做：

1. 不做移动端大改；移动端保持当前可用状态，不扩大范围。
2. 不新增后端 API。
3. 不修改 `apps/api` 或 `apps/admin_management/server` 的主流程。
4. 不改变业务状态机、认证体系、计费语义或 Sandbox 生命周期语义。
5. 不做大面积装饰渐变、插画、玻璃拟态或营销 Hero。
6. 不做复杂拖拽拓扑图、canvas 图谱或外部 graph 库。
7. 不给每个普通字段都加图标。
8. 不新增第二套弹窗系统。
9. 不恢复 `window.confirm` 或原生 `confirm`。
10. 不把危险操作伪装成蓝色主按钮。

## 6. 核心原则

### 6.1 Command Center，而不是 Hero

顶部是状态驾驶舱，不是营销展示区：

1. 标题区域保持紧凑。
2. 只展示实体身份、当前状态、最近时间、关键风险、关键指标与安全操作。
3. 不使用大标题、大背景图、大渐变或巨型 KPI。
4. Body 第一屏避免重复展示 Header 已有摘要。

### 6.2 异常优先，不平均展示字段

详情默认信息排序：

1. 错误 / 失败 / 未恢复异常。
2. 运行中任务 / 未完成任务。
3. 安全风险 / 权限风险 / 高影响变更。
4. 关键关系与最近操作。
5. 常规配置字段。
6. Raw Data / JSON / 低频调试信息。

无异常时再展示常规摘要。

### 6.3 Inspector 是上下文，不是第二主内容

右侧 Sticky Inspector 只承担辅助判断：

1. 当前状态。
2. 最近异常。
3. 最近操作。
4. 快捷跳转。
5. 关联对象。
6. 危险区入口。

Inspector 不承载长表格、长 JSON、完整编辑器或主流程表单。

### 6.4 图标只服务识别与动作

使用 `lucide-react`，但必须克制：

1. 标题区可以使用模块图标。
2. 状态 badge 可以使用状态图标。
3. 主操作按钮可以使用动作图标。
4. Tab 可少量使用图标，但不强制。
5. 普通字段 label 不批量加图标。

## 7. AdminDetailShell 演进方案

### 7.1 新增能力概览

在保持现有调用兼容的前提下，扩展 `AdminDetailShell`：

```tsx
<AdminDetailShell
  icon={moduleIcon}
  entityType="Sandbox"
  title={sandboxName}
  subtitle={sandboxIdToken}
  status={<StatusBadge icon={...}>运行中</StatusBadge>}
  metrics={[
    { label: '最近活跃', value: '2 分钟前' },
    { label: '执行器', value: 'Altus' },
    { label: '风险', value: '无', tone: 'success' },
  ]}
  actions={safeActions}
  moreActions={moreActions}
  inspector={<DetailInspector />}
  tabs={<AdminTabs ... />}
>
  {children}
</AdminDetailShell>
```

### 7.2 Header：状态驾驶舱结构

建议 Header 分三层，均保持紧凑：

```text
┌─────────────────────────────────────────────────────────────┐
│ [Icon] 实体名称                         状态 Badge   操作区  │
│       实体类型 / ID / 最近更新时间 / 风险提示                 │
│       [metric] [metric] [metric] [metric]                    │
└─────────────────────────────────────────────────────────────┘
```

每个详情顶部应包含：

1. 模块图标。
2. 实体名称。
3. 实体类型。
4. 当前状态 badge。
5. 最近更新时间 / 最近活跃。
6. 关键风险提示。
7. 1-3 个关键指标，复杂模块最多 5 个。
8. 主要安全操作。
9. 更多操作入口。

危险操作进入 `dangerZone` 或 `DangerConfirmDialog`，不放为蓝色主按钮。

### 7.3 桌面端 Sticky Inspector

新增 `inspector` 插槽：

```tsx
<AdminDetailShell inspector={<AdminStickyInspector sections={...} />}>
```

桌面布局：

```text
Body
├─ Main Content: minmax(0, 1fr)
└─ Sticky Inspector: 300px - 360px
```

显示规则：

1. `>= 1180px` 显示右侧 inspector。
2. `< 1180px` 隐藏 inspector 或降级为普通内容区下方；本轮不专门重构移动端。
3. Inspector 内部可滚动，不能导致 Shell body 横向溢出。
4. Inspector 不改变 `tabs` 行为，tabs 仍是主内容导航。

### 7.4 保持兼容

现有 props 不删除：

1. `summary` 仍保留，但新模块优先用 `metrics`。
2. `actions / footer / dangerZone` 继续保留。
3. 未传 `inspector` 时保持当前单列详情。
4. 移动端现有样式不主动重写。

## 10. 信息分层统一

详情主内容统一命名为以下分区。不是每个模块都必须拥有全部分区，但命名与视觉节奏必须一致。

| 分区 | 用途 | 示例 |
|---|---|---|
| Overview | 关键摘要、异常优先卡、对象身份 | 用户状态、Sandbox 运行摘要、定价规则摘要 |
| Runtime | 运行状态、连通性、任务、进程、端口 | Sandbox runtime、OSAC 发布状态 |
| Configuration | 配置项、版本、参数、编辑器 | Skill governance、Connector policy、Billing pricing |
| Relations | 关联对象与轻量拓扑 | User → Session → Sandbox → Runtime |
| Audit | 审计时间线、最近操作、版本历史 | Connector revision、OSAC publish、Billing update |
| Raw Data | JSON、日志、payload、manifest | `CodePanel` 展示 |

## 11. 模块落地方案

### 11.1 Sandbox 详情（P1 试点）

目标：验证 Header 驾驶舱、Inspector、RelationTopology、AuditTimeline 的完整组合。

Header：

1. 图标：`Box` / `Container`。
2. 实体名称：Sandbox name / template / runtime label。
3. 状态：运行中 / 已暂停 / 已归档 / 失败。
4. 最近活跃。
5. 执行器：Altus / OpenCode。
6. 风险：无 / 缺 OSAC / 缺 OpenCode / 未纳管。
7. 操作：刷新、打开终端、更多；危险动作仍进确认弹窗。

Inspector：

1. 当前状态。
2. 最近异常。
3. 最近操作：开机、关机、重启、归档、文件操作。
4. 关联对象：User、Session、OSAC、Archive。
5. 快捷动作：复制 ID、跳转会话、查看 raw。

RelationTopology：

```text
User → Session → Sandbox → Runtime → Artifact
```

AuditTimeline：使用已有时间字段和前端操作上下文，优先展示最近状态、归档、恢复、文件操作、连通性检查。

### 11.2 Skill 详情（P2）

目标：把 Skill 从“编辑表单弹窗”升级为技能治理指挥台。

Header：

1. 图标：`Sparkles` / `Package`。
2. 实体名称：Skill name。
3. 类型：Skill / category。
4. 状态：启用 / 已归档。
5. 指标：发布版本、工作版本、资源数、最近更新。

Inspector：

1. 治理状态：systemRole、auto activation。
2. 资源健康：文档数、缺失资源。
3. 最近校验结果。
4. 危险区入口：归档 / 重新启用。

DiffDrawer：用于保存新版本前展示当前版本与即将保存内容的字段级 diff。没有后端 diff 时，只展示当前编辑值与原始值。

### 11.3 Connector Guide 编辑器（P2）

目标：消除“独立页面感”，让编辑器融入指挥台。

Header：

1. 图标：`Cable` / `Plug`。
2. 实体名称：connectorKey。
3. 状态：draft / active / archived / published。
4. 指标：published revision、当前编辑 revision、触发模式、最近同步。

结构：

1. 使用统一 tabs：`Overview / Configuration / Relations / Audit / Raw Data`。
2. 文本编辑仍在 Configuration 中，但右侧 Inspector 固定显示 revision、校验、发布状态。
