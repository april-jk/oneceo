# Connector Guide 启动全量重算改按需加载方案 [20260407-1403已采用]

## 对应事项

- Issue: #34
- 问题现象：API 启动后后台批量输出 `CONNECTOR_GUIDE_RECOMPUTE_*`，会话多时造成启动后阶段资源争用与体感变慢。

## 目标

1. 启动阶段不再全量重算历史会话 guide。
2. 保证活跃会话在实际访问/变更时 guide 正确。
3. 保持现有 attach/detach/recovery 链路语义不变，不引入兼容分支与兜底逻辑。

## 当前代码事实

- 启动流程在 `apps/api/src/index.ts` 中监听端口后异步触发：
  - `connectorGuideService.recomputeBuiltinPolicySessions()`
- `recomputeBuiltinPolicySessions()` 会按 connector 扫描 `attached` binding 并逐会话执行 `recomputeSessionGuides()`。
- `attach/detach` 已在 `session-connector-service.ts` 内触发 `recomputeSessionGuides(taskSessionId)`。
- `GET /api/task-creation/sessions/:sessionId/connectors` 仅返回状态，不会主动检查 guide 是否陈旧。

## 方案（最短路径）

### 1. 关闭默认启动全量重算

- 在 `apps/api/src/index.ts` 中将启动时 `recomputeBuiltinPolicySessions()` 改为受环境变量控制。
- 新增开关：`CONNECTOR_GUIDE_STARTUP_RECOMPUTE_ENABLED`
  - 默认：`false`
  - 显式 `true` 时才执行全量重算

### 2. 增加会话级按需重算入口

- 在 `apps/api/src/services/connector-guide-service.ts` 增加：
  - `ensureSessionGuidesUpToDate(taskSessionId)`
- 行为：
  1. 读取当前会话 attached connector keys（只含受支持 connector）。
  2. 读取当前会话已投影的 session guides connector keys。
  3. 两者集合不一致时执行 `recomputeSessionGuides(taskSessionId)`；一致则跳过。

### 3. 在读取 connectors 时触发按需校验

- 在 `apps/api/src/routes/task-creation-routes.ts` 的
  `GET /sessions/:sessionId/connectors` 中，先调用
  `connectorGuideService.ensureSessionGuidesUpToDate(sessionId)`，再继续返回 connectors 状态。

## 非目标

- 不改 connector guide 数据模型。
- 不新增后台巡检任务。
- 不修改 attach/detach/recovery 的既有触发点。

## 风险与验证

### 风险

- 按需校验带来一次额外 DAO 读取；但只发生在具体会话访问时，远小于启动全量扫描成本。

### 验证

1. 启动日志：默认不再出现成批历史会话 `CONNECTOR_GUIDE_RECOMPUTE_START/DONE`。
2. 访问 `GET /api/task-creation/sessions/:sessionId/connectors`：
   - 当 guide 过期/缺失时触发单会话重算。
   - 再次访问时不重复重算（集合一致）。
3. `attach/detach` 仍可立即更新 guide。
4. 最小校验：`pnpm --filter api type-check`。

- `apps/api/src/index.ts`
- `apps/api/src/services/connector-guide-service.ts`
