## 1. 文档目标

本文定义 connector guide 体系的 API。

注意：

1. 这里的“隐式 skills”是 connector guide documents
2. 不接入现有 platform skills API
3. 不走 sandbox skill sync API

## 2. API 分层

### 2.1 管理后台治理 API

用途：

1. 管理 connector guide policy
2. 编辑 guide revision 文本
3. validate / publish / rollback

### 2.2 运行时内部 API

用途：

1. 根据 session attached connectors 解析 relevant guides
2. 生成 prompt 注入片段
3. 为 MCP 工具调用提供 blocking rules 读取能力

### 2.3 调试 API

用途：

1. 查看某 session 当前有哪些 connector guides 生效
2. 查看每个 connector 注入了哪些 prompt 片段

## 3. 模块归属

建议新增：

1. `apps/api/src/services/connector-guide-service.ts`

## 4. 管理后台 API 设计

路由建议挂在：

`/admin/connector-guides`

### 4.1 列表 policies

`GET /admin/connector-guides`

query：

1. `connectorKey?`
2. `status?`
3. `query?`

返回：

```json
{
  "items": [
    {
      "id": "pol_xxx",
      "connectorKey": "github",
      "status": "active",
      "triggerMode": "on_attach",
      "publishedRevisionId": "rev_xxx",
      "publishedRevisionNumber": 2,
      "updatedAt": "2026-04-01T03:00:00.000Z"
    }
  ]
}
```

### 4.2 获取 policy 详情

`GET /admin/connector-guides/:policyId`

返回：

1. policy 基础信息
2. published revision 摘要
3. revisions 摘要列表

### 4.3 创建 policy

`POST /admin/connector-guides`

body：

```json
{
  "connectorKey": "github",
  "triggerMode": "on_attach",
  "description": "GitHub connector guide policy"
}
```

应用层约束：

1. 当前首批支持范围为 `github / supabase / vercel / notion`
2. 一个 connector 同时只允许一个 policy 容器

说明：

1. connector guide 支持集合以后端 `connector-guide-service.ts` 中的 `SUPPORTED_CONNECTOR_KEYS` 为准
2. 新增 MCP 若需要进入 connector guide 治理链路，必须同步补充该支持集合

### 4.4 更新 policy

`PUT /admin/connector-guides/:policyId`

允许更新：

1. `description`
2. `triggerMode`
3. `status`

### 4.5 创建 revision 草稿

`POST /admin/connector-guides/:policyId/revisions`

语义：

1. 从当前 published revision 复制出草稿
2. 没有 published revision 时创建空草稿

### 4.6 获取 revision 详情

`GET /admin/connector-guides/:policyId/revisions/:revisionId`

返回：

1. `serverInstructionsMarkdown`
2. `guideReminderMarkdown`
3. `blockingRulesMarkdown`
4. `notes`

### 4.7 保存 revision 文本

`PUT /admin/connector-guides/:policyId/revisions/:revisionId`

body：

```json
{
  "serverInstructionsMarkdown": "Before calling any write tool, first inspect repository scope.",
  "guideReminderMarkdown": "A GitHub guide is active for this session.",
  "blockingRulesMarkdown": "If repository authorization is unclear, stop and ask the user.",
  "notes": "Refine GitHub repository creation path."
}
```

说明：

1. 采用整包保存，不做局部 patch

### 4.8 校验 revision

`POST /admin/connector-guides/:policyId/revisions/:revisionId/validate`

校验规则：

1. 三段文本至少存在一段非空
2. 文本长度不能超过设定上限
3. triggerMode 与 connectorKey 必须匹配首批范围
4. 不允许出现试图引用 platform skill 的保留语法

返回：

```json
{
  "valid": true,
  "errors": [],
  "warnings": []
}
```

### 4.9 发布 revision

`POST /admin/connector-guides/:policyId/revisions/:revisionId/publish`

语义：

1. 必须先 validate 成功
2. 发布后 policy 指向该 revision
3. 旧 published revision 转 archived

### 4.10 回滚 revision

`POST /admin/connector-guides/:policyId/revisions/:revisionId/rollback`

语义：

1. 指定旧 revision 重新成为 published
2. 当前 published 转 archived

### 4.11 获取 connector catalog 快照

`GET /api/connector-guides/catalog-summary`

用途：

1. 给 Admin 页面返回当前最新 connector catalog
2. 为“新增 MCP 后页面候选项自动出现”提供统一入口

返回：

```json
{
  "items": [
    {
      "key": "notion",
      "name": "Notion",
      "available": true,
      "availabilityReason": "",
      "visibleInMenu": true
    }
  ],
  "stats": {
    "total": 4,
    "available": 4,
    "unavailable": 0
  },
  "updatedAt": "2026-04-11T08:00:00.000Z"
}
```

约束：

1. Admin 前端应统一消费该聚合接口，不再自行写死 connector keys
2. 该接口由 Admin server 聚合转发，内部透传 API `GET /api/connectors/catalog`

## 5. 运行时内部 API 设计

## 5.1 解析 session relevant guides

服务方法建议：

`connectorGuideService.resolveForSession(taskSessionId)`

返回：

```ts
type SessionConnectorGuide = {
  connectorKey: string;
  policyId: string;
  revisionId: string;
  triggerMode: 'on_attach' | 'on_active_use' | 'on_attach_and_active_use';
  serverInstructionsMarkdown: string;
  guideReminderMarkdown: string;
  blockingRulesMarkdown: string;
};
```

## 5.2 构造 prompt 注入片段

服务方法建议：

`connectorGuideService.buildPromptSections(taskSessionId)`

返回：

```ts
type ConnectorGuidePromptSections = {
  instructionsSection: string;
  reminderSection: string;
};
```

这两个片段将被 `altus-managed-prompt-service.ts` 注入：

1. `# Connector MCP Instructions`
2. `# Relevant Connector Guides`

## 5.3 工具调用前读取 blocking rules

服务方法：

1. `connectorGuideService.getActiveGuideForConnector(taskSessionId, connectorKey)`
2. `connectorGuideService.getBlockingRulesForConnector(taskSessionId, connectorKey)`

用途：

1. 给 `altus-managed-tool-runtime.ts` 读取完整 active guide
2. 对带 active guide 的 connector MCP 调用做前置阻断

## 6. 运行时触发链路

### 6.1 attach 时

1. 用户 attach GitHub / Supabase / Vercel / Notion profile
2. `session-connector-service.ts` 计算当前 attached connectors
3. `connectorGuideService.resolveForSession`
4. 结果进入 session 级 guide context
5. `altus-managed-prompt-service.ts` 注入 guide 文本

### 6.2 执行时

当 Altus 即将调用某 connector 的 MCP tool：

1. 从当前 session guide context 查找该 connector 的 active guide
2. 在 prompt 层提前声明“先调用 `load_connector_guide`，再调用 connector MCP 工具”
3. 若当前 run 还未加载该 connector guide，runtime 直接阻断
4. Altus 调用 `load_connector_guide`
5. 同一 run 内该 connector 的后续 MCP tool 放行

## 7. 不采用的 API 方向

本轮明确不做：

1. `platform-skills` 复用 API
2. `resolvedSkills` 合并 API
3. `sandboxSkillSyncService` 写入 API
4. 用户态 guide 查询 API

## 8. 错误模型

建议错误码：

1. `CONNECTOR_GUIDE_POLICY_NOT_FOUND`
2. `CONNECTOR_GUIDE_REVISION_NOT_FOUND`
3. `CONNECTOR_GUIDE_INVALID_CONNECTOR`
4. `CONNECTOR_GUIDE_VALIDATE_FAILED`
5. `CONNECTOR_GUIDE_NOT_PUBLISHED`

## 9. 验收标准

1. 后台可管理 GitHub / Supabase / Vercel / Notion guide revisions
2. attach connector 后 Altus prompt 能收到对应 guide 注入
3. guide 完全不进入现有 skills 模块
4. Admin 候选 connector 来源统一走 `catalog-summary`，新增 MCP 不再要求前端额外写死 key
5. 用户态无新增可见接口

## 10. 已确认实现边界

已确认：

1. `task_session_connector_guides` 首批直接落库
2. runtime 强约束通过 `load_connector_guide` + 首次 MCP 调用阻断闭环实现

因此本 API 文档后续实现按该边界推进，首批已包含 runtime blocking requirement。
