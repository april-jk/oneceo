# 20260328 PPT 多阶段协同技能实现与验证

## 1. 实现目标

基于 [20260328_PPT多阶段协同技能设计.md](/D:/oneceo-task-creation-agent-fresh/docs/agent研发文档/20260328_PPT多阶段协同技能设计.md)，将当前项目的 `PPT 办公` 从“单体 skill brief”升级为“一个主技能，内部多阶段子技能协同”的执行协议。

本轮坚持最短路径：

- 不改生成引擎
- 不新增 UI
- 不新增连接器
- 不要求用户手动选择多个技能

## 2. 实际改动

## 2.1 新增共享 PPT 契约

新增文件：

- [ppt-generation.ts](/D:/oneceo-task-creation-agent-fresh/packages/shared/src/ppt-generation.ts)

内容包括：

- `PPT_TASK_PHASES`
- `PPT_CONTENT_ARCHETYPES`
- `PPT_PAGE_TYPES`
- `PPT_CONTENT_SUBTYPES`
- `PPT_STYLE_PACKS`
- `PPT_PALETTE_KEYS`
- `PPT_STYLE_RECIPES`
- `PPT_FONT_PAIRINGS`
- `PPT_QA_GATE_RULES`
- `PptGenerationBrief`
- `PptEvidenceBundle`
- `PptStoryboard`
- `PptVisualSystem`

并在 [index.ts](/D:/oneceo-task-creation-agent-fresh/packages/shared/src/index.ts) 中导出，作为后续 Office 正式模式继续落地的共享基础。

## 2.2 重写 PPT skill 模板

重写文件：

- [skill-attachment-templates.ts](/D:/oneceo-task-creation-agent-fresh/apps/web/client/src/lib/skill-attachment-templates.ts)

这次不是只给 `PPT 办公` 增加更多要求，而是明确把它改成了六阶段协同协议：

1. `ppt_task_router`
2. `ppt_research_curator`
3. `ppt_storyboard_designer`
4. `ppt_visual_system_designer`
5. `ppt_builder`
6. `ppt_qa_reviewer`

同时补齐了：

- archetype 集合
- pageType 集合
- contentSubtype 集合
- style pack / palette / style recipe / font pairing 集合
- `presentation_manifest.json` 约束
- QA gate 规则

这样前端侧传入的 `PPT 办公` 不再只是“做个 PPT”，而是会明确要求 Altus 先做任务判型、故事板和视觉系统，再生成最终文件。

## 2.3 升级 Altus managed 的 PPT 系统提示

修改文件：

- [altus-managed-prompt-service.ts](/D:/oneceo-task-creation-agent-fresh/apps/api/src/services/altus-managed-prompt-service.ts)

新增了真正作用于执行链路的 PPT 多阶段协同规则：

- 强制按阶段顺序推进
- 明确 `PptGenerationBrief` 的最小字段
- 明确 `storyboard` 先于页面正文
- 明确 `paletteKey / styleRecipe / fontPairing`
- 要求写出 `presentation_manifest.json`
- 把“反同质化”和“QA gate”上升为完成前硬约束

这使得 Altus 在生成 PPT 时，不再只依赖“先选 archetype + style_pack”的弱约束，而是被要求走完整的多阶段协同链路。

## 2.4 补充 API prompt 测试

修改文件：

- [altus-managed-prompt-service.test.ts](/D:/oneceo-task-creation-agent-fresh/apps/api/tests/altus-managed-prompt-service.test.ts)

新增测试覆盖：

- prompt 必须包含多阶段 PPT 协同协议
- prompt 必须包含 `presentation_manifest.json`
- prompt 必须包含 `paletteKey`
- prompt 必须包含 PPT QA gate

## 3. 遇到的问题

在尝试让 API 直接运行时导入 `@oneceo/shared` 的新 PPT 常量时，发现当前 `shared` 包的运行时导入策略还不适合这次最短路径改动。

因此本轮采取的做法是：

- 共享 PPT 契约先落在 `packages/shared`
- API prompt 服务保留一份本地镜像常量用于稳定运行

这不是兼容性补丁，而是当前仓库结构下的最短正确实现：先把契约抽出来，再等后续 Office 正式模式继续推进时统一包导出策略。

## 5. 当前效果

当前 `PPT 办公` 已经从“单体提示模板”升级为“主技能 + 多阶段子技能协同”的执行协议，具备以下改进：

- 会先做任务判型，而不是直接开始写页
- 会先做故事板，而不是先写正文再塞页面
- 会先做视觉系统决策，而不是默认同一套模板
- 会带 QA gate，直接限制“纯文字页”“重复版式”“无收尾页”这类低质量结果
