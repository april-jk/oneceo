# 20260408 Railway Web BFF 反向代理部署方案 [20260408-1154已采用]

## 背景

- `oneceo-web` 直接访问后端域名时，部署环境容易出现跨域和地址漂移问题。
- 目标是让 `web` 仅暴露一个公网域名，浏览器流量由 `web` 服务反向代理到 `oneceo-api` 内网地址。

## 方案

- 在 `apps/web/server/index.ts` 增加 BFF 代理：
  - HTTP: 代理 `/api/*` 与 `/socket.io/*` 到后端。
  - WebSocket: 代理 `/ws/task-creation` 与 `/socket.io/*` upgrade 到后端。
- 在 `apps/web/client/src/lib/runtime-config.ts` 调整默认行为：
  - 开发态：默认 `http://<host>:4000`（保持本地联调习惯）。
  - 生产态：默认当前站点同源（由 BFF 转发）。

## 环境变量

- `WEB_BFF_API_TARGET`：BFF 目标地址，优先级最高。
- `ONECEO_API_URL`：未设置 `WEB_BFF_API_TARGET` 时使用。
- 均未设置时，默认 `http://127.0.0.1:4000`。

## 部署建议（Railway）

- `oneceo-web` 暴露公网域名（如 `dev.oneceo.ai`）。
- `oneceo-api` 不暴露公网域名，只保留 Railway private domain。
- 在 `oneceo-web` 注入：
  - `ONECEO_API_URL=http://${{oneceo-api.RAILWAY_PRIVATE_DOMAIN}}`

## 验证口径

1. 访问 `web` 域名后，所有前端接口请求应走同域 `/api/*`。
2. `ws/task-creation` 可正常建立并收流式事件。
3. 不需要对浏览器暴露 `api` 公网地址。
