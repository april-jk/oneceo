# 20260418 网站生成到会话内部署全链路真实验收方案 [20260418-2212已采用]

## 1. 测试目标

验证用户从真实会话发起“开发网站”，再在同一会话内要求“部署当前项目”时，平台满足以下要求：

1. 前端真实页面可完成会话创建与消息驱动。
2. Altus 能正确生成网站代码并落到工作区。
3. 会话内“部署当前项目”会触发正确的 managed deploy tool。
4. 部署相关 skill 会按治理配置自动挂载，而不是依赖硬编码。
5. 最终部署成功，可获得可访问公网地址。
6. 关键状态会同时反映在运行事件、数据库和 sandbox 元数据中。

## 3. 测试范围

本次仅覆盖真实用户主链：

1. 用户进入 `/new-task?q=...`
2. Altus 生成一个亚克力外贸网站项目
3. 在同一会话内继续发送“帮我部署当前项目”
4. Altus 通过部署工具完成部署
5. 平台返回部署结果并可访问线上地址

本次不扩展到：

1. 管理端手工治理操作回归
2. 多轮重新部署 / 回滚
3. 历史会话恢复后的二次部署
4. 多语言 / 多框架穷举遍历

## 4. 测试单元清单

### 单元 A：真实用户登录态建立

- 输入：测试邮箱、显示名。
- 预期输出：生成真实 `app_users` / `app_user_sessions` 记录，并得到 `app_session_id`。
- 边界条件：邮箱已存在时复用现有用户并重新创建 session。
- 失败条件：无法获得有效 cookie，或后续访问用户态接口返回 401。
- 验证方式：脚本通过项目 auth service 创建 session，并用 cookie 访问用户态 API。

### 单元 B：用户态真实页面启动新会话

- 输入：访问 `/new-task?q=帮我写个外贸的网站...`
- 预期输出：前端跳转到 `/session/:sessionId`，并自动发起首条消息。
- 边界条件：页面可能先经历 loading / processing 状态。
- 失败条件：不跳转、不创建会话、页面白屏或致命 console error。
- 验证方式：Playwright 打开页面，等待 URL 进入 `/session/:id`，同时收集 console/pageerror/requestfailed。

### 单元 C：网站代码生成完成

- 输入：首条网站生成请求。
- 预期输出：最新 managed run 进入 `completed`，工作区出现网站项目文件。
- 边界条件：允许经历 `queued/running/waiting_tool`。
- 失败条件：`failed/stopped/waiting_user`，或工作区为空。
- 验证方式：轮询 `GET /api/altus-managed/sessions/:sessionId/runs/latest` 与 `GET /api/task-creation/sessions/:sessionId/workspace/tree`。

### 单元 D：生成结果符合网站主题

- 输入：读取工作区关键文件与会话消息。
- 预期输出：页面内容与“亚克力产品出口、产品介绍、公司介绍”等要求一致。
- 边界条件：实现框架可不同，但必须是完整网站项目，不是单段文案。
- 失败条件：没有页面入口文件，或内容明显与要求不符。
- 验证方式：读取工作区入口文件 / 预览文件，检查关键词与结构。

### 单元 E：会话内继续发送部署请求

- 输入：同一会话内发送“帮我部署当前项目”。
- 预期输出：产生新的 managed run，并进入部署处理流程。
- 边界条件：允许先出现工具等待或运行状态。
- 失败条件：消息未触发新 run，或被当作普通文本结束。
- 验证方式：Playwright 在会话输入框继续发送；随后轮询 latest run，确认 runId 变化。

### 单元 F：部署工具调用正确

- 输入：部署 run 的运行事件。
- 预期输出：存在 `tool_call_started`，且 `payloadJson.toolName=deploy_application`；必要时允许后续状态工具调用。
- 边界条件：同一 run 内可同时出现文件修复与部署状态查询工具。
- 失败条件：没有部署工具事件，或直接绕过工具结束。
- 验证方式：数据库查询 `task_session_run_events`。

### 单元 G：部署 skill 自动挂载正确

- 输入：部署 run 的运行事件与系统消息。
- 预期输出：
  1. 存在“已自动加载技能”类运行状态；
  2. 会话消息中存在 `# Newly auto-attached skills`；
  3. 内容说明 `deploy_application` 触发了 skill 自动挂载；
  4. skill 包含 `deployment-orchestrator`。
- 边界条件：允许同 run 前半段未挂载，工具命中后才挂载。
- 失败条件：部署成功但完全无 skill 自动挂载证据。
- 验证方式：数据库查询 `conversation_messages` 与 `task_session_run_events`。

### 单元 H：部署成功并返回公网地址

- 输入：部署 run 完成后读取部署面板。
- 预期输出：`bindingState=ready` 或等价成功态，存在 `latestUrl/latestStaticUrl`。
- 边界条件：允许经历 `provisioning` 等中间状态。
- 失败条件：最终失败、无公网地址、状态空白。
- 验证方式：轮询 `GET /api/task-creation/sessions/:sessionId/deployment`。

### 单元 I：公网页面可访问且内容正确

- 输入：部署面板返回的公网地址。
- 预期输出：HTTP 200，页面正文仍体现亚克力外贸网站主题。
- 边界条件：允许冷启动重试。
- 失败条件：页面不可访问、部署成空白页或与本次生成内容无关。
- 验证方式：Playwright 打开公网地址并读取页面文本。

### 单元 J：部署状态写入 sandbox 元数据

- 输入：按 `taskSessionId` 查询 canonical sandbox 环境。
- 预期输出：`metadata.deploymentState` 存在，且与部署面板主状态一致。
- 边界条件：可能存在历史替换 sandbox，需要取 canonical 记录。
- 失败条件：面板成功但 sandbox metadata 无部署状态。
- 验证方式：数据库查询 `sandbox_execution_environments`。

## 5. 执行方式

1. 通过项目脚本创建测试 session cookie。
2. 使用 Playwright 跑用户态真实会话。
3. 在会话完成后，用脚本抓取数据库与 API 证据。
4. 对照以上测试单元逐项判定通过 / 失败。

## 6. 输出要求

最终交付必须包含：

1. 会话 ID 与部署 URL
2. 生成网站的关键文件证据
3. 部署工具调用证据
4. skill 自动挂载证据
5. 部署面板与 sandbox metadata 对照结果
6. 剩余风险与异常点
