# 20260418 部署状态持久化同步队列测试方案

## 测试目标

验证部署状态后台同步从“进程内队列”升级到“DB 持久化 job”后，具备：

1. 可恢复
2. 可重试
3. 同会话多次 deploy 的收敛能力

## 测试单元

### 1. DAO 层

#### 单元 1.1 `upsertPending()`

- 预期输入：
  - 相同 `sync_key`
  - 不同 `selectedDeploymentId`
- 预期输出：
  - 仍只有一条 job
  - payload 被最新请求覆盖
- 失败条件：
  - 同会话生成多条活跃 job

#### 单元 1.2 `listRunnable()`

- 预期输入：
  - `pending`
  - `failed + next_retry_at <= now`
  - `running`
- 预期输出：
  - 都可被 runner 取到
- 失败条件：
  - 可恢复任务漏取

### 2. Service 层

#### 单元 2.1 `enqueueTaskSessionDeploymentSync()`

- 预期输入：
  - `taskSessionId`
  - `orchestratorSessionId`
  - `selectedDeploymentId`
- 预期输出：
  - 写入 DB job
  - 不再只写进程内 Map
- 失败条件：
  - API 重启后任务丢失

#### 单元 2.2 `recoverTaskSessionDeploymentSyncBacklog()`

- 预期输入：
  - metadata 中存在 `bindingState=provisioning/repair_required`
- 预期输出：
  - 补录 deployment sync job
- 失败条件：
  - 旧状态存在但无 job

#### 单元 2.3 runner follow-up

- 预期输入：
  - panel 仍为 `provisioning`
  - 或 analytics 为 `pending_domain`
- 预期输出：
  - 当前 job 被重新置回 `pending`
- 失败条件：
  - 后续同步断掉

### 3. 真实链路

#### 集成 3.1 API 重启恢复

- 预期输入：
  - deploy 触发后，后台 job 已入库
  - API 重启
- 预期输出：
  - job 仍可被消费并推进状态
- 失败条件：
  - deploymentPanel 永远停在旧快照

#### 集成 3.2 主链 E2E

- 预期输入：
  - 真实会话生成代码并触发部署
- 预期输出：
  - 公网可达
  - `analytics.status=bound`
  - 持久化 job 最终收敛
- 失败条件：
  - E2E 主链回归失败

## 验证命令

1. `pnpm --filter api type-check`
2. `pnpm --filter api exec tsx --test tests/task-session-deployment-sync-job.dao.test.ts tests/deployment-template-bootstrap-service.test.ts tests/deployment-template-baseline-service.test.ts`
3. `pnpm --filter api test:deployment-main-chain:e2e`

若第 1~3 项任意失败，则本轮实现视为未完成。
