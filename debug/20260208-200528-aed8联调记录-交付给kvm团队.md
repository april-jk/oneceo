## 需要 KVM 团队重点核对的点

### 1) guest-exec 对后台进程/重定向的处理
我们当前启动命令（由编排端执行）：
```
/bin/bash -lc "mkdir -p /opt/.altus/opencode/log /opt/.altus/opencode/tmp && \
chmod +x /opt/.altus/opencode/osac /opt/.altus/opencode/opencode && \
setsid env OSAC_AUTH_TOKEN='<token>' OSAC_LISTEN_ADDR=':18080' \
OSAC_OPENCODE_PATH='/opt/.altus/opencode/opencode' \
OSAC_LOG_DIR='/opt/.altus/opencode/log' OSAC_UPDATE_TMP='/opt/.altus/opencode/tmp' \
OPENCODE_BIN='/opt/.altus/opencode/opencode' OPENCODE_PATH='/opt/.altus/opencode/opencode' \
/opt/.altus/opencode/osac >> /opt/.altus/opencode/log/osac.log 2>&1 < /dev/null &"
```

现象：**log 文件不生成**，`ss` 无监听。说明启动命令没有真正执行或被 QGA/virsh 侧处理掉。

请确认：
- QGA `guest-exec` 是否允许后台进程持续运行？
- `setsid` + `env` + 重定向 + `&` 是否会被 QGA 或 virsh 认为“已完成”而中断？
- 是否存在命令行截断/转义异常，导致 shell 实际没执行？

### 2) env 传递方式
我们已试过：
- 通过 `env` 内联设置
- 通过 `/etc/environment` 写入（发现实际上没有写入成功）

请确认：
- QGA `guest-exec` 对环境变量的传递是否有限制
- 是否建议只用 `env ...` 或改用 `--env` 形式（如果你们支持）

### 3) 工作目录/权限/umask
虽然 `mkdir` + `chmod` 成功，但 **log 没生成** 仍不合理。
请确认 QGA 是否有特殊 umask / 权限策略，导致 `>> log` 失败。

### 4) 推荐提供 KVM 侧“守护进程启动接口”
建议新增：
- `POST /v1/sessions/{id}/daemon` 或扩展 exec

这样可避免编排端重复拼 shell。
