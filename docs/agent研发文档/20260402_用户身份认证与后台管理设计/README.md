2. 当前 `apps/web` 仅通过本地 `X-User-Id` 伪身份工作
3. 当前 `apps/admin_management` 没有正式管理员登录态

## 1. 目标

本组文档定义 oneceo 的正式用户身份体系，覆盖：

1. 用户端登录页
2. 用户端注册页
3. 管理后台登录页与管理首页改造
4. 用户身份与对话、skills、连接器授权、Altus run 的绑定规则

目标不是只补几个 UI 页面，而是建立一套统一的用户认证和身份传播主链。

## 2. 采用边界

本组设计默认：

1. oneceo 主站与后台都接入正式账户体系
2. 用户端与后台端分离登录态，并使用两张不同身份表
3. `userId` 成为所有用户态会话、skills、connector profile、授权记录的稳定归属键
4. 不再依赖浏览器本地生成的匿名 `X-User-Id`

这里的“两张不同身份表”是硬约束：

1. 用户态使用 `app_users`
2. 管理端使用 `admin_users`
3. 两侧登录态、session 表、cookie 命名都分开
4. 不允许用同一张用户表同时承载普通用户与管理员登录

## 4. 当前结论

这组文档的核心落点只有四条：

1. `apps/web` 必须有正式登录页和注册页，不能继续把 `AuthDialog` 当作伪登录入口
2. `apps/admin_management` 必须有管理员登录页，不能继续作为无鉴权独立工具后台使用
3. 用户态和管理端必须是两套独立身份源，不共表、不共 session、不共 cookie
4. 用户态所有需要个人归属的能力都必须回挂到真实 `app_users.id`，不只限于对话、skills、连接器
