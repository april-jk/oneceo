# 缓存计费比例管理端可调 — 设计文档 [20260425-0146已采用]

## 1. 背景

当前缓存计费比例硬编码在 `PricingService` 中：

```typescript
const CACHE_RATIOS = {
  openai: { hit: 0.5, creation: 0 },
  anthropic: { hit: 0.1, creation: 1.25 },
} as const;
```

管理员只能通过修改代码来调整缓存折扣/加成，不满足运营灵活性需求。本方案将缓存比例持久化到数据库，并在管理后台提供配置界面。

## 2. 设计原则

- **向后兼容**： PricingService 读取数据库配置，无记录时回退到原硬编码默认值
- **最小改动**： 不修改现有定价表结构，新增独立配置表
- **权限控制**： 只有超级管理员可修改缓存比例
- **实时生效**： 修改后立即影响后续 LLM 调用计费，无需重启服务

## 3. 数据模型

### 3.1 新增表 `cache_pricing_config`

```typescript
export const cachePricingConfig = pgTable(
  'cache_pricing_config',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    provider: text('provider').notNull(),           // 'openai' | 'anthropic'
    hitRatio: integer('hit_ratio').notNull(),       // 缓存命中比例，单位：千分比（例如 500 表示 50%）
    creationRatio: integer('creation_ratio').notNull(), // 缓存创建比例，单位：千分比
    isActive: boolean('is_active').notNull().default(true),
    effectiveFrom: timestamp('effective_from').notNull().defaultNow(),
    effectiveUntil: timestamp('effective_until'),
    createdAt: timestamp('created_at').notNull().defaultNow(),
    updatedAt: timestamp('updated_at').notNull().defaultNow(),
  },
  (table) => ({
    providerUnique: uniqueIndex('idx_cache_pricing_config_provider_active')
      .on(table.provider)
      .where(sql`${table.isActive} = true`),
  })
);
```

**设计说明：**
- `hitRatio` 和 `creationRatio` 使用 **千分比整数**（如 500 = 50%，1250 = 125%），避免浮点数精度问题，与现有定价表 `promptPricePer1kTokens` 为整数的风格一致
- 同一 provider 同一时间只能有一条 active 记录（partial unique index）
- 更新配置 = 创建新记录 + 停用旧记录，保留变更历史

### 3.2 类型导出

```typescript
export type CachePricingConfig = typeof cachePricingConfig.$inferSelect;
export type NewCachePricingConfig = typeof cachePricingConfig.$inferInsert;
```

## 4. API 接口设计

### 4.1 新增接口

#### GET /api/internal/billing/cache-config

获取当前生效的缓存比例配置。

**响应：**
```json
{
  "items": [
    {
      "id": "uuid",
      "provider": "openai",
      "hitRatio": 500,
      "creationRatio": 0,
      "effectiveFrom": "2026-04-25T00:00:00Z"
    },
    {
      "id": "uuid",
      "provider": "anthropic",
      "hitRatio": 100,
      "creationRatio": 1250,
      "effectiveFrom": "2026-04-25T00:00:00Z"
    }
  ]
}
```

说明：`hitRatio` / `creationRatio` 前端展示时需除以 1000 转换为百分比。

#### POST /api/internal/billing/cache-config

新增/更新缓存比例配置。

**请求体：**
```json
{
  "provider": "openai",
  "hitRatio": 400,
  "creationRatio": 0
}
```

**约束：**
- `hitRatio` 和 `creationRatio` 必须为非负整数
- `provider` 限定为已知值（如 openai、anthropic），但后端不做硬编码白名单，允许未来扩展
- 同一 provider 的已有 active 记录自动停用

**响应：** 新创建的配置记录

### 4.2 修改接口

#### GET /api/internal/billing/meta（已有接口，行为不变）

仍然返回当前生效的缓存比例，但来源从硬编码改为数据库读取。

**响应结构不变：**
```json
{
  "creditToRmb": 0.01,
  "rmbPer100Credits": 1,
  "platformMargin": 0.25,
  "cacheRatios": {
    "openai": { "hit": 0.5, "creation": 0 },
    "anthropic": { "hit": 0.1, "creation": 1.25 }
  }
}
```

说明：`hit` 和 `creation` 为浮点数，由数据库千分比 `/ 1000` 转换而来。

### 4.3 用户端接口（不变）

- `GET /api/billing/pricing`： 仍然附带 `cacheHitRatio` / `cacheCreationRatio` 字段供展示
- 前端展示行为不变

## 5. PricingService 修改

### 5.1 移除硬编码

```typescript
// 移除以下代码
const CACHE_RATIOS = {
  openai: { hit: 0.5, creation: 0 },
  anthropic: { hit: 0.1, creation: 1.25 },
} as const;
```

### 5.2 新增方法

```typescript
async getCacheRatios(provider: string): Promise<{ hit: number; creation: number } | null> {
  const config = await db
    .select()
    .from(cachePricingConfig)
    .where(and(
      eq(cachePricingConfig.provider, provider),
      eq(cachePricingConfig.isActive, true)
    ))
    .limit(1);
  
  if (config[0]) {
    return {
      hit: config[0].hitRatio / 1000,
      creation: config[0].creationRatio / 1000,
    };
  }
  
  // 回退到默认值（硬编码兜底）
  const defaults = {
    openai: { hit: 0.5, creation: 0 },
    anthropic: { hit: 0.1, creation: 1.25 },
  };
  return defaults[provider as keyof typeof defaults] || null;
}
```

### 5.3 初始化数据

在数据库迁移脚本中插入默认配置：

```sql
INSERT INTO cache_pricing_config (provider, hit_ratio, creation_ratio, is_active)
VALUES 
  ('openai', 500, 0, true),
  ('anthropic', 100, 1250, true);
```

确保现有部署升级时自动获得默认值，无需手动配置即可正常运行。

## 9. 风险

| 风险 | 影响 | 概率 | 应对 |
|------|------|------|------|
| 数据库配置缺失导致计费失败 | 高 | 低 | PricingService 保留硬编码默认值兜底 |
| 千分比转浮点数精度问题 | 低 | 中 | 所有计算使用整数运算，最后一步转浮点数 |
| 并发更新产生多条 active 记录 | 中 | 低 | 使用 transaction + partial unique index |
