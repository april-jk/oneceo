# 01_环境标识与调试开关统一方案_[20260504-0725已采用]

## 1. 背景与目标

当前系统缺少统一的“运行环境标识”，导致：

1. 前后端难以快速确认当前运行环境（dev/staging/product）。
2. 调试能力（如注册免邮箱验证码）缺少统一治理入口，容易散落在代码中形成不可控分支。
3. 后续新增调试能力时，缺乏规范化扩展方式。

本方案目标：

1. 增加一个统一环境变量，明确当前环境：`dev`、`staging`、`product`。
2. 以该变量为总开关，在 `dev` 环境启用调试特性（首个特性：注册免邮箱验证码）。
3. 设计“可扩展调试开关”结构，支持后续追加调试能力，不破坏现有逻辑。

---

## 2. 总体设计

### 2.1 核心环境变量

新增统一变量：

- `ONECEO_RUNTIME_ENV`

取值限制：

- `dev`
- `staging`
- `product`

默认值策略：

- 未配置时默认按 `product` 处理（安全优先）。
- 非法值一律回退 `product`，并记录告警日志。

### 2.2 运行时能力模型

新增运行时能力对象（仅设计，不代表本次立即实现全部能力）：

- `runtimeEnv`: `dev | staging | product`
- `debugCapabilities`: 基于 `runtimeEnv` 推导出的布尔能力集合

示例能力集合：

- `skipEmailVerificationOnRegister`：注册时跳过邮箱验证码（仅 dev=true）
- `allowDebugEndpoints`：允许调试端点（仅 dev=true，后续可用）
- `verboseSecurityLogs`：增强调试日志（dev=true，staging可按需）

设计原则：

- 业务代码不直接判断字符串 `ONECEO_RUNTIME_ENV === 'dev'`。
- 统一通过能力对象判断（例如 `capabilities.skipEmailVerificationOnRegister`）。
- 避免未来大量 if-else 环境分叉。

---

## 3. 首批落地范围（本期）

本期只落地以下能力：

1. 统一环境变量读取与合法性校验。
2. 对外暴露当前环境（用于 UI/日志/调试识别）。
3. 注册流程在 `dev` 环境跳过邮箱验证码校验。

### 3.1 注册免邮箱验证码（dev）规则

适用范围：

- 用户态注册主链路（app 用户注册流程）。

行为：

- `ONECEO_RUNTIME_ENV=dev`：注册不要求邮箱验证码。
- `ONECEO_RUNTIME_ENV=staging|product`：保持现有验证码机制不变。

约束：

- 仅跳过“验证码校验步骤”，不放宽其他校验（密码强度、邮箱格式、账号唯一性等保持不变）。
- 日志中记录本次是否由 dev 跳过验证码，便于审计。

## 4. 后续扩展设计（预留）

你提到“还有其他调试选项后续再想”，本方案提供扩展位：

### 4.1 推荐变量结构（后续可启用）

除 `ONECEO_RUNTIME_ENV` 外，预留：

- `ONECEO_DEBUG_FLAGS`（可选）

格式建议：逗号分隔 key

- 例如：`ONECEO_DEBUG_FLAGS=skip_email_verification,enable_debug_tools`

解析原则：

- 仅在 `runtimeEnv=dev` 下读取并生效。
- staging/product 即使配置也不生效（安全兜底）。

### 4.2 能力优先级

1. 环境总开关（`runtimeEnv`）
2. 具体 flag（`ONECEO_DEBUG_FLAGS`）

即：

- 非 dev 环境：所有 debug flag 无效
- dev 环境：按 flag 精细开启对应调试能力

---

## 5. 配置与展示规范

### 5.1 环境变量示例

开发环境：

```env
ONECEO_RUNTIME_ENV=dev
```

预发环境：

```env
ONECEO_RUNTIME_ENV=staging
```

生产环境：

```env
ONECEO_RUNTIME_ENV=product
```

### 5.2 管理后台显示建议

在管理后台全局信息区展示：

- 当前环境：`dev/staging/product`

展示规则：

- `dev`：可高亮提示“开发环境（调试能力可能开启）”
- `staging`：提示“预发环境”
- `product`：提示“生产环境”

---

## 6. 安全与风险控制

1. 默认回退 `product`，避免因漏配导致放宽安全策略。
2. 所有 debug 特性必须经过 `runtimeEnv=dev` 前置校验。
3. 对“跳过验证码”行为打结构化日志，便于追踪。
4. 禁止在前端单独决定安全策略，最终以后端能力判断为准。

---

## 7. 实施步骤（待你确认后执行）

1. 在 API 配置层新增 `ONECEO_RUNTIME_ENV` 解析与能力对象。
2. 在注册流程中接入 `skipEmailVerificationOnRegister` 能力判断。
3. 增加一个只读环境信息接口（供管理后台展示，可选）。
4. 管理后台展示当前环境标识。
5. 补充单元测试：
   - dev 下注册可跳过验证码
   - staging/product 下必须验证码
   - 非法 env 值回退 product

---

## 8. 验收标准

1. 设置 `ONECEO_RUNTIME_ENV=dev` 时，注册可不填验证码完成。
2. 设置 `ONECEO_RUNTIME_ENV=staging|product` 时，注册仍需验证码。
3. 环境值非法时行为等同 `product`。
4. 日志可追踪“是否跳过验证码”决策。
5. 管理后台可见当前环境标识（若你同意本期一并做展示）。

4. 是否同步引入 `ONECEO_DEBUG_FLAGS`（可以先预留不启用）。
