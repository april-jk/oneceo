## 1. 背景与问题

你当前要求是：

1. Supabase MCP 接入方式对齐 Manus
2. 用户只需要填写 Token 即可使用
3. 不再要求 Project Name / Project Ref / Profile Name / Display Name 等附加参数

当前 oneceo 的 Supabase 实现仍要求 `projectRef`，导致和目标体验不一致：

1. 连接器定义中把 `projectRef` 设为必填
2. 运行时构建 URL 时强制校验 `projectRef`，缺失直接报错
3. 用户引导文案也默认要求先复制 project ref 再保存

结果是：

1. 用户配置步骤比 Manus 多
2. 首次连接成功率下降
3. 文案与目标产品心智不一致

## 2. 目标

本次只实现一个目标：

1. Supabase 连接器改为仅凭 Token 即可完成 MCP 接入与使用

并满足以下验收条件：

1. 创建/编辑 Supabase Profile 时不再要求 `projectRef`
2. 创建/编辑 Supabase Profile 时，`profileName` 与 `displayName` 均可留空
3. 运行时不再因为缺少 `projectRef` 报错
4. MCP remote URL 不再拼接 `project_ref` 查询参数
5. 会话 attach 后仍可正常完成工具发现与调用
6. 连接器引导文档更新为仅 Token 心智

## 3. 非目标

本次不做：

1. 不新增 Supabase OAuth 流程
2. 不改动 GitHub、Vercel、Figma 等其他连接器行为
3. 不改造连接器中心整体交互结构
4. 不引入新的数据库表或迁移脚本

## 4. 对齐 Manus 的目标行为

目标交互（对齐 Manus）：

1. 用户打开连接器中心，选择 Supabase
2. 仅填写 `accessToken`
3. 点击保存后即可 attach 到会话
4. 会话内 MCP 工具可直接调用

不再要求：

1. Project Ref
2. Project Name
3. Profile Name
4. Display Name
5. 其他项目级识别参数

## 5. 现状差异点（需改造）

### 5.1 后端定义层

当前 Supabase 定义中：

1. `configFields` 包含 `projectRef`
2. `projectRef` 是 `required: true`
3. `profileName` 当前为必填

目标改造：

1. 从 Supabase `configFields` 删除 `projectRef`
2. 保留 `accessToken` 必填
3. `profileName` 改为非必填（留空由后端默认命名）
4. `displayName` 继续保持非必填

### 5.2 后端运行时装配层

当前运行时 URL 构建中：

1. Supabase 分支会读取 `projectRef`
2. 缺失时抛错：`Supabase 连接器缺少 project ref`
3. 存在时拼接 `?project_ref=...`

目标改造：

1. 移除 Supabase 对 `projectRef` 的强校验
2. 移除 `project_ref` URL 参数拼接
3. Supabase URL 固定为 `https://mcp.supabase.com/mcp`（或环境变量覆盖后的 URL）

### 5.3 前端引导与文案层

当前文案强调：

1. 先去 Supabase 控制台复制 project ref
2. 配置时必须填写 project ref + token

目标改造：

1. 指南改为“仅 token 必填”
2. 相关示例模板从 `project_ref=...` 改为 token 场景

### 5.4 Supabase 隐式 Skills 挂载链路评估

检测结论：

1. 隐式 skills 挂载机制本身不需要修改
2. 挂载/阻断/解锁链路按 `connectorKey` 工作，不依赖 `projectRef`
3. 需要修改的是连接器定义、runtime URL 装配和测试 fixture，不是 guide 挂载主逻辑

已核查实现点：

1. `apps/api/src/services/connector-guide-service.ts`
2. `apps/api/src/services/altus-managed-tool-runtime.ts`
3. `apps/api/src/services/altus-managed-prompt-service.ts`

可选微调（非必改）：

1. 仅对 Supabase guide 文案做措辞同步，明确“依然需要确认目标项目范围，但不再要求配置阶段填写 projectRef”

## 12. 2026-04-03 OSAC 超时治理补充

为解决 `CONNECTOR_ATTACH_PROVIDER_FAILED` 中的 `OSAC 请求超时`，在不改变主链架构前提下补充以下最短路径改造：

1. `apps/api/src/services/sandbox-runtime-metadata-service.ts`
	- 将 `waitForOsacBridgeReady` 从异步 fire-and-forget 改为同步 `await`。
	- bridge 未 ready 时直接失败返回，避免后续 attach 提前打到未就绪链路。
2. `apps/api/src/config/osac-config.ts`
	- 默认 `OSAC_REQUEST_TIMEOUT_MS` 从 `20000` 提升到 `60000`。
3. `apps/api/src/services/session-connector-service.ts`
	- 在 `REGISTER_MCP_PROVIDER` 与 `ATTACH_MCP_PROVIDER_TO_SESSION` 阶段增加“仅超时错误”单次重试。
	- 增加分阶段耗时与重试日志，便于定位慢点。
4. `apps/api/src/routes/task-creation-routes.ts`
	- attach 路由遇到 OSAC 超时时返回 `504`，不再归为泛化 `400`。

说明：本补充只处理 OSAC attach 超时窗口，不扩展到其他连接器业务语义变更。

## 13. 2026-04-03 / 2026-04-04 Supabase MCP 代理补充

在保持其他连接器行为不变的前提下，Supabase MCP 远端传输使用 `streamable_http`，并增加代理环境变量透传：

1. 仅当 `connectorKey === supabase` 时生效。
2. 读取 `.env` 中现有代理配置：
	- `ONECEO_PROXY_ENABLED`（未配置时按开启处理）
	- `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`
3. 透传到 transport `env`：
	- `HTTP_PROXY` / `http_proxy`
	- `HTTPS_PROXY` / `https_proxy`
	- `NO_PROXY` / `no_proxy`
4. 其他连接器的 remote 传输 `env` 保持不变。
5. attach 回包若为 `failed_to_attach/attach_failed`，直接落失败状态并保留回包 `errorMessage` 作为 `lastError`，不进入泛化错误覆盖分支。
