## 1. 新增表：api_request_logs

记录用户端 Web App → API Server 的所有 HTTP 请求。

### 1.1 Schema（Drizzle ORM）

```typescript
// apps/api/src/db/schema.ts
export const apiRequestLogs = pgTable(
  'api_request_logs',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    appUserId: uuid('app_user_id').notNull(),
    // 请求基本信息
    method: text('method').notNull(),           // GET, POST, PUT, DELETE 等
    path: text('path').notNull(),               // /api/task-creation/sessions
    queryString: text('query_string'),          // 脱敏后的 query string
    // 请求内容（脱敏后）
    requestHeaders: jsonb('request_headers').default(sql`'{}'::jsonb`),
    requestBodySummary: text('request_body_summary'), // 关键字段摘要，JSON 字符串
    // 响应内容（脱敏后）
    responseStatus: integer('response_status'),
    responseBodySummary: text('response_body_summary'), // 关键字段摘要，JSON 字符串
    // 性能与上下文
    durationMs: integer('duration_ms'),
    ipAddress: text('ip_address'),
    userAgent: text('user_agent'),
    // 关联会话（如果请求中涉及 session）
    taskSessionId: uuid('task_session_id'),     // 从请求参数或响应中提取
    // 元数据
    metadataJson: jsonb('metadata_json').default(sql`'{}'::jsonb`),
    createdAt: timestamp('created_at').notNull().defaultNow(),
  },
  (table) => ({
    userIdx: index('idx_api_request_logs_user_id').on(table.appUserId),
    userCreatedAtIdx: index('idx_api_request_logs_user_created_at').on(table.appUserId, table.createdAt),
    pathIdx: index('idx_api_request_logs_path').on(table.path),
    statusIdx: index('idx_api_request_logs_status').on(table.responseStatus),
    sessionIdx: index('idx_api_request_logs_session_id').on(table.taskSessionId),
    createdAtIdx: index('idx_api_request_logs_created_at').on(table.createdAt),
  })
);
```

### 1.2 设计说明

| 字段 | 说明 | 保留策略 |
|---|---|---|
| `requestHeaders` | 完整 headers（脱敏后），JSON 格式 | 保留 |
| `requestBodySummary` | 仅保留关键字段摘要（如 sessionId、title 等），不存完整 body | 保留 |
| `responseBodySummary` | 仅保留关键字段摘要（如 id、status、error 等） | 保留 |
| `metadataJson` | 扩展字段，如 traceId、source（web/desktop）等 | 保留 |

**不存储完整 req/res body 的原因**：
- 用户上传的附件、图片 base64 等大体积数据会导致表膨胀
- LLM 流式响应体可能达数 MB
- 关键信息摘要已足够满足审计需求

## 2. 复用表：session_api_traces

现有表结构不做修改。需要补充的能力：

### 2.1 按用户 JOIN 查询

`session_api_traces` 有 `sessionId`，`task_creation_sessions` 有 `userId`，可以通过 JOIN 实现按用户查询：

```sql
SELECT t.*
FROM session_api_traces t
JOIN task_creation_sessions s ON t.session_id = s.id
WHERE s.user_id = $1
ORDER BY t.created_at DESC
LIMIT $2 OFFSET $3;
```

### 2.2 索引检查

现有索引已覆盖：
- `idx_session_api_traces_session_id`（sessionId）
- `idx_session_api_traces_session_type`（sessionId + traceType）
- `idx_session_api_traces_created_at`（createdAt）

需要新增（可选）：
- `idx_task_creation_sessions_user_id`：如果 `task_creation_sessions.user_id` 上无索引，需补充
