## 3. 核心断言

### 3.1 用户态 API

1. 发送注册验证码成功后返回 `success: true`，且不写入 `app_session_v2_id` cookie
2. 已注册邮箱请求发送验证码时返回 `400`
3. 注册成功后返回 `success: true`、用户公开信息，并写入 `app_session_v2_id` cookie
4. 注册失败时返回 `400`，不写入成功 cookie
5. 缺少验证码、验证码错误、验证码过期或验证码已消费时，注册必须返回 `400`
6. 登录成功后返回用户公开信息，并写入 `app_session_v2_id` cookie
7. 登录失败时返回 `400`
8. 登录成功后同时写入 `app_session_v2_state=authenticated` 辅助状态 cookie
9. `/session` 在无 cookie 时返回 `200 + authenticated:false`
10. `/session` 在有效 cookie 且中间件已解析用户后返回 `200 + authenticated:true + user`
11. `/me` 在无 cookie 时返回 `401`
12. `/me` 在有效 cookie 且中间件已解析用户后返回当前用户
13. 登出会同时清理 `app_session_v2_id` 与 `app_session_v2_state`，并尽量清理旧的 `app_session_id` 与 `app_session_state`
14. 浏览器可见页面协议为 `http` 时，即使反向代理头携带 `x-forwarded-proto=https`，也不能把 `app_session_v2_id` 写成 `Secure`，否则后续 HTTP 同源请求不会回传 cookie
15. 浏览器可见页面协议为 `https` 时，`app_session_v2_id` 与 `app_session_v2_state` 都必须写为 `Secure`
16. 会话 cookie 必须统一收口 `SameSite/Path/Expires/Max-Age/Priority`
17. 服务端必须兼容读取旧的 `app_session_id` / `app_session_state`，避免已经建立的旧会话立刻失效
18. 浏览器存在旧的 `Secure app_session_id` 时，HTTP 登录仍必须成功；正式做法是切换到新的 `app_session_v2_id` / `app_session_v2_state`，不能继续复用旧 cookie 名称
19. `POST /api/auth/legacy-client-id` 在未登录时必须返回 `401`
20. `POST /api/auth/legacy-client-id` 在已登录且携带合法 legacy id 时，必须 upsert `app_user_legacy_id_mappings`
21. `POST /api/auth/legacy-client-id` 在绑定成功后必须立即执行 legacy 会话回绑，避免前端继续通过 `X-Legacy-User-Id` 常驻透传
22. `task-creation` 等用户态业务路由不得再接受 `X-Legacy-User-Id` 或 `legacyUserId` query 作为授权输入
23. `POST /api/auth/login`、`POST /api/auth/register`、`POST /api/auth/logout`、`GET /api/auth/session`、`GET /api/auth/me` 必须显式返回 `Cache-Control: private, no-store, max-age=0`
22. 上述认证接口必须带 `Pragma: no-cache`、`Expires: 0` 与 `Vary: Cookie, Origin`，避免匿名态或旧登录态被缓存复用

### 3.2 API 内部管理员认证

1. `ONECEO_INTERNAL_TOKEN` 未配置时返回 `403`，不能把内部接口退化为匿名可访问
2. token 已配置但未携带或携带错误 `x-oneceo-internal-token` 时返回 `401`
3. 内部管理员登录成功返回 `sessionToken` 和 `adminUser`
4. 内部管理员登出成功返回 `ok: true`
5. 会话解析成功返回 `adminUser`
6. 会话失效时返回 `401`

### 3.2.1 API 其他内部管理接口

1. `ONECEO_INTERNAL_TOKEN` 未配置时返回 `403`
2. token 已配置但缺失或错误时返回 `401`
3. 只有携带正确 `x-oneceo-internal-token` 时才允许访问
4. 不允许复用用户态 owner 校验接口作为内部接口的匿名兜底

### 3.3 管理端代理接口

1. 管理员登录成功时写入 `admin_session_id` cookie，并只返回公开管理员信息
2. 管理员 `/me` 在无 cookie 时返回 `401`
3. 管理员 `/me` 在有效 cookie 时返回公开管理员信息
4. 管理员登出会清理 `admin_session_id` cookie，并透传调用后端登出
5. `apps/admin_management` 启动前必须校验 `ONECEO_INTERNAL_TOKEN` 为非空；不允许在缺少内部 token 的情况下继续启动并把所有内部代理请求推迟到运行期失败

### 3.4 用户态任务会话与 workspace 接口

1. 会话创建时数据库归属必须写入当前登录用户 `userId`
2. 会话列表在未登录时返回 `401`
3. 会话列表只返回当前用户拥有的会话，不能泄漏其他用户 session
4. workspace 目录读取在跨用户访问时返回 `403`
5. 会话列表缓存必须按用户隔离，不能继续共享全局缓存

### 3.5 用户态连接器个人配置接口

1. `/api/connectors/me` 在未登录时返回 `401`
2. `/api/connectors/me` 只能返回当前用户的 profiles
3. 创建连接器 profile 时必须把当前用户 `userId` 传入服务层

### 3.6 用户态深水区会话接口

1. 所有用户态会话接口在未登录时必须返回 `401`
2. 所有 owner 路由在跨用户访问时必须返回 `403`
3. `skills`、`runtime-config`、`draft session` 必须从当前登录用户身份派生，不能再依赖浏览器伪身份
4. `title/favorite/detail/messages/intent/task-description/execution-plan/delete` 必须先校验 `session.userId`
5. `attachments`、`deliverables`、`runtime`、`session connectors`、`debug`、`deployment`、`database rows` 必须先校验会话连接器 owner 边界
6. `workspace/raw` 与 `opencode/events` 不能绕过 owner 校验直接读取 runtime

### 3.7 Altus managed 用户态接口

1. `inputs`、`runs/latest` 在未登录时必须返回 `401`
2. `inputs`、`runs`、`stop` 必须把当前用户 `userId` 透传到 service
3. `run stream` 必须按当前登录用户校验 `run.sessionId -> session.userId`
4. `run stream` 不再接受查询参数伪造 `userId`

## 5. 通过标准

1. 所有接口至少覆盖一条成功路径
2. 所有鉴权接口至少覆盖一条未授权路径
3. 所有会话接口至少覆盖一条会话失效路径
4. 所有登录/登出接口必须断言 cookie 写入或清理行为
5. 用户态业务接口需要覆盖全部已暴露 HTTP 路由，至少有一条成功或拒绝路径
6. 对 owner 路由，必须至少覆盖一条跨用户拒绝路径
