# 13_默认会员初始化与权益同步闭环 [20260529-0053已采用]

## 1. 背景

会员管理已经具备会员类型、用户会员、默认积分和每日恢复字段，但默认会员配置依赖后台手动创建，不能保证每个环境天然存在同一套默认权益。

本次收口的是默认会员的完整闭环：

1. 新环境必须自动具备默认会员类型
2. 默认会员后续被后台更新时，注册默认用户必须继续跟随最新默认会员状态
3. Agent 等级配置必须在任务运行入口真实生效

## 2. 默认会员基线

系统初始化默认会员类型使用稳定 code：`default`。

首次缺失时创建：

1. 名称：`默认会员`
2. 初始积分：`500`
3. 每日自动恢复：开启
4. 每日恢复积分：`100`
5. 允许 Agent 等级：仅 `lite`
6. 会员权益：`Agent lite`
7. 状态：`active`
8. 是否默认：`true`

如果默认会员已存在，启动检查只保证默认会员存在，不覆盖后台已经调整过的积分、每日恢复和 Agent 权益配置。

## 3. 用户同步规则

当后台把另一个会员类型设为默认会员时，服务层必须在同一事务内同步所有仍属于注册默认来源的用户会员。

命中条件：

1. `user_memberships.status = active`
2. `user_memberships.source_type = register_default`
3. 当前 `membership_plan_id` 属于被替换的旧默认会员类型

同步行为：

1. 直接更新这些用户会员的 `membership_plan_id` 到新的默认会员类型
2. 不重新发放默认积分
3. 写入会员审计日志
4. 不覆盖管理员手动分配、激活码、付费升级等非注册默认来源的用户会员

## 4. Agent 权益校验

任务运行入口必须根据当前用户 active membership 对应 plan 的 `allowed_agent_levels_json` 校验请求的 Agent tier。

规则：

1. 无 active membership：拒绝使用 Agent
2. 请求 tier 不在允许列表内：拒绝，并返回当前会员允许的 Agent 等级
3. 默认会员基线只允许 `lite`

覆盖入口：

1. 用户直接提交 Altus managed run
2. Task creation 执行交接到 Altus managed run

## 5. 初始积分解释

`default_credits` 是注册绑定会员时的一次性初始发放值。

默认会员后续更新时，现有默认用户的会员权益和每日恢复配置应跟随最新 plan；不自动追加或重发初始积分，避免后台修改权益时造成重复赠送。

如后续产品规则要求“余额低于新默认初始值时补足”，应作为独立积分补偿规则设计，不混入默认会员同步链路。

## 6. 验证要求

至少覆盖：

1. 默认会员初始化检查会在数据库 bootstrap 完成后执行
2. 新用户仍通过默认会员发放初始积分
3. 默认会员切换时只同步 `register_default` 来源的 active 用户会员
4. 默认会员更新不重复发放初始积分
5. 默认会员只允许 `lite` 时，请求 `pro/max` 被拒绝
6. 管理后台新增会员类型表单默认值与默认会员基线一致
